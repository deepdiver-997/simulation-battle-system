## 1. 变威力（★ 核心，多处引用）—— **已落地 2026-09-14（场景 043）**

> **实现口径**（详见 `docs_local/docs/02-效果系统/技能判定流程与无效效果体系.md` §8.7）：
> - 触发 = "威力被**改过**"，不是"变了" → `ws.skill_power_view` 换成带 `rewritten` 标记的
>   `SkillView`，`operator=`/`operator+=` 自动置位（写 0 也算）；
> - 落点 = `apply_variable_power_recalc`（ATTACK_DAMAGE 桶**之后**、伤害管线**之前**）——
>   **管线仍只跑一遍**，绕开"跑两遍就错"的效果（次数免伤扣次数 / 概率挡伤重掷 / 粉伤重打）；
> - 暴击**不**重掷（`ctx->crit_happened` 一次技能只掷一次），伤害浮动 `rand()` **重掷**（用户裁定）；
> - 唯一肉眼可见后果：**暴击破防只对变威力技能生效**（非变威力本次伤害在破防前已算完）。
> - **effect 2501 已落地**（2026-09-14，场景 046）：「技能无效时，重新进行伤害结算且自身每有
>   260 点特攻值威力翻倍1次」= **SKILL_INVALID 分支**的效果在 SKILL_EFFECT 时点改写视图威力，
>   被 `handle_*_AttackDamage` **早退出口**的变威力检查点抓到 → 隔着盔重算并打出红伤。
>   ⚠️ 只对"带变威力词条"的技能生效（无标记时无效就是零伤害）。

**定义**：变威力 = **推翻第一次的初始伤害计算，重新计算第二次**，第二次**覆盖**第一次。

`L453`《【赛尔号】机制解析—变威力》`//www.bilibili.com/opus/791433890174599175`：
> 「变威力效果：在结算带有变威力效果的时候，会将**第一次的初始伤害计算推翻，重新计算第二次**的初始伤害，
> 在这个第二次结算的时候，会有许多东西被重新结算。」
> 「②在进行2次伤害计算的时候，敌我双方的**能力等级（双攻能力等级和双防能力等级，包含暴击破防）、
> 属性克制系数和技能威力**会进行一个重新计算，导致第2次计算造成的伤害会比第1次计算的伤害更高或者更低。
> ③这也就导致了第2次公式结算的时候，**会覆盖第1次的公式结算**。」

`L418`《【赛尔号】赛学必修4—变威力》`//www.bilibili.com/opus/857615264348373011`：
> 「变威力技能本质上就是推翻第1次的伤害计算，进行第2次的伤害计算。在进行第2次伤害计算时，
> 也许会出现跟第1次计算伤害的变量不同。」

**官方对「威力」的定义**（`L128`《官方名词解释—1》`//www.bilibili.com/opus/1156292190671994916`）：
> 「威力: "当命中效果对技能威力值进行修改时，**会以当前状态重新进行伤害结算覆盖原本的伤害值**"」

- `L173`《机制解析—乔列尼德》：「这个效果**就算是0连击，他也是变威力效果**」。

## 2. 连击（"一回合做 x~y 次攻击"）—— **已落地 2026-09-14（场景 044）**

> **实现口径**（详见 `docs_local/docs/02-效果系统/技能判定流程与无效效果体系.md` §8.8）：
> - `Skills::combo_min/combo_max` 从技能自己的 `side_effect` 参数解析（`combo_arg_indices` 开关表：
>   多数是 `{0}-{1}`，**1172/1577/1627** 是 `{0}回合做{1}-{2}` → 下标 +1）；**不碰文本**。
> - 每次技能使用掷一次 → `ws.combo_view[owner]`；区间退化 1~1 短路不消耗 `rand()`。
> - `×N` 打在 `stage_simple_attack_damage` 的 `base` 上、**暴击之后** → 增伤/减伤/护盾/
>   次数型免伤全部作用于**总数**（"一次公式 ×N"的官方语义）。
> - **N>1 本身即变威力** → 走第二次结算 → 连击吃得到暴击破防（044 C4：N=3 ≈ N=1 的 6 倍）。
> - **仍未做**：动态加数（1108/484/1795/1863/1930）、连击上限修正
>   （1500/1546/1577/1593/1627/1666/1685）、逐段子效果（"每次攻击有X%概率…"）、
>   无参数常量（1608/1609/1610）。`EffectMeta` 已补 `EffectCategory::Combo` 标注这 20 条模板。
> - **`moves.atk_num` 明确不碰**：用户 2026-09-14 判读为**不是段数**（极电千鸟 atk_num=5
>   疑为"命中后 5% 令对方麻痹"这类老旧异常施加字段）。

### 2.1 官方口径原文

`L101`《【赛尔号】赛学扩展4—连击计算（新）》`//www.bilibili.com/opus/1173979935440633860`：
> 「现在的连击计算调整
> `[(攻击方的等级×0.4+2)×技能面板威力×攻击方的攻击÷防御方的防御÷50+2]×本系修正×克制系数×(217~255)÷255×暴击抗性×暴击系数×连击次数`
> 该公式计算均需向下取整，方括号内属于一个整体不可拆分…对于能力等级导致的面板值需要自行提前换算」

`L99`《关于暴击对连击的影响》`//www.bilibili.com/opus/1174125414592806935`：取整顺序为
「浮动前一大段取整，浮动计算后取整、**暴击系数计算后取整**、抗性计算后取整、**连击次数取整**」。

**结论**：
- **暴击/浮动整段共用一次判定**（不是每段各掷一次）——与用户 2026-09-13 定的"一次技能使用掷一次"一致 ✓
- 每段威力 = 同一个**面板威力**，不逐次变化
- 那个 `+2` 常数修复后也吃连击次数（`L102`：90 连击相当于多 180 点初伤）

**用户 2026-09-14 的裁定（把它与变威力合并起来）**：
> 「文章说的应该是**先破防，然后再次按照单次暴击计算伤害，然后 ×N**，和我的说法不冲突」

即：`算第一次 → 破防 → 按归零后的双防重算单次 → ×连击次数`。

⚠️ **已落地**（场景 043 变威力 + 场景 044 连击）：`算第一次 → 破防 → 按归零后的双防重算单次
→ ×连击次数` 这条流水线现在完整了。
`月下伏` / `重新结算` 在语料里**都没有命中**，所以具体某个技能走哪套仍需游戏内确认。

## 3. 增减伤时点（★ 犀牛那条）—— **阶段骨架已落地 2026-09-14（场景 045）**

> **实现口径**（详见 `docs/02-效果系统/效果系统内核设计.md` 与场景 045）：
> - `DamagePhase` 重排为 10 阶段：`GUARD_DETECT → AMP → AMP_EXTRA → REDUCE_FLAT → REDUCE_PCT
>   → FLOOR → CAP → BLOCK → DETECT → FINAL_CORRECT`。**`kOrder` 是可改常量——顺序即机制。**
> - `GUARD_DETECT`（犀牛检测）在链首看到**未增伤**的值 → 之后被 693/保底抬起来的伤害它看不到
>   ——「693 增伤乱穿犀牛」「保底不触发超350回满」两条现象由此**结构性**成立（场景 045 P7）。
> - 增伤分两条通道：`AMP`（通用·**加法**，`damage_add_pct`）/ `AMP_EXTRA`（非通用·**乘法**，
>   `damage_add_extra_mul`）。判据 = 文本里的"**额外**"。**693 已迁到乘法通道**（776「翻倍」不带
>   "额外" → 留在加法通道）。
> - 减伤分两条：`REDUCE_FLAT`（点数 `damage_reduce_flat`）/ `REDUCE_PCT`（百分比 add+mul）。
> - `FLOOR`（保底）在减伤之后、`CAP`（锁伤）之前；**锁伤最后再拦一次**。
> - **犀牛 / 693 端到端已落地**（2026-09-14，场景 049）：魂印 **1217**（`effect_icon` pet_id=[3637]
  不灭地威·萨瑞卡）实现受击两分支 ——
  · 判定值 = **链首快照** `ws.guard_detect_damage`（新：core 的 `install_default_damage_guard_detect`
    在 GUARD_DETECT 阶段写，**含暴击与暴击抗性减免、未含任何增伤/减伤**）；
  · 回血/反弹挂 **EVENT_TAKE_DAMAGE**（伤害落地之后）—— `_AFTER_ACTION` 那些时点的桶只跑当回合
    mover 一侧，犀牛作为非 mover 时不执行（谱尼虚无同款坑）；
  · 回满血走 `heal_amount` **原语**（吃封回血/恢复修正），旧的 `heal_to_full`（直写 hp）已删。
  · 实测：693（AMP_EXTRA）把实际伤害从 ~250 顶到 **440**，犀牛**不回满** = "693 乱穿犀牛" ✓；
    暴击把裸伤顶过 350 → **照样回满**（检测含暴击）；必暴 + 100% 暴击抗性 → 链首值回到 ~232
    → 不回满（**暴击抗性参与判定**）。
  · 待做：魂印 1217 的第三条「回合开始时令自身双防+1、速度+1、对手双防-1、速度-1」。
- **仍未做**：FLOOR / CAP 的具体效果（保底/锁伤）（阶段在、零注册）；**实现锁伤时必须消费 697
>   `ignore_damage_limit` 凭证**（现在是死凭证）；护盾/护罩是否挪进管线**待实测**（官方两处说法
>   不一致）；粉伤通道**完全不过管线**（无减伤/锁伤/保底）；犀牛 350 / 坚硬 / 反伤的具体实例。

| 通用/非通用增伤的加/乘 | 未区分 | `ws.damage_add_pct` 是加法；非通用需另设乘法通道 |

## 4. 附带：effect 854「令对手下1次使用的威力高于{0}的攻击技能无效」—— **已落地 2026-09-14（场景 050）**

**技能**：天叶领域 24560（`side_effect=[532,191,854]`，args 含 120）、余温之辰 26170（`[191,1065,854]`，同一阈值 120）。

**用户口径（2026-09-13）**：检测的是**面板威力**（`moves.power`）——
**威力宝石的加成不会被检测到**，也不看 `ws.skill_power_view`。

**用户给的实现方向（2026-09-13 + 2026-09-14 追加）**：
1. 注册一个**随切换失效**的监听器（`EffectScope::ON_STAGE`）。
2. **每次对手选完技能后**检查其面板威力，>120 就**消耗自己**并注册一个**当回合生效的狮盔**。
3. 2026-09-14 追加疑问与方案：
   > 「应该要**确保对手本回合会出手**才注册当回合盔吧，要不然不是白瞎浪费？
   > 或者也注册一个事件监听，如果触发了就撤销之前的"监听威力大于120"的监听器，否则不触发？」

**★ 已解决（2026-09-14）**：原来那两个方案（"选完技能后注册当回合狮盔 + 事件撤销监听器" /
"确保对手本回合会出手"）**整个不需要**——854 是**条件盔**，直接复用 `RuleTicket::condition`：
- `RuleCenter::notify` 对**条件不满足的条目是"跳过、不消耗"**，于是
  威力 ≤阈值 的攻击技能 / 属性技能 / 本回合没出手（被控·换宠·notify 根本没跑）**都不会白白吃掉它**；
- 判定时机 = **对手真正使用技能时**（`query_usage` 的门判定），正是"下1次**使用**"的字面语义；
- 判据 = `notify` 传来的 **`Skills::power`（面板威力）**，不是 `ws.skill_power_view`
  （用户 2026-09-13 口径：威力宝石/变威力类改的是视图，条件盔看面板）。
- 为了让条件拿得到这两个值，`RuleTicket::condition` 的签名从 `(ctx, attacker, defender)`
  扩成 **`(ctx, user, power, is_attribute_skill)`**（原先无人使用，改动零影响）。
- `penetrable=false`（条件盔 = 龙威一侧，699 穿盔凭证也穿不过去）；`scope=ON_STAGE` 随切换失效。
- 实测（场景 050）：150 被拦且消耗 / 35 与属性技能与边界 120 都不拦不消耗 / 带 699 仍被拦 / 施放方换宠即清。
