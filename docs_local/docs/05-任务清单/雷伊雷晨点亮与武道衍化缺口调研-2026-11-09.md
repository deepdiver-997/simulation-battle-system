1. **「雷晨点亮」定位闭环**：官方名**雷辰**，机制本体=效果 **2289**（威力变体，

   同族还有 **2290**（全属性变体，唯一载体 29044 雷·天霆之怒）与 effect_des 444/445/568
   （雷辰/觉醒状态/辰律三词条）。主库+20261022 备库切片逐字一致；registry 1520 无 2289/2290。
2. **武道衍化「2292 缺口」记档已过期**：e_block_family.cpp:30 的跳过记档（2026-09-29）
   已被 **J11（feat/j11 0b66631，2026-10-02）取代**——2291/2292/2293/2294/2298/2300/2301/779
   八宏全部落地且在 registry（2291-2294 在册，主 checkout build/registry.json 现读）。
   盘点文档 §3.2「武道衍化 ❌ 全族」（eb9fb8c7，10-01）早于 J11 收官，属**过期标记**。
3. **真缺口是存储粒度，不是状态机**：J11 姿态/账本/进化次数/武装旗五键族存 **battle 全局
   plugin_storage、按 side 键入**（j_gaia_stance.cpp:63-68），换宠不清（头注:27 自记
   「换宠不清——boss 战无换宠交互，记档」）——与用户要求的下场重置语义直接冲突；且武装旗
   同样不清，换宠后再登场**不会重武装** CAP/BLOCK 记账观察者（观察者本体已随
   `invalidate_on_stage_effects` 的 pipeline epoch 作废，battleContext.h:1123）——现 scope
   （无换宠）下未炸，补换宠用例即炸的**潜伏缺陷**。
4. **用户预判裁决：成立**。引擎原生 per-pet 双槽
   `ElfPet::soulmark_storage`（下场保留）/ `ElfPet::on_stage_storage`（本次上场，引擎自动清）
   （elf-pet.h:202-210）；`perform_switch` 是主动中切与死亡换宠的**共同漏斗**，在其中
   `old_pet.on_stage_storage.clear()`（battleFsm.cpp:609、629 注）。雷辰点亮状态进
   on_stage_storage = 「上下场刷新从头开始」**零内核支持**；武道衍化修正=J11 五键族迁
   `pet.on_stage_storage`，**纯插件改动**。
5. **雷辰的下场语义与武道的下场重置同理由双槽解决**：两者都不需要下场事件监听、不需要
   内核新通道。J11 的「换宠不清」是当时的有意 scope 裁定，修正路径是迁槽，不是补内核。

### 2.3 pet storage 粒度验证（用户预判的核）

- **双槽语义（引擎一等支持，elf-pet.h:202-210）**：
  ① `soulmark_storage`——**下场保留**（跨回合+跨切换，随 pet 对象存活；阵亡/战斗结束随 pet
  销毁）；② `on_stage_storage`——**本次上场**（换宠由引擎清空）。头注明写「选错槽的后果是
  静默的」，即生命周期由**选槽**决定，无需效果侧自理。
- **自动清理点（无需任何效果侧代码）**：`perform_switch`（battleFsm.cpp:580）内
  `old_pet.on_stage_storage.clear()`（:609）；该函数是**主动中切与死亡换宠的共同漏斗**
  （:629 注），两路都清。战斗结束/清场 `clearAllEffects` 双槽全清（battleContext.h:1195-1196）。
  soulmark_storage 只有 clearAllEffects 清（:1195），下场/阵亡保留。
- **插件直取先例（零内核改动即用）**：crawford_runtime.h:8-13——构造点亮位图放
  on_stage_storage，「换宠由引擎清空=『构造数下场重置』天然成立，无需手动复位」；跨插件
  只走 fundamental type（int 位图）的 any_cast 纪律同文件:11-13。gaia_runtime.h（圣甲·盖亚
  3056）soul/on_stage/plugin 三槽分置同款。反例护栏：abnormal-types.h:295-297——
  「不能放 on_stage_storage（下场清）」的场景选择清单。
- **结论（预判裁决）**：
  - 「雷晨点亮其实不需要内核支持吧，自己存 pet 的 storage 里面状态就行了」——**成立**。
    雷辰点亮计数/连线序列是典型「本次上场」状态，`pet.on_stage_storage` 原生满足；
    Crawford 构造点亮是同形先例。
  - 「雷伊的有上下场刷新从头开始」——**成立且有引擎级保证**：on_stage_storage 在
    perform_switch 漏斗自动清，主动切换与死亡换宠全覆盖，无需挂任何下场事件。
  - 武道衍化：J11「换宠不清」是有意 scope 裁定而非内核缺失；修正=**五键族迁
    `ctx->getPet(side).on_stage_storage`**（getPet(side)=该方在场宠；2291-2294 使用时点
    使用者必在场），armed 旗随槽清，再登场自动重武装观察者。若官方语义实为「下场保留轨迹」
    （无证据支持），则改投 soulmark_storage——同样是迁槽，无内核工作。**两案均零内核影响**。
