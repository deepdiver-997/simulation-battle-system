# 开工：异常状态系统（扣血分档 / 限制切换 / 限制附加 / 自我衍化）

> 建于 2026-09-18。工作区 `agents/anomaly`，分支 `feat/anomaly`，基线 `main-local`。
> 台账入口见 `docs_local/agents/README.md` 的"异常状态系统"行。
>
> **本线要解决的四个问题（用户 2026-09-18 提出）**：
> 1. 异常状态的扣血**大多是真实伤害结算** —— 现有实现是"裸 `pet.hp -=`"，既不分档也不进管线；
> 2. 异常状态**影响切换** —— 凝滞、瘫痪下无法主动切换；瘫痪还无法行动；
> 3. 异常状态**影响异常附加** —— 凝滞下无法受到控制类异常、只能受非控制类（如烧伤），但主动/被动毒无法免疫；
> 4. 异常状态**会自我转化** —— 焚烬回合结束转化为烧伤 + 命中等级-1（无视任何免疫弱化）；
>    沉默附加伤害并**无效**携带者的第五技能（是"无效"不是"命中效果失效"）；失神 50% 无效携带者的属性技能。

## 〇、结论先行（三分钟版）

1. **官方全表不在语料里，在数据库**：`effect_des` 的 `kind=2` 共 **43 条**"异常状态定义"，
   每条给出【官方名字 + 完整效果文本】。它是本线的**第一手底本**，比攻略语料权威。
   引擎的 `abnormal-types.h` 36 槽映射（0~35）与它的 `icon` 字段**逐条对得上**（已核对），
   `37~43` 七条在 2026-09-18 按用户口径「36 槽是之前的数量，新增了就继续加呗」**已扩表收进来**
（`kOfficialAbnormalStatusMaxId` 35→43、槽数 44；`icon=36` 官方无条目 → 槽 36 故意留空）。
2. **用户描述的四点，官方文本逐字支持**（见 §一），且**引擎现状基本为零**：
   扣血是裸直扣、无禁切换、无"已有异常过滤新异常"、无到期衍化、沉默/失神无行为。
3. **本线真正的结构核心是"异常自然结算点"**：引擎没有"异常到期的瞬间"，
   过期是**纯读比较**（`roundCount < end_round`）、**从不回写**。而衍化（焚烬→烧伤）**必须**有一个到期瞬间
   → 先补这个时点，衍化/到期伤害才有落点。
4. **第二个结构核心是"命中等级"的**正名**（不是扩槽）**：官方**能力提升状态就是 6 种**
   ——双攻 + 双防 + 速度 + **命中**；**基础数值**也是 6 项但第 6 项是**体力**。引擎把这两套
   索引混在了一个数组里：`view_levels[5]` 的注释写成"体力"，可 `getTempAbilityValue` 里
   还留着 `index == 5 && level < 0` → 返 `85/70/55/45/35/25` 的注释"**命中等级为负时的特殊处理**"；
   `resources/moves_lib/stat_dispel.cpp:403-409` 更是早已写明"官方序 [攻,防,特攻,特防,速,**命中**]
   → 引擎序 `kStatMap[6]={0,2,1,3,4,5}`（**5命中→5**）"并真的在调 `stat_change(..., 5, ...)`。
   → 所以槽 5 **本来就是命中**，本线做的是把它正名 + 接进精度公式，**槽数仍是 6**。

## 二、引擎现状（盘点，含 `文件:行号`）

### 2.1 数据结构

- 异常状态**本体没有 struct**：一条异常 = 一个 `int`（失效回合，exclusive end），
  存在 `battleContext.h:54-59` 的 `abnormal_status_end_round[2][36]`。
  **无层数、无来源/owner、无剩余回合、不 per-pet**（只按"方"记，靠换宠清）。
- 读写口：`src/fsm/battleContext.cpp:637-663`（`set/get/apply/has_active`）；
  **`has_active = roundCount < end_round`（唯一正确的判活口径）**。
- 过期**从不回写**：没有任何代码在到期瞬间跑逻辑 → `end != 0` 判"有异常"是**假阳性**
  （`src/effects/effect_unit.cpp:72-82` 的 `TargetHasAnomaly` 在用）。
- 清除点只有三处：换宠 `clear_on_stage_abnormal_statuses`（`battleFsm.cpp:345`）、
  初始化（`battleContext.cpp:109`）、药品 `CLEAR_ANOMALY`（`seer-robot.cpp:52-54`）。

### 2.2 施加链（`src/primitives/battle_primitives.cpp:70-231`）

`apply_anomaly_impl` 顺序：`[1]参数 → [2]存活 → [3]次免/回合免疫(+弹控反弹) → [4]异常抗性 → [5]魂免/Mark0
→ [6]转化(施加时单跳) → [7]同种延长 → [8]落地`。三通道 `Modern / Ancient(主动毒) / Raw(被动毒)`
（`battle_primitives.h:49-55`）。

**死值**：`REPLACED_EXISTING`（控场替换）与 `BLOCKED_BY_EFFECT` **全仓库无任何 return 点**
→ 多个控制类异常可并存。`resolve_anomaly_conversion` 读的 `anomaly_conversion` 表
**生产代码无写入者**（只有测试预置）。

### 2.3 扣血（`src/fsm/battleFsm.cpp:693-775`）

- 时点：`ACTION_START`（先手 `1259/1261`、后手 `1389/1391`）。
  **注意**：`docs/02-效果系统/effect-trigger-timing.md:80/200` 写的是 `ROUND_END`，**文档与代码不一致**；
  `docs_local/docs/02-效果系统/时点判定流程表.md:61-63` 写的 ACTION_START 是**对的**。
- 名单：`deals_damage_at_action_start` = 中毒/冻伤/烧伤/流血/寄生（5 条）。
- 金额：**每条各 `max(1, max_hp/8)` 再求和**；`DamageSnapshot` 填了 `isTrueDamage=true` 但
  **没有任何管线读它**；落血是**裸 `pet.hp -= snapshot.final`**（`battleFsm.cpp:767`），
  不走 `deal_damage` → 护盾/护罩/抗性/免粉/E05 事件/死亡漏斗**全不参与**。
- 缺：烧伤的"攻击威力减半"、寄生的"对手回等量"、流血固定 80、混乱 5%×50、
  沉默/束缚/烈焰诅咒的**百分比档（回合结束后/结束时）**。

### 2.4 限制行动

`has_blocking_control_status`（`battleFsm.cpp:81-95`）：遍历 36 槽，`has_active` 且
`is_control_abnormal_status` 为真即禁行动，闸门在 `should_skip_action_flow`（`:156-169`）。
名单（`abnormal-types.h:167-184`，11 条）：麻痹/寄生对手/疲惫/害怕/睡眠/石化/感染/冰封/瘫痪/焚烬/诅咒。
→ **瘫痪禁行动已对**；凝滞不在名单（弱化类，不禁行动）**也对**。

### 2.5 限制切换 —— **完全没有**

- 唯一相关的是 `ElfPet::is_locked`（`elf-pet.h:186`），**唯一写入者是构造函数且硬编码 false**
  （`pet_factory.cpp:133`）→ 该门（`battleFsm.cpp:933`）**恒不生效**。
  语义还反着：它挡的是"**换上场**"。
- 唯一自愿切换关口 = `operation()` 的 `case CHOOSE_PET`（`battleFsm.cpp:928-939`）。
  ⚠️ 它被**死后换宠**复用（`handle_ChooseAfterDeath:1625`）→ 门必须只拦**主动**切换。

### 2.6 影响异常附加 —— **完全没有**

`apply_anomaly_impl` 里没有任何"查目标已有异常 → 决定放行/过滤"的分支。

### 2.7 衍化 —— **完全没有**

只有"施加时单跳转化表"（且生产无写入者）。过期是纯读比较，**没有到期瞬间**，
所以"焚烬结束后转化为烧伤"无处落脚。

### 2.8 沉默 / 失神 —— **名字在、行为全无**

36 槽里只有 `失明(20)` 有真实行为（`skills.cpp:528-545` 参与命中判定，场景 041）。
`Silence(29)/Distraction(30)` 仅作为名字被引用（`soul_lib/miaoshi_4872.cpp:265-266` 的随机弱化池）。

### 2.9 能力等级只有 6 项（**命中等级无处安放**）

`kAbilityLevelSlotCount = 6`（`battleContext.h:231`），索引 0=攻击 1=特攻 2=防御 3=特防 4=速度 5=体力。
`battleWorkspace.h:191` 的 `view_levels[2][6]` 是公式读取源。
→ 官方**能力等级有 7 项（含命中）**，引擎缺"命中" → 焚烬的"命中等级-1"当前无法表达。

### 2.10 抗性系统生产侧从未填充

`include/abnormal-system/resistance-system.h` 已定义、已在 `apply_anomaly_impl:138-145` 接线，
但 `PetFactory` **不建** `pet.resistance` → 实战恒不触发（本线**不动**，单列）。

    要么把掷点收在一个可注入的口子上，别在断言里赌概率。

### 8.1 三条设计决定（为什么不"注册效果"而是"就地查"）

1. **一律用"常驻管线条目 + 回调里实时 `has_active_abnormal_status`"，不写 `ws` 回合槽。**

   不参与断回合）→ 写 ws 会退化成"只在施加那回合生效"的静默失败。
2. **红/粉伤修正都不新增 ws 字段**，而是各加一条默认管线条目。默认条目是 TEAM 绑定、
   换宠不作废（异常本身也不随换宠以外的原因消失）。
3. **`install_default_abnormal_mods()` 必须排在 `pink_damage_pipeline_.clear()` 之后**
   （它同时注册粉伤条目；放前面会被 clear 整条清掉，而红伤侧没有 clear 所以看不出问题）。

### 9.2 星赎(38)的"回合数+1"：`end_round += 1`，不是永久字段

用户口径（原文）：「是一种**增加剩余回合数**的手段，相当于永久保持指定异常状态的回合数不变了，
**但不能简单加一个永久字段，这样容易丢失剩余回合数，有的效果和剩余回合数有关**，
所以应该是要给该异常**结束回合数加一**」。

⇒ 实现为 `tick_abnormal_statuses` 里对**非限制类**异常 `set_abnormal_status_end_round(id, end + 1)`：
- 剩余 = `end - roundCount`，每回合 `roundCount` +1、这里再给 `end` +1 → **剩余保持不变**；
- 而"按剩余回合数办事"的效果（如衰弱 11 的 25/50/100/250/500% 分档）自动看到正确值；
- 位置必须在 **②b 清槽之后**（本回合该到期的已失效并清 0；清槽前 +1 会把它们复活成 active
  且跳过衍化与"结束时"伤害）；
- 限制类（瘫痪 19 / 凝滞 32）**排除**在"非限制类"之外。

### 9.3 臣服(31) 的拦截范围（用户口径）

「只拦截**红伤**（让裸伤直接归零，变威力也无法造成伤害）和**粉伤**，但是**真伤拦不住，
属性直伤也拦不住**，身上有臣服也可以给对面附加烧伤然后造成真伤」。

| 伤害档 | 是否被臣服拦 | 拦在哪 |
|---|---|---|
| 红伤 `NORMAL` | ✅ | `deal_damage` 的 NORMAL 早退（变威力重算最终也走这里） |
| 粉伤 `FIXED/PERCENT/PERCENT_VALUE` | ✅ | `deal_pink_damage`（插件唯一粉伤入口）+ `drain_hp_amount` |
| 真伤 `TRUE` | ❌ **放行** | ——（含异常扣血的 TruePercent 档） |
| 属性直伤 `ATTRIBUTE` | ❌ **放行** | ——（之诗 2088 族的 `deal_attribute_damage`） |

⚠️ **为什么不改 `deal_damage` 的 FIXED/PERCENT/PERCENT_VALUE**：异常自身的扣血走这三档，
且 `tick_abnormal_statuses` 的**回合扣减点档把 actor 记成对面** → 在那里拦会把
"对手的异常扣血"一起误封，与用户口径直接冲突。这是本线最容易写错的一处。
⚠️ `fixed_damage()`（actor = -1，无归因）拦不到，已记待办。

### 9.4 顺带修掉的 bug：`derive_anomaly` 的转出回合数少 1

衍化发生在**回合扣减点**，而该回合的**行动阶段早已跑完** → 转出异常的第一个生效回合是
**下一回合**。原先按 `roundCount + rounds` 写，`has_active` 是 `roundCount < end`
→ 实际只生效 `rounds - 1` 个回合（少一回合）。改为 **`roundCount + rounds + 1`**。
（对照：`apply_anomaly` 在**选择期**施加，那时本回合还没打，故它仍用 `roundCount + duration`；
易燃的**条件**转化发生在 ON_SKILL_HIT（回合中途）→ 也用 `roundCount + rounds`，不改。）

发现方式：场景 081 的 N 组按官方文本核"转出异常的**剩余回合数**"（而不是只核 `has_active`）
——只核 active 的话这个少 1 的 bug 会一直藏着。

## 十、两条待做的设计结论（2026-09-18 调研完，落档备做）

### 10.1 41 狂信：「信仰对象」放 **pet 上、下场保留**

**结论：pet 上，且必须"下场保留"——不能用 `abnormal_status_end_round`（那是 per-side + 下场清）。**

证据（三条独立直述互证 + 一条反证，**依据强度：有直述**）：

1. **官方对"信仰对象"本身下了定义**（数据库 `effect_des` **id=517，`kind=6`** 规则/概念词条）：
   > 信仰对象：**战斗中每只精灵恒常存在的规则属性**，初始为无对象
   —— 逐精灵持有 + 生命期"战斗中"。
   ⚠️ 同族词条是**标注生命期的惯例**：`id=536 临时体力上限：…未注明消失时点时，**默认为精灵下场时**`
   —— 官方要"下场清"时会**明写**，517 没写、反而写了"恒常存在"。
2. **语料**（`reference/scrape/out/all_posts.jsonl:73`《机制解析—教皇》）：
   > 这个效果必须是对方所有精灵都信仰教皇，**哪怕是阵亡精灵也得信仰教皇，除非该精灵消逝**
   > **额外精灵是不会信仰任何精灵的**
   > 如果对手进入狂信后，信仰我方在场精灵时，如果此时我方切换为非信仰对象的精灵，
   > 那么对手挂着狂信异常依然可以正常出招
   —— 阵亡仍保留（只有**消逝**才剔除）；"额外精灵不信仰"反证对象挂在 **6 槽本体 pet** 上；
   最后一条是"**存的是对象引用、判的是当前是否在场**"的两段式语义（切换不改引用）。
3. **`effect_info` id=2544**（第二条独立的写入点，最强的"下场保留"证据）：
   > 自身登场时，若己方精灵中存在索伦森，则将自身的**信仰对象改为**索伦森；
   > **自身位于场下时**，为自身的信仰对象提供支援魂歌报丧
   —— 精灵在**背包里**仍在读自己的信仰对象；若随下场清空，这条语义不可能成立。
4. 反证：**没有任何文本**支持"下场清/每次上场重算"，也没有支持"全场一份"
   （恰恰相反：教皇魂印 `effect_icon` 2084 写"对方**每有1只精灵**的信仰对象是自身"→ 逐精灵语义）。

**语义要点**（狂信 `effect_des` id=515 原文）：
> 控制类异常状态，该状态下**对手为信仰对象时自身无法行动**；**进入狂信状态时，若自身没有信仰对象，
> 则本次狂信状态的来源成为自身信仰对象**

- 写点是**条件写**（"若自身没有"）→ 必须**同时**存在一个"**强制改写**"入口
  （教皇魂印的"改为其"、索伦森的"改为索伦森"），否则只能实现"首次生效"。
- **只在真的施加成功时写**：语料「如果对手**免疫或者抵抗**都是没有信仰对象，同样**通过转移异常**
  也是不会信仰对手」→ 写点落在 `apply_anomaly_impl` 的**成功分支**，不能落在入口。
- ⚠️ **弹控（`REFLECTED`）路径未找到口径**（`battle_primitives.cpp` 把 actor 换成原目标）→ 需实测。
- ⚠️ **消逝要显式处理**：`vanish_spirit` 只把体力上限归零、**不删 slot**，放 pet 上的字段不会自动消失
  → 所有"信仰对象是自身/均为自身"的统计要按"剔除已消逝"口径走。
  "信仰对象所指的那只宠后来被消逝"该怎么算 → **未找到**，需定口径。
- 落点二选一：`ElfPet::soulmark_storage`（零新字段，key 建议 517，值 `{side, slot}`，`-1,-1`=无对象）
  或 `ElfPet` 显式字段（类型安全，但要**同时补 4 处拷贝构造/赋值**，漏一处静默丢状态）。
- 下游（不在本线）：教皇 4898 魂印 2506 需要"**遍历对方整队（含场下/阵亡）**统计信仰对象"；
  `effect_des` 342 的「**支援**」机制（"由存活的不在场精灵发起的，为在场精灵提供的效果"）
  引擎**零实现**，`effect_info` 2544 卡在它上面。

### 10.2 37 砥砺：**不需要** ws 的"真伤数值"槽，但需要**一个条件位**

官方原文（`effect_des` id=300，`kind=2`，`icon=37`）：
> 附属类异常状态，处于该状态的精灵**受到真实伤害后**，若**本回合未执行过附加异常状态的效果**，
> 则**增加此伤害值 80%** 的体力

**① "本回合造成/受到的真伤数值"不需要开槽**：语料 idx=157 明说是"**受到真伤后触发实时结算**的增加体力"
→ 回血量在 `deal_damage(TRUE)` 落地的那一瞬间就可得（`amount` / 实际扣血量），
不存在"跨时点传递"的需求。开数值槽反而会把"实时"做成"迟一拍"。
**更该就地钩在内核 `deal_damage` 的 TRUE 分支**（雷解 42 是同款先例，`battleFsm.cpp` 的
`finish_attack_damage` 里那段）。理由还有一条硬的：**真伤目前没有 kind 标记**——
`BattleEvent` 结构体里没有 `damage_kind`，`deal_damage` 三种档共用同一个 `EVENT_TAKE_DAMAGE`
→ 靠事件"事后"判"刚才那次是不是真伤"根本做不到，只能在结算点就地判。

**② 真正缺的是一个"本回合"条件位**：`ws` 里没有"本回合是否执行过附加异常状态的效果"。
`ws` 每回合 `memset` → 它天然就是"**本回合**"语义的落点，加一个 `bool` 即可（如
`ws.anomaly_applied_by_opponent[2]`）。
- 语料口径（idx=90/157）：**"执行过"= 效果被执行过**（不要求真的落地）；且
  **主动毒/被动毒不算**、**来源必须是对方**、**第三方效果不算**（"比如圣武砥砺、涂碟黑幕"）
  → 写点选在 `apply_anomaly_impl` 的 **Modern 通道**入口（`channel == Modern && actor >= 0 && actor != target`）。
- ⚠️ "本回合"边界：元神神印 1581 的真伤发生在**操作选择期**（其实现与官方"战斗阶段结束时"有偏差，
  见 `resources/soul_lib/qiling_1581.cpp` 注释），与"本回合附加异常"的边界需显式拍板。
- 回血落地已有：`heal_amount(ctx, target, amount * 80 / 100)`（吃封回血/恢复修正，语料 idx=165
  "可以被免疫效果响应"）。⚠️ 砥砺**不受臣服拦**（真伤本就拦不住）。

| 缺的那个位是什么 | `ws.anomaly_applied_by_opponent[2]`（**bool**，不是数值槽） | "本回合是否执行过附加异常效果"；`ws` 每回合 memset → 天然"本回合" |
| 谁置位 | `apply_anomaly_impl` 的 **Modern 通道入口** | 语料 idx=90/157：主动毒/被动毒不算、来源必须是对方、第三方效果不算 |
| ⚠️ 例外 | **砥砺自己不算**置位 | 语料同句点名「比如**圣武砥砺**、涂碟黑幕」——否则"登场即砥砺"的场次条件位被自己占满，砥砺永久失效 |

⚠️ 已知缺口：语料同句的「**涂碟黑幕**」是**名词级附属类**、本引擎未建模 → 无从排除。
若实测表明"所有附属类都不算"，把置位处的排除条件扩成
`abnormal_status_kind(anomaly_id) == AbnormalStatusKind::Special` 即可（一行）。

### 11.2 狂信：信仰对象的两段式

- 新状态 `FaithTarget{side, slot}`，存 `ElfPet::soulmark_storage`（key = 官方词条 id **517**），
  三个访问器在 `battleContext.h`：`faith_target(side)` / `set_faith_target(...)` /
  `opponent_is_faith_target(side)`。
- **两段式**是这条的关键：存的是**对象引用**，判的是"**当前在场的对手是否就是它**"。
  所以狂信**不能**当无条件控制类 —— `has_blocking_control_status` 里把它摘出来单独判。
- 写点是**条件写**（"若自身没有"），只在**落地成功**时写（免疫/抵抗/转移都不设），
  改写必须走 `set_faith_target`（魂印的"强制改写"入口）。

### 11.3 踩坑记录：同锚点文本导致的"钩错函数"

砥砺的回血钩一开始误落进了 **`run_pink_damage`**（`src/primitives/battle_primitives.cpp:617`），
而不是 `deal_damage`（`:709`）——因为这两个函数的**尾部 emit 语句完全相同**，
`str.replace(old, new, 1)` 命中了文件中**先出现**的那一个。真伤不走粉伤管线 → 钩子成了死代码，
表现为"砥砺完全不回血"。
⇒ 教训：**用"尾部 emit"这种重复锚点定位插入点时，必须带该函数特有的上下文**
（改造为按 `last_damage_actor` 那段特有代码定位）。这条与本项目的 `git add -f` 红线同类：
**看起来唯一的锚点其实不唯一**。
