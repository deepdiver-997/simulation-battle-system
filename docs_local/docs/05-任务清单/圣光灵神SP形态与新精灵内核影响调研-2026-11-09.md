### 1.2 「SP 形态」的真实载体：同 id 三表联动（不是新精灵）

**14 段 ID 先排掉**：monsters 表 1400000-1409999 段共 872 行，是**皮肤段**——630 行全零占位

`real_id` 指回基础精灵（如 1400005 小乔 real_id=3191）。皮肤段没有种族值/技能表，
**与 SP 形态无关**。编排侧"14 段行存在但 4399 不覆盖"的疑点就此解开：那些行只是皮肤
目录行，4399 不收录皮肤（无战斗数据），两说并不矛盾。

### 1.6 引擎影响评估（两条路线）

**路线 A：同 monster id + 形态标记（官方实际走法，能力强化解锁）**

结构性改动 = **零**。理由：
- 没有新 monsters 行 → `pet_factory` 装配（`src/entities/pet_factory.cpp:330-366`）原样吃 3311；
- 形态开关天然复用 K1 的**神谕尾段通道**：battle create 载荷已带 per-pet
  `[count][flag×N]` 尾段（`src/entities/pet_factory.cpp:117-139`，2026-09-24 精灵王线），
  客户端解锁能力强化后置 flag 即可，wire 协议零新增（是否复用同一 flag 位待协议采样确认，
  见下）；
- 技能装填直接吃 K1 的 ON 路径（`pet_factory.cpp:392-433`：normal → learnable 池、
  fifth → hidden 第五）。

但有 **1 个必炸 bug + 1 个语义待定**，立案必须带上：

①**分类判据 bug（不修则装填即错）**。`load_monster_oracle_moves`
（`src/db/official_data_repository.cpp:606-640`）按 moves 威力 ≥155 分第五/常规，注释自述
「sp_hide_moves 自身无威力」——**但 sp_hide_moves 表有 `movetype` 列**（1=第五/2=常规，
本地 12 行 movetype=1 样本全部对应威力 160 的第五，新数据 3311 五行 movetype 与
adv_move tag 完全自洽）。新技两个直接踩雷：
- 众我的凯歌 38634：威力 160 但 movetype=2（第 4 号强化位）→ 会被误分进 fifth；
- 神诏之诀别 38635：威力 0 但 movetype=1（真第五）→ 会被误分进 normal。
修法：SQL 取 `s.movetype`，有值用 movetype、无值回退威力判据（老行兼容）。

②**adv_move tag 语义待定**。3311 的四把强化位 tag=1..4（=替换第几号技能位；与既有槽位
技能一一镜像：盛凌 90/3 ↔ 王凌盛世 90/3、谳世还生/诸魔挽章 ↔ 寰宇纵横/剑定天穹、
