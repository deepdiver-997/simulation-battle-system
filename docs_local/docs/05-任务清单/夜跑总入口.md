# 夜跑总入口（无人值守自取协议）

> 你（agent）被一句"**开始夜跑**"叫起，没有更多上下文——从本文开始，按序完成
> 「开工六步」，然后进入主循环直到 `should_stop` 为真。不需要等人派活：
> 看板自取（taskctl flock+CAS 防双领），做一单领一单。
>
> ⚠️ **2026-10-13 协议改造**：会话现在有**唯一身份**（agent ID 领取制），且**停止条件
> 由用户可写的策略档决定**（不再由 agent 记忆里的"早上 8 点停"这种约定）。
> 详见 §一·0 与 §一·3。

## 一、开工六步

### 0. 领身份（第一步，2026-10-13 起）

```bash
export SBS_AGENT_ID=$(sh tools/night/agent_id.sh claim <前缀> "本会话备注")
export TASKCTL_WORKER=$SBS_AGENT_ID
echo "我的 agent ID：$SBS_AGENT_ID"
```

- **前缀**自取但要能认人：`kprod` / `jprod` / `fix` / `author`…（注册表会自动编成
  `a01-kprod`、`a02-kprod`…，同前缀不会撞号）。
- 这个 ID 从此贯穿：看板行的 worker 字段、worktree 名、注册表心跳、用户停用指令。
- **收摊时才释放**：`sh tools/night/agent_id.sh release $SBS_AGENT_ID`。
  ⚠️ **finish.sh 不再自动 release**（2026-10-21 抢单事故后改口径，见 §六）——
  完工一单只是"交还这一单"（清 busy），会话通常还要接着领下一单。
- **`status=released` ≠ "这个会话不干活了"**：它只表示"不接新单"。
  **判断一个会话还在不在干活，只看心跳 `last_seen`，不看 status。**
  （事故成因就是另一会话拿 status 当生死判据，把别人正在做的单判成遗弃单。）
- 用户随时可 `sh tools/night/agent_id.sh disable <id>` 让某个会话立刻收摊——
  **这条是用户侧开关，agent 不要自己调用 disable**。

`docs_local/docs/00-组件导航/常识与工具速查.md`
（ID 口径/黑话/切片双表/属性双序等高频坑——开工前置三查的依据）。

### 2. 读工具

### 3. 读停止策略（**每次判定停不停都以此为准**）

```bash
sh tools/night/policy.sh show
```

- 策略档在 `build/night/policy.json`，**用户可随时改，agent 只读**。
- 字段含义：`mode` = `run`（不限窗口跑）｜`stop`（全员停）｜`window`（只在
  `window_start`~`stop_at` 之间跑）；`allow_overtime=true` = 允许越过 `stop_at`
  继续跑（**限时免费模型期间用户会开这个**）；`note` = 用户给会话的一句话。
- ⚠️ **不要靠记忆里的"几点停"**——协议里的任何"到点自己停"都以策略档为准：
  用户改档后**下一次 `should_stop` 判定立即生效**，不需重启会话。
- 判定优先级（lib.sh `check_stop`）：STOP 哨兵 > 策略档 mode=stop > 本 agent 被停用
  > window 模式窗口 > 旧晨窗口径。

### 6. 领单

```bash
sh tools/night/claim.sh $SBS_AGENT_ID --wait    # --wait=队列空时阻塞轮询，零 API 消耗
```

claim 会建 worktree `~/.agent-workspaces/workspaces/sbs-local/agents/<任务号小写>`（2026-10-24 迁移至 agent-workspace-kit 约定的新 workspace，旧 `../agents/` 为历史区；SBS_AGENTS_DIR 可覆盖）——**构建与运行都在 worktree 目录内**
（CWD 决定加载哪份插件 dylib，这正是多 agent 互不干扰的机制）。

**看到 🔄 行不代表它被遗弃**（2026-10-21 事故后加的两道闸）：

| 闸 | 位置 | 行为 |
|---|---|---|
| ① busy 记录 | `taskctl claim/release` | claim 成功自动在注册表登记 `busy={task}`；该单有**活着的** busy 属主（心跳 15 分钟内 + 未 disabled）→ **拒领/拒代退** |
| ② 行文属主 | `taskctl release` | 🔄 行文本里的属主不是你 → **拒绝代为退回**（除非 `--force`，且会写 `forced_from` 进 tasklog 留痕） |
| ③ worktree 在用 | `claim.sh` | worktree 目录已存在且注册表里有活属主 → 退回该单，不接管 |

**正确姿势**：别人标 🔄 的单**不要碰**。要接管只有三种正当前提——对方主动
释放、对方心跳超时（默认 15 分钟）、对方被用户 `disable`。

## 二、主循环（每单）

```
should_stop → heartbeat（agent_id.sh heartbeat $SBS_AGENT_ID）→ claim → 按工单行实现
→ tools/night/build.sh（限流构建+全量回归）
→ tools/night/finish.sh <单号> ok（卡住则 blocked 自动重入队）→ 下一单
```

心跳每轮刷新一次（用户看注册表能知道"这个会话还活着吗"；30 分钟无心跳标 ⚠️ 失联）。

### 自主立单（author 协议，2026-10-02 起）

看板清空且**未收到明确停止信号**时不要停——抢占唯一"探索制定权"补单：

```
claim 返回 ALL_DONE → tools/night/author.sh <会话名> [超时秒]（阻塞等待内建）
  ├─ stdout AUTHOR（拿到唯一制定权）：
  │    探索补单素材（registry 对 moves 表扫未实现族 / 覆盖率盘点长尾 /
  │    4399 新精灵缺口）→ 动工前置三查 → 场景段分配与立项落看板：
  │      python3 tools/taskctl.py alloc --block 10        # 场景号段（全局计数器）
  │      python3 tools/taskctl.py add --board <板> \
  │            --row "| <新单号> | <家族：效果id×载体数> | <模板先例> | <号段> |"
  │    → tools/night/author_done.sh <会话名>            # 必调！释放制定权
  │    → 回 claim（立单者优先自领自己刚立的单——上下文最热）
  ├─ stdout CLAIM  → 队列有活了，直接回 claim
  ├─ exit 2 STOP   → 收摊
  └─ exit 75       → 等待超时，重新调 author.sh 即可
```

护栏：全局单制定者（锁 `$NIGHT_DIR/author.lock`，超 30 分钟视为遗弃可被接管）；
同会话卸任后 10 分钟冷却（轮转给其他等待者，防止一人霸占探索权）；立单必须附
载体切片核查与三查结论；一次探索建议 ≤3 单；立单行格式必须过 taskctl add 的
校验（同号拒绝 / 不得自带状态 cell）。
**立单/动工前必读**：《K 系魂印实现形态 SOP》
（docs_local/docs/02-效果系统/K系魂印实现形态-SOP.md）——注册形态/时点口径/
事件语义/桶语义/断言方法论的定版口径，2026-10-05 决策清单 K1-K10 拍板后立。

- **每任务一 commit**（worktree 分支上）；新场景/新文件 `git add -f`（ignore 会静默吞）。
- **全量回归必须绿**才 finish；registry 数字（moves/soul=多少）写回看板状态列。
- 不合并 main-local、不 push——worktree 留给白天人工 review 合并。
- 卡住就 `finish.sh <单号> blocked "原因"`，换下一单，别死磕（v2 语义=自动重入队）。

## 四、收摊

- 单 agent：看板清空或 `should_stop.sh` 为真 → 停在安全点（无未提交改动），tasklog
  已由 finish 写好；写一条晨报（做了什么/回归数/registry/遗留）即可结束。
- 多会话并行：各会话各拿一板（J×2 + K×1 + 官方验证线×1 是常见配比）；构建由 build.sh 信号量限流，
  不用互相谦让。
- **释放身份**：`sh tools/night/agent_id.sh release $SBS_AGENT_ID`（**只在真收摊时调**；
  finish.sh 明确**不再**代劳——见 §六）。注册表状态转 released，用户看得到"这个会话已收摊"。
- **收摊时念一遍策略档**：`sh tools/night/policy.sh show`——若 mode=stop，说明是用户主动叫停；
  若是窗口/超时，说明是额度用尽；两者在晨报里都要写清（用户据此判断要不要再开一轮）。

## 六、抢单事故与防护（2026-10-21 实证，必读）

**事故**：a01-kprod 做完 K259 时 `finish.sh` 自动把它标成 `released`，但它紧接着又领了
K260 继续干。另一个会话（a02）看到 K260 行是 🔄 且注册表显示属主 `released`，判定
"这单被遗弃"→ `taskctl release K260` + `claim` 抢占 → **两个会话在同一个
`agents/k260/` worktree 里对同一个文件并发写**（a02 的变异测试改动差点被带进
a01 的提交）。

**三个根因**：

1. `finish.sh` 无条件 `agent_id release`——完工一单 ≠ 会话收摊，但状态被写成了收摊。
2. `taskctl` 的 CAS 只断言"状态 == 待领取/进行中"，**不校验这一行有没有活着的属主**。
3. `claim.sh` 看到 worktree 目录已存在就"复用"，**不问里面是否有人在干活**。

**已修（本文件 §一·0 / §一·6 / §四 同步更新）**：

| 修点 | 文件 | 行为 |
|---|---|---|
| 完工不清身份 | `finish.sh` | 只 `agent_id idle`（清 busy），不改 status |
| 属主活跃拒领 | `taskctl.py` | claim 前查 busy，活属主存在即拒 |
| 跨会话拒退 | `taskctl.py` | release 校验行文属主，非本人拒（`--force` 留痕） |
| worktree 在用拒接管 | `claim.sh` | 目录在 + 活属主 → 退回该单 |
| status 语义澄清 | `agent_id.py` | `released` 只表示"不接新单"，生死只看心跳 |

**接管一单的正当前提只有三个**：原属主主动释放 / 心跳超时（15 分钟）/ 被用户 disable。
**看到 🔄 就假定"有人在干"**——这是默认假设，不是例外。

## 五、红线（历史事故，勿重蹈）

0. **编排会话派子代理一律后台启动（`run_in_background: true`），永不前台启动**（2026-11-10 用户立规）：
   前台派发会阻塞编排会话——worker 干活的一小时里主会话什么都做不了；后台模式完成时
   自动通知，期间照常与用户对话/收单/部署互不阻塞。通知只有好处没有坏处。
1. 绝不 `git add -f <目录>`（要精确到文件）；不加 GitHub 远端、不 push。
2. 构建必须 `cmake --build build -j8` 全量（单编插件 target 不跑 `*_deploy`，
   resources 里是旧 dylib——假绿）。
3. `side_effect.arg_count` 本地补丁：管线重建（import）后**必须** `apply_all.sh` 重放。
4. 真精灵口径 = id≤5000 且 4399 图鉴收录；5000+ 多为皮肤污染，别对着皮肤立任务。
5. 场景号先占后写：`docs_local/tools/claim-scenario.sh <前缀>`（工单已预留段的按段填）。
6. 共享热点（`test/scenario/scenario_harness.h`、内核 `battleFsm`/`battleContext.h`）
   同一时间只允许一个 agent 动——需要内核改动的任务不立夜跑板。
7. **停止条件只认策略档，不认记忆**（2026-10-13 用户口径）：协议里任何"到点自己停"
   的表述一律作废——`build/night/policy.json` 是唯一事实源（用户可写、agent 只读），
   每次判定都重读盘。用户在限时免费模型期间会把 `allow_overtime` 打开，此时
   **不要再按老习惯在早上 8 点自行收摊**。同理，用户 `disable <agent-id>` 可让单个
   会话立刻停——那是用户侧开关，agent 不得自行调用。
8. **官方对战夜间可跑，必须带熔断（2026-10-07 用户口径，替代原"夜跑禁登官方号"）**：
   常驻会话复用（不反复登录）前提下，夜间允许官方对战/培养；fx_probe / battle_agentd
   内置**熔断**——S 帧静默超阈（连接死亡/被踢）→ 自动落闸 `queue/SESSIONS_OFF` + **exit 5**，
   任务按 **blocked** 收单、**不自动重登、不死等**，晨报必须呈现熔断事件。
   **熔断只停"官方验证"线**：夜跑主循环继续领取其他板任务（J/K/R 照常），被打断的验证点
   回写协议文档 §19.4 待验清单；闸门落下期间任何会话不得登录（恢复 = 删文件或
   `fx_probe --allow-sessions`）。验证去重：动手前先读 §19.4 总账（§21.6）。
   房间常驻：进房不退房、跨场复用（fx_probe 自动），就绪后房主立即开战。
   **引擎侧对打（`engine_probe.py` ↔ 本机 sim_server :4399）纯本地、无官方服务器**，
   无此约束，可随时用于效果对账样本生成。

9. **对外发布前先切回本人身份（2026-10-22 事故）**：`gh` 默认激活的是 agent 账号
   （`ghagent-4ae8bd3a`）。对本仓（`deepdiver-997/*`）做任何**写操作**（issue 评论 /
   PR / close / label）之前必须：

   ```bash
   gh auth switch --user deepdiver-997
   gh api user --jq .login        # ← 确认真的是本人，别只凭记忆
   # …发内容…
   gh auth switch --user ghagent-4ae8bd3a   # 给他人仓库干活时切回 agent
   ```

   事故实证：2026-10-22 的 issue #3 回复以 `ghagent-4ae8bd3a` 名义发出（本意是本人
   名义），公开约两小时后才发现并删除重发。**注意删评论不可恢复位置**——GitHub 评论
   是追加时间线，没有"插回原位"的 API，删掉只能重发到末尾。
   另注：git **提交**身份不受影响（本仓 `user.email` 就是本人 noreply 地址），
   受影响的只有 `gh` 走的 token 身份。
10. **工具调用禁用管道吞退出码**（2026-10-26 a01-orch 实证）：`sh build.sh | tail`、
   `sh xxx.sh | head` 这类写法会把脚本的真实退出码抹成管道末命令的 0——编译/回归
   失败被假绿（本轮 gate 前的增量回归就因此假绿过一次，靠独立复跑抓回；坑 13
   「`;` 串联掩盖构建失败」同族）。要看输出就 `sh xxx.sh > /tmp/x.log 2>&1; echo "rc=$?";
   tail /tmp/x.log`——**先单独取 rc 再看日志**。
