## 一、结论与边界

1. **连击优先：建议把三个零参模板规范化为显式 `[5,10]` 行参，再将全部 16 项静态连击索引迁到小表。** 当前 `[5,10]` 并不在 DB 参数里：1608/1609/1610 的 arg_count、args_num 都是 0，三载体的平铺参数只有前序 451 的 `[100,1]`；5、10 来自 `combo_fixed_range`。这里是迁移目标与现状的纠偏，不应照任务简称误判为「只删旁路即可」。〔源: src/entities/skills.cpp:93-110〕〔源: resources/moves_lib/j_combo_constant.cpp:4-8〕（附录 A 现查）

## 二、连击常量表 DB 化

### 2.1 现状考古

- `combo_arg_indices` 实有 **13** 个 case，不是旧注释的 12：31、1172、1577、1627、1141、1454、1455、1500、1546、1593、1666、1685、1732；加三个常量 case 共 16。1172/1577/1627 取局部 args 下标 `(1,2)`，其余十项取 `(0,1)`。〔源: src/entities/skills.cpp:65-87〕
- `loadSkills` 先删除 disabled 效果、应用参数覆盖，再读连击；现状先查常量表，再查参数表，且**不 continue**，让同一效果的 rider 继续走插件。常量旁路目前也意味着调试台无法通过该效果局部参数改变其连击基数。〔源: src/entities/skills.cpp:478-525〕
- 数据切片契约是 `side_effect.arg_count` 优先、缺行才以 `effect_info.args_num` 兜底；参数来自 `moves.side_effect_arg`，不是 `side_effect.raw_json` 中的描述串。`SkillEffectRecord.args` 是该链位的局部切片。〔源: src/db/official_data_repository.cpp:126-152〕〔源: src/db/official_data_repository.cpp:155-186〕〔源: include/db/official_data_repository.h:18-25〕
- 静态区间在每次用技时 `roll_combo_count()` 掷一次，等上下限时不消耗随机数；随后物化到 combo_view，公式处尾乘并写 hitCount。迁移不得顺带改成逐段重算伤害或增加 RNG 消耗。〔源: include/entities/skills.h:299-317〕〔源: src/fsm/battleFsm.cpp:509-532〕〔源: src/fsm/battleFsm.cpp:730-744〕
- 三个 rider 分别是下回合全技能先制+3、攻击增伤+100%、封对手属性技；**不是首回合选择期路由**。插件当前只要求至少 owner/target 两参，新增尾参不改变它们的读取，但需同步头注。〔源: resources/moves_lib/j_combo_constant.cpp:9-21〕〔源: resources/moves_lib/j_combo_constant.cpp:86-126〕

**拟新增 `custom_skill_combo_rules`（名字可在立单评审时定）：**

| 列 | 类型／约束 | 用途 |
|---|---|---|
| effect_id | INTEGER PRIMARY KEY | 技能空间效果号；不是精灵号或魂印号 |
| min_arg_index / max_arg_index | INTEGER NOT NULL，均 ≥0 | `SkillEffectRecord.args` 的零基下标，不含 owner/target 的 +2 前缀 |

种子共 **16 行**：1172/1577/1627 为 `(1,2)`；其余既有十项及 1608/1609/1610 为 `(0,1)`。通用内核只做「查规则 → 校验下标 → max(1,参数) → 排序写 combo_min/max」，不再包含特定效果 id 或 `{5,10}` 常量；保持链上顺序和既有「后一个连击节点覆盖前一个」行为，不加新的叠加语义。既有实现依据：〔源: src/entities/skills.cpp:65-87〕〔源: src/entities/skills.cpp:516-534〕

**装载接缝与失败策略：**

- 建议在 repository 内按 DB 连接生命周期缓存 typed rows，`close()/open_read_only()` 清缓存；在 `loadSkills` 的 disabled 过滤和参数覆盖之后消费规则。非连击效果无匹配行仍为普通效果；元数据表缺失、版本不支持、已声明规则下标越界则显式失败，不能悄悄退为单击。已有只读连接和缓存清理形态可复用。〔源: src/db/official_data_repository.cpp:195-231〕〔源: src/entities/skills.cpp:478-525〕
- 发布要绑定「新内核 + 新补丁版本」；种子完整性由数据版本／种子清单及测试比对保证，不把 16 个必有 id 重新硬编码进战斗循环。旧库未打补丁应报缺迁移，而不是保留永久静默旁路。
- **不建议直接借用现在的 custom_effect_overrides 存 16 条后就算完成。** 当前查询按 effect_id `LIMIT 1`，没有按 override_type 取特定能力，而且 `loadSkills` 对查询结果仅 `(void)custom_ovr`；这是未接 dispatch 的接缝，不是可用的 combo 执行器。若坚持复用，要另审类型化读口、多类型同 id 与缓存，不应隐含在本单。〔源: src/db/official_data_repository.cpp:307-329〕〔源: src/entities/skills.cpp:660-686〕

**备选而非同时实施：**若评审要求绝不改官方定义表，可在独立规则表增加 `value_source=fixed/args` 与 fixed_min/max，以三行固定值存 5、10；保留零参和三载体原参数。这条线切片风险更低，但引入两个取值分支、不能直接获得调试台参数覆盖能力。建议主选规范化行参，立单时二选一，不能两套真相并存。

### 3.2 拟表结构与加载点

建议专表 `custom_skill_selection_routes`，先不扩成「任意生命周期 DSL」：

| 列 | 类型／首版约束 |
|---|---|
| effect_id | INTEGER PRIMARY KEY；只管 moves 命名空间；避免同 id 多条路由导致重复注册 |
| phase | TEXT NOT NULL，首版只接受 `selection` |
| state | TEXT NOT NULL，首版只接受 `FIRST_MOVE_RIGHT`；使用语义名字，禁止存 C++ enum 整数 |
| arg_adapter | TEXT NOT NULL，`plain` 或 `skill_static_elements` |
| schema_version / evidence | INTEGER=1 / TEXT NOT NULL；迁移版本与来源可审计 |

**加载顺序建议：**repository 只读批量装载并缓存 → `loadSkills` 原有 disabled／参数覆盖之后 → 原先 554-658 的位置查询一行 → clone 对应插件 → 按 adapter 喂参 → push selection_effects_ → **continue，阻止同一节点再进入普通执行分支**。原来的 custom program 查询发生在选择期路由之后；保留这个优先级，不能把它提前造成插件被离线程序截走。〔源: src/entities/skills.cpp:478-497〕〔源: src/entities/skills.cpp:624-630〕〔源: src/entities/skills.cpp:642-686〕

`skill_static_elements` 首版严格仅用于零参效果：构造 `[owner,target,element[0],element[1]]`，用技能的静态槽原值，不在此解析成组件，也不读 `ws.skill_element_view`。785 保持 plain，插件读精灵系别视图；2030/2490 读静态技能槽，2490 随后的神灵系改写不能倒灌进自身微弱判据。〔源: src/entities/skills.cpp:636-651〕〔源: resources/moves_lib/selection_seal.cpp:528-582〕

**首版故意不开放任意 state。**`on_selected` 虽遍历 SkillEffectNode，实际创建和注册 ContinuousEffect 时固定使用 FIRST_MOVE_RIGHT，不消费 `node.registerState`；只在 DB 写别的 state 会形成「表面可配置、实际上无效」的接口。若未来开放多个选择期桶，须另单改注册器与时序测试。〔源: src/entities/skills.cpp:824-853〕

```sh
python3 -I - docs_local/docs/05-任务清单/数据刀清缴线二批计划.md <<'PY'
from pathlib import Path
import re, subprocess, sys
text = Path(sys.argv[1]).read_text()
marks = re.findall(r'\u3014源:\s*(.*?)\u3015', text)
seen, errors = set(), []
for mark in marks:
    m = re.fullmatch(r'([^:]+):(\d+)(?:-(\d+))?', mark)
    if not m:
        errors.append('bad format: ' + mark)
        continue
    p, lo, hi = Path(m[1]), int(m[2]), int(m[3] or m[2])
    if not p.is_file():
        errors.append('missing: ' + mark)
        continue
    lines = p.read_text().splitlines()
    if not 1 <= lo <= hi <= len(lines):
        errors.append('out of range: ' + mark)
        continue
    if mark in seen:
        continue
    seen.add(mark)
    out = subprocess.run(['sed', '-n', f'{lo},{hi}p', str(p)],
                         check=True, text=True, capture_output=True).stdout.splitlines()
    if out != lines[lo-1:hi]:
        errors.append('sed mismatch: ' + mark)
for err in errors:
    print('ERROR', err)
print(f'R4 plan-citations: marks={len(marks)}, unique={len(seen)}, errors={len(errors)}; rc={int(bool(errors))}')
sys.exit(bool(errors))
PY
```
