# 技能判定流程与无效/效果失效体系

> 整理自设计讨论（2026-08-11）。本文是技能结算判定的权威口径，代码实现需对齐本文。
> 2026-08-22 更新：①澄清"攻击无法造成伤害"是独立的伤害层限制，**不阻断命中效果注册**；②穿透词条分级（无极圣武实测）；③新增第六节"固有效果的可否决性"（星皇之怒/强制执行实测）。

## 一、技能结算的三个阶段

玩家使用技能，命中判定按**固定顺序**分三个阶段：

```
阶段① miss 判定（最早，优先级最高）
  ↓ 若 miss → 技能无效（进入"无效"结果路径）
阶段② "无效"效果判定（次数类/回合类都算）
  ↓ 若无无效词条 → 命中
阶段③ "命中效果失效"判定（注册效果前）
  ↓ 若有 → 技能变白板/效果失效（补偿效果也不触发）
  ↓ 若无 → 正常注册技能效果 + 补偿效果
```

**关键顺序**：**先判命中（miss/无效）→ 再判命中效果是否失效**。
- 若对手只有"命中效果失效"，但你 miss 了且有补偿效果 → **补偿效果正常触发**，并跳过后面的命中效果检测。

## 二、"技能无效"层面（最常见）

所有导致"本次技能无效"的因素，结果相同：技能按无效处理，**若有补偿效果则触发**。

### 2.1 无效的来源

| 来源 | 判定方式 | 结果 |
|---|---|---|
| **miss** | 命中率判定失败 | 技能无效 |
| **狮盔** | 封攻击技能 | 攻击技能无效 |
| **龙威** | 封攻击+属性技能 | 攻击/属性技能均无效 |
| **封属** | 封属性技能（如米斯蒂克魂印） | 属性技能无效 |

> miss 严格说是"技能无效"的一种，只是判定方式不同（概率 vs 效果存在），**结果相同**。
> 例：南霜·大雪纷飞"若未命中则免疫下1次受到的攻击，免疫成功则令对手全属性+1"——"未命中"可以由 miss 触发，也可以由封属效果触发，都走同一补偿路径。

### 2.2 狮盔 vs 龙威

| | 狮盔 | 龙威 |
|---|---|---|
| 无效范围 | 攻击技能 | 攻击技能 **+ 属性技能** |
| 可否被"无视攻击免疫效果"穿透 | 分两种 | **不可**被"无视免疫"穿透 |

**狮盔的两种描述**：

1. **可穿透**：可被有"无视对手攻击免疫效果"词条的技能穿透。
   一般描述："免疫下一次/xxx回合内的攻击"。南霜·大雪纷飞的补偿效果就是这种。
2. **不可穿透（条件盔）**：带条件，无法被"无视免疫"穿透。
   - 坦普瑞·"禁术·契灭"："若消耗的PP值≥5点……额外令对手下1次攻击技能无效"
   - 不羁·弗里德·"天叶领域"/"余温之辰"："若下次对手使用的攻击技能威力大于120，则免疫此次攻击"

**龙威**：无法被"无视免疫"穿透。

**可穿盔被穿时消不消耗次数 —— 看盔模板有没有后续子句**（★ 用户 2026-09-13 游戏实测）：

| 盔模板 | 被穿 |
|---|---|
| **带后续子句**：2270「免疫下{0}次对手的攻击，**触发成功则**{1}%令对手{2}」/ 2006「技能无效时，免疫下1次对手的攻击，**免疫成功则**令对手全属性+1」/ 1288「…**未触发则**…」/ 1293「…**免疫成功则**自身全属性+{1}」 | **消耗次数** |
| **裸的**「免疫下{N}次对手的攻击」：570 / 2269（"技能无效时，消除对手回合类效果并免疫下次对手的攻击"）/ 2203 | **保留次数** |

实测样本：赫星千年 28989(**2270**) 被穿消耗 / 火种永存 25744(**570**) 被穿保留 /
无念归空净 37087(**2006**) 被穿消耗 / 遗颂 37834(**2269**) 被穿保留。

引擎落点：`RuleTicket::consumed_when_pierced`（默认 false = 保留，与改动前一致），
经 `seal_skill(..., consumed_when_pierced)` / `grant_seal(..., consumed_when_pierced)` 设置。
**回合类不看这个**：回合类被穿是否结束，取决于穿盔技能**有没有断回合效果**（自然语义，
无需额外字段）。

**effect 2006 已从"伤害管线 BLOCK 挡伤"迁成 SEAL 盔**（2026-09-13）：
`无念归空净 37087` 的这条「技能无效时，免疫下1次对手的攻击，免疫成功则令对手全属性+1」——
官方实测它能被**穿盔凭证穿透**，而穿盔凭证只作用在 RuleCenter 的 SEAL 条目上 → 必须是盔。
旧实现（`DamagePhase::BLOCK` 挡伤）在"打下来不扣血"上表现一样，但**被穿 / 断回合 / 强制执行**
三种行为全不对。迁移落点是 `resources/moves_lib/lib_1.cpp` 的 `effect_skill_2006`
（挂 `consumed_when_pierced=true` 的可穿次数盔 + 监听盔生效事件）。
回归：smoke 段 7 按新机制改写、场景 029（大雪纷飞被命中失效）**不变仍绿**。

**带子句的盔的"子句"怎么挂**（★ 用户 2026-09-13 问、2026-09-13 定）：
不要特判"被穿"——`RuleCenter::notify` 只对**真正生效**（未被穿透、条件通过）的拦截条目
回调 `on_armor_triggered(source_effect_id, source_owner)`，core 据此发
`EventType::EVENT_SKILL_ARMOR_TRIGGERED`（`amount` = 该盔的 `source_effect_id`）。
插件按 effect_id 匹配自己的盔挂 watcher 即可；**被穿的盔根本不走这条 → 子句天然不触发**。

**穿透词条分级**（2026-08-22 实测确认）：穿透不是布尔，而是**词条等级 vs 盔等级的比较**。无极圣武魂印虽列出一整张"无视"清单（能力提升效果、护盾承伤效果、攻击免疫效果），其中对"攻击免疫"的穿透只能穿**最低级的可穿盔**，条件盔/龙威照旧有效。后续遇到更高等级的无视词条（如可穿条件盔的）需单独收录等级。

盔侧等级（低→高）：可穿盔 < 条件盔 < 龙威。
攻侧词条：目前已知"无视对手攻击免疫效果"（含无极圣武的清单）= 最低级，只能穿可穿盔。

### 2.3 次数类的消耗判定

- **回合类**：自然减扣，回合减扣点统一减。
- **次数类**：一旦本次技能命中失败（miss 类），**会消耗所有可响应的次数类效果**。
  - 例：对手身上有一个"狮盔"，你发一次攻击技能但 miss 了 → miss 判定和"攻击技能是否有效"虽先后发生，但都属于攻击技能无效 → 狮盔**被响应并消耗**。
  - 对手有两个来源的次数"狮盔"各一个 → 一次攻击会**全部消耗掉**。

### 2.1 封属·命中失效变体 `SEAL_ATTRIBUTE_HIT`（2026-09-12）

普通**封属**（`SEAL_ATTRIBUTE`）让属性技能走 ②被无效 → 触发技能无效补偿。但一部分官方"令对手属性技能无效"实际表现为**命中效果失效**：属性技能照常命中（`EVENT_HIT`）、效果不注册、**不触发无效补偿**。

引擎在**统一规则容器 RuleCenter**（非 §三 的 ③层）内表达此变体：

- `SealKind::SEAL_ATTRIBUTE_HIT`：仍**只响应属性技能**（`responds_to(is_attribute_skill)` 与封属一致），唯 `notify` 归类为 `HIT_INVALID`。
- RuleCenter 门判定统一消费/三态返回：`INVALID`（盔威封属→SKILL_INVALID+补偿）/ `HIT_INVALID`（命中失效→走 execute 的 hit-invalid 路径，**不注册补偿分支**）/ `NONE`。
- 归入 RuleCenter 而非 ③层：次数/回合、同源覆盖、换宠清理、断回合清回合类等**全复用容器已有语义**。
  ⚠️ 2026-09-13 更正：③层**不再**是"对所有技能无差别"——它按技能类型拆成攻击/属性两类（§8.6）；
  而 `SEAL_ATTRIBUTE_HIT` 依然**只响应属性技能**（那是"封属"的语义，两者不是一回事）。
- 代表：不灭·艾恩斯·秩序之助(31268) 效应 781"消除成功则2回合内令对手属性技能无效"，场景 029。

> 判定时把"某一类技能的命中失效"放容器（借其类别过滤+覆盖+断回合），把"所有技能通用失效"放 ③层（HIT_INVALID 类）——两类都命中 §三"补偿不触发"。

## 三、"命中效果失效"层面

**统一称"命中效果失效"**，两种表现形式：

1. **白板**（常见）：对手使用属性/攻击技能都不触发效果。
   - 属性技能：无伤害只有效果注册 → 什么都不发生。
   - 攻击技能：可能有两种——
     a. 和属性技能一样：不造成伤害，也不注册效果（= 威力为 0 的白板技能）
     b. 效果失效但**伤害照常结算**。
   - 代表：赤胆游龙·赵云魂印"胆"："自身每次登场后当回合免疫异常状态并令对手攻击技能的**附加效果失效**"——只是效果失效，基础伤害保留。
   - "白板"型（a）比赵云这种更常见。

**关键**：**"命中效果失效"级别的阻止，任何补偿效果都不触发。**

### 3.1 "攻击无法造成伤害"不属于命中效果失效（2026-08-22 确认）

"无法造成伤害"是**伤害层的独立限制**：伤害管线结算时把伤害归 0，但**命中效果照常注册生效**。

实战中它经常与"命中效果失效"**组合出现**（组合后既没伤害也没效果，看起来像白板），容易误以为它也阻断效果——判定时必须把两层拆开：

| | 效果注册 | 伤害 |
|---|---|---|
| 命中效果失效（白板 a） | 阻断 | 归 0 |
| 命中效果失效（保留伤害 b） | 阻断 | 照常 |
| "攻击无法造成伤害" | **照常** | 归 0 |

对应的官方规则佐证（`effect_des` 词典，见《官方数据关联查找指南》）：词条 318"免疫对手的攻击"明确层级为"计为无效 → 不计为命中 → 无法执行命中效果"——**效果阻断挂在命中/无效层，伤害归零挂在伤害层**，两层独立判定。

## 四、完整判定流程总结

```
使用技能
├─ ① miss 判定（优先级最高）
│   └─ miss → [技能无效] → 触发补偿效果 → 结束（跳过②③）
├─ ② 无效效果判定（狮盔/龙威/封属）
│   ├─ 无视词条等级 ≥ 盔等级？→ 穿透 → 命中
│   └─ 被无效（含 miss 类）→ [技能无效] → 消耗可响应的次数类 + 触发补偿效果 → 结束
├─ ③ 命中效果失效判定
│   ├─ 白板（a）：无伤害无效果
│   ├─ 效果失效（b）：伤害照常，效果不注册
│   └─ 正常：注册效果
├─ ④ 伤害层（与③独立，见 3.1）
│   └─ "无法造成伤害" → 伤害归 0，已注册的命中效果不受影响
└─ 命中 → 注册技能效果 + 补偿效果 → 伤害管线结算
```

## 五、代码实现：统一规则容器（RuleCenter）

现状：`Skills::query_usage` 返回 `{ OK, MISS, SEALED }`。**免疫 + 盔/威/封属(含命中失效) + ③层命中失效 已轧入单一容器 `RuleCenter`**（`include/effects/rule_center.h`，header-only 供插件直调）。本节讲它的结构与语义。

### 5.1 统一结构：RuleTicket（替代 SkillArmor/InvalidEntry + 免疫 Provider）

免疫与盔威封属统一为一条"规则票据"。**每条显式带 `source`(挂载方) 与 `target`(生效对象) 两维**——这是旧容器借 `owner` 兼任两维后暴露问题的根治：

```cpp
struct RuleTicket {
  //── 挂载维度（"属于"谁 → 生命周期 + 覆盖键）──────────
  int source_owner;          // 挂载方 (0/1)
  int source_slot;           // 挂载精灵槽（-1=未知/锚当前在场精灵）
  int source_effect_id;      // 来源效果 id（覆盖键 + 审计）
  EffectScope scope;         // ON_STAGE=上场精灵(换宠清) / TEAM=全队保留(复用既有 EffectScope)
  int source_id;             // 授予句柄（revoke / 快照 re-grant）
  int source_valid_id;       // 来源效果 epoch（注册时 ctx->round_effect_valid_id[source_owner]）。
                             // 0=不参与断回合作废（免疫天然豁免）；非免疫随来源 ON_STAGE 效果被断 → 作废(Q2)
  //── 生效维度（"作用于"谁）──────────────────────────
  int target;                // 免疫=被护方自身(source==target)；封属/③层=被封锁方
  //── 规则身份（覆盖键 = source_owner, source_effect_id, category, subtype）──
  RuleCategory category;     // IMMUNE | SEAL | HIT_INVALID_ATTACK | HIT_INVALID_ATTRIBUTE | REFLECT
  int subtype;               // 免疫→ImmunityType；封属→SealKind；③层→HitInvalidMode
                             // ⚠️ ③层**按技能类型拆两类**（攻击/属性），不是一条加通配 —— 见 §8.6
  //── 免疫参数 ── uint64_t coverage / anomaly_mask;  bool soul(魂免)
  //── 封属参数 ── bool penetrable;  condition(条件盔)
  //── 消费 ── int remaining_counts(次数,响应即减) / remaining_rounds(回合,tick减) / register_round
};

enum class SealKind { SEAL_ATTACK, SEAL_ALL, SEAL_ATTRIBUTE, SEAL_ATTRIBUTE_HIT };
// SEAL_ATTACK=狮盔(只封攻击) / SEAL_ALL=龙威(封攻+属) / SEAL_ATTRIBUTE=封属(只封属性)
// SEAL_ATTRIBUTE_HIT=封属·命中失效(只封属性，但照常命中、效果失效、不触发无效补偿)
```

**覆盖键**：`(source_owner, source_effect_id, category, subtype)` —— **同来源同效果覆盖刷新、不追加**。subtype 区分细类，故"免异常+免弱"(903)同源同 effect 因 subtype 不同各占一条，不被误合并。**不同来源绝不合并**（哪怕底层效果代码相同，用户 2026-09-11 定）。

> ⚠️ **2026-09-13 补：免疫的来源维度此前是空的**——`grant_immune` 把 `source_effect_id` 硬写成 `-1`，
> 于是"不同来源绝不合并"在免疫上根本表达不出来：同一精灵身上**同类型的免疫只能存在一条**，
> 后授予的会把先授予的窗口覆盖掉（典型："窗口类免控 + 次数型次免"并存 → 窗口没了）。
> 现已给 `grant_immune` 加 `source_effect_id` 形参（默认 `-1` 保持旧行为、旧调用点零改动），
> 需要并存的调用方各传自己的 effect_id（技能 effect id / 魂印 id）即可各占一条。场景 031 Q8 验证。

**次数型免疫的消费（`counts>0`）**：`is_immune*` 纯查询不消费，命中后由 `consume_immune` 扣 1 层、扣到 0 注销。两条官方规则（`docs/02-效果系统/官方机制理解与引擎缺口对照.md` §二，idx=418/375）：
1. **存在回合类免控/弹控时，次免依旧正常消耗** → `consume_immune` 的扫描**跳过 `counts==0` 的窗口条目**继续找次数型条目（不是"扣 is_immune 命中的那一条"）；
2. **被弹回来的异常不消耗**（`reflect_depth>0`，"不属于精灵受到异常"）→ 调用点各自用 `reflect_depth==0` 守住，但**仍照常被免疫挡下**。
顺序上必须**先判定、后消费**（颠倒会把 counts=1 的条目在判定前扣光注销，该挡的没挡住）。

### 5.2 三个入口（RuleCenter 分三组语义）

```
授予/撤销：
  grant_immune(owner, type, coverage, mask, duration, register_round, source_id, soul, scope, slot)
  grant_seal(source, target, effect_id, SealKind, counts, rounds, penetrable, scope, condition)
  grant_hit_invalid(target, slot, effect_id, HitInvalidMode, count, is_attribute_skill)  // ③层并入
  revoke(source_id)

纯查询(免疫,不消费)：is_immune / is_immune_effect / is_immune_soul（扫 target==被护方）
消费查询(封属门)：notify(user, is_attribute, power, ignore_attack_immunity)
   → 扫 target==user 的 SEAL，任一无效果→INVALID、否则任一命中失效→HIT_INVALID、否则 NONE
   次数类响应即减(全部消费)、回合类响应不消耗；条件不满足/可穿盔被穿透 → 跳过保留
③层消费：consume_hit_invalid(defender, is_attribute_skill) → 只扫**与本次技能类型匹配**的那一类
   （HIT_INVALID_ATTACK / HIT_INVALID_ATTRIBUTE），取首条消费返回 mode。消费点在 query_usage ②.5。
```

**全部消费**：一次技能使用会消费**所有响应它的次数类条目**，不因某个盔/龙威挡了另一个就保留次数。例：
```
对手身上：1次属性无效 / 3回合属性无效 / 无条件盔 / 3回合龙威 / 1次龙威
我方用攻击技能 → 无条件盔、1次龙威各减1；3回合龙威响应但不减（回合类）；
                封属性的两条不响应（只封属性），不动。
```

**唯一标识（2026-09-11 用户澄清，修正原"合并计数"表述）**：键 = **(挂载方 source_owner, 来源效果 id, category, subtype)** → **同来源覆盖刷新，不累加**。

> 用户原话："同一个技能使用多次是累加还是取最大值覆盖——同来源（同精灵同技能注册的）应该**覆盖**而不是累加……比如使用了技能A，有一条每回合吸取对手200点体力的效果，接着又使用了技能B，同样有一个每回合吸取对手200点体力的效果，但是**因为来源不同，不能被覆盖成一个效果，即使底层效果代码都是一个**。"

推论：**不同来源绝不合并**——哪怕底层效果代码完全相同。这也印证了效果桶的 key `(source_id << 32) | effect_id` 是对的（不同技能 → 不同 source_id → 两条独立存在）。

例：精灵A给全队注册 2 次属性无效 + 精灵B自己注册 1 次属性无效 → 两条独立条目（A 的 2 次、B 的 1 次）→ 对手用一次属性技能 → A条目 2→1，B条目 1→0 注销。

### 5.3 生命周期（统一锚 source）

**规则属于挂载方(source)**。统一规律（用户总结，2026-09-12）——**绝大多数效果（无论主动被动、是否被查询消费）的生命周期都落在这一矩阵**：

```
生命周期矩阵（绑定对象 × 类型）
──────────────────────────────────────────────────────────────
绑定对象 = 队伍(TEAM)   → 无法被任何方式影响（断回合/切换都豁免），
                          只随自然到期(窗口/rounds tick)或主动 revoke
绑定对象 = 精灵(ON_STAGE)：
   回合类(rounds>0)  → 响应「断回合 + 切换」——清"被断方身上的" / "被切换方身上的"
                       （断谁清谁、切谁清谁：即挂在那个精灵 layoff 的回合类）
   次数类(counts>0)  → 只在它绑定的精灵切换时清（不随断回合、不随对方切换），
                       自身消费完即消
──────────────────────────────────────────────────────────────
注意：免断(ImmunityType::BREAK)是例外门——被免断时不响应断回合；
     免疫(ANOMALY 等)天然不可被断（只看它的窗口/scope）；永久魂印(ROSTER→TEAM)视为队伍级不动。
```

> 逐条对照实现：
> - **TEAM**：`clear_on_stage` / `clear_round_type` / `invalidate_stale` 全按 `scope==ON_STAGE` 过滤，TEAM 豁免。
> - **ON_STAGE 回合类**：断回合 → `clear_round_type(被断方)` + `invalidate_stale`(来源被断回撤)；切换 → `clear_on_stage(被切换方)` 按 scope+slot。
> - **ON_STAGE 次数类**：断回合不清（`invalidate_stale` 只作废回合型）；切换 → `clear_on_stage` 按其挂载槽清。

`invalidate_on_stage_effects` 换宠时

- `rule_center_.clear_on_stage(owner, on_stage[owner])` 清 **source_owner==换宠方** 且 `scope==ON_STAGE`（且槽位匹配）的条目；
- `scope==TEAM`：切换保留，直到自然到期。

由此：**封属挂施放方** → 施放方换宠清、被封方换宠**保留**；**断回合** `clear_round_type(target)` 清嵌在 **挂载方名下** 的回合类封属（断施放方回合才解封）。免疫单对象（source==target=被护方）：被护方换宠清 ON_STAGE，与旧语义一致。③层 HIT_INVALID 挂 target(被失效方)一侧，该方换宠清。

> 免疫/封属/③层的"换宠清、断回合清、回合 tick"统一由 RuleCenter 的 `clear_on_stage` / `clear_round_type` / `tick_rounds` / `cleanup` 承包（见 §2.1 表），不再分散在多个容器。

**Q2 — 来源效果被断 → 规则作废（epoch 回撤，对齐 timed_bucket）**：`grant_*` 记 `source_valid_id` = 当时 `round_effect_valid_id[source_owner]`。断回合(`invalidate_all_round_effects` → `rule_center_.invalidate_stale(owner, current_epoch)`)作废**来源 ON_STAGE 回合类效果已被断**的非免疫规则。两处豁免：`IMMUNE`（恒 source_valid_id=0，天然不可被断，只随上下场清）+ `scope==TEAM`（TEAM 效果不随断回作废）+ 非回合类规则（次数型封属不随断回清，与 clear_round_type 一致）。`round_count_[2]` 缓存非免疫回合类规则计数，`has_round_type` O(1)（学 timed_bucket `active_round_count_`）。

**Q3 — 回弹（REFLECT 规则种）**：原 `ctx->reflect_anomaly[bool]` 移入 RuleCenter 作 `REFLECT`（rounds/source 锚，随切回清、来源被断回撤）。`apply_anomaly` 次免/魂免命中时查 `rule_center_.has_reflect(target)` 决定是否反弹；`reflect_depth`(防乒乓)保留。异常**转化**(`anomaly_conversion` 入→出)保留在 apply_anomaly 内（内联变换查表、优先级最高直穿魂免，非被查询消费规则，不入 RuleCenter）。

### 5.4 判定顺序（对齐第三、四节）

```
Skills::query_usage(ctx, owner):
  ① miss 判定（最高优先级）
     → 若 miss：仍 notify 中心（miss 也消费可响应的次数类）→ 返回 INVALID
  ② 命中：notify 中心（rule_center_.notify）→ 三态分流：
     INVALID（无效果）→ SEALED → SKILL_INVALID + 补偿
     HIT_INVALID（命中失效封属）→ execute 走命中失效路径，照常命中、效果失效、**不注册补偿**
     NONE → 继续
  ③ 无无效：查"命中效果失效"（防御方，rule_center_.consume_hit_invalid）
     → 白板(kFullNull)：伤害归0 + 不注册效果
     → 保留伤害(kEffectsOnly)：伤害照算 + 不注册效果（赵云"胆"）
     → 无 → OK
```

- 命中效果失效的伤害归零在**伤害管线结算**时看标记执行（白板抹零，保留伤害不动）。
- "无法造成伤害"同样只在**伤害管线**处理（伤害归 0），**不影响效果注册**——与命中效果失效是两个独立开关，可单独存在也可叠加（见 3.1）。
- 补偿效果：`INVALID` → `SKILL_INVALID` 分支触发；`HIT_INVALID` / 命中失效 → 不触发任何无效补偿分支。

## 六、固有效果（选择期效果）的可否决性

固有效果在技能选择期触发、天然不受 miss 影响。但**能否被各层无效体系废掉是逐效果的属性**，不能从"固有"这个类别推导——同类固有效果在"命中效果失效"面前的表现不同：

| 效果 | miss / 技能无效层 | 命中效果失效层 | "无法造成伤害" |
|---|---|---|---|
| 条件先制（如 1002"对手处于异常状态则先制+1"） | 选择期已结算，正常生效 | **仍生效** | 不影响 |
| 南霜·大雪纷飞的"未命中"补偿 | 触发 | **被阻断** | 不影响 |
| 瀚宇星皇·星皇之怒（固有效果："技能无效时 50% 额外行动"） | **触发**（miss 与技能无效层均允许） | **不触发** | 不影响（其本体是额外行动，非命中效果） |
| 无为觉者·强制执行（PP=0 技能：必定命中 + 强制执行命中效果） | — | **无视命中效果失效** | **同时无视"无法造成伤害"**（2026-08-22 实测） |

**强制执行 vs 狮盔/龙威（★ 用户 2026-09-13 游戏实测补充）**：
**狮盔/龙威这类"攻击无效"一定把伤害降为 0，强制执行也不例外**——它只是"让效果生效"
（技能效果照常注册），但**不会造成红伤**。唯一的例外是**威力被效果改回去**：威力视图在
`SKILL_EFFECT` 时点被效果改写、`ATTACK_DAMAGE` 才读它，所以"强制执行把视图置 0 →
技能自己的威力效果再改回来 → 伤害自动恢复"这条路**天然成立，不需要任何"重新结算"机制**。
（例：无为觉者·无相谛 179「同属性则威力提升170」把 0→170，魂印再"用过一次威力+50"。）

> ⚠️ 2026-09-14 用户澄清：我先前按字面短语搜出"全库只有 effect 2501 一条重新进行伤害结算"
> ——**这个结论说窄了**。真正要区分的是两件事：
> - **改威力**（无相谛 179 / 魂印 +50 / 2501 的威力翻倍）：**自动重算**，因为结算时读视图威力，
>   **已实现**——而且不止"读得晚"：写视图本身就是声明"这是变威力"，收尾会再跑一次公式
>   （见 §8.7）；场景 042 N8 与 043 验证；
> - **多段结算**（"一回合做 x~y 次攻击"：星光·浪打千击 37381 / 阴阳三合 / 月下伏）：
>   需要**多次独立结算**（每段各自的威力、各自的暴击/破防收尾），引擎**尚未实现**——
>   这是独立的一块，也是"暴击破防后再次结算可无视对手提升"（§8.2）真正要落地的场景。

要造成红伤，正常途径只有**穿盔凭证**穿透**可穿盔**。

引擎落点（`Skills::query_usage` ②.0）：盔/威/封属**照常响应与消耗**（`notify` 照跑），
但**不拦截**——直接返回 `OK` 让 `execute` 按 HIT 分支注册效果；同时把
**`ws.skill_power_view[owner]` 置 0**，于是非变威力技能"有特效、无红伤"。
⚠️ 因此 `calculateDamage` 的"未物化"哨兵是 **-1** 而不是 0——视图威力 0 是**合法值**。
⚠️ 残余：伤害公式有 `+2` 常数项，视图威力 0 时仍会打出 **1~2 点**红伤（场景 042 N7 实测 1 点），
不是严格 0；要严格 0 需另加"本次攻击强制归零"标记（未做，待定）。

结论与实现口径：

1. 可否决性做成**效果元数据标签**（`hit_effect_invalidatable` / `invalid_compensatable` 等），数据来源优先对齐官方 `effect_icon.kind` 分类（游戏内固有/命中效果图标不同即此分类的 UI 体现）。
2. 引擎按标签过滤分支节点，不做类别级一刀切——`is_hit_effect_invalid` 命中时，只跳过带 `hit_effect_invalidatable` 的节点。
3. 强制执行是"请求携带通行凭证"方向的极端案例：执行请求带 bypass 掩码，过门时查凭证。`must_hit`（必定命中，官方词条 312）是同族的最小成员，宜一并纳入统一的凭证体系。

## 七、技能替换的两种时点

> 2026-09-11 用户提出 + reference 核对。本节是"技能替换"的**规格判断**（实现另计）。

技能会被替换：**星光·艾欧丽娅**的"骑士对决"把双方下次使用的技能转化为第五技能；
**讳迹·米修莉**的"入魅印记"把对手下次技能转化为"摸摸"。
但"技能替换"**不是一件事**——至少两种时点，差别在于是否连带替换**固有效果**（选择期效果，见第六节）。

### 7.1 两种替换的对照

| | 艾欧丽娅（骑士对决） | 米修莉（入魅印记） |
|---|---|---|
| 替换时点 | **执行期**（"**使用时**转化技能"） | **触发之前**（前置） |
| 固有效果（先制等） | **保留** | **一并替换**（"被替换的技能会**失去天生先制**"） |
| 惩罚/绕过 | — | "可以**绕开强制执行**"、"没有什么东西可以避开替换技能" |
| PP | "**消耗原有技能pp**，而不是消耗第五的" | — |

原文（reference `all_posts_final.jsonl`）：
- idx=51（星光·艾欧丽娅）："由于是**使用时**转化技能，所以你点原本的技能效果还是可以享受一些效果，
  比如**计算先制、无视先制、视弱为强**……你点击先三技能，可以享受先制+3，然后打出第五技能的效果"
- idx=179（讳迹·米修莉）："其余的调用技能也会在**触发之前**就替换为摸摸，而且这种还可以绕开强制执行"
  "被替换的技能会失去天生先制，并且可以触发一些魂印效果"

### 7.2 引擎映射（现有两层天然对应）

`Skills` 已天然分两层，恰好承接这两种替换：

- **选择期 / 固有效果层**：`selection_effects_`（`on_selected` 注册到 `BATTLE_FIRST_MOVE_RIGHT`，先制等）
- **执行期层**：`effectBranches`（`execute` 按执行结果分叉注册）

→ **艾欧丽娅式** = 只改**执行期**（效果来源指向替补技能），`selection_effects_` 保留；
→ **米修莉式** = **前置替换**，两层都换（所以连天生先制都没了）——引擎实现为描述符
`level=kFull` + 在 `on_selected` 之前置位（§7.5），不改写任何技能对象内存。

### 7.3 "读当前技能数据"的读法（★ 实现要点）

被替换的技能若其效果/结算需读"当前技能"的数据（PP / 先制 / 系别…），**读的必须是被替换的那个技能**，
不是替补技能。引擎侧**已经天然满足，无需任何改写**：

- **PP 扣除**：`consume_selected_skill_pp` → `resolve_selected_skill_index` 读
  `roundChoice[robot_id][1]`（**玩家点击的槽位**）→ 扣的是原技能的 PP。
- **效果读 PP**：效果函数读 `ctx->roundChoice[owner][1]` 拿槽位 →
  `ctx->getPet(owner).skills[slot].pp` 即原技能 PP。

### 7.4 实现方式：加**间接层**，不要"覆盖 + 还原"

⚠️ **不要**用"改写技能对象内存 → 下个时点还原"的写法。理由：本游戏存在**跳过时点**语义
（星皇之怒"体力因此归 0 的对手无法触发任何效果"），"还原"那一步**可能被跳过** → 替换变成永久。
凡是"必须保证撤销"的写法，都要为每条 skip 路径补还原逻辑，而我们已知 skip 路径真实存在
（见 `魂印机制设计与精灵表现档案.md` §4.3）。

正确做法是**只加一层间接**（重定向，非物理拷贝——Skills 拷贝有 parsed_units_ 悬垂地雷，
物理副本也放不进 memset 重置的 ws）。两级替换**按生命周期分家、拆两个载体**（2026-09-11
场景 V 验证时定案：单一 ws 描述符装不下 kFull——它在选择期设置，会被中途的 ROUND_START
reset 清掉，执行期就读不到了）：

```cpp
// ① kExecOnly（艾欧丽娅式）→ ws 载体：随 ws 每回合 reset 自动失效，"仅本次技能生效"
//    是结构性保证，无需任何还原逻辑
struct SkillReplaceSource {          // battleWorkspace.h（命名空间作用域）
    bool active = false;
    int source_owner = 0;            // 替换技能所在方（跨精灵替换：艾欧丽娅=施放方）
    int slot = -1;                   // 替换槽位（0..4）
};
SkillReplaceSource skill_effect_source[2];   // BattleWorkspace

// ② kFull（米修莉式）→ context 载体：必须跨越"选择期(on_selected) → ROUND_START(reset)
//    → 执行期(ON_SKILL_HIT)"，故住 context；用后即耗 + 换宠即清
SkillReplaceSource pending_skill_replacement[2];   // BattleContext
```

`resolve_replacement_skill`（battleFsm.cpp）统一解析两个载体（pending 优先）；
`resolve_executing_skill` 按它决定"从哪个技能对象取 effectBranches"。
PP 扣除恒走玩家点击的原槽位。`selection_effects_` 的注册目标：艾欧丽娅式走原槽位
（固有效果保留）；米修莉式走替换技能（见 §7.5）。

**代码落点（2026-09-11 已落地）**：`battleFsm.cpp` 的 `resolve_executing_skill(ctx, robot_id)`
是**"执行什么技能"的唯一取用点**（`effectBranches` / 威力视图 / 系别视图 / 暴击率 / 伤害公式都走它）；
"玩家点了哪一格"仍走 `resolve_selected_skill_index`（PP 扣除、艾欧丽娅式的 `selection_effects_`）。

**⚠️ 赋值时机约束**：`ws` 在 `BATTLE_ROUND_START` 被 `reset()`，而 ROUND_START 排在
`OPERATION_CHOOSE_SKILL_MEDICAMENT` **之后**（线性序：CHOOSE → PROTECTION_1 → ENTER_STAGE →
ROUND_START → 战斗链）。**kExecOnly（ws 载体）必须在 ROUND_START 之后设**（实战落点即
`ACTION_START` / `BEFORE_SKILL_HIT` 这类时点），选择期设会被 reset 清掉；
**kFull（context 载体）正相反**，必须在操作提交时（on_selected 前）设——见 §7.5。

### 7.5 kFull（米修莉式）的抓手：抢在 on_selected 之前（2026-09-11 定案，场景 V 验证）

米修莉式"前置替换"（失去天生先制、绕开强制执行）在引擎里的落点不是改写技能本体，而是
**context 级 pending 标记 + 抢在 on_selected 前生效**：

- 先制/固有效果注册的唯一时机是选择期的 `on_selected`（`selection_effects_` →
  `BATTLE_FIRST_MOVE_RIGHT` 桶）。`handle_OperationChooseSkillMedicament` 已接线：
  pending 对该方 active 时，`on_selected` 跑在**替换技能**对象上——原技能的固有先制
  根本不注册（"被替换的技能会失去天生先制"自动成立），先手权判定代码零改动。
- **赋值时机 = 操作提交瞬间**（早于 on_selected、更早于先手权判定）。真实实现中由
  米修莉的印记在对手提交操作时触发置位（印记本体=对手身上的 pending 状态，机制落地待做，
  场景 V 以"两次提交之间置位"模拟，机制等价）。
- **用后即耗**：`resolve_skill_execution` 结算完（无论命中/miss/被盔封）消费 pending
  （"对手**下次**技能转化为摸摸"）。被控/切宠跳过主流程不经过结算 → 不消费，转换留给
  下次真正出手。
- **换宠即清**：`invalidate_on_stage_effects` 清 pending（"印记绑定对手，下场不保留"）。
- 可选性检查（`query_selectable`：PP/锁定）仍走玩家点选的原技能——玩家用自己的 PP 做选择，
  替换是施加的不是选择的。
- "绕开强制执行"：强制执行等一切凭证物化都晚于操作提交 → 替换生效后，强制执行推动的
  已是替换后的技能（"没有什么东西可以避开替换技能"结构性成立）。
- PP：官方文本未指明米修莉式的 PP 归属，暂按艾欧丽娅口径扣原槽位（有 reference 证据再改）。
- 场景 V 三断言：V1 对照（光闪击先制先手）/ V2 转换（先制剥除 + 威力视图=摸摸 + PP 原槽 +
  pending 消费）/ V3 下一回合恢复（"下次技能"语义）。

## 八、暴击机制 + 暴击重置防御等级（★ 已实现，场景 040）

> 2026-08-22 用户游戏实测确认规则；2026-09-13 用户补充判定位/顺序口径并落地。

### 8.1 暴击判定

- **只在使用攻击技能时触发**：属性技能（`SkillType::Attribute`）不掷。
- **暴击率来源**：`moves.crit_rate`，它是**分母 16 的分子**——`crit_rate=8` → 8/16 = 50%、
  `=16` → 100%；**`0` = 走基础暴击率 1/16**（绝大多数技能是 0，**不代表"不会暴击"**）。
  最终概率 = 技能暴击率 × `ws.crit_rate_mod[owner]`（效果改 `crit_rate_mod` 来缩放；
  "下N回合暴击率提升"类效果**每回合写 ws**，同 `damage_add_pct` 的写法）。
- **判定位：miss 之后、门判定之前**（`Skills::query_usage` 的 ①.5 步）。
  **只有 miss 会阻止暴击**——技能无效（盔/威/封属）与命中效果失效（③层）**都保留暴击结果**。
- **为什么必须前移**：技能无效时伤害结算**整段不执行**（`handle_*_AttackDamage` 因
  `allowAttackDamagePipeline == false` 早退），在那里掷就永远掷不到；
  而"打在盔上一样触发暴击并破防"是官方要求。
- 结果写 **`ctx->crit_happened[owner]`（住在 BattleContext，不是 ws）**；
  `stage_simple_attack_damage` **只消费不重掷**。放 context 的理由：伤害管线分阶段算，
  暴击改了能力等级后**变威力要按新等级/威力量再算一遍**，标志的生命周期跟"这次攻击"对齐而非"这个回合"。
- **一次技能使用掷一次**（多段/变威力技能共用同一结果）。
- 暴击倍率/暴击抗性算法不变（默认 2 倍，暴击抗性只削"加成"部分）。

### 8.2 暴击破防（重置防御正等级）

- 物理暴击 → 对手的**正防御等级**（`levels[2]`）归 0；特殊暴击 → **正特防等级**（`levels[3]`）归 0
  （与伤害公式同索引：`type + 2`）。
- 只清**正等级**，负等级不动。
- **不查任何免疫**（用户 2026-09-13 口径）：免消除强化 `STAT_CLEAR` **挡不住**它——
  暴击破防不是"消除强化效果"，是暴击自带的规则。
- **顺序：先结算伤害再重置等级**——本次伤害按**旧**（提升后的）等级算完并落地，然后才清零。
  推论：**变威力/多段技能在重置后再次结算的那一段可以无视对手的提升**
  （如星光·浪打千击 37381 这类"一回合做 N 次攻击"的技能）。
- **调用点（2026-09-14 调整为官方时点）**：`handle_Battle{First,Second}AttackDamage` 的**两条出口**都调
  `apply_crit_defense_break`——正常出口**紧跟第一次 `stage_simple_attack_damage`**
  （官方口径："**命中之前，伤害公式计算之后**"，且"**在技能特效生效之前**"就已把双防重置为 0），
  早退出口（技能无效/被盔）在清伤害快照之后。
  ⚠️ **不是**处理器末尾——放中间是为了给**变威力**让路：变威力"推翻第一次、按归零后的双防**重算第二次**"，
  重算必须在破防之后。对单段技能两种位置等价（第一次伤害已物化）；场景 040 C9 用 ATTACK_DAMAGE 桶里的
  探针锁定"破防早于桶"。
  **为什么不做时点效果**：①ATTACK_DAMAGE 的桶跑在 `stage_simple_attack_damage` 之后，
  但技能无效时**整段早退、桶根本不执行** → 打盔破防会丢；②再往后挪一个时点（AFTER_ACTION）
  虽无条件执行，却落在"下一次结算"之后 → 变威力在同一个 ATTACK_DAMAGE 内重复结算时读到未重置的等级。
  它是**引擎内建规则**（与克制倍率/暴击倍率同类），不属于"效果"。
- 原语 `crit_defense_break(ctx, defender, skill_type)`（`battle_primitives.h`），
  返回是否真的破了（留给将来"破防成功→…"类补偿）。

### 8.3 已知边界

- **变威力（§8.7）与连击（§8.8）均已实现**。
- 未实现：连击的**动态加数**（1108/484/1795/1863/1930）、**连击上限修正**
  （1500/1546/1577/1593/1627/1666/1685）、**逐段子效果**（"每次攻击有 X% 概率…"）、
  无参数常量（1608/1609/1610）。见 `docs/05-任务清单/待做-变威力与增减伤时点.md` §2。
- 同一回合内**额外行动**复用 `ws.crit_happened`（不再重掷）——与"一次技能使用掷一次"一致，
  但"额外行动算不算同一次技能使用"待官方口径确认。

### 8.4 必中凭证（★ 2026-09-13 用户口径）

判"本次技能是否必中"一律读 **`ws.attack_credential[owner].must_hit`**，**不要只读技能里写死的
`moves.must_hit`**——因为存在**条件必中的固有效果**。凭证三合一（`materialize_attack_credential`）：

| 来源 | 说明 |
|---|---|
| `skill.must_hit` | 官方 `moves.must_hit` 固有必中 |
| `ws.must_hit_grant[owner]` | **本回合效果授予的条件必中**（效果体在 MOVE_RIGHT 时点写） |
| `cred.force_execute` | 强制执行隐含必定命中 |

**条件必中怎么授予**：效果（如 2000「对手处于能力提升状态则先制+1**且必中**」）在**选择期**
就与条件先制一起注册进 MOVE_RIGHT 桶；效果体在该时点同时写 `ws.preemptive_level` 与
`ws.must_hit_grant`。MOVE_RIGHT 是唯一正确窗口——`on_selected` 早于 `ROUND_START` 的 ws reset（会被冲掉），
而直接改 `skill.must_hit` 是**永久**的（那场仗之后该技能永远必中，切宠/跨回合都不复原）。

### 8.5 失明（异常 20）★ 2026-09-13

处于**失明**的精灵：

- **非必中技能 → 必定 miss**（不看命中率，直接判 miss）。
- **必中技能 → 50% 正常命中 / 50% 命中效果失效**（`HIT_INVALID`，无补偿）。
- **强制执行最先短路**：`force_execute` 完全绕过失明（既不 miss 也不失效）。

落点 = `query_usage` ① 步（在常规命中率 roll 之前、暴击判定之前）。失明的 50% 档**照常走 ② 门判定**
（与 miss 分支一致：文档 §2.3「一旦本次技能命中失败（miss 类），会消耗所有可响应的次数类效果」）。

### 8.6 ③层"命中效果失效"按技能类型分两类（★ 2026-09-13 用户口径）

**命中效果失效不是属性技能专用**——攻击技能同样会被失效。因此 `RuleCategory` 里
**拆成两个显式类别**（而不是给一条加"通配"标记）：

- `HIT_INVALID_ATTACK` —— 只对**攻击技能**生效
- `HIT_INVALID_ATTRIBUTE` —— 只对**属性技能**生效

**要"两种技能都失效"就注册两条**（调两次 `hit_effect_invalid`，`is_attribute_skill` 分别传 false/true）。

- **票据挂"防御方"**：`grant_hit_invalid(target=...)` 的 target 是**持有这个防御性标记**的一方
  （语义："令对方攻击的命中效果失效"）；攻击方出手时从 `1 - owner` 侧消费。
- **消费点收口在 `query_usage` ②.5**（而不是 `Skills::execute` 里各判一次）：与 miss/sealed 同一处出结果，
  按本次技能类型只消费对应那一类。结果模式记在 `ws.hit_invalid_mode[owner]`（供伤害路径判 kFullNull 白板归零），
  是否发生失效记在 `ws.hit_invalid_detected[owner]`。
- ⚠️ **与 ② 门判定的 `SEAL_ATTRIBUTE_HIT` 不是同一件事**：后者是"封属·命中失效"
  （781 秩序之助原文："令对手使用的**属性技能**无效"），**天生只响应属性技能**，由 `SealKind::responds_to` 决定。
  两者共用同一执行路径（逐节点 nullify 过滤 + EVENT_HIT + 不 emit SKILL_INVALID），但来源与响应面不同。

### 8.7 变威力（★ 2026-09-14 已实现，场景 043）

**定义**：官方对"威力"的定义**本身就是**变威力规则——
「威力：当命中效果对技能威力值进行修改时，**会以当前状态重新进行伤害结算覆盖原本的伤害值**」
（reference L128《官方名词解释—1》）。即"改威力"不是一个单纯赋值，而是**推翻第一次伤害计算、
按当前状态重算第二次、第二次覆盖第一次**（L453/L418）。

**触发条件是"威力被**改过**"，不是"威力变了"**：
「**提升0点威力也属于变威力**」（L453）、「就算是0连击，他也是变威力效果」（L173）。
所以判据是"有人写过威力视图"——`SkillView`（`battleWorkspace.h`）用 `operator=`/`operator+=`
自动打标记 `rewritten`，效果侧零纪律成本（写 0 也算）。**值比较是错的**。

**第二次结算重算什么**（L453）：敌我双方的能力等级（双攻/双防，**包含暴击破防**）、
属性克制系数、技能威力 —— 全都是 `calculateDamage` 当场读的字段，所以"重跑一遍公式"即天然覆盖。
**不**重掷暴击（`ctx->crit_happened` 一次技能只掷一次）；伤害浮动 `rand()` **重掷**（用户 2026-09-14 裁定）。

**落点**：`apply_variable_power_recalc(ctx, attacker)`（`src/fsm/battleFsm.cpp`），
`handle_Battle{First,Second}AttackDamage` 里位于
**`execute_registered_actions(ATTACK_DAMAGE)` 之后、`damage_pipeline_.run()` 之前**：

```
stage_simple_attack_damage(第一次) → apply_crit_defense_break → 桶(效果可改威力/等级/克制)
  → 【★ rewritten? → stage_simple_attack_damage(第二次，覆盖)】→ damage_pipeline_.run → apply_resolved_damage
```

- **唯一肉眼可见的后果：暴击破防只对变威力技能生效**。破防在"第一次公式之后"（§8.2），
  非变威力技能本次伤害**已经算完**，享受不到；变威力技能的第二次结算读到归零后的双防——
  这正是 L418「暴击重置比较早…然后再进行变威力计算」的全部含义。场景 043 V1/V2 锁这条。
- **变威力"结算靠后" → 可以隔着盔打出攻击伤害**（L390）：强制执行把视图置 0 后，技能自己的
  变威力效果把它改回来 → 红伤照常（场景 043 V4 / 042 N8）。
- ⚠️ **管线仍然只跑一遍**（重算在管线之前）——这是这个落点的全部意义：绕开"跑两遍就错"的效果
  （`install_default_damage_block` 的 `consume_immune` 会**再扣一次次数型免伤**、effect_525 概率挡伤**重掷**、
  effect_1236 **再打一次粉伤**、`resolvedDamage.addPct` **累加**）。
  `stage_simple_attack_damage` 本身是"覆盖式"的（开头清两个快照 + 末尾局部整体赋值），重算不会叠加。
- **标记生命周期**：物化（`materialize()`）与**强制执行置 0**都**不算**效果改写；
  `resolve_skill_execution` 在 `execute()` 返回后 `consume()` 清一次 → 此后 SKILL_EFFECT / ATTACK_DAMAGE
  桶里的任何写入才算。重算消费后再 `consume()` 一次 → 不跨技能泄漏（场景 043 V5）。
- **不覆盖的两条**（L453 ⑤⑥）：**本系加成**不会被重写（`calculateDamage` 里 `involve` 用技能真实系别，
  "改系别"只写 `skill_element_view` 影响克制）；**"无视微弱"**（760 `no_weakness`）是独立钳位、
  也在公式内当场读 → 重算后仍成立，与官方"打了补丁"的结论一致。

### 8.8 连击（"1回合做 x~y 次攻击"，★ 2026-09-14 已实现，场景 044）

**是"一次伤害公式 ×N"，不是 N 次独立结算**。官方公式（L101）把 `×连击次数` 排在**最后**：
> `[(等级×0.4+2)×面板威力×攻击÷防御÷50+2] ×本系修正 ×克制系数 ×(217~255)÷255
>   ×暴击抗性 ×暴击系数 ×**连击次数**`；「方括号内属于一个整体不可拆分」

L99 的取整顺序也确认："浮动前一大段取整 → 浮动后 → **暴击系数后** → 抗性后 → **连击次数**"。

- **静态基数**：`Skills::combo_min / combo_max`，由 `loadSkills` 从技能自己的 `side_effect` 参数里取
  （`combo_arg_indices` 开关表：1141/1454/… 是 `{0}-{1}`；**1172/1577/1627** 是 `{0}回合做{1}-{2}次`，
  下标 +1）。**不碰 `effect_info.info` 文本**。
- **每次技能使用掷一次**：`Skills::roll_combo_count()` → `ws.combo_view[owner]`（区间退化 1~1 时
  短路**不消耗 `rand()`**）。第一次/第二次结算、多段共用同一个 N。
- **落点**：`stage_simple_attack_damage` 里**暴击乘完之后**、快照落地之前 `base *= N`。
  乘在 `base` 上（不是单独字段）是刻意的——下游 `deal_damage`／伤害管线／日志**只消费 `final`**，
  于是**增伤/减伤/护盾/次数型免伤自动作用于总数**：挂"免疫下 1 次攻击伤害"时 N=3 的攻击
  **整段归零**（场景 044 C6），而不是只挡第一段。
- **连击本身就是变威力**：官方把"n次连击"与"威力提升n%/n点"**并列**为变威力描述（L453），
  且用户 2026-09-14 裁定连击走「先破防 → 按归零双防重算单次 → ×N」。
  落点 = `apply_variable_power_recalc` 的判据加一条 `combo > 1`（见 §8.7）。
  效果：**连击技能吃得到暴击破防**——场景 044 C4 实测 N=3 的伤害 ≈ N=1 的 6 倍（3×连击 × 2×破防）；
  若不做第二次结算，比值会停在 3。
- **未做**：动态加数（1108「每处于一种能力提升则连击数+1」等）、连击上限修正、逐段子效果。
  `ws.combo_view` 是 `SkillView`（写它自动打"变威力"标记），补效果时直接 `+=` 即可。

## 九、设计方向（2026-08-22 讨论中，未定稿）

**典型案例：希拓「烬灭神咒剑」37218**（side_effect=[2000, 1287, 2126]，一次包含三种触发形态）：

| effect | 模板 | 触发形态 |
|---|---|---|
| 2000 | 若对手处于能力提升状态则先制+1且必定命中 | 选择期条件先制 + 必中凭证 |
| 1287 | 吸取对手能力提升，**吸取成功则**下{0}次受到的攻击伤害减少{1}% | 主效果返回值驱动分支（吸取成功与否） |
| 2126 | **技能无效时**，消除对手回合类效果、能力提升效果，令对手焚烬 | 事件触发（技能无效补偿） |

**讨论中的方向：效果组合单元语法**。效果不再是一层扁平函数指针列表，而是"单一条件效果单元"组合：

- 单元 = 主动作（原语调用）→ 返回值 → if-else 分支（可能嵌套）。
- 例：`吸取对手200点体力，若吸取少于[预期]则改为附加200点真实伤害`、`全属性+1，若XXX则翻倍（全属性+2）`。
- 三种 if 形态映射到现有引擎：选择期前置条件（`selection_effects_`）、返回值后置条件（需新增结果槽通道，`EffectResult` 目前只有 kOk/kSkillInvalid/kHitEffectInvalid 三个粗码，`apply_anomaly` 的 TARGET_IMMUNE 等细码在函数边界被丢弃）、事件触发（watcher）。
- 好处：Type B 补偿（"施加异常/吸取体力被天生免疫挡住"）自然化解为效果自身的 if-else 分支，不需要独立补偿表。

**凭证放 workspace 的结论（已验证）**：`BattleWorkspace` 每回合在 `handle_BattleRoundStart` 开头 `reset()`（battleFsm.cpp:683），"下一回合自动刷新"成立 → 本回合内穿透凭证可直接放 `ws` 字段，回合结束自动清，无需手动销毁。**多回合/次数授予**（"下N回合无视"）仍需走效果桶生命周期，攻击时并入凭证。详细讨论见 git 对话记录。
