## 三、白名单机制

**历史机制记录（2026-10-22）**：`id_collision.h` 的 `known_collisions()` 当时逐条登记
32 处存量 + 处置结论；2026-11-06销六项后当前为26项技能重复。以下是历史规则：
- 白名单按 **(类别, id)** 匹配——同一 id 再撞（第三处）仍记 count>2 并报告；
- **新增撞号不在表里 = 必须报**，严格模式下直接失败（门禁能挡住新坑）；
- 白名单条目**必须带处置结论**（"同族双载体" / "实验遗留" / "死代码"）——
  将来收敛时逐条销账，销账时从表里删（届时严格模式会重新拦它，直到真正修好）。

**2026-11-06现行规则**：豁免完整匹配 `(类别, id, secondary)` 且最多允许备案的两次
注册；第三次起撤销豁免，完整报告所有来源并在末尾统一失败。手动、批量与标准入口共用
记账，typed宏携带来源；CHECK关闭且STRICT关闭时不记账，STRICT强制启用检查。
门禁要求四种开关矩阵及真实注册入口共5个测试齐全，缺源码或缺产物都失败。

### 5.4 存储槽键段自注册（2026-11-07，python 静态扫描的运行期化）

`std::any` 存储槽键段的所有权从「无注册环节、只能静态扫」升级为**运行期契约**：
常量定义处 `SBS_STORAGE_SEGMENT(容器枚举, 常量, 说明)` 宏（plugin_interface.h）→
per-dylib hidden 表 → 各 lib_1 钩子 `plugin_reg::flush_storage` 经
`CoreApi::report_storage_segment`（**ABI v3**）回推宿主 `StorageLedger`
（id_collision.h，与效果 id 账本同文件）→ `initialize_runtime_data` 末尾统一审计
→ registry dump 导出 `storageSegments`。与效果 id 账本的两点差异：
①**无存量放行档**——键段从零回填（一次性 sweep 495 段），未备案撞段即缺陷直接失败；
②幂等键 = **basename(文件):行**——同一共享头被不同目录以不同相对拼写包含时
`__FILE__` 拼写不同，整串比对会把同一逻辑头误判成撞段（crawford/tianqi/burn_trio
等 shared 头实测全中）；basename 归并的边界（不同目录同名头共享段被并入）记档于
dedupe_key 注释。intentional-shared 交接面在 `storage_intentional_shared()` 备案
（自 check_storage_keys.py INTENTIONAL_SHARED 迁入 + 曝锚点 4697200）；
`tools/check_storage_keys.py --registered build/registry.json` 退役为兜底
（校验"写入点 ⊆ 注册集"，门禁 scan 步即此模式）——新增键段忘登记会被门禁拦住。

## 五、2026-10-22 二次改造（用户口径：末尾统一判定 + 覆盖 any 容器）

### 5.1 分类 = 真实的 map（修误报）

原「魂印」一个类别并了**单效果表**（`effect_cache_`）与**程序表**（`program_cache_`）——
两张独立的表，同 id 各注册一次**互不覆盖**，并类会误报。拆成 8 类：

| 类别 | 对应表 | 覆盖语义 |
|---|---|---|
| 魂印单效果 | soul `effect_cache_` | `effect_cache_[id] = fn` |
| 魂印程序 | soul `program_cache_` | `program_cache_[id] = nodes` |
| 魂印钩子 | soul `hooks_cache_` | `hooks_cache_[id] = hooks` |
| 技能效果 | moves `effect_cache_` | `effect_cache_[id] = fn` |
| 携带类效果 | moves `carry_effects_` | `carry_effects_[id] = fn` |
| 套装单效果 | suit `effect_cache_` | `effect_cache_[id] = fn` |
| 套装程序 | suit `program_cache_` | `program_cache_[id] = nodes` |
| 战前补丁 | 两个管理器的 vector | **追加**语义 → 同 (id, 时段) 两次 = **补丁被执行两次** |

后四条（携带类 / 钩子 / 套装 / 战前补丁）原先**完全没被审计**——它们也是覆盖/重复语义，
同 id 两处一样出事。补齐时顺带把注册宏的**来源**（文件:行）打通到这些路径。

### 5.2 判定时机：从"第一次撞到就报"改成"全部 flush 完统一判定"

用户口径：**不要一遇到冲突马上报错，要跑完所有动态库 flush 过来的 map，把冲突记录下来，
最后才 throw 一个 runtime error 停止进程**——否则一轮只改一处、反复重编译。

改法：
- `record()` **只记账不抛**（账本 = 唯一真相）；
- 判定点搬到 `PetFactory::initialize_runtime_data()` 末尾——**三个插件目录全部加载并
  flush 完毕**的时点（跨 dylib 撞号只有此时可见）；
- 那里调 `id_collision::audit_now()`：**新增撞号 → 抛 `std::runtime_error`** 停进程；
  已备案存量 → 报告但不失败；`SBS_ID_COLLISION_STRICT=ON` → 连存量也失败。

判定点为什么从 `dump_registry_json` 搬走：原来只在 `--dump-registry` 跑，
**普通开服与场景测试根本不查**。搬到 `initialize_runtime_data` 后**所有入口**都查
（服务器 / 场景测试 / 工具）。

### 5.3 顺手抓到的**真 bug**（不是审计假阳性）

**① 跨 dylib 符号插入 → 插件注册表被串用**

`plugin_reg` / `suit_reg` 的注册表是头文件里的 `inline` 函数 + 函数内静态量 →
编译器导出为 **weak 外部符号** → macOS 动态链接器做**符号插入**（interposition）：
后加载的 dylib 对该符号的引用被绑定到**先加载** dylib 的副本。

实测（`dladdr` 实证）：moves_lib 先加载 → soul_lib 里的 `plugin_reg::flush`
**实际跑的是 moves_lib 的副本**、读的是 moves 的表 →
- soul 的注册**从未被推给宿主**（soul 效果整批丢失）；
- moves 的条目被**推了两遍**（同 id 两处注册 = 后者静默覆盖前者）。

> ⚠️ 本文件开头写的"插件侧的表是 per-dylib"这个前提**在 macOS 上不成立**——已修正。
> 修法：把两个命名空间整体标 `hidden` 可见性（不导出、不被插入）→ 回到"每 dylib 一份"。
> **CoreApi 等跨库契约必须保持默认可见性**（插件要调用宿主的 `core_api()`），不能一起藏。

**② `std::any` 存储槽键撞号**（`tools/check_storage_keys.py`，新工具）

运行期状态槽按 **int 键**索引，**没有"注册"环节** → 运行期审计**抓不到**（没时点可盯），
只能静态扫（键是编译期 `constexpr` 常量）。抓出真实撞键：

`plugin_storage[3056200]` —— moves 侧 **826 击败旗**（值=施放回合数）与 soul 侧
**死亡判定求解中守卫**（`kGaiaResolvingKey + side`，值=1）同键。后果：魂印侧写守卫会
把 826 的旗盖成 1 再 `erase` 掉 → **826 的"击败"技能不触发**；反向则魂印侧把 826 的旗
当成"还在求解中" → **误判反同归**。已把 826 旗迁到独占段 `3056300`。

同扫描器还标出 `plugin_storage[4644100]`（crawford 减伤桶槽位）——那是**故意的**跨 dylib
交接（头文件键约定段有说明），已备案为 intentional shared，不算撞键。

扫描器已接进 `tools/night/build.sh` 全量门（新增退出码 4）。

## 六、坑记

- **插件不链接 sim_core** → 插件侧的 inline 静态表**本意**是 per-dylib；但**默认可见性下
  macOS 会做符号插入**，实际会串（见 §5.3 ①）。要用 hidden 可见性才真正 per-dylib。
  撞号本身**只能在宿主侧查**（宿主合并各库表后才看得见同 id 两个来源）。
- **改动插件后必须全量构建**：`cmake --build build`（ALL 挂 `*_deploy` 目标）才会把新 dylib
  拷到 `resources/*_lib/`；只编 `--target sim_server` 会加载**旧插件** → 撞号检测看着"没反应"。
  （本次排查就被这个骗过一次。）
- **插件侧的表用 `std::map` 会让宿主审计瞎掉**：`map` 语义"同 id 后到者覆盖先到者"，
  **同一 dylib 内**的重复注册在推到宿主**之前**就被丢了 → 宿主侧根本看不见。承载类效果
  的表已改成 vector（宿主侧仍是 map，覆盖语义不变）。
- **同名常量在不同文件里是不同的量**（仓库里 `kGateBase` 在三个文件里是三个不同值）
  → 静态扫描器的常量表**必须按文件建**，不能全局按名字建。
- **`git ls-tree` 默认对非 ASCII 路径做 C 转义**（`"docs/00-\347\273..."`）→ 输出行带
  字面引号 → 后续 `git rm <path>` 报 "pathspec did not match" 失败。提升脚本里全程
  `-c core.quotepath=false`。
