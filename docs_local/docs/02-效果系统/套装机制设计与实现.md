# 套装机制设计与实现（feat/suit，2026-09-19）

> 状态：**三套经典套装已实现，全量回归 93/93**（feat/suit-fx，2026-09-19 第二批；
> 骨架批次 86/86 见 git 历史）。内核自动执行点（init_battle → activate_suits）已随内核线合并生效。

## 0. 一句话

套装 = **第三类效果来源**（魂印/技能之外）：独立套装桶（魂印 → 套装 → 技能），
条目一律 TEAM 常驻（全队、整场、不可抹除/屏蔽），数据来自 Unity `equip.bytes` +
`suit.bytes`（已入库），效果实现走 `resources/suit_lib` 动态库。

## 1. 数据来源（已钉死）

| 内容 | 来源 | 入库表 |
|---|---|---|
| 套装 → 部件清单 | Unity `suit.bytes`（478 套，社区镜像 SeerAPI/seer-unity-assets） | `suit(id, name, cloths, suitdes)` |
| 部件 → 所属套装/描述/档位 | Unity `equip.bytes`（351+ 件） | `equip(item_id, name, quality, suit_id, rank_json, desc)` |
| 单件数值加成 | **官方已无结构化字段**（H5 的 Attribute 六维/AddWay/BattleLv 在 Unity 端被删） | `custom_equip_stats`（认证数据层，离线编码） |

- 成套效果全文**逐件重复**写在每件部件的 `desc` 里（人读校验源；与 B站机制专栏互证）。
- 例：影翼裁决 = suit 462（部件 1301099–1301102）；"晨曦之心" = suit 447 晨曦之星战甲
  （1301035–1301038）。抓取：`fetch_seer_unity_bytes.py` 已补 equip/suit 两项；
  H5 老快照 `scripts/data/raw/official/probably/equip_92b5f90a.json` 有结构化数值字段
  （老装备可用），新装备只有 desc 文本。

## 2. 装备模型（用户 2026-09-19 口径）

- 装备穿在**赛尔（玩家）**身上，效果全队（官方 desc 口径"背包内精灵…"）→ **per-side**，
  不 per-pet。协议 `BattleCreateRequest` 加 `equip_item_ids[2]`（二进制可选尾段兼容旧包；
  JSON lineup 可选 `"equip": {"side1": [...], "side2": [...]}`）。
- **成套激活**：某套穿戴件数 ≥ suit 表 cloths 全长（官方无独立"需求件数"字段）。
  构造时一次算定（`resolve_equipment`），战斗中零判定。
- **单件数值 ≠ 效果**：`equip_stat_flat/pct[2][6]` 纯数值累计（per_piece 每件算一次；
  per_suit 成套算一次，行编码在 cloths 首件上），并入基线视图由消费方读取，不进效果桶。
- **成套特性 = 查表**：激活套装 id → SuitManager 程序 → 套装桶。

## 3. 生效范围与不可抹除（用户口径：全队、无法被任何效果抹除或者屏蔽）

条目展开（`suit.h::Suit::register_suit_effect`）一律 `EffectScope::TEAM`：
不进 epoch 作废体系（换宠/断回合碰不到）、非回合类效果（`break_round_effects` 无效）、
插件自选非抑制敏感类别。与"引擎默认回调必须 TEAM"同一纪律，且**没有**任何引擎取消通道。

## 4. 插件面

- `include/plugin/suit_reg.h`：独立注册 API（`SuitPluginApi` + 入口符号
  `suit_plugin_register` + `SUIT/SUIT_PROGRAM` 宏）。**刻意不往 IEffectRegistry 加虚函数**
  （该文件另有 carry-effects 线在改，避免冲突；且套装装载走独立目录，装错目录的 dylib 自然跳过）。
- `SuitManager`（include/entities/suit_manager.h + src/entities/suit_manager.cpp）：
  仿 SoulMarkManager，加载 `resources/suit_lib`（PetFactory::initialize_runtime_data 挂入）。
- 首个实现：`resources/suit_lib/yingyi_462.cpp` 影翼裁决——常驻增伤 40%（ROUND_START 节点写
  `ws.damage_add_pct`，与通用增伤同一加算除法，官方"增伤均为加法"）+ 无护罩减粉
  （ROUND_START 快照到 plugin_storage + REDUCE_EXTRA 常驻条目乘法结算）。
  **未实现**：登场首回合"每损10%体力→50护罩→每50护罩+10%增伤"联动（需事件监听 +
  登场窗口 + 护罩增量归因，待内核合并后一起收口，见文件头 TODO）。

## 5. ⚠️ 待内核合并的接驳点（本分支的过渡形态）

1. **激活时机**：`activate_suits()` 目前由场景测试在 `start()` 前手动调用（模拟内核执行）。
   内核"游戏开始前加载并跑一遍"落地后改为 `init_battle` 内自动调用（在
   `install_common_trait_effects` 附近，需在首回合选择前完成注册）。
2. **伤害时点**：官方"套装造成伤害前"节点位于魂印伤害前之后、通用增伤**之前**——
   当前 462 增伤并入 AMP 阶段（同除法合并，数值等价、阶段序不严格）。若要严格分档，
   在 `DamagePipeline::kOrder` 的 AMP 前插 `SET_AMP` 阶段（一行 + 注释，属内核文件）。
3. clearAllEffects 清 `suit_effects`（已做）；重新激活随新对局的 activate_suits 自动覆盖。
