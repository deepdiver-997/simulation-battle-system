# 官方机制理解与引擎缺口对照

> 来源：`reference/seer_bilibili_专栏合集.jsonl`（赛学必修1-13 / 选修1-11 / 扩展1-3，共 27 篇，2026-04-23 抓取）。
> 用途：①粉伤抗性系统的官方依据；②引擎基础机制缺口清单。部分机制官方仍在新版调整中，以"记录为主"。

## 一、粉伤抗性系统（必修8 免疫粉伤 / 选修6 免粉补偿 / 选修8 吃月亮）

**粉伤** = 固定伤害(FIXED) + 百分比伤害(PERCENT)（血条粉色字）。

**粉伤计算流程**（必修8 流程图）：`增粉 → 抗性(%) → 百分比免减 → 免疫 → 护罩`。
特殊说明：粉转真有两个，顺序 **"未受到在前、免疫在后"**。

**免粉 4 形态**（选修6）：
1. 减粉 X%（=100% 时等价免疫）
2. 免疫粉伤
3. 将伤害抗性视为 100%
4. 免疫并反弹粉伤

**免粉补偿 3 类**（选修6）—— 对手没吃到粉时触发：
| 类 | 检测 | 代表 |
|---|---|---|
| 一（主流） | 附加粉伤**立即检测对手体力是否变化**（增减都算），不变→补偿（如粉转真），变→不补偿 | 技能 1531/1662/1668/1674/1749/1892/1885/1895/2093 |
| 二 | 体力 **+护罩** 都未变→补偿 | 技能 1647/1693/1697/1737/1740/1788 + 吉罗德/科萨斯魂印 |
| 三 | 体力变化 **< n** →补偿 | 技能 2077/2078 |

**吃月亮 2 类**（选修8）：一类按"恢复体力值"（原始值，不受恢复效果提升/降低/封回血影响）；二类按"实际恢复体力值"（受上述修正）。

**注意**：选修7 的"抗性"是**异常抗性**（概率抵抗异常），与"伤害抗性"是两个东西，别混。

## 二、异常体系（必修3 异常和免疫 / 必修11 免疫并反弹 / 扩展1 免控）

- **免疫异常**：范围内免疫；与异常抗性平行结算。
- **次数免疫（次免）**——补充自 reference idx=375《机制解析—次数免疫异常》、idx=418《异常抗性，免控与弹控》：
  - **消耗条件 = "精灵受到异常状态"**（本体真实受到），扣减至 0 即终止免控判定。
  - ⚠️ **存在回合类免控/弹控时，次免依旧正常消耗**（idx=418 第2条）。这与直觉相反，容易实现错。
  - **唯一不消耗**：**被弹回来的异常**——"被弹回来的异常不属于精灵受到异常"（idx=375）。且次免可免疫被弹回的异常（idx=418 第5条）。
  - 分**可视化次免 / 不可视次免**，本质同一物；区别是**可视化次免默认可传承给下个精灵**（idx=375）→ 对应引擎侧要表达的"可传承 / 不可传承"。
- **异常抗性**：每受 1 次异常结算 1 次概率抵抗，触发后显示"异常抵抗"图标（固定 2 回合），抵抗本质也是异常。需异常"可被响应"才结算抗性。
- **反弹异常** = 免疫异常 + 将受到的异常反弹给对手。新弹控：反弹回的异常**不过抗性**，但可被免疫/转化，可消耗对方次免；**异常最多只反弹 1 次**（防打乒乓球）。免控精灵不触发"进入异常"类效果（琉梦希望是"受到异常断回合"）。
- **转化异常**：精灵进入异常状态时转化为另一指定异常。
- 指定免控（远古异常）有历史 bug，多数效果模板 id：10麻痹/11中毒/12烧伤/13寄生/15冻伤/16害怕/22睡眠/94疲惫/99石化/103混乱/114易燃。

## 三、伤害流程（必修12 新版 / 选修1 增伤 / 选修2 减伤）

- 红伤顺序：**点数减伤 → 百分比减伤 → 伤害锁定 → 伤害免疫**；护盾/护罩后移（在通用减伤之后）→ 减伤先扣、护盾兜底。
- 增伤：**通用增伤**（"造成攻击伤害提升x%"）加法叠加；**非通用增伤**（"额外提升x%"）乘法叠加；**伤害翻n倍**=独立乘区。稀释现象。
- 减伤：**通用减伤**加法（上限 100%，超 100% 失效）；**非通用减伤**乘法。点数减伤时点零散。
- 变威力（必修4）：本质推翻第 1 次伤害计算做第 2 次，多个变威力取最后覆盖前面；变威力会无视部分点数减伤。

## 四、击败 / 免死 / 回合结束

- **击败与未击败 4 时点**（必修13 新版）：①未被击败/被击败时 ②未击败对手/击败对手时 ③被击败后 ④击败对手后。同时点"挨打方优先"。**保护机制：致死伤害必定保留 1 点体力**防卡死。
- **免死**（选修4/9）：残留体力（锁 n 点或 n% 体力）+ 重生（回满 pp/血）。检测时点：固定时点（死亡结算时点）或范围检测（一定范围内即时检测 0 血）。
- **回合结束 3 类**（选修5）：①自身体力 0 不触发 ②双方体力任一 0 不触发 ③不因体力 0 不触发。

## 五、其他系统

- **宝石**（必修5/选修10）：本质是技能特效 id（固定伤害宝石=29、威力宝石=1402-1411、二代异常宝石=756…），一代+二代。
- **精灵特性**（必修6）：单属性增伤 15 个、被动/主动异常特性、减伤、免死（回神/顽强）、瞬杀、虚无（概率闪避）、会心（独立暴击）、坚硬（红伤减伤）等，等级 0-5。
- **属性**（扩展2）：克制=技能系别 vs 防御方系别；属性技能 type 默认 8（普通）；属性反转/龙琰=改系别（引擎已支持 skill_element_view）；"免疫非本系技能伤害"（岚）=检测精灵系别 vs 技能系别。
- **转化技能**（扩展3）：替换对手技能（操作阶段就替换，原技能先手权/穿盔/效果全失效）。
- **天敌判定**（★ 用户 2026-09-13 游戏内实测确认）：「遇到天敌时效果翻倍」类效果（如落芳天华 17912 的
  effect 497"附加100点固定伤害，每次使用额外附加100点，最高400点，遇到天敌时效果翻倍"）判的是——
  **看当前场上对手的「固有属性」是否克制自己的「固有属性」，克制倍数 > 1**。
  三条否定条件（实测）：
  1. **不看技能属性**（与克制伤害计算不同——那个是"技能系别 vs 防御方系别"）；
  2. **不看属性视图**——用**固有属性** `pet.elementalAttributes`，不是 `elf_element_view` / `ws.view_elementalAttributes`；
  3. **实测反证**：用龙琰改掉谱尼的系别后，落芳天华的翻倍逻辑**不变** → 印证"改系别效果（属性反转/龙琰）不影响天敌判定"。
  引擎落点：`calculateRestraintMultiples(对手固有属性, 自己固有属性) > 1.0`（双属性按官方组合相乘，
  即 `elementalAttributesRestraints` 双向查表）。
  （J322 勘误 2026-11-05：底层聚合口径已改官方**算术平均**——组件集合全组合均值，
  "相乘"表述作废；>1.0 的天敌判定语义不变，1v1 退化单格值零行为差。）
  ⚠️ 插件侧**必须**走 `CoreApi::restraint_multiplier`（`moves_lib` 的 `is_predator()` 就是这么做的）：
  克制表是**运行时从 DB 加载**的全局数据（`elemental-attributes.cpp`），插件不链接 sim_core、
  拿不到该符号——即使函数是 static inline 也一样（inline 只解决"头文件可见"，不解决"表从哪来"）。

- **强化清除 / 弱化清除的免疫查询**（用户 2026-09-13 定，神圣复苏 1237 类"清双方强化/下降"）：
  **消除强化走 `clear_stat_boosts`（查免消除强化 `STAT_CLEAR`）**——虽然"先断回合再清强"通常已经把
  对手的强化保护一起断了，但**规范起见仍要查**：万一对手同时有"免断 + 免消除强化"，才真的清不掉。
  **清理弱化什么都不用查**（弱势不是"提升"，不受 `STAT_CLEAR` 保护，也不受 `STAT_DROP` 约束——
  那是挡"新增弱化"，不是挡"清除已有弱化"）。
- **"全属性+1 且翻倍"的翻倍口径**（用户 2026-09-13 定，光荣之梦 1238）：翻倍的是**本次提升的等级数**
  （即 +1 翻倍 = 净 +2），**不是**把已有等级翻倍。等价说法："提升等级数 ×2"。
  同一 effect 里"对手不为{1}系"读的是对手**固有属性** `pet.elementalAttributes`（双属性任一命中即算），
  与天敌判定同源（不看属性视图）。
- **概率类封属 = 每次响应掷一次**（695「{0}回合内{1}%令对手使用的属性技能无效」、
  936「未触发则令对手{2}回合内使用的属性技能无效」）：官方表现是**窗口期内每次对手用属性技能都各掷一次**，
  而不是"授予时掷一次、决定这几回合封不封"。引擎落点 = `RuleTicket::condition`（`notify` 逐条求值时掷），
  不中就当这条没响应、**不消耗次数**。
- **"造成伤害前附加"的落点**（1236 圣光吟诵"若对手使用攻击技能则造成伤害前附加对手最大体力1/{1}的百分比伤害"）：
  伤害管线的 **`DETECT` 阶段（防御方桶）**——此刻红伤已算出但 `apply_resolved_damage` 还没扣血，
  所以在这里给攻击方结算粉伤确实早于攻击伤害落地。DETECT 也是引擎给"受击惩罚/弹伤/转化体力"预留的阶段。
- **N 回合增伤（"下N回合伤害翻倍/额外提升{X}%"）不要直接注册管线回调**：
  管线回调注册后**永久驻留**（不随回合过期、不被断回合移除）。正确做法是**回合效果每回合写
  `ws.damage_add_pct`**——ws 每回合 reset 天然清空，效果走时点桶 → 断回合/切换作废免费获得；
  AMP 阶段由 `install_default_damage_amp()` 读取（该 ws 字段此前是死字段）。
- **窗口型免伤 vs 次数型免伤**：次数型（"免疫下N次攻击伤害"）走 RuleCenter `counts` +
  `install_default_damage_block`；窗口型（525「{0}回合内有{1}%概率免疫对手的攻击伤害」）因为要
  **逐次掷概率**、且必须吃 BLOCK 类别的"挡伤失效"掩码，走"BLOCK 阶段管线回调 + 自算回合窗口"。
  ⚠️ **已知边界**：管线回调不随时点桶作废 → **断回合目前不解除这两类免伤**，待官方口径核对后定。
- **属性技能无效状态**（选修11）：被封属即处于此状态（不看绑定方/回合次数/是否触发）；龙威≠属性技能无效状态；封属覆盖封属性。
- **"免疫威力高于 {X} 的攻击技能"（effect 854）——待做**（用户 2026-09-13 记录）：
  典型案例 天叶领域 24560 / 余温之辰 26170 的 effect 854「令对手下1次使用的**威力高于{0}**的攻击技能无效」。
  关键口径：**检测的是"面板威力"**——`moves.power` 这一列，**威力宝石的加成不会被检测到**
  （即不看运行时算出来的最终威力 / `ws.skill_power_view`）。
  用户给的实现方向：注册一个**监听器**（随切换失效，即 `EffectScope::ON_STAGE` + `invalidate_on_stage_effects`）；
  **每次选择完技能后**检查对应技能的面板威力，决定是否**消耗自己**并注册一个**当回合生效的狮盔**。
  ⚠️ 落点注意：选择期在 `on_selected`（此时 `roundChoice[owner][1]` 是本次点选的槽位；
  但技能替换后"执行用什么技能"要看 `resolve_replacing_skill`，面板威力应以**实际执行技能**为准——
  待实现时确认）。

### 五.0 回合数判定：先出手 / 后出手（★ 用户 2026-09-13 定，引擎级通用规则）

官方"**{N}回合内**"类效果的生效范围**取决于本回合自己先出手还是后出手**：

| 本回合出手顺序 | 描述为 N 回合时，实际生效回合 |
|---|---|
| **先出手** | 当前回合就结算一次 → `R, R+1, …, R+N-1` |
| **后出手** | 当前回合已经"错过结算" → 顺延延长 → `R+1, R+2, …, R+N` |

例：描述"4 回合内"，当前回合是 1 —— 先出手 = 生效于 1/2/3/4；后出手 = 生效于 2/3/4/5（未被断回合的前提下）。
**"其它技能的生效回合判定也是如此"**（用户原话）→ 这是通用规则，不是某只精灵的特例。

⚠️ **两个家族必须分开处理**（都在 DB 里且都常见）：
- 「{N}**回合内**」（`effect_info.info LIKE '%回合内%'`，约 495 条）——适用上表；
- 「**下**{N}回合」（`%下%回合%`，约 287 条，如"下2回合必定先手"）——语义上**本回合就不算**
  （先出手也是从下一回合起算），故它的窗口起点天然是 `R+1`，**不能再叠加后出手顺延**（用户 2026-09-13 裁定）。

**引擎实现（已落地，提交 `11de130` + 场景 038）**：
- `EffectWindowKind { InRounds, NextRounds }`（`include/effects/continuousEffect.h`）；
  `EffectMeta::window` 字段；catalog 从 `custom_effect_overrides(override_type='window',
  map_value='next_rounds')` 加载（`OfficialDataRepository::load_effect_window_overrides`）。
  **未声明 = 默认 `InRounds`**——家族靠认证数据层**显式声明**，不靠文本正则自动判族
  （文本解析是脆弱层；声明格式与理由见 `docs/03-数据与数据库/认证数据层.md` §3.1）。
- 折算入口 **`BattleContext::round_effect_start_round(owner, duration_rounds, window)`**（inline，
  插件可调）；插件侧查家族用 `CoreApi::effect_window_kind(effect_id)`。
- 需要插件配合的一点：**core 的 `register_branch` 只对 `left_round > 0` 的窗口效果折算**——
  一次性动作节点（`left_round == 0`）**不能挪**，否则"下N回合"技能的**执行节点**会被推后一回合才跑
  （动作迟到一拍）。插件自建多回合效果（如 843）必须自己调 `round_effect_start_round`。
- 顺带修掉一个真 bug：**843「下{0}回合自身所有技能先制+{1}」少一回合**（原先写死
  `registered_round = roundCount` → "下2回合"实际只覆盖 1 次 MOVE_RIGHT）。

### 五.1 龙威 / 封属 / 盔（技能拦截）——reference idx=473《机制讲解—龙威（附带封属）》

> ⚠️ **优先级（2026-09-11 用户定）**：技能判定 / 龙威这一块，**以
> [`技能判定流程与无效效果体系.md`](技能判定流程与无效效果体系.md) 为准**，本小节降为**辅助参考**。
> 理由：用户对比后确认该专栏文章的表述不如前者准确。冲突时一律以 `技能判定流程与无效效果体系.md`
> （尤其 §二 狮盔 vs 龙威、§2.3 次数类消耗、§五 SkillArmor/SkillInvalidCenter 设计）为准。
> 本小节保留的是文章里**独有的补充细节**（优先级序、不可断、绑定方），有疑问需回游戏实测确认。

这一节是"可响应效果容器"设计的辅助参考（与 `battle_primitives.h` 的 `seal_skill` / `SkillSeal` 对应；
目标结构见 `技能判定流程与无效效果体系.md` §5.1 的 `SkillArmor`）。

- **龙威的定义**："对手下一次（下X回合）技能失效。技能包括攻击技能和属性技能。"即
  **龙威 = 封攻击 + 封属**（原文："攻击技能无效＋属性技能无效＝龙威"）。
  → 一个"龙威"实为**两个响应器的组合**：对手用**属性技能**时响应"封属"那一半，用**攻击技能**时响应"盔/封攻击"那一半。
- **伪龙威**："伪龙威 = 封属 + 盔/封攻击（不分绑定方，回合或次数均可）"。与真龙威的差别只是**组成方式**，判定上"龙威本身没有高级或低级之分"。
- **分层**：真龙威/伪龙威 × 魂印/技能 × 次数/回合。
- ⚠️ **消费发生在"技能使用时"，不是命中时**："对手**非必中技能 Miss 依旧消耗次数龙威**"。
- ⚠️ **优先级序**（打谁的判定顺序）：
  **Miss ＞ 封攻击 ＞ 龙威 ≥ 狮盔 ＞ 挡伤**（原文凭"我方非必中技能在对手有闪避+狮盔时显示 Miss 而非红伤 0"证明）。
  → 容器查询不能是平铺的，要有优先级。
- **不可断**（文章原话）："魂印回合龙威不可断"、"魂印伪龙威均为不可断"；对照"技能回合真龙威
  **会被魂印消回合**"。
  ⚠️ **但"不可断"不是 seal 的属性**——它是 owner 级的 `ImmunityType::BREAK`（免疫内核）。
  用户实测口径（2026-09-11）：游戏内免断**只有**"保护自身回合类效果不被断"这一种描述，
  即该回合类效果存在就拦截断回合，"断回合相当于断了个空"；**不存在**"某个效果不可断、
  其它效果不被保护"的粒度。
  证据：reference idx=413（免断也是回合类效果，分响应/不响应）、idx=184（断回合"未消除成功"
  = 对手无回合类效果 **或** 对手处于免断）。
  → 实现：龙威效果自身 `grant_immunity(owner, BREAK, coverage, 0, 持续回合, source_id)`；
  穿透靠 `coverage` 位覆盖时点（低级免断只覆盖部分时点），**不需要**给技能开特例。
- **绑定方**：技能龙威均**绑定自己**；魂印伪龙威的封攻击**不分绑定方**、被动封属**绑定对面**。绑定方影响"被拦截方换宠是否洗掉"。
- **穿透**：穿盔技能可消耗次数狮盔（同时被穿盔）；条件狮盔（"伤害低于XXX"实为**裸伤**低于 200）等特殊类。
- 相关：**点数减伤打盔不消耗**（idx=53）——"既然不消耗那自然也不会触发"，即被盔挡下的攻击不算"造成伤害"，减伤类效果不响应。
- **房主/挑战方**（必修1/7/9）：决定同时点效果谁先结算。引擎已编码：robot 0 = 房主（`execute_registered_actions(-1, state)` 先 0 后 1）。挑战方可换（bp 先选完者）；双方都不出手时按挑战方判定先手。
