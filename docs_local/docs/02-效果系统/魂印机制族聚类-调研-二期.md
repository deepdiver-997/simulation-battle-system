**注册集口径教训（对后续调研最重要的一条）**：注册宏有**五种形态**——
`SOUL_MARK / SOUL_PROGRAM / SOUL_MARK_TYPED / ~~SOUL_PROGRAM_TYPED~~ / SOUL_PRE_BATTLE /
SOUL_MARK_HOOKS`（定义在 `include/plugin/plugin_interface.h:425-469`）。首期与
S3/S4 前各单的"grep 注册集"只扫了 MARK|PROGRAM 两形态，会漏掉 PRE_BATTLE 面注册
（247/137 面板宏就是纯 PRE_BATTLE 注册、不占 SOUL_PROGRAM 数）与 MARK_HOOKS。
且常量名跨文件复用（`kMarkId` 在不同文件 = 不同值），**必须逐文件解析常量**，
头文件半径含 `resources/**/*.h`（S1 方法论第 3 条的加强版）。

> **勘误（2026-11-05，S16 回灌，S9 现查关单）**：本文写作时把注册形态误列为
> 「六种」，多出的 `SOUL_PROGRAM_TYPED` **从未存在**——`git log -S
> "SOUL_PROGRAM_TYPED"` 全史仅命中 S5/S9 文档提交（3f82fa74/39aa3a95 等），

> 类型化面实际只有 `SOUL_MARK_TYPED`（单效果）与 `SOUL_NODE`（程序节点）两个入口
> 〔源: include/plugin/soul_node_args.h:63-71〕〔源: docs_local/docs/10-游戏百科/04-魂印系统.md §二〕。
