# 效果实现套路目录（收敛口径）

> **性质**：实现前的**第一站**。本项目效果量大，实现路径必须收敛到尽可能少的
> 已验套路——总是自己另起一套方法，方法论上违背"使用原语"原则，且路径发散后
> 冲突面和维护成本都不可控。
> **用法**：拿到新单先过 §零决策树 → 命中套路的**照抄先例文件**（结构、注释密度、
> 断言口径一起抄）→ 套路覆盖不了的走内核原语组合 → 组合不出 = 立内核微任务，
> **禁止私造等价机制**（自记状态绕原语、直写 hp、自掷骰等）。
> 时点/注册/断言口径见《K系魂印实现形态-SOP.md》（本文不重复）；场景坑见
> 《06-交接/场景断言口径坑集》。

## 零、决策树

```
新效果单
 ├─ ① 本文有同形套路？ ──→ 照抄先例文件（含断言口径），行参走 db_at 原序
 ├─ ② 《battle_primitives.h / core_api.h》原语能组合？ ──→ 组合实现（SOUL_NODE/SKILL_EFFECT）
 ├─ ③ 检测面靠事件？ ──→ 查 §五事件对照表选事件；没有对应事件 → 内核微任务
 └─ ④ 都不行 → 内核微任务立项（新增原语/通道/事件），不私造
```

## 一、递增类（"每次使用额外 +X，最高 Y"）

**先例**：落芳天华 497（`moves_lib/heal_drain.cpp`）、神灵之触 906（同文件）。

- **计数容器三选一**（用户 2026-10-21 拍板）：
  - `pet.on_stage_storage` —— 本次上场有效、**下场不保留**（官方实测默认口径，
    "每次使用递增"族绝大多数如此）；
  - `pet.soulmark_storage` —— 跨切换保留（无相谛 2260 蓄力类）；
  - `ctx->plugin_storage`（`std::map<int, std::any>`，any 容器）—— 跨宠/全局资源
    （方级计数、水/泪类资源发布槽基底）。
- **注册/触发函数读计数定档**：`amount = base + step × (uses-1)`，先封顶后吃翻倍
  （497 的"最高{2}点→封顶后天敌翻倍"次序），落点走原语（fixed_damage /
  deal_pink_damage），不直写 hp。
- 递增的**幅度进乘区**时走 §二 或 §四，计数本身仍存容器。

## 二、常驻平乘区（"每回合 X% 增/减伤、闪避、增伤"）

**先例**：噬神狂天 352（`resources/soul_lib/k344_dodge_hitmod.cpp`，受伤 +20%）。
条件门在每段伤害期间可能变化的效果不适用回合首快照，见下方「逐刀动态增伤」。

- 载体 = **ws 槽 + 每回合重写**：ws `reset()` 从全默认实例逐成员拷贝（结构性清零），
  魂印节点在 ROUND_START（技能效果在开门时点）重写。退场残留至多当回合（记档口径）。
- **减伤槽负值 = 增幅**：`damage_reduce_add` 的算术对称钳 ±100
  （`calculation.h applyDamageReduction`），-20 = ×1.2、-100 = ×2；乘算槽
  `damage_reduce_mul` 同理连乘。**不要新增"正向受伤通道"**——就是负值减伤槽。
- **槽位纪律**：4 槽跨槽求和，写"第一个空槽"（diwang/crawford 同款惯例）；
  同槽两写手互相覆盖。
- **一切 int 乘区统一走 `checked_pct_mul`**（`calculation.h`，溢出响亮报错）——
  场景堆超大 HP 会当场 throw，改小 HP 值而不是绕。

### 2.1 逐刀动态增伤（条件门可能在同回合内变化）

**先例落点**：659，`resources/soul_lib/k289_boost_damage_amp.cpp`。
**用户 2026-11-06 已定**：逐段实时检查自身 boost（任一能力等级 >0）；本轮在
**每段红伤结算时**现场判断，门开才给通用增伤，同回合获得/失去强化后，后续红伤
应读变化后的状态。`ws.damage_add_pct` 目前只由红伤管线消费，**粉伤不消费**，
不能沿用旧文件头「全部伤害生效」的说法或顺带扩大本轮范围。
不能把回合首一次采样或技能效果时点一次采样当成逐段动态，也不能因再次结算而重复累计
常驻 ws 加成。K289 已复用 GUARD_DETECT 写入 / DETECT 回收的管线模式，并通过
4390/4450、全量940场景及11个关联场景的同平台重复快照验证。六项重复背景见
`docs_local/docs/02-效果系统/效果id撞号审计-2026-10-22.md` §零。

## 三、持续 N 回合窗（"登场/触发后持续 N 回合"）

**先例**：探针 `test/scenario/scenario_2994_soul_window_probe.cpp`；注册面 T6（2026-10-21）。

- **SoulMarkNodeRef 直接声明 `duration_rounds=N`**：锚点 = 本次上场首次注册，
  更新器重注册自动携带剩余、窗过期自动跳过、离场清锚再上场重开窗。
- **不要手写 plugin_storage 窗账本**（K7/K12 是 T6 之前的过渡形态，存量不强制
  迁移，新代码一律注册面窗界）。

## 四、次数/窗口型凭据（"下 N 次……"）

**先例**：霍光 1926（PENETRATE_ATTACK counts=2）、奥菲（INSTANT_KILL 次免）、
1287（吸取成功授"下{0}次受伤 -{1}%"）。

- 载体 = **RuleCenter 票**：counts>0 次数型（响应即扣）/ counts=0 窗口永久型；
  绝对窗口免 tick、断回合作废、换宠清（ON_STAGE）——生命周期全自动，不要自记。
- 授予走 `ctx->grant_immunity` / `grant_attack_boost` 等内联入口；覆盖键语义
  （source_effect_id 默认 -1 同类型互相覆盖）先读 `rule_center.h` 注释再传参。
- **次数型增幅乘区**（如"下 3 次受伤翻倍"）通道未建——遇到先立内核微任务
  （管线查询票，用户 2026-10-21 方向），不要用 ws 槽凑。

## 五、事件检测面对照表（选事件 = 认"机制"不认"结果"）

| 事件 | 何时发 | 典型消费者 |
|---|---|---|
| `EVENT_ANOMALY_IMMUNED` | 异常免疫票命中（次免/魂免；弹控反弹也算） | "每被免疫 1 次…"（2059/4829） |
| `EVENT_ANOMALY_RESISTED` | 异常抗性 roll 命中（与上互斥，抗性在前） | 圣芒佑界 476 |
| `EVENT_ANOMALY_CONVERTED` | [6] 转化层改写且落地（amount=原始/converted_to=转化后） | 4829"每被转化 1 次" |
| `EVENT_DAMAGE_IMMUNED` | 红 BLOCK 相/粉 IMMUNE 相**免疫票挡下**（带挡前 final + damage_kind） | 4830"对手免疫固伤则…" |
| `EVENT_ANOMALY_ATTACH_LOW_CHANCE` | 异常附加裁定面：申报过概率且**闸门改写后实际 ≤50%**即发（与掷中无关；chance_source=来源）。两处 emit：apply_anomaly_impl [2.2] / 随机附加池 ②（2026-11-06 曝线新增） | 梅赫维特永沐"≤50% 控场→挂曝"（8031） |
| `EVENT_SKILL_ARMOR_RESOLVED` | 盔每结算一条（blocked/grant_id；**被穿也发**——监听器须自删） | 2006/2270"触发成功则…" |
| `EVENT_ATTACK_BLOCKED` | 结算面 final≤0（分不清谁挡的——要归因用上一条） | 反伤族 |
| `EVENT_HEAL_RESTORED` | 实际恢复落地（actual>0；吸取回血半边也算） | 蛊插入真伤 |
| `EVENT_STAT_REMOVED` | 消除/吸取强化成功（带归因，一次动作一条） | 混地插盾 |

- 事件是**入队 + 晚 drain**、emit 时快照 state——回调里读现场面过期（K1 病灶），
  读 `ev.*` 载荷或走 DETECT 相位同步查询。
- 事件不够用时**新增事件面**（如上表 2026-10-21 新增两条），不拿别的_event 语义凑。

## 六、资源计数（印记/水/泪/律/庇类"第几层"）

**先例**：`resources/nutao_runtime.h`（4690000 段）、`diwang_runtime.h`（4691000 段）、
`gelaorui_runtime.h`（4692000 段）、`monika_runtime.h`（4693000 段）。

- 新资源照抄 runtime.h 分段结构：`constexpr int k<X>Pub<Base> = 469N000;  // + side`
  段即命名空间，只增不改；锁定/下场保留语义建独立槽（如 nutao 的 Water/Lock 双槽）。
- "附加某印记到最大值"= 写对应发布槽的锁定通道到 cap（格劳瑞 1551 发旗标
  `kGlaPubMarkBase+pet_id`、各王自理拉满——**不在发放端硬编码枚举**）。
- 广播/审计走 §五(规划中)命名表静态映射，不往 map value 塞 string。

## 七、直查类口径（容易误诊的三条）

- **deal_damage(NORMAL) 直调不跑相管线**（裸扣血路径）——BLOCK/减伤相只在技能
  攻击结算里跑；场景要测红伤挡下/减伤必须真实技能结算驱动（2993 探针实证）。
- **deal_pink_damage 直调可测粉管线**（IMMUNE/REDUCE 相在内跑）。
- **effect_icon 查库**：pet_id 是 TEXT 存 JSON 数组 `"[3740]"`，整数等值查必空；
  行 id ≠ effect_id（沧岚 2343 行 id=1932 的坑）；神谕双版本行按 icon 高低调
  （工厂 K1 开关选行，无需特例）。

## 七点五、条件先制族（"条件成立 → 本技能先制+N"）

**先例**：`resources/moves_lib/j_cond_prio2.cpp`（J115：958/1174/1081）、
`resources/moves_lib/j_cond_prio3.cpp`（J312：1956/1292）、
`resources/moves_lib/crawford_skills.cpp`（954 低体先制）、
`resources/moves_lib/j_cond_priority.cpp`（J53：454/1484/1487）。

- **必须走选择期路由**：先手权在**选技阶段**就定——注册进用技期分支
  （`effect_register_state` case 路由）赶不上首回合先制判定（J66 勘误：case 版
  先手断言必挂）。正解 = 在 `src/entities/skills.cpp` 的 `selection_effects_`
  硬编码表加一行 id（`on_selected` 统一注册到 `BATTLE_FIRST_MOVE_RIGHT` 桶，
  先手权比较前生效）。
- **门判据三型**（判据在插件效果体内算，id 只进路由表）：
  ① 异常门 = `has_active_anomaly` 扫全集 0..43（"任一异常"）/ 指定码；
  ② 能力提升门 = `ability_levels[side][slot] > 0` 任一正槽（六槽含命中）；
  ③ 体力比较门 = `hp` 整数直比（严格小于，954 同款）。
- **先制量**：有行参的读行参（在位即消费，不写死文案数字）；零参宏把量写死在
  模板文案里（+1/+2），插件侧写死并在注释注明。
- **断言口径**：**先手权结构断言**（硬于数值）——先制等级不等时先手权只看等级不看
  速度 → 己方速度 100 < 对手 300 仍抢到先手 = 等级确实加了；门闭时等级相等 →
  回落速度 → 对手先手。配审计槽（触发标记 / 授予量）证明"确实走到了目标分支"。
- ⚠️ **变异批处理的陈旧二进制坑**：同一源文件连续改两次做变异时，第二次构建可能
  判定无需重编 → 跑出的是上一个变异的二进制。**每次变异后先 grep 确认变异已落到
  源文件 + touch 再构建**，并核对失败点是否符合该变异的预期特征。
