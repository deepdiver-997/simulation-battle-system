# 回合制对战基础设施 —— 2026-09 重构总结

> 本文是九月重构的**顶层架构叙事**：明确了回合制对战引擎需要哪几类基础设施，以及
> 为什么它们是批产爆发式增长的真正原因。分片细节见各专档（文内引用）；本文不重复
> 细节，只回答"这套系统由什么组成、为什么长这样"。
> 用户总结（2026-09-29）："最重要的是明确了回合制对战需要什么——生命周期、两种触发
> 模式（主动查询用 rule ticket，事件触发用 event）、主动执行效果的 timed bucket，
> 这几个消息传递基础设施才是真正支持爆发式增长的原因。"

## 〇、核心命题

九月的本质转变：**效果 = 数据，住进固定的基础设施**。八月之前每做一个机制都要动内核；
九月之后新效果只写 handler + 三个声明（时点桶、生命周期、触发方式），内核零改动——
于是有了 D 组 29 精灵一夜 24 支、E 组 13 家族、F 组持续批产。爆发的原因不是写得多，
是**地基先打平了**。

基础设施共四层：**生命周期**（状态住哪、活多久）、**两种触发模式**（主动查询 rule
ticket / 事件触发 event）、**时点桶 TimedBucket**（主动执行效果的挂载与调度）、以及
把它们缝起来的**伤害管线**（有序阶段机）。

## 一、生命周期（状态住哪、活多久）

每一条效果状态都必须回答"绑定谁、活多久"。四类绑定（矩阵详见《技能判定流程与无效
效果体系》§5.3）：

| 绑定 | 语义 | 载体与机制 | 典型 |
|---|---|---|---|
| **在场 ON_STAGE** | 换宠即失效 | `EffectScope::ON_STAGE` + valid_id/epoch 惰性作废（watcher、on_stage_storage、管线 `pipeline_valid_id`） | 46 挡伤票、登场窗口 |
| **队伍 TEAM/ROSTER** | 切换/离场保留 | `WatcherScope::TEAM`、`soulmark_storage`（下场不清，消逝才清） | 星皇 903 场下赐福、跨回合受击 watcher |
| **次数 counts** | 消耗型：命中才扣 | RuleCenter counts 票（被抑制**不扣**——031 Q4 契约）、闭包计数器 | 次数盔/次免、穿透凭证、1036 计次附伤 |
| **回合 duration** | 窗口/永久 | `InRounds`（含当回合）/`NextRounds`（下回合起算）绝对回合模型；`ws.reset()` 每回合重基（view_levels/preemptive_level）；duration=0 永久 | 794 挡伤窗、1123 先制窗、无尽八荒之力 |

工程纪律随生命周期而来：plugin_storage 键段分立（bool 与 int 分键防撞）、视图与本
体分家（view_levels 每回合重基 vs ability_levels 本体）、凭证放 ws（回合 reset 自动
清，"下一回合刷新"免费获得——技能判定流程 §九）。

## 二、两种触发模式（消息如何流动）

**判据一句话：《技能判定流程与无效效果体系》："消费语义 ≠ 通知语义"——
门禁/查询用 rule ticket（pull），事后反应用 event（push）。**

### 2.1 主动查询（pull）—— RuleCenter 票
- 授予与消费分离：`grant_immune/seal_skill` 授票 → 消费点（伤害管线 BLOCK 默认回调、
  攻击门、切换门）`is_immune/consume_immune` **现查现扣**；
- 票按类别自治：IMMUNE（DAMAGE 红伤挡/ANOMALY/BREAK 免断/INSTANT_KILL）、ARMOR、
  SKILL_BAN、SWITCH_LOCK、CHANCE_GATE（概率申报亮节闸门）……
- 伤害类再叠 `DamageEffectCategory`（AMP/MITIGATE/BLOCK/DETECT）→ 支持按类抑制
  （沧岚 4 滴掩码废 BLOCK|DETECT、减伤不废）；
- 关键语义：命中才扣、被抑制**不触发不扣次**、纯查询（窗口/永久票）不消费。

### 2.2 事件触发（push）—— EventCenter
- `emit` 只入队，FSM 在 State 桶跑完后**统一 drain**（根除重入；波次上限 8 响亮报警）；
- watcher = (type, owner, register_round, duration, once, scope)——订阅即声明生命周期；
- 事件族 + payload 扩展字段**追加在 struct 末尾**（纪律）：TAKE_DAMAGE（+damage_kind
  区分红/粉）、SKILL_USED（+used_attribute，"使用即触发"）、STAT_BOOSTS_LOST
  （+stat_loss_kind 消除/吸取）、SKILL_ARMOR_RESOLVED（+grant_id 精确匹配）、DEATH 族；
- 典型消费：反伤/转体（462/580/1219）、消强监听（573）、使用监听（469）。

**反例入档**：soul_lib 直调守卫不经过管线 walk → 自读同一掩码（真相源单一，插件不
维护 allow-check 列表）；三种抑制形态辨析（掩码=持续态、票=消耗态、凭证=穿透态，
不可互换——见《挡伤票据与内核扩展-设计定档》§2.3）。

## 三、主动执行效果 —— TimedBucket 时点桶

`include/effects/timed_bucket.h`：按 State 触发的效果容器，封装"注册 → 同源去重 →
到时点执行 → 过期清理 → epoch 作废"全套生命周期（技能桶/魂印桶/更新器桶共用一个类）。

- 30+ 个 State 时点（ROUND_START → FIRST_MOVE_RIGHT → BEFORE/ON_SKILL_HIT →
  SKILL_EFFECT → ATTACK_DAMAGE → AFTER_ACTION → …回合收尾族），桶按序执行、
  桶后统一 drain 事件；
- **效果三要素正交**：时点（哪桶）× 生命周期（§一）× 触发（§二）——写新效果 =
  三个声明 + 一个 handler；
- **伤害管线是平行的有序阶段机**（GUARD_DETECT→AMP→AMP_EXTRA→REDUCE_TRAIT→
  REDUCE_FLAT→REDUCE_PCT→FLOOR→CAP→BLOCK→DETECT→FINAL_CORRECT）——"顺序即机制"，
  `kOrder` 是可改常量；犀牛链首快照、693 乱穿、锁伤最后拦，全是阶段序的表达。

## 四、为什么能爆发式增长

1. **效果 = 数据**：新效果 = 新 handler + 声明，不动内核（本周期 100+ 效果落地，
   内核增量仅三次且都是"新事件/新字段/新视图旗标"级别的通用件）；
2. **插件边界干净**：CoreApi 函数指针槽（插件不链接 sim_core）+ plugin_storage
   （跨 dylib 通信）+ 静态自注册宏（SKILL_EFFECT/SOUL_MARK，写错 id 编译期报错）；
3. **每任务一文件**（moves_lib/e_*.cpp/f_*.cpp）→ 零合并冲突 → 多 agent 并行批产
   成为可能（D 组一夜 24 支；E/F 组子 agent 流水线）；
4. **守护网**：212+ 场景回归 + registry 记账（coverage_scan 重盘）+ EffectArgFault
   快速失败——批产不回退。

  从死凭证转为有消费面）；

  常识速查"4 水清泪时点口径"）。
