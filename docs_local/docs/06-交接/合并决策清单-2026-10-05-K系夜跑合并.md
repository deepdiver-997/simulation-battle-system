### K4 时点口径四连——定版为 SOP 还是内核改时点

本夜实测的四条时点语义（各单头注+晨报记档）：
1. preemptive_right 在 FMR 桶执行**前**已重置 → "上回合先手权"计数必须 ROUND_COMPLETION 收口（K12 310 实测）；
2. ws.preemptive_level 的 memset 在 MOVE_RIGHT 时点 → "下回合先制±N"必须 FMR 桶写（1123/636 同款；K14 头注同记档）；
3. EVENT_SKILL_USED 时点写 skill_power_view 会被物化覆盖 → 威力改写必须 SKILL_EFFECT 时点，且该时点 skill_use_seq 未自增、executed_* 门不可读（K4 636 直系，K165 291 实测）；
4. ROUND_START 桶内 roundCount 滞后一轮 → 窗口类效果统一用 plugin_storage 窗账本口径（K7 实测）。

选项：
- A. 四条定版进《K 系实现形态》SOP / 立单模板（零内核改动）
- B. 逐条评估内核改时点（高风险：存量 488 场景全量回归 + 与已落地宏的兼容）

**建议**：A。

决定：变威力一般是技能效果，所以在技能效果生效处改写视图触发再次重算应该也合理吧？还有你看暴击破防应该是在第一次计算红伤之后、第二次检查有没有变威力重算之前，这样符合变威力暴击无视对应防御等级。上回合先手权你说要不在内核context加一个字段记录算了，要不然依赖的效果就要自己注册监听效果不断记录到自己的storage，现在怎么做的？技能效果带下回合先制改变的，应该是在技能效果生效时点执行一个效果，这个效果再注册一个效果到先手权判定时点前的效果桶，而不是直接在点击技能时就注册到先手权时点桶。然后我再次确认一下技能使用流程，是不是在选择完之后马上拷贝一个技能副本到视图中，后面都是读取视图而不是原本的skill槽，这样方便技能替换等，但是消耗技能pp还是指向原技能槽位的，一些和当前技能pp有关的效果也是会看回选择槽位的pp。你说的 SOP 是什么意思？

**逐条答复（2026-10-05 白班查证，行号可点击核对）**：
1. **变威力在技能效果生效处改写视图**——确认，现状即此设计：`skill_power_view.consume()`
   （battleFsm.cpp:527）之后的写入才算"效果改写"→ ATTACK_DAMAGE 收尾重算第二次。SOP 收编，无改动。
2. **暴击破防时序**——查证：**现状已符合你的口径**：`apply_crit_defense_break` 紧跟第一次
   红伤计算（battleFsm.cpp:1889/1903），变威力重算 `apply_variable_power_recalc` 在其后
   （battleFsm.cpp:817/883），第二次天然读到归零后的双防（battleFsm.cpp:788 注释即此意）。无需改动。
3. **上回合先手权**——现状：**内核无字段**，效果自记。K12 310 的做法 = FMR 桶节点读当回合
   `ctx->preemptive_right`（FMR 判定完成后仍为当回合值）+ `plugin_storage` 累计连续计数；
   "上一回合"语义则靠 ROUND_COMPLETION 收口进自管 storage。**采纳你的方案：内核加字段**
   （`ctx->prev_round_preemptive_right`，ROUND_COMPLETION 时点快照，早于下回合 FMR 的
   memset）→ 任务单 T2。
4. **下回合先制改变**——确认现行形态正确：技能效果时点执行 → 再注册进先手权判定前的
   FMR 桶（不是点技能时直挂）。SOP 收编，无改动。
5. **技能使用流程**——查证：**没有"拷贝副本"这步**，机制是**取用点重定向 + 视图物化**：
   - "执行什么技能"的读取（effectBranches/威力视图/系别视图/暴击率/伤害公式）统一走
     `resolve_executing_skill`（battleFsm.cpp:366）→ 替换生效，**不拷贝技能对象，只重定向取用点**；
   - 威力/连击/系别/类别四个视图在 ON_SKILL_HIT 物化（battleFsm.cpp:504-524），效果后续可改写；
   - "玩家点了哪一格"走 `resolve_selected_skill_index`（roundChoice[1]，battleFsm.cpp:328）
     → **PP 扣在原点选槽位、替换不生效**（battleFsm.cpp:363 注释明文约定；
     consume_selected_skill_pp 在 battleFsm.cpp:423）；PP 反转（2260）等 PP 相关效果同样读
     原槽位 `skills[i].pp`。
   - 结论：**与你理解的语义一致**（执行读"视图化"的技能、PP 落在原槽位），机制是重定向不是副本。
6. **SOP 释义**：Standard Operating Procedure，这里指"标准作业约定"——把定版口径写进
   《K 系实现形态》那类记档/立单模板（如 zhr-night 晨报 §二.1 那三条），后续夜跑立单直接
   引用，不是代码改动。→ 归入任务单 T1。

### K7 must_hit 语义边界 + 参数防混

**现象**：①must_hit 攻击绕过 hit_rate_mod_attack 乘区与 hit_invalid 封技
（K165 实测）；②query_usage 的 must-hit 分支跳过闪避——accuracy_100 误传
must_hit 会让闪避窗完全失效（j-prod-3 §三.4）。

决策点：must_hit 绕封技/乘区是否符合官方口径（未见对证）；接口参数防混。

选项：
- A. 记档维持现状，立单检查单加"acc vs must_hit 防混"提示
- B. 接口层拆参防混（kernel API 改动）
- C. 先对官方口径核对 must_hit 与封技/乘区的关系，再定 A/B

**建议**：C。

决定：“必中”效果只能保证一定命中，即不可能Miss，但是命中效果不会保证，而且面对技能无效（封属、盔、龙威）照样是按照未命中结算，命中效果是否生效也无法影响只有强制执行可以无视命中效果失效，必中也会受到“失明”异常的影响，处于该异常时没有必中凭证者必定Miss，有凭证则命中但是50%命中效果失效、50%正常（仅命中环节，要是有命中效果失效还是得看有没有强制执行），必中凭证存在时跳过命中率掷骰子

**2026-10-05 追更正（用户口述）**：影响必中攻击技能的是"**失明**"（上文已更正）；
"**失神**"则是导致**属性技能 50% 无效、50% 正常——这是"技能无效"，不是"命中效果失效"**
（用户自注"好像"，失明/失神精确文本待官方对证后回填）。

**内核后果（本清单最重要的实测冲突）**：引擎现状 must_hit **绕过 hit_invalid 封技**
（K165 实测）——与"面对技能无效照样按未命中结算"的官方口径**相反**。
**立项（T3）**：①must_hit 不再绕过 hit_invalid（封属/盔/龙威 → 按未命中结算）；
②query_usage 拆分 acc_100 与 must_hit 参数（accuracy_100 误传 must_hit 使闪避窗失效）；
③必中仍跳过命中率掷骰、不保证命中效果。⚠️ 2950 等 K165 断言可能翻转，逐个核对。
