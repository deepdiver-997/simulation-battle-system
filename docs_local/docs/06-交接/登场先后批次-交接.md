## 一、开工流程（每个 agent 相同）

1. **建工作区**：`docs_local/tools/new-agent-worktree.sh <名字>` →
   `../agents/<名字>`，分支 `feat/<名字>`（基于 main-local 当前 HEAD）。
2. **先读**：根目录 `CLAUDE.md`（插件 ABI 边界 3.9 / 构建纪律 / git 纪律）、
   `docs_local/docs/06-交接/魂印与技能机制-交接.md` 的「深夜」段（登场先后三层规则 +
   对齐落地记录）与「2026-09-21」各段（固有效果 INHERENT / 消逝交互 / ATTACK_NULLIFY）。
3. **构建纪律**：改插件后必须完整 `cmake --build build -j8`（单独 --target 场景
   不会重部署插件 dylib）；**禁止** `-DCMAKE_BUILD_TYPE=Release`。
4. **plugin_storage 新键**：先 `grep -rn plugin_storage resources/` 扫键段
   （撞键坑已发生 2 次：armed_flag bool 撞 int）；只放 int/bool 基本类型，
   **结构体跨 dylib 的 any_cast 必炸**（状态在魂印 dylib、技能要读 → 走 int 发布槽，
   样板：`resources/kongyuan_runtime.h` / `qiling_runtime.h`）。
5. **实现效果前先 grep**：`grep -rn "SKILL_EFFECT(<id>," resources/moves_lib/` ——
   效果 id 是全局共享的，同 id 效果跨精灵复用（1208/1531/936/843/1475/821 等已存在，
   重复注册=重定义冲突；要用同 id 效果直接白拿）。
6. **场景**：新场景从 `scenario_112` 起编号；一条精灵线至少一个场景文件锁核心判定。
7. **收尾**：全量回归（基线 111/111 + smoke）→ 提交 → 汇报合并。
   并行分支**不要用 --ff-only 合并**（分叉后必然失败），用普通
   `git merge --no-ff feat/<名字>`；后合并者先 rebase 或解冲突。

ROUND_END + 待结算位；共享时点结算序 = 房主→挑战方（本批的地基规则）。
