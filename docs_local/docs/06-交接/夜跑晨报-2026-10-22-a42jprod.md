## 三、勘误与记档

1. **spawn 级"不自行立项"与任务书 author 协议的冲突**：本会话按任务书走了 author 协议
   （J278-J284 均自建）。a38 晨报的先例是**不**续立；后续 spawn 若沿用同一措辞，建议
   在任务书里显式二选一，避免每会话各解一次。
2. **同 worktree 多会话并发构建**（a43/a44）：同一 `build/` 与 `resources/moves_lib/liblib_1.dylib`
   被并发重建时，`scenario_6130` 曾出现**间歇性假红**（插件处于另一会话的中间态）。
   纪律：直连 cmake 时"构建+运行"必须同一条命令连续执行；最终门一律 `tools/night/build.sh`。
3. **taskctl add 的 git commit 在并发下可 exit 128**：行已写入看板、仅提交失败；下一次
   add 会把两行一起提交。事后核对 `git log` 与 `git status` 即可，不要重复 add（同号拒绝）。
4. **author 冷却 600s**：`author.last` 记录本会话时，10 分钟内 `author.sh` 会静默让出
   制定权（表现为反复 exit 75）。这是设计行为，等待冷却后再调即可。
5. **heal_amount 返回的是 HealResult 枚举**，不是实际恢复量；实际量读
   `ctx->ws.last_heal_amount[target]`（heal_impl 写入）。
6. **事件"入队 + 晚 drain"**：场景在 FSM 外调 `heal_amount` 后，回血事件要到下一回合
   首个时点桶后才投递——触发审计断言必须**放到下一回合之后**（J282 首版踩过）。
7. **miss 不执行 SKILL_EFFECT**：accuracy=0 时技能在 Before Skill Hit 即返回，插件效果
   根本不会跑（J280 初版想用它测"miss 不延长"，审计槽读到 -2）。侧面证明"miss 不触发
   本次技能效果"是 FSM 级行为，不需要插件再判。
8. **179 是盘点假阳性**：内核文本解析器 `effect_unit_parser.cpp` 已内建（SameElement+PowerBoost），
   插件再注册会被解析路径遮蔽。扫"未实现"清单时先排除解析器覆盖项（kbatch
   `j_rand_anom_same_elem.cpp` 有实证注释）。
9. **J279（1586）归属**：本会话先写了实现/场景（6120），随后 a43-jprod 正式 claim 并完成
   提交（f69b56a1）。最终产物归 a43，本会话不重复记账。
