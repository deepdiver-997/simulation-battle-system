### 路由对照（2026-10-13 晚实测）

| 出口 | 到服务器 | 特征 |
|---|---|---|
| 上海移动（本机） | traceroute 经 **Telia**（62.115.x / 80.239.x）→ 第 14/15 跳**死在 Telia 骨干内**；RTT 245→368ms **抖动极大** | 拥塞/路由劣化 |
| 阿里云深圳（跳板） | RTT 稳定 **170ms（mdev 0.17）**；TCP/SSH/HTTP 全部正常（banner 秒回、rsync 成功） | 路径健康 |

补充判据：① 当天**中午前**该 IP 从本机尚可访问（banner 延迟约 45s），**晚高峰起完全不可用**
→ 时间依赖 = 典型拥塞而非固定策略封锁；② 路由断点在**运营商骨干（Telia）内部**，非在国内出口
被 ACL 拦下；③ 服务器所在网段（**LA，AS36352 HostPapa（原 ColoCrossing），廉价 transit**）与上海
移动的国际出口（无优质 peering）是一对劣质组合；阿里云走自有骨干到 LA 则很好——**"广东松、
上海紧"的实际差别在路由质量，不在明文策略**。

即**特定路径的路由/拥塞问题**，非服务器故障、非爆破、非 OOM、非垃圾邮件封禁。

## 三、处置：阿里云跳板链路

`~/.ssh/config` 中已有 `ProxyJump root@120.24.169.213`（阿里云，本机公钥已授权）。
在服务器 `/root/.ssh/authorized_keys` 追加本机公钥后，用跳板完成全部运维：

```
ssh -J root@120.24.169.213 -p 2222 root@107.174.127.252          # 登录
rsync -az -e "ssh -J root@120.24.169.213 -p 2222" ...            # 传文件
```

## 六、后续建议

1. **可达性监控**：在阿里云上加一条每分钟探测（`curl -m 5 http://107.174.127.252:8070/api/health`），
   异常时告警——本次故障本可第一时间发现是"路径"而非"服务器"。
2. **运维通道固定走跳板**：上海移动（AS24400）晚高峰到该 IP 的路径不可用；移动办公/居家时
   一律走 `-J root@120.24.169.213`（阿里云深圳，RTT 稳定 170ms）。`deploy/deploy_racknerd.sh`
   建议支持 `-J` 跳板参数（本次部署用 /tmp/deploy_jump.sh 临时脚本完成）。
   **控制台访问也可零成本走隧道**（2026-10-13 实测可用）：
   `ssh -N -L 8070:127.0.0.1:8070 -J root@120.24.169.213 -p 2222 root@mx2.scut.email`
   → 浏览器开 `http://127.0.0.1:8070`（WebSocket 同样走隧道，功能完整）。
3. **可选：Cloudflare 免费版挡在控制台前**（已有 scut.email 域名）：`console.scut.email` →
   源站 `107.174.127.252:8070`（Origin Rules 改端口，或 cloudflared tunnel——后者还能顺带让 SSH
   免跳板 `cloudflared access ssh`）。注意当晚实测本机连 Cloudflare **部分**节点也不稳
   （ctrl.racknerd.com 直连超时、digitalocean 的 Cloudflare 边缘正常），故 CF 值得试但非保证。
4. **IPv6**：本机内核支持（`/proc/net/if_inet6` 在）但未分配地址；RackNerd 的 IPv6 需工单申请、
   免费、仅部分机房（LA DC02(Multacom)/DC03/法国等）；社区报告 **CC 系机房（本机所属 AS36352）
   不支持**——可提工单确认，但别当救命方案（且上海移动到该网段 v6 路由质量未验证）。
5. **代理节点选择**：家用/移动网络下用代理时，选**日本/香港且与美西有优质 peering 的节点**；
   当前所用的香港节点（Kidc）当晚同样读不到数据——说明其回程也走了劣化路径。
6. **端口与防护现状**：SSH 现监听 2222 + fail2ban；`Invalid user` 2387 条为常态扫描，
   0 次失败密码、0 次未授权成功。
7. **邮件外投**：当前无异常外发；如需长期保障可考虑与 web 服务分 IP，避免外投声誉影响网站可达性。
8. **换机与否**：本机已部署可用、$20/年便宜；故障在路径而非主机。若确需从上海低延迟直连，
   才考虑**面向中国大陆优化的线路**（搬瓦工 CN2 GIA、DMIT CMI/Pro、三网 9929/CMI 优化），
   普通廉价小鸡大概率重复同一坑；且"免备案"是海外机共性、不是选机理由。
