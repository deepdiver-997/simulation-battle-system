## 二、虚拟烧伤（本线核心口径）

**官方依据**：语料 `reference/scrape/data/detail/1171177636822515734.json`
（新萌小山东《【赛尔号】机制解析—永烬劫炎·上古炎兽》，文集「精灵魂印判定细节」132 篇）。
原文要点（逐条对应实现）：

| 文章原文 | 落地 |
|----------|------|
| 「实时结算，对手免弱期间内都会视为处于烧伤状态」 | 查询式判定（免弱票命中才算），非一次性标记 |
| 「视为烧伤状态**可以响应**"处于烧伤状态则xxx"之类的效果，但"**处于异常状态**则xxx"就不响应」 | 按**描述措辞**分流：烧伤词条 → 感知层；"异常状态"泛称 → 不查虚拟 |
| 「"视为处于烧伤"的精灵会**扣 1/8 真伤**和**威力减半**，同时会给炎魔印记（= 神惧劫炎），不论免弱精灵是否处于烧伤状态」 | **伴生效果**接进引擎（见 §三） |
| 「这个"攻击处于烧伤的对手，令对手焚烬"（572）在**解控之后**，正常拿不到，**配合视为处于烧伤就可以触发**」 | 572 = **条件式** → 查虚拟（§四） |
| 「神惧劫炎：绑定自身，下场不保留，以回合计数，最多 8 回合」 | on_stage_storage 剩余回合数 int，cap 8 ✓ |
| 「你对应技能位置损失多少 pp，对手对应技能位置也要损失相同 pp」 | PP 调整取"对手侧"读法 ✓（实现即此） |
| 「第五减疗 =（对方异常数量 − 烧伤）/ 对方异常数量；没烧伤但有其他异常就是 100% 减疗」 | 2419 的减免比例 = 非烧伤个数/总个数（对手侧）✓ |

**异常体系本体零改动**：虚拟烧伤不是异常槽状态（不占槽、不吃抗性弹控、无回合数、
不进免粉/免控判定），实现为插件侧查询层 = `对面背包有活着的 4875 && 本方在场宠免弱票命中`。
引擎只在**伴生效果**（§三）与**条件式判据**（§四）两处接入。

## 三、虚拟烧伤的三类用法 + 伴生效果（写新效果前必读）

`include/effects/burn_perception.h` 提供三个查询，**按描述措辞选**：

| 类 | 判据 | 查什么 | 本线用例 / 将来用例 |
|----|------|--------|---------------------|
| §1 **检测类**「**处于烧伤状态**则…」 | `is_burn_effective` | 真实 ∪ 虚拟 | 96 破魂枪威力翻倍、993 剑意流转翻倍、希拓 2217 锁疗+战意真伤、织焰 2300 换血/回损、上古炎兽自己「对手处于烧伤→神惧劫炎」 |
| §2 **条件类**「**若**对手处于烧伤则…」 | `is_burn_all`（同 §1 语义的别名，便于检索） | 真实 ∪ 虚拟 | **572 焚烬**（文章明确配合视为烧伤可触发） |
| §3 **状态转化类**「**将**对手所处的烧伤**转化为**…」 | `is_real_burn` | **只认真异常** | 影中艳（库拉塔克 4671，未实现）「将对手所处的烧伤转化为焚烬」——槽里得先有烧伤**可转** |
| §4 **伴生效果**「1/8 真伤 + 威力减半」 | 引擎已接入 | 真实 ∪ 虚拟 | battleFsm：威力物化处 `is_burn_effective`；`stage_action_start_abnormal_damage` 在**无真实烧伤时**补一段虚拟烧伤段（同一异常语义不双算） |

⚠️ **"处于异常状态则…"（泛称）不查虚拟**（文章明确）——那类走 `abnormal_status_end_round`
的槽位扫描，虚拟烧伤天然不在其中，**无需改动**。
⚠️ 库拉塔克 4671 落地时：**灼眼焰华**「若对手处于烧伤状态则 2 回合令其使用的技能无效」
= §2 条件式 → `is_burn_all`；**影中艳**「将对手所处的烧伤转化为焚烬」= §3 → `is_real_burn`。

## 四、伴生效果与新增/变更的引擎语义

### 4.1 虚拟烧伤的 1/8 真伤 + 威力减半（battleFsm）
- **威力减半**：`handle_BattleFirst/SecondActionStart` 的威力物化读 `is_burn_effective`（原为
  `has_active_abnormal_status(Burn)`）→ 被视烧伤者的攻击技能面板威力减半（35→17）。
  仍走 `materialize()`（不是赋值），**不会**触发"变威力重算"。
- **1/8 真伤**：`stage_action_start_abnormal_damage` 在扫描完真实异常段后，**若无真实烧伤
  且有虚拟烧伤**则追加一段（id=Burn、数量=max_hp/8）→ settle 期按 TruePercent 走
  `deal_damage(TRUE)`（直通护盾/护罩、吃伤害抗性之外的免疫语义与真实烧伤一致）。
  真实烧伤在场时不追加（同一异常语义不双算）。
- 验收：097 的 A4（1/8 真伤 + 锁疗）、F1/F2（威力减半 / 免弱解除后恢复）。

### 4.2 异常免疫成功事件（EVENT_ANOMALY_IMMUNED，本线新增）
秘纹护体 2059「每次免疫成功吸取对手{1}点体力」需要感知"免疫票被消耗"，原来无任何信号。
- `apply_anomaly_impl` 的 [3] 次免/回合类免疫 与 [5] 魂免 命中分支各 emit 一条
  （target=免疫方、actor=施加方、amount=被挡异常 id）。弹控反弹也算免疫成功 → 照发；
  凝滞(32) 自带免疫**不发**（不消费票）；抗性成功走既有 `EVENT_ANOMALY_RESISTED`。
- `emit_anomaly_events` 同时给 `EVENT_ANOMALY_APPLIED` 补了 amount=落地异常 id
  （上古炎兽"下1次进入的异常转化"撤除判定需要；旧监听不读 amount，无行为影响）。

### 4.3 次免消耗 = **all-once**（用户 2026-09-20 拍板）
`RuleCenter::consume_immune` 旧版在**第一条**命中的次数型票处 `return true`（多条次免并存
时只扣一条）；现改为**所有条件命中的次数型票各扣一次**（官方实现里每张次免都是独立的响应
条目，各自判定、各自递减）。`BattleContext::consume_immune` 包装层对 **ANOMALY** 传
`consume_all=true`；**免伤/免粉/免杀族保持"一层一威胁"**（多个"抵挡下N次攻击"是独立的层，
一次攻击只消耗最外那层）。
- 验收：097-G1（两张"免下2次异常"票，一次毒 → 4 次变 2 次）。

### 4.4 秘纹护体 2059 的**不可传承**（用户 2026-09-20 确认）
- 票 = `EffectScope::ON_STAGE` + `source_slot=-1` → 宿主一侧**任何**换宠都由
  `RuleCenter::clear_on_stage` 清掉（下场即失效，重上场要重新使用技能）。
- **覆盖键独占**：`source_effect_id=2059`。覆盖键 = (source_owner, **source_effect_id**, subtype)
  → 与"可传承的可视化次免"（将来实现时自带 effect_id）**不会互相覆盖**。
- **记账（剩余次数）挂 `ElfPet::on_stage_storage`**（不是 battle 级容器）：与票同生命周期，
  换宠一起清 → 杜绝"票没了、残留记账继续吃别人免疫票事件"。
- ⚠️ 引擎目前**没有**"可传承次免"的表示（docs/02-效果系统 官方机制理解与引擎缺口对照.md
  §二 idx=375：可视化次免默认可传承给下只精灵）——该缺口落地时，**2059 必须保持不可传承**。
- 验收：097-G2（换宠后票与记账归零、毒直接落地）。

### 4.5 2126 焚烬修正（历史 bug）
烬灭神咒剑 effect 2126「技能无效时…令对手**焚烬**」旧实现注释写焚烬、直写的是**烧伤槽
(id=2)**（异常扩表前的历史混同）。改为 `apply_anomaly(22)`（现代通道，免疫/抗性全检查）。
scenario_002 断言同步改为 Incinerate(22)。

### 4.6 沸涌（icon 36）入编
"icon 36 官方空号"的记录已过时：现库 effect_des **304** = 沸涌（`kinddes=沸涌`，弱化类：
「受到的攻击伤害至少为其最大体力的30%，对手打出致命一击时效果提升至50%」）。
燔薪照日 effect 1676 args={3,100,36,1} 直接按 id 36 施加。落地：枚举 + FLOOR 保底管线
（红伤保底 30% / 暴击 50%，与 447 保底取 max）。验收：097-D。

### 4.7 "对手使用技能后"的桶捕获模式（重要）
**AFTER_ACTION 族桶只跑行动方自己的条目**（`execute_registered_actions(mover, state)`），
本方节点抓不到"对方桶"。可行捕获点只有两个，双节点 + 已响应回合号去重（on_stage_storage）：
1. 本方为**后手** → 本方 `BATTLE_SECOND_ACTION_START`（先手对手刚行动完，最早响应点）；
2. 本方为**先手** → 本方 `BATTLE_ROUND_END`（ROUND_END 桶双侧都跑；对方行动后本方没有更早的
   自有桶）。

先手方判定与 FSM `resolve_first_mover_id` 同源（`ctx->preemptive_right == SEER_ROBOT_2 ? 1 : 0`）。

## 五、各魂印实现要点

### 希拓 2217（soul_lib/xitao_4622.cpp）
- **条件锁疗**：「对手处于烧伤时无法恢复体力」= HEAL_BLOCK 票 + **条件回调**（实时查
  `is_burn_effective(opp)`，虚拟烧伤同样锁疗）。票 TEAM 域长挂（覆盖键=2217、重授幂等），
  `SOUL_MARK_HOOKS` 的 on_exit 撤销。引擎 `ctx->grant_immunity` 包装不透传条件回调 →
  直接调 `ctx->rule_center_.grant_immune`。
- **战意**：soulmark_storage（下场保留 ✓ 官方"层数下场保留"），cap 20；+2/回合 + 己方场下
  每只**系别带火**（elementalAttributes 含 3，存活、非在场、未消逝）+1。增伤/减伤走管线实时读
  层数：攻击伤害 +5%/层（AMP·加法）、受固定/百分比伤害 -4%/层（粉伤 REDUCE_EXTRA）。
- **命运庇护**：达 10 层一次性改写抗性数据（已配置抗性槽拉满 100%、全免抗性清零）。
  "boss无效"：引擎暂无 boss 概念，未设例外。
- 回合结束定序：先用**当前**层数结算真伤（层数×10），再获得新层数。
- 引擎烧伤扣血时点实测：**被烧者自己行动开始时**扣 1/8。

### 绮影罗心·织焰 2300（soul_lib/zhiyan_4696.cpp）
- 换血 = **百分比互换**（`new_self = 对手hp × 自身max / 对手max`，64 位中间量）；换到 0 血走
  `defeat_pet(EFFECT)` 死亡漏斗。773 的绝对值互换是另一回事。
- 回损 30% 走 heal 原语 → 吃封回血（含希拓锁疗——两魂印同场互锁）。

### 永烬劫炎·上古炎兽 2481（soul_lib/yanshou_4875.cpp）
- **神惧劫炎**：on_stage_storage 剩余回合数 int（下场不保留 ✓ 文章），cap 8。ROUND_END 定序：
  ①PP 调整（自身某槽已损失 PP 高于对手对应槽 → 把**对手**的已损失拉到与自身相同）
  ②先出手 → -1 且对手**真实**烧伤 +1 回合 ③自然 -1 ④主子句（对手有效烧伤：已持有 +1 /
  未持有得 3）。持续被烧时 +1-1 相抵，断烧后逐回合衰减——**待实测**。
  先制 +2（MOVE_RIGHT 桶）、攻击伤害 +100%（管线 AMP 实时读）。
- **"下1次进入的异常 → 2回合烧伤"**：预置 `anomaly_conversion[owner][*]=烧伤` + APPLIED 监听
  （落地烧伤即改 2 回合、清转化表）；监听按事件 amount 过滤 → 古早通道落地别的异常不算。
- 主子句恢复分支：回 1/3 → 恢复量 PERCENT_VALUE 粉伤；粉伤一点没落 → 额外 1/3 魂印盾。

### 技能组（moves_lib/burn_trio_skills.cpp，44 效果）
见文件头官方参数总表。特别项：881 加入 skills.cpp 选择期路由；136/2418 加入

### 通用模板族补齐（4 个已实现 + 1 个"不用注册"）
三只精灵的技能引用了若干**通用模板**（不属于本三精灵专属）。审计方式：
把三只精灵可学技能的 `moves.side_effect` 全部取出（58 个 id）逐个查 `SKILL_EFFECT` 注册。
- **补实现**：`2`（对方体力<1/2 威力加倍，变威力视图 ×2）、`53`（{0}回合攻击伤害×{1}，
  乘法 AMP_EXTRA 槽 + in_rounds 首回合立即写）、`1268`（击败→下回合开始随机附加烧伤/冻伤/中毒
  中{0}种，结构照盖亚 826：MOVER_DEATH 探测立旗 + NextRounds ROUND_START 消费，池固定三种）。
- ⚠️ **`916` 不要注册**（"命中后{0}%使对手{1}，若未触发则恢复自身全部体力"）：引擎有**两条
  实现路径**——(a) 注册 C++ 函数（`SKILL_EFFECT`）、(b) **官方文本 → EffectUnit 解析器**
  （`src/effects/effect_unit_parser.cpp`，支持 `使对手{状态}` + `，未触发则` 兜底 + 恢复/固伤）。
  916 属于 (b)：`test/test.cpp` 的冒烟用例以它作**解析器样本**守护（`parsed_units_` 根+兜底、
  `on_other` 指向 Heal 自身）。注册 C++ 函数会**把该技能从解析器路径上摘掉**、冒烟当场挂。
  ⇒ **审计"未注册 effect"时必须先排除解析器可覆盖的模板**，否则会误判为缺口。
- 另注：96（破魂枪）"对手处于烧伤状态时，威力翻倍"按**变威力**实现（视图 `= view.value*2`，
  与 40/30 同款），不是通用增伤——与烧伤减半的乘法次序可交换，无歧义。
