## 三、勘误与记档

1. **allocator 默认段撞号（已修）**：worktree 内 `taskctl alloc` 计数器缺失时从默认
   970 起，直接返回 970-979/980-989/990-999——三段分别与 J12/J13/J14 的存量场景撞号。
   本会话把计数器置 5820 后重分配 **5820-5829/5830-5839/5840-5849**（tasklog 有 alloc
   台账），三个场景文件与看板行段号同步；原 970/980/990 三条 alloc 记录成为无效预留。
2. **自身烧伤会改写威力基线（已记档）**：物理技能在自身烧伤时于物化阶段威力减半——
   用烧伤当"错异常"对照会让 758 基线从 150 变 75。对照门测试改用中毒/失明等不触发
   减半的异常，并在场景注释中写明。
3. **异常自身扣血污染伤害比值（坑集 §5 再现）**：638 用烧伤当门时，对手每回合 1/8
   最大体力自扣把"掉血比"抬到 68.9×。伤害比值侧证改用**失明**（不扣血异常），
   字段断言不受影响。
4. **179 是盘点假阳性（不立）**：`若属性相同则技能威力提升{0}` 已由
   `effect_unit_parser.cpp` 的 SameElement+PowerBoost 内建（J88 记档），registry 不计
   单元解析效果 → 未实现清单里的 179 不是缺口，本批未重复实现。
5. **finish.sh 与 worktree 看板分离（操作口径）**：`lib.sh taskctl()` 走 `$HUB/tools/
   taskctl.py`（主板），而本 worktree 的 `python3 tools/taskctl.py` 走分支内看板副本。
   本会话的 J251-J253 行落在 `feat/jbatch` 的看板副本，因此 `finish.sh` 的 done 会报
   "没有 🔄 进行中行"（已实测）。看板登记改用 worktree 内 `taskctl claim/done`
   直接完成，台账与任务行均在分支上，合并后一致。
6. **taskctl 与 agent 注册表的路径分裂（工具侧问题，已手工收尾）**：`taskctl.py` 的
   busy 表默认读 `REPO/build/night/agents.json`（worktree 副本），而 `agent_id.py`
   经 git-common-dir 固定写 `$HUB/build/night/agents.json` → claim 的活属主校验在
   worktree 里恒空、done 的 clear_busy 也找不到人。本会话完成三单后 hub 注册表仍显示
   `手上=J253`，已用 `agent_id.sh idle a27-jprod` 手工清理；release 后状态为 released。
   建议后续把 taskctl 的 AGENTS_REG 默认值也改为 hub_root（与 agent_id.py 同源）。
