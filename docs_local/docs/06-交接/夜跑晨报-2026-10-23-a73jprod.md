- **439 回合末固伤窗**：窗 = `register_round_effect(BATTLE_ROUND_END, self, {0} 回合)`
  （common.h helper，走 `round_effect_start_round` 的"N 回合内"口径，持续窗由
  ContinuousEffect 自动到期——**不手写 plugin_storage 窗账本**，套路目录 §三）；
  tick 判**自身** `has_any_active_abnormal_status(self)` 或 六槽任一负等级

  最容易被"照抄先例"抄错的一条，场景 T6460.d 专门锁它（降态在**对手**侧 → 不触发）。
- **189 受击降攻**：`EVENT_TAKE_DAMAGE` watcher（TEAM scope、InRounds {0} 含当回合），

  可穿强化保护、钳 -6），actor 如实声明 = 施术者 self（不是攻击者自己）。

## 三、勘误与记档

1. **`finish.sh` 打错板（新坑，务必记档）**：`tools/night/lib.sh` 的
   `NIGHT_BOARD="${SBS_NIGHT_BOARD:-K}"` —— **默认板是 K**，`finish.sh <J单号> ok`
   会把 `taskctl done` 发到 K 板 → 报"没有 🔄 进行中 行（不存在/状态不符）"，
   **J 板那一行仍是 🔄**（finish.sh 不会因此报错退出，脚本照常打印"已登记"）。
   正解：`python3 tools/taskctl.py done <单号> --board J --commit <sha> --summary "…"`
   直接指名板。（与 a48 勘误同源：**看板操作必须显式 --board**。）
2. **taskctl 的看板/台账落在本 worktree 的 docs_local 副本**（按 CWD 的 repo root 解析），
   hub 侧同一文件的副本停在 J250 —— 分支合并时按"行级 ✅ 优先"裁决（既有口径）。
   本轮台账条目：alloc 6460-6469 / add J313 / claim J313 / done J313（4 条，tasklog.jsonl）。

   （allow_overtime=false）被 `check_stop` 拦下返 STOP，而此时 J 板仍空。

   pid + owner，仍受"唯一制定权/30 分钟过期接管"互斥保护），立单后**必调**
   `author_done.sh` 释放。机制保证（并发互斥）没有丢，丢的只是"停领"闸门——

   而 439 侧其余 **6/7** 载体文本与模板自洽，如 27421 防御阵型"若自身处于能力下降状态
