## 勘误记档

1. **同 worktree 双会话（本轮实证）**：supervisor 目标并发 2，a51-jprod（J288/J289）与
   a52-jprod（本会话，J290）共用 `jbatch` worktree 与 build 目录。按协议各自领不同单，
   构建前确认无并发 cmake；但 `build.sh` 的 2 槽信号量**不能**保护同一 build 目录，
   supervisor 目标并发与单 worktree 的设计存在冲突，建议后续把并发 session 分到不同
   worktree，或把目标并发降为 1。
2. **场景起始当前体力 ≠ 最大体力**：首版 loss 用 `10000 - hp`，但对手是 3000 起始 →
   断言必红。改为“本局起始当前体力 - hp”后精确通过（坑集 §4 的延伸）。
3. **`apply_anomaly` 会走抗性掷骰**：冻伤首测未落地，导致门未关、误判为假红。
   场景造状态改用 `ctx.apply_abnormal_status_for_rounds()`（绕抗性、确定落地）。
4. **冻伤有回合末自伤 tick**：门闭局的 loss 不能与“红伤等式”对齐；门闭断言只认审计槽 0，
   同参开闸局（T6231.d=1200）做对照。
5. **变异恢复的同秒 mtime 坑**：`cp` 恢复源码与 object 同一秒，`cmake --build` 判为
   已最新、未重编 → 恢复后场景仍红。`touch` 源码强制重编后恢复绿；变异脚本收尾应显式 touch。
6. `.agent-env` 是别的项目模板且 `source` 路径失败；`SBS_AGENTS_DIR` 未注入——手工导出。
   claim 行元数据写 `../agents/j290` / `feat/j290`，实际按 spawn 指令仍在 `feat/jbatch`。
