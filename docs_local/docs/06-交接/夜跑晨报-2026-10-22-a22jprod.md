## 四、勘误记档

1. **共享工作区并发（a22/a23 同时在 feat/jbatch）**：提交必须用 pathspec
   （`git commit -- <files>`）；`tools/night/build.sh` 回归会把对方未提交 WIP 一起
   编进来（本会话末段 738 场景含 a23 的 J242/J244 场景）。`finish.sh` 记录的
   `impl_commit` 是**收工时 worktree HEAD**，不一定是本单提交——J240 行记成
   `9e1fc0eb`（a23 的 J239），实际本单提交为 `bb75e7c8`，以本表为准。
2. **J247 看板行 claim 被回退**：hub 板上曾出现 J247 已 claim 后又变回“待领取”
   （tasklog 无 claim 记录），`finish.sh` 因“没有 🔄 进行中行”失败；重新 claim 后
   成功 done。疑为并发看板写入，已在本会话内自愈；建议后续排查 taskctl 的
   CAS/写盘时序。
3. **args_num → int_count 公式**：装载布局 = `[owner, target] + args`，故
   `int_count = 2 + args_num`。J248 首版按 `>=4` 守 args_num=1 → 触发
   `EFFECT-ARG-FAULT` fail-fast（state=9，args=[0,1,2]）。写新效果先按此公式算。
4. **链上兄弟效果会制造本效果的判定条件**：J248 正等级对照最初用 35891（链上 1009
   在“消除成功”后全属性-1）与 38400（1726 吸取后走“不处于提升”分支全属性-1），
   都会自己把对手变成负态 → 1438 门开，测试被污染。改用 38113
   `[1684,1478,1438]`（两兄弟不碰等级）后对照成立。
   同理 J241 选 19048 `[180,858]`（180 清回合效果，无则 no-op）。
5. **窗形效果的“当回合”口径**：965 在 SKILL_EFFECT 注册 ON_SKILL_HIT 窗口——注册
   回合的 ON_SKILL_HIT 已过，3 回合窗的未来攻击触发面是 R2-R3（R1 只靠当次手动 tick）。
   属性技开窗时当次无 tick，因此有效触发面 = 2 次。断言按“窗 R1-R3”写，不按
   “未来 3 次”写。
6. **J249 满体统计**：对手每回合会蹭掉 2 点血 → 满体档必须每回合重置 hp/PP，
   否则 R2 起就不是满体（统计口径，不是实现缺陷）。
7. **场景用 `core_api()`**：需显式 `#include <plugin/core_api.h>` +
   `<primitives/battle_primitives.h>`（J250 首版漏 include 编译失败）。
8. **worktree 内看板副本不可作领取依据**：本 worktree 的 J 板仍是 J185-J188 旧状态；
   领取/翻状态必须走 hub `taskctl.py`（`HUB` = git-common-dir 的父目录）。
