## 二、本夜关键记档（白班必读）

### ⭐ A. 【工程·重要】魂印行参读取路径缺陷 —— `a.row` 在真实对局偏移 2 位

**K257 实施过程中的副产品，已写完整交接文档**：
`docs_local/docs/06-交接/魂印行参读取路径缺陷-2026-10-21.md`（S3 板已立调研单交白班）。

- **现象**：`SoulNodeArgs::row`（类型化行参）在真实对局里相对 DB `effect_icon.args`
  **偏移 2 位**——多数情况**是空的**，导致按 `a.row_or(i, …)` 读行参的存量实现
  **全部走 fallback 硬编码值**。
- **机制**：`bind_soulmark_args`（`src/entities/soul_mark_manager.cpp:351`）丢弃
  `owned_int_args` 前两位，而真实对局的 `owned_int_args` **就是 DB args 原样**
  （`pet_factory.cpp:502` → `EffectArgs(display.args)`）→ 绑定后 `a.row` = DB args[2:]。
- **实测**（探针场景 `scenario_4149_probe_soul_row.cpp`）：
  | effect | DB args | 真实对局 a.row |
  |---|---|---|
  | 827 row521 | `[80,1]` | `{}`（空） |
  | 827 row536 | `[80,1,1]` | `{1}` |
  | 357 | `[2,1,1,30]` | `{1,30}` |
- **影响面**：`resources/soul_lib/` **17 个文件、30 处 `a.row_or`**（含 K193 827——
  其 `row_or(0,80)` 在真实对局读到的其实是 1 或 fallback；**3212 行的"属性技命中
  则消除对手回合类效果"子句疑似从未触发**）。
- **两种修法待白班裁决**：A 改内核绑定（一处改动，但 30 处读值整体位移 → 需逐个
  复核 17 个文件）；B 存量迁移到 `db_at`（改动面大但语义干净、零内核风险）。
- **本夜起新代码一律走 `db_at`**（读 `owned_int_args` 原序），场景**按 DB args 原样**
  构造（不补 `{0,0}` 前缀）——两边语义一致。

### ⭐ B. 【内核·重要】`BATTLE_*_ACTION_START` 挂魂印节点**不会被执行**

K261 探针实证：内核 `execute_registered_actions(first_mover_id / second_mover_id,
State)` 按**行动方 id** 索引桶，而魂印节点注册到**持印者**桶——两者只在"持印者
恰是当前行动方"时重合。实测持印者**后手**时该节点**零调用**（探针槽始终 -1）。
同探针确认 `BATTLE_ROUND_END` 桶会跑且此时 `ws.preemptive_right` 已定
（`is_second_mover` 读值正确）→ "后出手时速度+1"类效果应挂 ROUND_END。

### C. 【时点·坑】回合末读 `roundChoice` 恒为 -1

K261/K280 实证：`roundChoice` 在回合末已被重置 → **技能类型判读必须在
SKILL_EFFECT 时点做**（不能用 EVENT_SKILL_USED watcher 里读）。

### D. 【场景·坑】属性技载体自带**自身**能力增益会污染"等级和"断言

K265/K280 实证：缩头 20001 的 `side_effect=[4]`（effect 4 = 改**自身**等级）——
用它当属性技载体时"等级和=1"恒成立 → 门被破坏也不红。须用**瞪眼 20004**
（effect 5 = 改**对手**等级，不动自身等级）。

### E. 【场景·坑】门闭断言须用**绝对值**而非"与对照局相等"

K264 实测：两局同时增伤时"与对照局相等"仍成立 → 破坏门也不红。须断言
`ratio < 1.10` 这类绝对比例。

### F. 【场景·坑】随机槽去重失效的观测口径

K282 实测：统计"被降槽数"必须数 **< 0**（含 -2），只数 `== -1` 会漏掉
"去重关闭→同槽被降两次"（变异测试曾因此假绿）。

### G. 【场景·坑】`make_pet` 的 hp **同时是最大体力与初始体力**

K277 实测：门限判据（"体力 < max/3"）必须**满血构造后单独压
`ctx.getPet(0).hp`**（max 不变），否则 max 一起变、门恒假。

### H. 【场景·坑】异常自身的每回合扣血会污染掉血断言

K285 实测：对手带烧伤时掉血含**烧伤自身**的每回合扣最大体力 1/8（≈12500）
→ "烧伤分支不附加固伤"必须用**双局差值**判定（对照组无魂印、同样烧伤）。

### I. 【口径·辨析】魂印概率的**百分比 vs 千分比**逐宏不同

K288 实测并用变异测试**证明该辨析可测**：K1 151「攻击时有2%秒杀」args[20,0] 是
**千分比**（db/10），而 1147「5%秒杀」args[5,…] 与本单 627「4%秒杀」args[4,0]
是**百分比**。K4 头注"概率单位逐宏互锚，严禁跨宏复用换算"——K288 的变异测试
"把 4 改成 0.4"会转红，正是防后人误改的护栏。

### J. 【断言口径】威力改写族必须**字段断言**

SOP §五.1：威力改写会重跑公式 → 伤害比例断言不可对齐。K333 采"停泊到
FIRST_SKILL_EFFECT 读 `ws.skill_power_view[0].value`"（K9 场景 2861/2862 同款）。

### K. 【并行协作】心跳超时会被其它会话**接管**（v5 抢单防护）

实测两次：a12-kprod（本人）在长变异测试期间未刷新心跳 → a02-kprod 按 busy
判定失效、`--force` 接管 K288，**基于本人的实现**补验证与变异测试后提交
（975e92fc，commit message 已留痕）。**教训：变异测试/长构建期间要定期
`agent_id.sh heartbeat`**，否则辛苦的实现可能被判定失联（实现不会丢，但
接管方会重做验证）。
