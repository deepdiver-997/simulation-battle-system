## 二、机制改造（v5 抢单防护）——本会话最独特的产出

### 事故背景

00:53 a01-kprod 领 K260，00:54 我进场时它注册表显示 `released`（**finish.sh
自动 release 了它的 agent ID**——它只是做完 K259，会话还活着）。我据此判定"K260
是遗弃单"→ `release` + `claim` 抢占 → **两个 agent 在同一 `agents/k260/`
worktree 对同一文件并发写约 7 分钟**（我的变异测试改动差点带进它的提交）。
最终双方各自 git 回退，**无代码损失**，但属高危未遂。

### 三个根因

1. `finish.sh` 无条件 `agent_id release` → 完工一单被写成"会话收摊"。
2. `taskctl` 的 CAS 只断言"行状态 == 待领取/进行中"，**不校验这一行有没有活着的属主**。
3. `claim.sh` 见 worktree 目录存在就复用，**不问里面是否有人在写文件**。

### 修复（六处，提交 `eeb5d2fd`）

| 文件 | 改动 |
|---|---|
| `tools/night/agent_id.py` | 注册表新增 `busy={task,since}`；新增 `busy`/`idle`/`owner-of`/`claimable` 子命令；`busy_is_live()` = 心跳 ≤15min 且未 disabled（**`released` 不作废 busy**——这正是原缺陷点）；`list` 显示手上单号 |
| `tools/taskctl.py` | `claim` 前查活属主 → 拒领；`release` 校验行文属主 → 拒代退（`--force` 逃生口写 `forced_from` 进 tasklog 留痕）；`claim` 登记 busy、`done`/`release` 按**单号**清 busy |
| `tools/night/claim.sh` | worktree 已存在时先 `owner-of`，有活属主 → 退回该单不接管 |
| `tools/night/finish.sh` | 完工改 `agent_id idle`（清 busy），**不再动 status** |
| `tools/night/agent_id.py` | `registry_path`/`lock_path` 支持 `SBS_AGENTS_REG` 覆盖（隔离自测） |
| 协议文档 | `夜跑总入口.md` 新增 §六 + §一·0/§一·6/§四 口径同步；`tools/night/README.md` 新增 v5 节 |

**自测**：`taskctl selftest` PASS（原流程无回归）；**8 项端到端断言全绿**（抢单防护
+ busy 生命周期，隔离注册表，不碰真看板/真注册表）。

## 三、机制裁决交接（两份，白班必读）

### ① boss免疫 尾注口径（提交 `bea3aadc`）

**"（boss免疫）"= 该效果对 boss 也生效（boss 有效），不是"对 boss 无效"**——
与尾注"（boss无效）"相对。三方独立取证：

1. 官方语料《机制解析—战龙哈莫》(bilibili opus/784274231187734528) 把
   "（boss免疫）"用在**主角自己的魂免效果**上：「每回合开始时若自身体力大于
   1/2最大HP则免疫异常状态（boss免疫）」——是"我的免控对 boss 也生效"。
2. `resources/boss_invalid_effects.json`（1397 个 id）**只收 tips 含"boss无效"的行**
   ——644/357/360/738 均不在内；其 `note` 已处理"反向标记"（"仅boss有效"要排除），
   说明官方 boss 措辞**存在两个方向**。
3. 工单行由立单方查证后写明"boss 有效"。

**K275（644）按此落地**（`boss_invalid=false`）。**K257（357）用了相反解读**
（`boss_invalid=true`，注释未给依据）——两份并存，需白班统一（改任一方即可，
K275 头注已完整记档含 opus 链接）。**另立 S4 调研单跟踪**。

## 四、本夜关键记档（白班必读，均已落各分支头注/场景注释）

1. **【场景·大坑】随机效果的断言必须多种子采样**（K267/K313 教训）：单一固定种子
   只覆盖一个抽样点——破坏去重的实现可能恰好在那个点不撞槽，**单种子场景不转红**。
   本会话两处随机效果（645/686）均改 12~20 局循环 + 统计"恰 N 槽"的局数。
2. **【场景·坑】"所有技能"必须用全技能判据**（K316 教训）：官方"使对手**所有**PP
   降低N点"= 每个技能各降 N 点——用"任一技能被削"的判据会让"只降 1 个技能"的
   实现也通过（变异测试实测 exit=0 仍绿）。
3. **【机制·坑】"自己受击"的两条守卫互补**（K318 实测）：`ev.target != owner` 与
   `ev.actor == owner` **任一条都能挡住**"不是自己受击"——单独删任一条都不改行为
   （MUT1 首测 exit=0 差点误判"断言无效"）。两条都在才完整（自伤也被挡）。
4. **【机制·坑】时点门同时防住"固伤递归放大"**（K320 实测）：`EVENT_TAKE_DAMAGE`
   watcher 里**自己附加的粉伤也会发该事件**——不限时点则附加的固伤会再次触发
   watcher → 无限递归放大（MUT2 实测对手掉血 **484** 而非 64）。限定
   `ev.state ∈ {FIRST/SECOND_ATTACK_DAMAGE}`（只认红伤攻击结算时点）即断掉自触发。
5. **【机制·坑】`ws.must_crit` 每回合 reset 且命中时点被消费**（K300 实测）：
   ①旗每回合 reset → 跨回合必暴必须**每回合重写**（不能只写一次）；
   ②**不出手时 BEFORE_SKILL_HIT 桶根本不跑**，旗也写不上 → 断言不能读旗，
   改读 `ctx.crit_happened`（本次攻击是否真的暴击，权威结果）。
6. **【机制·坑】"等量/等比"子句不占参数位**（K293/K313 实证）：K293 872「恢复200HP
   **并造成等量**固定伤害」args=[200,0] —— 固伤量 = 恢复量，**db[1] 是废位**；
   K313 686 与 K690 690 args **完全相同**（[200,3,1]）但子句内容不同（回血 vs 固伤）
   → 由此确证"**每子句一参**"的排布规律。
7. **【机制·辨析】必中凭证 vs "命中率钉100"**（K304 实证）：引擎有两条通道——
   `ws.must_hit_grant` = **真必中**（跳过掷骰）；`ws.accuracy_fix_grant` = "基础
   命中率钉 100"（**≠ 必中凭证**，弱化仍可 Miss、必闪词条无效）。**唯一区分判据
   是弱化**：命中等级 -6（命中率 25%）下真必中 10/10 全中、钉100 通道 1/10。
8. **【机制·辨析】"不消耗PP" ≠ `ws.ignore_pp`**（K322 实证）：`ignore_pp` 是
   "**PP=0 技能仍可选**"（选技限制）；"使用技能不消耗PP"的真通道是
   `ws.skill_pp_cost_multiplier = 0`（内核 PP 消耗点 AFTER_ACTION 读它，≤0 则不扣）。
   且该槽**回合初 reset 回 1** → 免耗是"本次使用"语义、**不留残留**。
9. **【机制·辨析】"无视X%防御"与"自身双防提升X%"方向相反**（K327 实证）：
   `ws.defense_ignore_pct` 是"**攻击方**无视**对手**X%防御"（668 同款）；
   "自身双防能力值提升"是**自己面板**变高（`numericalBase` 直加，k249 同款）。
10. **【口径·待拍板】"双防能力值提升30%"未说基数**（K327 记档）：全库仅本行该措辞，
    无同族行可交叉锚定 → 本单按字面取"当前双防的 30%"（提升到 130%），**记档待
    白班拍板**（改基数只需改一行公式）。
11. **【参数·坑】db 下标同值 → 读错下标不可观测**（K279/K286/K313 实证）：真实行
    常出现 db[0]==db[1]（如 601 args=[2,2]）→ 变异测试"读错下标"**不会转红**。
    须补**参数化**断言块（用不同值的 args 变体）才能让下标读错可观测。
12. **【流程·坑】立单前必查重**（本会话实误一次）：首批立的三单中 K291/K292 与
    并行会话的 K256/K276 撞号（346/606）→ 只能领到后标 ✅ 作废。**立单前应扫
    registry + 全部 worktree 实现 + 看板历史单**。
13. **【流程·坑】`claim` 到的未必是自己想做的单**（本会话实遇）：K316 在我立单
    与领单之间被另一会话先立 → 我先到先得领到它（**合法**），只能把它做完。
