## 1. 考古结论：调用链与 2×2 行为矩阵

### 调用链（行号为 feat/r8 修复后现况，均已 sed 验证）

miss/无效趟的判定与放行：

1. `resolve_skill_execution`（src/fsm/battleFsm.cpp:517）
   `ctx->ws.combo_view[robot_id].materialize(skill.roll_combo_count())` ——引擎打底物化，

   `SkillUsageResult::MISS` → execute 返回 SKILL_INVALID，flags = {registerSkillEffects=true,
   allowAttackDamagePipeline=false}（skills.cpp:1129-1140 resolution_flags_for）。
3. SKILL_INVALID 分支效果**照常注册**（skills.cpp:1234-1239），在 BATTLE_*_SKILL_EFFECT
   时点执行——只有这一层的效果写入才会置 `rewritten`（SkillView::operator=/+=，battleWorkspace.h:81-82）。
4. `handle_BattleFirstAttackDamage`（battleFsm.cpp:1906 起）：`allowAttackDamagePipeline==false`
   → 清快照 → `apply_crit_defense_break` → **`run_attack_damage_from_invalid_skill`**

5. 修复前：出口门 = `variable_power_requested`（:831-838）三条件全集
   `power.rewritten || combo.rewritten || combo_view>1`——第三项把**静态连击基数**也放行
   → miss 趟 stage+finish 全额重结算（stage 里 `combo_count>1 → base×N`，:742-746）。

## 2. 官方语义取证：miss 趟不应有攻击伤害（置信度：高）

- 官方补偿模板族：effect 72「若没有命中对手则自己失去全部体力」/ 136「若Miss则自己恢复
  1/{0}体力」（effect_info 直查）——官方给 miss 专门开补偿模板，且二者只注册在
  SKILL_INVALID 分支（include/entities/skills.h:346 分支语义注）→ miss 趟默认零伤害零效果，
  唯一后果是补偿分支明说的那件事。
- 1141 模板自身措辞「每次攻击{2}%令对手{3}」：伤害来自"落地的攻击"；8070 T7 已锁
  miss 趟逐段异常钩子全不触发。
- 语料（reference/scrape/out/all_posts_final.jsonl，idx452 变威力专篇 / idx100 连击计算 /
  idx98 暴击×连击）只定义"一次公式×N""变威力第二次结算覆盖"，**无任何"miss 结算伤害"
  表述**——直接语料缺位，落回引擎既有原则：无效出口注释自述"没有靠后的变威力改写 →
  无效就是无效，零伤害"（battleFsm.cpp:997 注释段），静态连击载体违反该原则即勘误本体。
- 反面证据：零。20/20 vs 0/20 的隔离（K424）只证明行为差异，无任何官方/语料文本支持
  "miss 趟该有伤害"。

## 3. 修复方案（最小面，src/fsm/battleFsm.cpp 单文件）

新增 `variable_power_rewritten_by_effect`（:845-851，只认两视图 rewritten 标记）；
无效出口**两处 gates 同步窄化**：
- `run_attack_damage_from_invalid_skill`（:1021-1030）门改窄判据；
- `run_invalid_skill_damage_hooks`（:1034-1046）"已接管"守卫同步窄化（两处判据必须同源，
  否则 miss 趟静态连击会漏问咒怨保底钩子）。
命中趟收尾 `apply_variable_power_recalc`（:853-858）**保持全集判据不动**——静态连击的
"破防→按归零双防重算→×N"两趟流水线（044 C4 口径）一字不变；J326 数据化装载/查表
（official_data_repository.cpp load_combo_rules/find_combo_rule、skills.cpp 切片取参）零改动。
