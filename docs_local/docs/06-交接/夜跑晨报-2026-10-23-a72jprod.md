## 三、勘误与记档

1. **变异批处理的"第二次变异不重新编译"陷阱（新坑，务必记档）**：同一源文件连续改两次
   做变异时，第二次 `cmake --build --target moves_plugin_deploy` 可能**判定为无需重编**，
   跑出来的是**上一个变异的二进制** —— 现象是"M4 变异跑出的失败点与 M3 一模一样"
   （实测 M4 首跑 T6452 审计槽 = 1，正是 M3 的签名，而 M4 应为 2）。
   正确做法：每次变异后 **grep 确认变异确已落到源文件** + `touch` 源文件再构建 +
   看失败点是否符合该变异的预期特征；否则会把"陈旧二进制"误记成"该变异转红"。
2. **author 锁过期接管**：`author.sh` 提示「制定权过期接管（>1800 s）」——上一次持锁者
   （前序会话）未调 `author_done.sh` 释放，锁目录滞留。本会话拿到制定权后**必调**
   `author_done.sh` 释放。
3. **taskctl claim 的 worktree 路径元数据与实际工作区不符**：claim 行写入
   `worktree ../agents/j312`（`AGENTS_DIR` 默认值推导），而实际工作区是
   `.../workspaces/sbs-local/jbatch`（分支 feat/jbatch）——与 a48 勘误同源，台账以
   本仓路径为准。
4. **spawn 级「不自行立项」与任务书 author 协议冲突**：本次按**任务书**（更具体的
   本会话指令，且《夜跑总入口》§二规定"看板清空且未收到停止信号时不要停"）走 author
   协议；同工作区先例 a67/a68 亦同。**若要严守 spawn 级口径，请在下一轮 spawn 里写明
   "看板空即收摊"**，否则会与任务书正文长期互斥（a64 那轮就是只读复核收摊）。
5. **拍打伤害实测锚**：拍打（物 40）@ 攻 300 / 防 100 实测 **99 点/发**（J311 注释反推带
   [87,102] 一致）；邪灵花蕊（特 130）@ 攻 300 / 防 100 实测 **288~306 点/发**
   （反推带 [280,329] 一致）。两者带宽均比 1/3 伤害小 → T6452 用状态手术而非伤害带
   做"条件翻转"，不依赖浮动带。
