# 调研：重生之翼（2987）与王之哈莫（3022）——魂免窗口、先制+3 与下场保留

> 分支 `feat/chongsheng-wanghamo`（2026-09-23）。两只均未落地，本文先定口径与实现路径。
> 语料来源：`reference/scrape/out/all_posts_final.jsonl` 三篇——
> 《机制解析—重生之翼》《机制解析—王之哈莫》（新萌小山东）、《机制解析—战龙哈莫》（同作者，同族判定参照）、
> 《浅谈主动毒与魂印免控判定》（老魂免补丁名单：**王之哈莫、重生之翼均在列**）。

## 一句话结论

官方（老 Flash 引擎）的"每回合开始时免异常"**不是**"回合开始挂一层当回合免控"，而是
**判定点与生效窗口分离的锚点窗口式魂免**（玩家社区称"转换式魂免"）：

1. **判定点**（回合开始 / 游戏开始 / 后手行动结束后）只做**条件评估**（体力比较）；
2. **生效窗口**锚在全局共享时点上：`任意先手方技能命中前 → 下一次先手方技能命中前`——**窗口跨回合边界**；
3. 免疫状态挂在**精灵本体**（不在"在场槽"上），所以**下场不清**（下场保留），窗口到期锚点全局触发；
4. 上一窗口的到期点恰好是下一窗口的武装点 → 条件持续成立时形成**无缝闭环**。

重生之翼"6层击杀后保留魂免+先制3直到下回合且下场保留"是同一套模型 + 一份**挂在本体上的 pending 标记**
（层数清零锚点 = "下回合先手方命中前"，不到锚点层数不清 → ≥2 层闭环免控自然还在）。

## 一、语料口径（实测判定）

### 1.1 重生之翼（2987，2016 年费，王系）

魂印（第 6 层为 2016-10-14 增补）：

| 条件 | 效果 | 引擎落点 |
|---|---|---|
| 被击败后 | 100%（强化前 50%）随机复活出战背包内已被击败的 1 只精灵；**被消逝的精灵除外**；无法复活自己 | `defeat_pet`（覆盖场下死亡）+ `revive_pet`（battle_primitives.h 注释已引官方 idx=251）+ `is_vanished` 拒绝 |
| 神耀能量 ≥1 | 受到的攻击伤害额外减少 8%/层（**乘法**） | 伤害管线 REDUCE 乘算通道 |
| ≥2 | **免疫受到的异常状态和能力下降**；细节原文："免控免弱是开启后**闭环免控**，直到层数低于2为止" | `IMMUNE/ANOMALY`（soul=true）+ `IMMUNE/STAT_DROP`，`coverage_all()`，`anomaly_condition = layers>=2` |
| ≥3 | 首次使用过技能后每回合结束恢复 1/3 最大体力 | ROUND_END 族节点 + `heal` |
| ≥4 | 立即免疫并**记录**受到的固定伤害，对手行动结束后附加等量固伤；晚于对手行动结束的固伤推迟到下回合对手行动结束后；**记录效果下场保留** | 固伤记录存 `soulmark_storage`（下场保留）；HOOK 在粉伤管线 + 对手行动结束锚点 |
| ≥5 | 攻击技能先制 +1 | `BATTLE_FIRST_MOVE_RIGHT` 桶：`ws.preemptive_level += 1` |
| ≥6 | 攻击技能伤害 +60%（**加法增伤**）；第五技能不再消耗层数 | AMP 加算通道（非通用增伤·乘法槽——按语料是加法，走 `damage_add_pct`） |

**击杀 bundle（用户问的核心）**：
> "赛尔对战**击败对手后且层数≥6**：自身神耀能量**在下回合先手方命中前自动清0**，且**所有技能先制+3**。
> （清零效果和先制效果均**下场保留**）"

实测细节原文（关键）：
- "6层击杀后**层数不会立即清0**"——清零锚点是"下回合先手方命中前"，所以击杀当回合到该锚点之间 ≥2 层免控**还在**；
- "层数清0和先制+3可以下场保留：你可以当回合击杀对手立马下场，直到重生**下次登场**的时候依然还会有层数清0和先制+3，
  **此时重生还会有一小段免控**，可以让重生免疫**出战击杀控、登场控、回合开始控和部分命中前控**"；
- 非赛尔对战：6 层后 4 回合触发同样（引擎暂无 PvE/对战模式标志 → **缺口，见 §四**）。

由"回合开始控也在被免列表"可反推：下场再登场时，清零锚点不早于**登场后的下一回合**的先手方命中前
（若锚点在重入当回合就触发，覆盖不到下一回合开始）——见 §3.1 的统一口径。

### 1.2 王之哈莫（3022，活动）

魂印三条：减伤（满体力 75%，每降 10% 减伤 -15%，**乘法**）；触发效果；限定（体力上限 +20% → 战前补丁 STAT_MODIFY；受伤 -20%）。

触发效果实测（描述"每回合开始时"是简化，语料原话）：

- "**每回合开始时，若自身体力高于对手，则任意先手方技能命中前开启免控效果，免控效果延续至任意先手方下1次技能命中前（下场保留）**"
- 每回合开始时，若自身体力低于对手**且任意一方技能命中前**则触发低体效果，**回合结束后（扣减点之后）**恢复 1/3；
  体力为 0 不触发；**击杀对方最后一只进入结算时不再触发**（对局先于回血锚点结束）；
- 判定"不需要激活也会正常判断"；**双方均不出手**（嗑药/空操作）→ 拿不到高体免控与低体回血；
- 语料作者原话："**跟重生之翼的2层免控效果极其相似，怀疑是不是偷懒抄代码**"——同族同模型。

注意：王之哈莫语料**没有**战龙哈莫那条"游戏开始时高体 → 首免到任意一方下1次技能命中前"的固定首免
（王哈开战第一回合先手方命中前**无免控窗口**）——与战龙哈莫的差异点，落地时别顺手带上。

### 1.3 同族参照：战龙哈莫"转换式魂免"（两判定点）

1. 游戏开始时高体 → 首免延续至任意一方下 1 次技能命中前（限定 1 次）；
2. 任意先手方下 1 次技能命中前判定：高体 → 免控延续至**后手方出手流程结束后**（比回合结束晚一点）；
3. 后手方出手流程结束后再判定：高体 → 再次开启，延续至任意先手方下 1 次技能命中前（**下场保留**）。

一回合两个判定点、窗口首尾相接，即"转换式"名称的由来。王之哈莫是它的单判定点简化版。

## 三、落地草案

### 3.1 重生之翼（插件侧为主）

- **层数账本**：`pet.soulmark_storage` 存 `layers`（本体、下场保留）。技能加层/第五消耗层数走各技能效果。
- **≥2 闭环免控免弱**：战斗开始授两条 TEAM / 永久 / Ancient 票（ANOMALY mask=0 + STAT_DROP），
  `anomaly_condition = layers >= 2`。层数涨到 2 自动开、跌破 2 自动关——"开启后闭环直到层数<2"。
- **击杀 bundle**：`BATTLE_AFTER_DEFEATING_OPPONENT` 节点判 `layers>=6` → 置本体 pending 标记
  `{kill_pending=true}`（soulmark_storage）。
  - `BATTLE_FIRST_MOVE_RIGHT` 节点：在场且 `kill_pending` → `preemptive_level[side] += 3`（≥5 层的 +1 同点叠加）；
  - **清零锚点**：命中前锚点（见 3.3）回调：若 `kill_pending` 且本回合已在场完成过 MOVE_RIGHT（= 已吃到 +3）
    → `layers = 0`、`kill_pending=false`。在场未下场时即"下回合命中前"；击杀当回合立刻下场的，pending 跨场滞留，
    重入回合吃到 +3、下一回合命中前清零——与语料"回合开始控也被免一段"吻合。
  - ⚠️ 待实测确认项：重入当回合若以**后手**登场，当回合先手方命中前是否就清（按上述口径应不清，语料"回合开始控被免"支持本口径）。
- **被击败复活**：`BATTLE_AFTER_DEFEATED`/EVENT_DEATH(self) → 从背包已阵亡（未消逝）中随机 `revive_pet`，
  复活体力按官方 idx=224 口径记录（效果侧自理）。

### 3.2 王之哈莫（插件侧 + 一个跨侧锚点）

- **`BATTLE_ROUND_START` 节点**（STAGE）：判体力高于/低于对手 → 置**回合级** pending 标志
  （`plugin_storage` 或 ws 均可——本轮用完即弃；双方均不出手时标志自然作废，满足"均不出手拿不到效果"）。
- **命中前锚点**（见 3.3）回调：
  - 先 `revoke_immunity(kWangHamSoulHandle)`（= 上一窗口"延续至任意先手方下1次技能命中前"到期）；
  - 本轮 ROUND_START 判过"高体" → `grant_immune(ANOMALY, coverage_all, mask=0, rounds=0, scope=TEAM,
    soul=true, tier=Ancient, source_slot=自己槽)`（固定句柄幂等）→ 窗口 `[本轮命中前, 下轮命中前)`。
  - 条件链断裂时只撤不授 → 窗口恰好开到"下一次命中前"为止。
- **低体回血**：命中前锚点确认 pending_low → 回合扣减点后（state 28）`heal(maxHP/3)`；体力 0 不触发。
- **减伤**：满体力 75% 每降 10% -15%（乘法）→ 伤害管线 REDUCE 乘算通道按当前体力比例现算；
  限定 -20% 同通道；上限 +20% → `SOUL_PRE_BATTLE(3022, STAT_MODIFY)`。

### 3.3 唯一内核缺口：跨侧的"先手方命中前"锚点

`BATTLE_FIRST_BEFORE_SKILL_HIT` 桶**只跑先手方 owner**（`battleFsm.cpp` `handle_BattleFirstBeforeSkillHit`）；
被动桶也不行（`execute_at(state, robotId)` 同样按 owner 过滤）。后手方的王之哈莫/重生之翼在"任意先手方技能命中前"
这个全局锚点**没有任何自己的桶会跑**。引擎自己的答案历来是事件面（"受击类效果不归时点桶管，注册在 event 中心，
由对方出手派发"）。

**建议**：`event_center.h` 增列 `EVENT_BEFORE_SKILL_HIT`（事件枚举增长 = 数据扩展，符合设计原则），
在 `handle_BattleFirstBeforeSkillHit` 桶执行**之前** emit（actor=先手方）。两只精灵的魂印程序 watch 它：

- 王哈：撤旧窗 → 条件成立则授新窗（固定句柄）；
- 重生：kill_pending 且已吃 +3 → 层数清零。

事件在 miss 技能上也会发（BEFORE_SKILL_HIT 跑在失效判定之前）→ "下1次技能**命中前**"按字面取"命中结算前"，
miss 也推进窗口锚点——语料未覆盖 miss 场景，**待实测**（若实测 miss 不推进锚点，改为在命中确认后 emit）。

备选（不推荐）：把武装点提前到 `BATTLE_FIRST_MOVE_RIGHT`（双方桶都跑）——语义早了一段
[MOVE_RIGHT → 命中前]，"行动开始控"会被错误挡住，弃。

### 3.4 顺序敏感点（实现时注意）

- 王哈窗口到期点与重生清零锚点是**同一个时点**，且都发生在该时点桶**之前**（事件先于桶）——
  该时点上先手方的"命中前控"要能被窗口挡住 → 事件回调先于该时点的施加结算即可，事件模型天然满足。
- 王哈 ROUND_START 判定 → 命中前武装之间的体力变化**不回判**（判定点是回合开始）。
- `preemptive_level` 写点必须在束缚(28)清零**之后**才不被废——MOVE_RIGHT 桶内写入天然满足；
  但若绑定异常在 MOVE_RIGHT 之后的桶里被施加则不适用（现状束缚在异常修正段统一处理，无需额外处理）。

## 四、缺口与待拍板

1. **无 PvE/对战模式标志**："非赛尔对战 4 回合后触发击杀 bundle"需要 battle-level 模式位（场景配置注入），
   内核暂无此概念。
2. **miss 是否推进锚点**（§3.3）。
3. **封回血对王哈低体回血是否有效**：`heal` 原语走封回血检查，按引擎口径会被 HEAL_BLOCK 挡；官方未实测，默认走 heal 即可。
4. **王哈是否有开局首免**：语料未列（战龙有）——按"没有"落地，待实测翻。
5. **重生 ≥4 固伤记录**的"立即免疫"是否含属性直伤/真伤（语料只说固定伤害）——按 PINK_DAMAGE 族落地。
6. **镜像对局**：票按 owner 维度，两只同名精灵分属两边不冲突；同边不可能重复，无需额外处理。
