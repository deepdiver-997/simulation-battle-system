## 二、⚠️ 重要发现（待白班裁决/复核）

1. **🔴 内核 bug：heal_impl 大额恢复整型溢出 → 整笔静默归零**（K332 实证+插桩定位）：
   `battle_primitives.cpp` heal_impl 内 `heal_amount = heal_amount * (100 + heal_mod) / 100;`
   ——int 乘法在 **heal ≥ INT_MAX/100 ≈ 21,474,836**（mod=0）时溢出变负，被随后的
   `if (heal_amount < 0) heal_amount = 0;` **整笔归零**（last_heal=0，非钳半）。
   插桩实证：amt=20,000,000 放行、24,000,000/26,666,666 归零，阈值严丝合缝。
   **修复建议（内核，白班）**：乘法用 int64 中间量——大额恢复本就该由既有的
   `pet.hp = min(max_hp, hp + heal)` 钳到上限即可（用户口径"钳制到上限就行了"），
   不存在"1/4 拒回"官方规则（我此前晨报口径有误，已更正）。
   **受影响面**：所有大血量宠（max ≥ ~85.9M 时 1/4 族恢复、大额吸取/吸血）——
   K332（688 增长吸取 3/9=26.6M）场景断言的是当前带 bug 行为，内核修复后
   scenario_4880 的 R3/R4 断言需同步改（回血应落地）。
2. **烧伤结算口径澄清**（用户口径+源码实锤，修正我此前"即时伤害"误判）：
   烧伤**非施加即结算**——在**行动开始的异常结算点**扣 **max_hp/8 的真伤**
   （battleFsm.cpp:1084，`deal_damage(TRUE)`；虚拟烧伤同档互斥）。同轮 drive 内
   落地，故场景掉血断言会含这笔；K340 实现头注已更正。
3. **`a.row` 偏移缺陷验证**：a01-kprod 晨间交接文档结论正确；本夜新代码全部走
   **宿主 owned_int_args 原序通道**（K236/K257 口径），在真实对局与场景两侧一致，
   未踩坑。存量 17 文件仍待白班裁决（未动）。
4. **must_crit 消费时点**：在伤害管线内、**先于 SKILL_EFFECT 桶**（K305 实测）——
   板行处方"SKILL_EFFECT 时点写 must_crit"不可行，须 ROUND_START/命中前挂。
5. **暴击倍率实测 ×2**（非 ×1.5 常识假设）——伤害带推导注意。
6. **boss_invalid 在节点进桶口过滤**：is_boss_challenge 须 **b.start() 前置位**，
   start 后置位不生效（K294 实证）。
7. **stat_drop 量参须正数**（负值被原语吞，K299）；**is_valid_abnormal_status_id
