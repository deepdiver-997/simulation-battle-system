## 0. 总纲：为什么场景容易假绿

场景测试里，**"对照组"和"实验组"必须只在被测的那一个变量上不同**。一旦两组的
其他差异（载体自带效果、异常自身扣血、等级上限、rand 序列）也被带进断言，
就会出现两类假绿：

1. **断言写得太弱**（如"与对照局相等"）→ 实现被破坏时两组一起变 → 仍相等 → 绿。
2. **断言写得太强/观测面选错**（如用满血观测回血、用 == -1 观测降级）→ 差异被
   clamp 或被别的效果掩盖 → 恒定成立 → 绿。

**通用处方**：
- 门闭断言用**绝对值/绝对比例**（"ratio < 1.10"），不要用"与对照局相等"。
- 观测前把量调到**不会 clamp 的区间**（回血→半血；降级→不是满级）。
- 用**审计槽**（plugin_storage）把"本次实际发生了什么"记下来，让场景能断言
  "前提真的成立"（否则用例可能压根没走到目标分支）。
- 关键断言做**变异测试**：故意破坏实现 → 确认对应断言转红。

## 1. 【D】属性技载体自带**自身**能力增益 → 污染"等级和"断言

### 现象

用属性技做载体时，"能力等级总和"断言恒等于预期值，**即使被测的门被破坏也不红**。

### 根因

属性技载体**自身带效果**。以缩头 20001 为例：

| 技能 | side_effect | effect_info | 语义 |
|---|---|---|---|
| 缩头 20001 | `[4]` | effect 4 = 「技能使用成功时，{1}%改变**自身**{0}等级{2}」 | 防御提升了 |
| 瞪眼 20004 | `[5]` | effect 5 = 「…改变**对手**{0}等级{2}」 | 防御降低了（对手） |

用缩头当"属性技载体"时，**印主自己的防御 +1**（槽 2）→ 等级和 = 1 恒成立。
于是"属性技不触发"这条断言（期望等级和 = 0）**永远失败**，或被写成
"等级和 == 1"而变成假绿。

### 正确写法

- **属性技载体选"效果改对手"的那种**（如瞪眼 20004 / 鸣叫 20002 / 挑拨 20005），
  自己的等级不受影响；
- 或把断言从"等级和"改成"**指定槽**的等级"（如"防御槽仍为 0"）——这样载体的
  自身增益若落在别的槽也不干扰。
- **追加纪律（用户拍板 2026-10-21 白班）**：①能力等级类断言一律**记录效果生效
  前后的槽位快照**逐槽比对，不看总和；②**起始就处于上限（±6）的槽，"生效后不变"
  也是合法通过态**——原语到顶钳住 ≠ 效果未触发，快照前后相等 + 起始即满 cap 即可
  判过（否则"上限对照块"会被误写成假红）。
- **② 的适用范围修订（2026-10-25）**：②只适用于**观测弱化原语本身**的断言（原语
  确实被调用、只是数值被钳）。对"**未触发则补偿**"类条件效果（2161/2320/1393/1122/
  2351/1876/63 全族），官方实测（灼眼焰华 2161，补偿以状态栏图标呈现）证明**对手
  等级到 -6 无法继续下降 = 未触发、照样补偿**——该族实现一律改为 SUCCESS 才算
  落地，AT_FLOOR 与 IMMUNE 同入未触发分支（混合档＝任一槽落地即算触发，官方未
  单独实测，记着）。原语层 AT_FLOOR 的返回语义不变。

### 实证

- K265（382 随机属性+1）：首版用缩头 20001 → T4211 假绿；改瞪眼 20004 后转红，
  变异"破坏攻击技门"才被捕获。
- K280（884 技能类型门）：同样问题，改瞪眼后 T4361 有效捕获。

## 2. 门闭断言须用**绝对值**而非"与对照局相等"

### 现象

"对照组掉血 == 实验组掉血"在实现被破坏时**仍然相等**。

### 根因

若破坏的是"门"本身（如减伤门），实验组会**不再减免**；但对照组根本没挂魂印，
也不减免 → 两组掉血**都变大了** → 仍然相等 → 绿。

### 正确写法

- 门闭用例断言**绝对量**："实验组掉血 ≥ 对照组掉血 × 0.9"（或干脆断言绝对值）；
- 或给对照组也挂一个"无效化"的魂印版本做同源对照。

### 实证

K264（356 低体门增伤）：T4201 原写 `CHECK_EQ(mark_loss, ctrl_loss)` → 破坏体力门
后仍绿；改为 `ratio < 1.10` 后转红。

## 3. 随机槽"去重失效"的观测面：须数 **< 0** 而非 **== -1**

### 现象

关闭随机选槽的去重后，断言没红。

### 根因

去重失效 → 同槽被选两次 → 该槽等级变成 **-2**。而断言统计的是"等级 == -1 的
槽数" → 那个槽从 -1 变成 -2 → **不再被计入** → 计数反而变少（1 而非 2）。

### 正确写法

统计"被降过的槽"要用 **`< 0`**（含 -2 及更负），不是 `== -1`。

### 实证

K282（645 回合随机属性+1）/ K268（796 随机对手降能力）：变异"关闭去重"→
T4380 / T4240 转红。

## 4. `make_pet` 的 hp **同时是最大体力与初始体力**

### 现象

"体力低于最大HP的 1/3"这类门恒假或恒真。

### 根因

`make_pet(id, name, skills, speed, atk, hp, ...)` 的 `hp` 同时写进
`numerical_base[HP]`（= 最大体力）与 `initial_hp`。所以"造一个 10000 血、低体力的
精灵"实际是"最大体力也是 10000" → 门判据恒为"等于阈值"或"不低于阈值"。

### 正确写法

**满血构造 → 开局后单独压当前体力**：

```cpp
ElfPet p = make_pet(1, "印主", {...}, /*speed=*/300, /*atk=*/1, /*hp=*/99999, mark);
ctx.getPet(0).hp = 10000;   // 只压当前体力，最大体力不变
```

### 实证

K277（610 回合回血低体翻倍）：首版把 hp 传 10000 → 阈值恒错 → 门恒闭。

## 5. 异常自身的每回合扣血会污染"掉血"断言

### 现象

对手带异常时，"对手掉血 == 0"（期望不附加固伤）失败，实际掉了一大截。

### 根因

**烧伤(2) 自身每回合扣最大体力 1/8**（≈12500 @99999）、中毒/流血同理。
断言里的"对手掉血"包含了异常自身那一份。

### 正确写法

- 用**双局差值**：对照组（无魂印、同样带异常）vs 实验组 → 差值才是被测效果；
- 或换一个**自身不掉血**的异常当门（如麻痹/睡眠——控制类不扣血）。

### 实证

K285（618 烧伤门回血/固伤）：T4410 原写 `foe_loss == 0` → 实测 12499；
改双局差值后准确。

## 6. 威力改写族必须**字段断言**，不能断言伤害比例

### 现象

"伤害提升 20%"这类断言不稳定或对不上。

### 根因

`ws.skill_power_view` 被改写后，引擎**重跑伤害公式**（`apply_variable_power_recalc`）
→ 伤害里含 85%~100% 随机浮动 + 取整 → 精确等式/紧比例带都对不上。
（SOP §五.1）

### 正确写法

**停泊到 FIRST_SKILL_EFFECT 跑完，读威力视图字段**：

```cpp
ctx.debug_step_mode = true;
b.submit_operation(0, SELECT_SKILL, 0);
b.submit_operation(1, NONE, -1);
ctx.debug_step_mode = false;
b.step_past(State::BATTLE_FIRST_SKILL_EFFECT);
const int view = ctx.ws.skill_power_view[0].value;
```

对照组用**同 seed 的无魂印局**取 base，再断言 `view == base * (100+pct) / 100`。

### 实证

K333（667 累积威力提升）：base=35 → v1=36（×105/100）、v6=v8=45（封顶 ×130/100）。

## 7. 魂印概率的**百分比 vs 千分比**逐宏不同

### 现象

同一个宏族里，有的 args 是百分数、有的要除 10。

### 根因

官方各魂印独立编码：**151「攻击时有2%秒杀」args=[20,0]** 是**千分比**（db/10），
而 **1147「5%秒杀」args=[5,…]**、**627「4%秒杀」args=[4,0]** 是**百分比**。
K4 头注明写："概率单位逐宏互锚，**严禁跨宏复用换算**"。

### 正确写法

- 按该宏的 **tips 字面**落地（写"5%"就用 5）；
- **用变异测试锁住**：把 4 改成 0.4（千分比折算）必须转红——否则后人
  迟早会"顺手统一"成 /10。

### 实证

K288（627）：变异"4→0.4"→ T4440 转红。

## 8. 满级(+6)槽：随机仍会选中它，只是看起来没发生什么

### 现象

实现里"预筛跳过满级槽"和"照常调用让原语内钳"两种写法，**断言分不出来**。

### 根因

`stat_change` 的 `AT_CAP` 档：等级已在 +6 → 不变、不报错、正常返回。
若断言只写"该槽还是 6"，两种实现都过。

### 正确写法

- 加**审计槽**记录"本次随机选中了哪些槽"（bitmask），让场景能断言
  "随机确实选中了那个满级槽"——否则用例可能压根没走到目标分支；
- 断言"被选中的槽数 == 期望值"（预筛会少选一个 → 槽数对不上）。

### 实证

K2536（2152 库拉塔克）：首版 T5232 假绿（seed 下没选到满级槽）；加审计槽
`pick_mask` 后，变异"预筛跳过满级槽"→ T5232 转红。

## 9. 吸取体力（drain_hp）：回血与"伤害是否落地"**解耦**

### 现象

直觉上"对手免粉 → 吸取不生效 → 自己也不回血"，但实测**自己照样回血**。

### 根因

`drain_hp` / `drain_hp_amount`（battle_primitives.cpp）：

```cpp
deal_damage(ctx, target, amount, DamageKind::FIXED, actor);   // ← 粉伤路径
heal_impl(ctx, actor, amount);                                 // ← 无条件调用
```

- 伤害走 **FIXED = 粉伤** → 查 `PINK_DAMAGE` 免疫 → 对手免粉时**伤害不落地**；
- 但 `heal_impl` 是**无条件调用**的 → 吸取的"回血"与"伤害是否落地"**解耦**
  → 对手免粉**不影响**自己回血；
- `heal_impl` 查 `ImmunityType::HEAL_BLOCK`（:1438）→ **自己被封回血则恢复 0**。

### 正确写法

观测自己回血量时**必须半血**（满血被 clamp 到 max_hp 掩盖差异）。

### 实证

scenario_017 Q1b/Q2c/Q3b/Q3c（2026-10-21 补测）：对手免粉 → 对手 5000→5000、
自己 400→800；自己封回血 → 自己 400→400。
