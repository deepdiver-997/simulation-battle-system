### K358（1421）——自身半血门攻击附伤族

tips（effect_icon row1107，权威文）：「自身体力高于最大体力的1/2时攻击技能命中后附加150点
固定伤害，自身体力低于最大体力的1/2时附加的固定伤害效果翻倍」。db[0]=2（1/2 分母）、
db[1]=150（附加固伤点数）。

- 门：DETECT 相位 own 红伤命中（d.attackerId==owner && isRed && final>0）+ 印主魂印在场。
- 分档：**印主自身当前HP×db[0] vs 印主自身最大HP**（tips 主语是「自身」，不是对手）；
  乘分母比大小而非先除后比（避免整数截断把恰好一半判错档）。
- 效果：deal_pink_damage(对手, amount, FIXED, owner)。

### K359（1045）——附当前体力固伤 + 命中回合末回最大体力族

tips（effect_icon row760）：「攻击附加自身当前体力1/3的固定伤害；当回合自身攻击命中对手则
战斗阶段结束时恢复自身最大体力的1/3」。db[0]=3（子句①「当前体力1/3」分母）、
db[1]=3（子句②「最大体力1/3」分母）——**两参同值 → 顺序不可观测**，两个基数由 tips

- 子句①：DETECT 相位 own 红伤命中 → 附「印主**当前**HP/db[0]」点固伤。
- 子句②：DETECT 命中时置「本回合命中旗」→ BATTLE_ROUND_END（战斗阶段结束时）读旗 →

## 勘误记档

1. **场景号段分配器计数器与实际已用号段脱节（真坑，已修）**：hub
   `build/night/scenario.alloc` 停在 5850，但 5850-5859 已被 J 板
   `scenario_5850_boost_level_power.cpp` 占用（直接 alloc 会**撞号**）。本会话先把计数器
   seed 到 7000（核对全分支 7000+ 未占用）再 alloc，拿到 7000-7009 / 7010-7019。
   → 记档：alloc 前必须核对「全分支最大已用号段」，计数器本身不可信。
2. **变异测试的陈旧产物坑（与 a72-jprod 同款，代价是白跑一轮）**：第一次跑 M4
   「命中旗不清（跨回合残留）」时场景仍绿——变异**没被断言咬住**（场景原本只跑单回合，
   跨回合残留无人观测）。补 T7018（两回合：第 1 回合命中回血、第 2 回合未命中不回）后
   M4 转红。→ 记档：变异必须先确认「该变异的失效特征在场景里有观测点」，再改实现。
3. **变异脚本把「构建失败」当成「未测」**：第一版脚本里 `denom` 是 `const`，改写它导致
   编译不过，脚本只打印「构建失败（跳过）」就过去了（看着像没转红）。改成「把 denom 改成
   非常量再改写」后才真正测到。→ 记档：变异脚本必须**区分构建失败与断言失败**，构建失败
   一律当失败处理。
4. **K358 等号档口径（待官方实盘复核）**：tips 只写「高于」「低于」，等号无归属。本实现取
   **两分支皆不触发**（与 K347 663 / K245 / K246 同款严格档）。备选读法（基准 150 + 低体力
   翻倍修饰 → 等号取 150）同样讲得通；若官方实盘证伪，改 K358 一处分档判定即可，场景 T7002
   是该口径的锚点。
5. **K359 两参同值（3/3）**：顺序在数值上不可观测，子句①/②的归属靠 tips 文字分工（当前体力
   vs 最大体力）判定——不是按参数位置猜的。
6. **1045 在 moves 空间有 `SKILL_EFFECT(1045, ...)`**（j_hp_basis_pink.cpp）：属**技能效果
   空间**（moves effect_cache_），与魂印程序空间（soul program_cache_）分开，**不构成同族
   撞号**；id 撞号审计两次门均报「新增 0 处」。
7. **补交上一会话孤儿晨报**：`docs_local/docs/06-交接/夜跑晨报-2026-10-22-kbatch.md`
   （a15-kprod 写于 worktree、**从未入库**，hub 上查无此文件）本会话一并提交，避免再丢一次。
