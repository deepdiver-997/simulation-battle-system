# 夜跑 token 预算与并行度基准（2026-11-03 建档，编排会话维护）

> 用途：夜跑前按剩余 token 预算估算「能跑几单、开几路、几点截单」。
> 数据源 = ZCode 会话实际消耗（含子 agent 全部 token）；两晚实测，样本量尚小，逐夜修订。

## 一、单任务消耗基准（子 agent 侧）

| 任务类型 | 典型消耗 | 实测样本 |
|---|---|---|
| 文档/调研型（S6 百科章、S5 调研） | **7-10M** | S6 9.1M、S5 8.3M、S7 6.6M |
| 查证型（内核钩子可达性/哑模板考据，含落地） | **10-16M** | J320 10.3M、J319 14.1M |
| 常规批产 2-3 宏（先例直系、无坑） | **14-20M** | K406 15.7M、K408 15.9M、K407 27.5M* |
| 复杂族/带调试循环 | **25-45M** | K405 44.8M、K394 37.5M、J315 33.1M |
| 白皮书/大盘点型（全量现查+体系化成章） | **11-13M** | S23 11.4M（475 行/148 引注，超文档型带宽） |

\* K407 带 5 处变异+108 断言偏上限；**断言数与消耗正相关**（每 +20 断言约 +3-5M）。

- 两晚均值：11-02 夜 12 单 ≈ 250M（**~21M/单**）；11-03 夜 9 单 ≈ 135M（**~15M/单**，查证型占比高拉低均值）。
- **预算规划公式**：可跑单数 ≈ 剩余 token × 0.9（留收尾余量）÷ 18M（保守均值）；按任务类型加权后取整。

## 三、并行度实录

| 夜 | 双发结果 | 结论 |
|---|---|---|
| 11-02 | 双开成功（K394+J314）→ 后 S5 首发被限流 | 额度 2 |

## 四、截单与收尾纪律

- 收尾包 = 终合并 + 终门（~8-12 min）+ 晨报 + 分支/worktree/身份清理（~5 min）。
- **停止发单条件**：剩余墙钟 < 单均时长（串行 40min / 双开 25min）+ 收尾包 15min。
- token 剩余 <2 单预算时也停发（避免尾单写一半预算枯竭）。

## 六、额度耗尽接管实录（2026-11-03 08:41 首例）

- 免费额度 08:41 耗尽，K409 agent 死于实现+场景写完之后、构建验证之前（`exceed quota limit`）。
- **半成品完整度体检法**：SOUL_PROGRAM 注册数/收尾完整性/场景 main 完整/断言计数——4 项粗检 5 分钟，

- 额度窗口边界的发单判据更新：**预估完成时刻越过窗口边界 ≤15min 的轻量单仍可发**——即使中途死也有半成品接管路径兜底；更长的单不发。

## 七、额度接口实测（2026-11-04 00:40）

- `billing/preview` 的 `code=3001 parameter error` **不是参数形态问题，是缺指纹头**：带
  `X-ZCode-App-Version: 3.17.1` + `X-Platform: darwin` 后返回 `code=0`（数据为空）。
  推论：preview 空数据 = 当前账号无可用重置券，不是接口不可用。`zcode-quota` 脚本未带这两个头，故一直误报 3001。
- `billing/current` 只列**当前凭据账号**的套餐：本机此刻只见 `zcode-v3-start-plan-1103`（夜间 3 亿），
  看不到周订阅套餐 → 订阅额度挂在另一个 provider/账号，需另一份 JWT 才能查/领重置券。
- 带指纹头请求 `current` 反而返回空 data（疑似头切换到另一 API 版本）——查套餐数据时**别带这两个头**，
  查 preview 时**必须带**。两者口径不同，脚本应分头配置。

## 八、claim 端点被验证码闸死（2026-11-04 00:52，脚本刷新路线判死）

- `POST billing/claim` 任意 plan_id → **code=3007 captcha verify failed**——验证码校验在
  plan_id 校验之前，脚本claim 无解（即使拿到有效 plan_id 也过不去）。用户预判成立：刷新最终靠 UI 点击。
- credentials.json 是**两层账号结构**：`zcodejwttoken`（zcode 平台，current 只见 Start Plan、
  preview 空=无券）+ `oauth:bigmodel:access_token`（bigmodel 账号，订阅 Individual Coding Plan
  大概率挂这边）。「周额度看不到」的根因 = 查错了账号的 token。
- 可行后续（需人工/CDP）：①GUI 点一次重置抓包（AGENTS.md 预判的「抓一次 CDP 可补全」——
  补齐 captcha 处理或 bigmodel 侧端点后可脚本化）；②或确认订阅刷新本就是 UI-only。
- preview 3001 修正：之前不带指纹头报 3001 是缺头；带头后 code=0 但数据空=真无券。

## 九、额度消耗纪律（2026-11-04 用户拍板，长期有效）

- **免费额度不过夜原则**：Start Plan 09:00 过期制——窗口内哪怕只剩 30 分钟也继续派单榨干，
  跨窗任务靠「半成品体检+收尾型 agent 接管」兜底（§六，实测 2M vs 重做 15-20M）。
- 不因「额度还剩很多但时间不够」而提前收摊；订阅额度同理——用户会在耗尽时手动刷周卡。
- 并发上限实证 3（用户级）：workflow 3 槽 + 直发第 4 个必死（连续两次幽灵领取实证）。
  workflow 运行期间不直发；直发模式最多 3 并发。
