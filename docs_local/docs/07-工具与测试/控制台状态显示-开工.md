# 控制台状态显示与全量状态导出 —— 开工文档（2026-09-27）

> 目标：控制台调试视图 + AI 训练观察空间**同源**——同一份全量状态导出，两个消费者。
> 用户 2026-09-27 定稿两条原则：① 协议**只传 ID**，名字解析全在客户端；② UI **分组折叠**，
> 不一股脑铺开。分三阶段施工，每阶段独立可验收、不碰战斗逻辑（纯加只读序列化）。

## 一、现状（已完成 60%）

`BattleContext::getFullStateJson`（battleContext.cpp:1295，335 行）已吐：双方全队
（HP/六维面板/种族底/能力等级/系别/魂印名/五技能全属性/marks/护盾护罩/嗑药库存）、
44 槽异常状态带剩余回合、回合数/状态名/断点调试。传输走**双向调试命令 23**
（C_DEBUG_FULLSTATE）按需拉取。

缺口：时点桶、RuleCenter 票、ws 视图（威力/系别/凭证/执行结果）、storage 三张表
（soulmark/on_stage/plugin——值是 std::any）。

## 二、两条设计决策（用户定稿）

### 2.1 协议只传 ID，名字客户端解析（服务端不存显示字符串）

| 数据 | 名字来源 | 服务端要做的 |
|---|---|---|
| effect id（桶条目/票） | DB `effect_info.info` 模板 + args 代入（既有） | 只传 effect_id + args |
| 异常状态 id | 引擎 `abnormal_status_name_cn` 已随 fullstate 传（44 个固定名，可挪客户端） | 已完成 |
| **storage key** | **效果实现者自注册**（STATE_DISPLAY 宏，见下） | registry dump 时导出 |
| 票类型 | RuleCenter 类型是引擎固定枚举 | 引擎侧固定显示表 |

**STATE_DISPLAY 自注册**（仿 SOUL_PROGRAM 静态自注册先例）：

```cpp
// 插件/效果侧顺手登记；编译进 dylib，--dump-registry 时导出。
STATE_DISPLAY(kSuanliKey, {
    .name_zh = "算力",
    .decode  = [](const std::any& v) -> DisplayValue { /* int → {label,value} */ },
});
```

- 导出：`--dump-registry-exit` 的 JSON 增加 `display` 段
  （`storageKeys: {key: {name, type}}`），网关 `/api/meta` 分发，客户端**每注册表版本拉一次**。
- ⚠️ 跨 dylib 纪律：解码器必须 header-only 或经 CoreApi 回调表注册（插件不链接 sim_core）。
- 未知 key 优雅降级：客户端显示 `key=241402` 裸值——旧效果永不因缺注册而崩。

### 2.2 UI 分组折叠（不一股脑铺开）

面板按类分**可折叠分组**，默认收起、点击展开：
- **异常状态**（一个按钮/徽标 → 点开展示 44 槽明细 + 剩余回合）；
- **印记类**（soulmark_storage 下的计数/形态条目）；
- **效果类**（时点桶条目 + RuleCenter 票，按 source_effect_id 归组，模板渲染）。
场上满员时组标题显示计数（如"异常 ×3"），空组隐藏。

## 四、AI 训练侧（同源消费者）

- 观察空间 = Stage 1+2 的**数据面**（id+数值，无名字）；奖励信号 = tape 的 HP 采样（既有）。
- 确定性已有（std::rand 播种 + 场景零 rand 消费纪律），训练可复现。
- 批量训练走网络时再考虑二进制序列化；先 JSON。

## 五、网络量化（结论：无压力）

fullstate 现状 ~8-10KB；+ws 视图 ~1KB；+桶票（常规 10-50 条）~3-5KB；+storage ~2KB
→ 满打满算 **15-20KB/次**，按需拉取（非每帧），localhost/局域网毫秒级。
名字元数据开局拉一次不进每包。真正成本 = 序列化代码 + 解码器维护纪律。
