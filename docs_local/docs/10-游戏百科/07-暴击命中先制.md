## 〇、总览：一次攻击技能的判定序列

`Skills::query_usage` 是三判的总入口，步骤固定〔源: src/entities/skills.cpp:842-851〕：

| 步 | 名称 | 干什么 | 谁能拦它 |
|---|---|---|---|
| 0 | 凭证物化 | materialize_attack_credential：穿透 + 次数授予 + 强制执行 + **必中**，落 `ws.attack_credential` | — |
| ① | 命中判定 | 三分支：强制执行直过 / 失明特判 / 常规 roll | miss 出口 |
| ①.5 | 暴击判定 | 只在攻击技能掷，写 `ctx.crit_happened` | **只有 miss 能拦** |
| ② | 门判定（技能无效中心） | 盔/威/封属/命中失效统一 notify 与消费 | 强制执行绕过拦截但消费照常 |
| ③ | 效果注册 + 伤害结算 | 伤害端**只消费** ①.5 掷好的 `crit_happened`，不再重掷 | — |

序列口诀（J320 查证结论）：**凭证物化（第 0 步）→ ① miss → ①.5 判暴 → ② 盔 notify**〔源: resources/moves_lib/j_crit_invalid_window.cpp:22-23〕。
为什么暴击必须在 ①.5 掷、不能等伤害结算处：技能无效时伤害结算**整段不执行**（`allowAttackDamagePipeline=false` 早退），在那里掷就永远掷不到〔源: src/entities/skills.cpp:970-971〕；伤害端注释亦明示「只消费 query_usage 已掷好的结果」〔源: src/fsm/battleFsm.cpp:702-704〕。

## 一、暴击模型

### 1.1 判定时点：miss 之后、门判定之前

官方口径（用户 2026-09-13 定）〔源: src/entities/skills.cpp:964-973〕〔源: docs_local/docs/02-效果系统/技能判定流程与无效效果体系.md §八〕〔源: 场景040:3-13〕：

- **只有 miss 阻止暴击**。失明的「命中效果失效」档不算 miss，照样保留暴击结果；
- 技能无效（盔/威/封属）、命中效果失效**都保留**暴击结果——「打在盔上一样可以触发暴击并且破对应的防御正等级」；
- **只在使用攻击技能时触发**（属性技能不掷）。

`crit_happened` 每次技能使用先清，miss 时不残留〔源: src/entities/skills.cpp:851〕。
场景侧验证点覆盖：C4 打盔照样暴击破防、C6 属性技不掷、C7 miss 不暴击、C8 命中效果失效也能暴击破防〔源: 场景040:15-24〕。

### 1.2 暴击率：分母 16 的分子，与攻击方三槽

技能暴击率来自 `moves.crit_rate`，是**分母 16 的分子**：=8 → 50%、=16 → 100%；**`0` = 永不必暴**（不是「基础 1/16」——确实有天生暴击率为 0 的技能，没有引爆效果就永远不会暴击）〔源: src/entities/skills.cpp:455-460〕〔源: 场景040:83-93〕。

①.5 的完整掷点式〔源: src/entities/skills.cpp:974-996〕：
`rate = 技能暴击率 × ws.crit_rate_mod + ws.crit_rate_add`（+ 会心特性项）；
`crit_happened = must_crit ∨ 特性二次roll ∨ rate≥100 ∨ (rate>0 ∧ rand<rate)`。

攻击方**三个槽**——为什么必须是三个：乘算槽在技能 `crit_rate=0` 时表达不了「必定」（0 × 任何数 = 0）〔源: include/fsm/battleWorkspace.h:255-276〕：

| 槽 | 语义 | 典型写入方 |
|---|---|---|
| `crit_rate_mod` | 乘算修正，「下N回合暴击率提升」每回合重写（reset=1.0） | 窗式效果 |
| `crit_rate_add` | 加算百分点（effect 32 蓄气族 +1/16 = +6.25pp；add>0 时 base=0 也能暴——add 是引爆效果） | effect 32 族 |
| `must_crit` | 必暴开关（effect 58 圣光气「下N回合自身攻击技能必定致命一击」） | effect 58 / pending 窗 |

通用特性·会心（CritBoost）双形态：0 星（args[0]≤1）与技能初始暴击率**加法**结算（+6.25%，即 1/16）；1-5 星是**独立二次结算**——「只要有一个触发则当次攻击必定暴击」〔源: src/entities/skills.cpp:982-993〕。

### 1.3 倍率与暴击抗性：先放大、再削整段

结算端两步，顺序不可换〔源: src/fsm/battleFsm.cpp:706-713〕：

1. **暴击系数**：`base × cached_crit_damage / 100`，默认 200（2 倍）〔源: src/fsm/battleFsm.cpp:714-716〕〔源: include/fsm/battleWorkspace.h:554〕
2. **暴击抗性**：`× (100 - eff_crit_resist_pct) / 100`，读守方**有效视图**（临时 buff 可修改，基线由 sync 重基）〔源: src/fsm/battleFsm.cpp:717-720〕〔源: include/fsm/battleContext.h:898〕

★ 关键口径：抗性乘的是**整段**，**不是**只削「暴击加成的那部分」（用户 2026-09-14 纠正）：原本 100 的伤害 → 暴击 ×2 = 200 → 35% 暴击抗性 → **200×0.65 = 130**（**不是** 100 + 100×65% = 165）；100% 抗性 → **0**。官方同源（L99）：「暴击系数×暴击抗性…可以折算为 **2×0.65=1.3**」；两步**各自取整**〔源: src/fsm/battleFsm.cpp:706-713〕〔源: 官方原文 L99〕。
S17 旁证（L155《伤害抗性提升的冷知识》）：官方早期把"伤害抗性提升魂印"**加算**进暴击抗性（「我暴击抗性35，魂印提升25，计算的时候会以 2×(1−0.35−0.25)=0.8 倍」）——该 bug 被官方删除，即**加算路线已被官方否决**、乘整段模型为现行口径的唯一读法；100% 极端档（→0 伤）是乘法模型的算术推论，官方无直接文本（见清单#4）〔源: 官方原文 L155〕。

连击 ×N 排在暴击乘完之后（完整序：本系修正 → 克制 → 浮动 → 暴击抗性 → 暴击系数 → **连击次数**）〔源: src/fsm/battleFsm.cpp:722-727〕。

### 1.4 暴击破防（收尾步骤）

暴击附加效果：物理 → 对手**防御正等级归 0**，特殊 → **特防正等级归 0**；只清正等级（负等级不动）；**不查任何免疫**（免消除强化 STAT_CLEAR 挡不住它）；时点在**第一次伤害公式之后、技能特效生效之前**——为变威力「按归零双防重算第二次」让路〔源: 场景040:3-13〕〔源: docs_local/docs/05-任务清单/待做-变威力与增减伤时点.md §1.1〕。
C3 实测：物理暴击 → 对手防御正等级归 0、特防正等级保持不动〔源: 场景040:123-130〕。

### 1.5 暴击反写命中凭证（三判闭环）

暴击不只改伤害——2380「自身下{0}次致命一击视为命中并强制执行命中效果」：暴击落地即消费 1 层计数（plugin_storage `990238000+owner`，技能效果侧武装）→ 写 `ws.attack_credential.force_execute`——「视为命中」与「强制执行」都由它承载〔源: src/entities/skills.cpp:997-1011〕。

## 二、命中模型

### 2.1 必中是一张凭证，不是一个字段

「是否必中」一律读**凭证** `cred.must_hit`，不要只读技能静态字段——条件必中固有效果是**出手前授予**的。凭证三来源〔源: src/entities/skills.cpp:342-346〕〔源: resources/moves_lib/j_crit_invalid_window.cpp:22-24〕：

1. `moves.must_hit` 固有必中（DB 字段，loadSkills 时读入）〔源: src/entities/skills.cpp:452〕
2. 本回合效果授予的条件必中（效果体在 MOVE_RIGHT 时点写 `ws.must_hit_grant`）
3. 强制执行 `force_execute`（隐含必定命中）

凭证在第 0 步物化进 `ws.attack_credential`——query_usage 里的 cred 是同一对象的 const 引用，效果侧直接写 ws 槽即可改写本次判定〔源: src/entities/skills.cpp:847-849〕。

### 2.2 命中判定三分支（顺序不可换）

三个分支，**顺序不可换**〔源: src/entities/skills.cpp:853-871〕：

- **(a) 强制执行**：隐含必定命中 → 跳过一切命中判定（含失明）；
- **(b) 失明（异常 20）**：非必中技能**必定 miss**；必中技能 50% 正常命中 / 50% 命中效果失效（官方口径，用户 2026-09-13 确认）；
- **(c) 常规 roll**：走 2.3 乘算链后掷点。

必中技能绕过的门（三处同款）：

- 「必定 miss」治不了必中——含 effect 86 圣洁的 `attribute_must_miss`（被保护方置旗、攻方出手查 `1-owner`）；其语义是「技能打空」走 miss 路径（照常 notify 消费对方的次数类盔），不是 SKILL_INVALID〔源: src/entities/skills.cpp:873-878〕；
- 命中等级治不了必中——必中技能根本走不到该分支〔源: src/entities/skills.cpp:905〕；
- 失明的 50% 档对必中技能只掷「正常命中 / 命中失效」，不会直接 miss〔源: src/entities/skills.cpp:863-866〕。

miss 的既有约定：**miss 也照常 notify 中心**——「一旦本次技能命中失败（miss 类），会消耗所有可响应的次数类效果」，狮盔会被响应并消耗，尽管技能是 miss 的〔源: src/entities/skills.cpp:954-960〕。暴击侧对称：miss 路径 `crit_happened` 保持 false → 675 型回合盔无消耗面〔源: resources/moves_lib/j_crit_invalid_window.cpp:18-19〕。

### 2.3 命中率乘算链（顺序固定，可复现）

非必中、非强制执行才进这条链；乘法链的 int 截断有 ±1 差异，**固定顺序**让结果可复现〔源: src/entities/skills.cpp:879-959〕：

| 序 | 乘子 | 落点 |
|---|---|---|
| 1 | `accuracy_fix_100` 凭证 → roll 起点钉 100（先于精准/回避与命中等级，弱化照样乘下去；且**跳过必闪减避**——「必定闪避词条都无法生效」） | :883-888 |
| 2 | 攻方精准特性 ×args[0]%、守方回避特性 ÷（**都作用于属性技能**；无特性者零行为、零 rand 消耗） | :889-896 |
| 3 | 命中等级档位（view_levels 槽 5 + `hit_level_extra` 视为修正；负档官方表 -1→85% … -6→25%；正档暂无官方表→通用等级换算 (lvl+2)/2，用户 2026-09-18 口径——S17 语料 495 帖全扫确认正档表缺文，见清单#1） | :897-912 |
| 4 | `ws.hit_rate_mod` 乘算修正（圣芒佑界 476 战盔「己方命中率提升15%」每回合写 1.15；此前是无消费点死字段，套装线接入） | :913-918 |
| 5 | 攻击技门控 `hit_rate_mod_attack`（1314/1576/1673/1843 族魂印「对手使用攻击技能命中率降低X%」）+ 异常修正：混乱 ×20%、易燃 ×70%（effect_des 10/13，官方措辞限定「攻击技能」→ gate 非属性技） | :925-939 |
| 6 | 守方 `dodge_rate` 必闪减避（accuracy_fix_100 跳过）+ 虚无特性 roll（本质是闪避、不是挡伤；rand 只在带虚无时消耗） | :940-953 |
| 7 | `sbs_rand % 100 ≥ hit_chance` → miss | :954 |

命中等级的三类来源：① 异常衍化族（焚烬结束后「转化为烧伤与命中等级-1」）；② 效果层「令对手命中等级±n」（stat_change/stat_drop 的 stat=5）；③ **视为修正** `ws.hit_level_extra`（蚩庸之锁每层视为命中等级额外 -1，与命中强化相互抵消，官方口径）〔源: src/entities/skills.cpp:897-912〕。

## 三、先制模型

### 3.1 槽位与唯一切换点

先制等级 = `ws.preemptive_level[2]`，数值越大优先级越高；同区还有 `guaranteed_first`「必先」——必先比先制更强，是**独立比较项**〔源: include/fsm/battleWorkspace.h:177-178〕。

判定点 `handle_BattleFirstMoveRight`：**先 memset 清零双槽（FMR 桶）**，再跑两侧 BATTLE_FIRST_MOVE_RIGHT 桶（选择期先制在这时累加），最后做**异常修正唯一点**〔源: src/fsm/battleFsm.cpp:1727-1732〕：

- 束缚（28）「先制效果失效」→ 清零该方先制等级；
- 先制失效区（精灵王线，`priority_nullified` 旗，非异常条件区）→ 同语义清零；
- 超频（35）「技能先制+1」→ **清零动作之后**再 +1 → 天然不被束缚废掉（「有的靠后改变先制的效果依旧可以绕过束缚」，用户 2026-09-18 口径）；
- 「必先」**不动**（若实测要求束缚也废必先，改的是必先比较那一行——**见清单#3**，
  与清单同题不再行内重复挂 ⚠；
  S17 语料补注：「必先→先制→速度」的**比较序**有坊间佐证（L465「先判定必先，
  在判定先制，最后判定速度」、L136「根据双方必先、先制、速度来决定」），但
  束缚×必先的官方裁决句 495 帖扫描无直接文本）〔源: 官方原文 L465〕〔源: 官方原文 L136〕。

〔源: src/fsm/battleFsm.cpp:1734-1756〕

比较收口：preemptive_level 大者先手；「基值先制已在选择期（on_selected）累加，此处不再重复读 skill.priority」〔源: src/fsm/battleFsm.cpp:1799-1803〕。

### 3.2 先制的三类来源

| 来源 | 落点 | 例 |
|---|---|---|
| 技能固有 priority | loadSkills 读 `moves.priority`，作为一条**选择期效果**进 `selection_effects_`，on_selected 统一注册到 MOVE_RIGHT 桶 | 香雪纷飞 33913 priority=3 |
| 基值先制效果模板 | `effect_apply_base_priority`：MOVE_RIGHT 时点 `preemptive_level[owner] += args[2]` | 效果族通用 |
| 条件先制 | **selection_effects_ 路由表**（见 3.3，勿走 case） | 747 负槽门、1491 天敌 |

〔源: src/entities/skills.cpp:453〕〔源: src/entities/skills.cpp:233-246〕〔源: src/entities/skills.cpp:726-735〕

坑：技能固有 priority 经 `ws.preemptive_level` **残留跨回合**——先制对照必须 priority=0 载体〔源: 速查§五〕。

### 3.3 路由表 vs case 表坑（J66 勘误）

**条件先制走路由表，不走 case**（J66 1491 实测勘误，2026-10-03）〔源: 速查§五〕〔源: docs_local/docs/05-任务清单/已收官/J组批量效果工单.md J66 行〕：

- 「条件→先制+N」族要在**首回合当次生效**的，路由必须加在 loadSkills 的 `selection_effects_` 硬编码表（2000/610/954/1848/881/1532/2298/779/1860/1491）；
- `effect_register_state` 加 case（2020 形）注册进的是**用技期分支**，**赶不上首回合先制判定**——SBS_SCENARIO_CHECKS 佐证：选择期表版绿、case 版先手断言必挂；
- 选场景载体时另查 `moves.priority`——priority≠0 的载体会污染先制断言。

J74 的 747（负槽门先制族，16 载体「自身处于能力下降时先制+{0}」）即此勘误直系，同样走路由表〔源: docs_local/docs/05-任务清单/已收官/J组批量效果工单.md J74 行〕。

### 3.4 pending 先制窗与先制累计（K395/K402）

- **pending 先制窗**：FMR 桶 memset 后写 `preemptive_level`（K394 ③ 与 K395 行 881「先手50%冰封未触发→下1次先制+2」同构；1126「属性技下回合先制+1」同族）〔源: docs_local/docs/05-任务清单/已收官/K组魂印批产工单.md K395 行〕〔源: docs_local/docs/05-任务清单/已收官/K组魂印批产工单.md K402 行〕

## 四、三者交互案例

### 4.1 J320 effect 675：盔门在判暴后求值

官方模板：「下{0}回合对手打出致命一击的**非必中技能**无效」（675×12 载体，例 灵气护体 23644）〔源: resources/moves_lib/j_crit_invalid_window.cpp:3-4〕〔源: docs_local/docs/05-任务清单/已收官/J组批量效果工单.md J320 行〕。

内核钩子查证（J320 证据链核心，2026-11-03）：判暴点 ①.5 本体**无插件钩子**（无事件、无 RuleCenter notify、无反向旗槽——ws 只有 must_crit 对称位）。若把 675 语义读成「压暴击」（判暴点读旗）则读旗点在内核且无现有钩子 → 内核缺口记档停手；但官方语义是**技能无效（盔族）**——盔层 ② 在同一次 query_usage 内位于 ①.5 **之后**，notify 时点免费读到两个现成值：`crit_happened`（①.5 已掷好）+ `must_hit` 凭证（第 0 步已物化）→ **可达，不停手**〔源: resources/moves_lib/j_crit_invalid_window.cpp:6-21〕。

这同时回答了「必中判定与暴击判定先后」：**凭证物化（第 0 步）→ ① miss → ①.5 判暴 → ② 盔 notify**——两判据在盔层均为现成值〔源: resources/moves_lib/j_crit_invalid_window.cpp:22-24〕〔源: test/scenario/scenario_7680_crit_invalid_window.cpp:15-16〕。

落地形态：NextRounds 窗（本回合不算，窗 [R+1, R+N]）+ tick 每回合重授予 rounds=1 盔；判据 = 会暴击（crit_happened）+ 非必中（读凭证不读静态字段）；豁免三支 = 必中技 / 非暴击技 / 属性技；本盔 penetrable=false（条件盔），穿透凭证（697/699）也穿不动〔源: resources/moves_lib/j_crit_invalid_window.cpp:25-28〕〔源: test/scenario/scenario_7680_crit_invalid_window.cpp:10-14〕。交付记录：场景 7680 六用例 24 断言、变异 4/4 转红还原、回归全绿〔源: docs_local/docs/05-任务清单/已收官/J组批量效果工单.md J320 行〕。

### 4.2 必暴窗：三槽协作的样本
