## 一、魂印是什么：行、宏、宠三个口径

官方侧，一条魂印是 `effect_icon` 表的一**行**：`id / pet_id 数组 / effect_id / kind / args / tips`。
tips 全量有文本（最长 650 字符，id=1724），kind 是 0~16 的多值数组且**全库无字段说明**
〔源: docs_local/docs/02-效果系统/魂印机制族聚类-调研.md §一〕。三个统计口径必须分开说：

| 口径 | 规模（2026-11-04 现查） | 含义 |
|---|---|---|
| 行 | 2149 | 官方文本单位，「行×宠」是批产对行的真实单位 |
| 宏（effect_id 去重） | 1864 | **批产单位**：一个 handler 注册一次 |
| 引用精灵 | 2006 | `pet_id` 数组解析去重；引用分布极度长尾 |

〔源: docs_local/docs/02-效果系统/魂印机制族聚类-调研.md §一〕（复算命令见 §七）。

### 1.1 行≠宏（本系统最重要的结构事实）

同一 effect_id 的多行**各有自己的 tips 与 args**，是同一效果宏的不同参数化实例。
实证（effect 150，dump 现查 2026-11-04）：

| 行 id | 宠 | args | tips 节选 |
|---|---|---|---|
| 19 | 万魔天尊 2468 | 空 | 50% 免疫对手致命一击造成的伤害 |
| 257 | 圣皇 2378/2379 | 350 0 | 有 35% 概率免疫对手致命一击 |
| 2027 | 4837 | 600 0 | 60% 免疫受到的致命一击伤害（boss有效） |

〔源: tools/soul_effects_dump.py:7〕〔源: docs_local/docs/02-效果系统/魂印机制族聚类-调研.md §一〕。
因此批产协议 = **handler 按 effect_id 注册一次，行的 args 驱动每宠数值；实现必须读 args/行文，
禁止照抄任一行文本硬编码**〔源: docs_local/docs/05-任务清单/已收官/K组魂印批产工单.md:4-8〕。
行级数据的对行工具：`python3 tools/soul_effects_dump.py [effect_id…]`〔源: tools/soul_effects_dump.py:9-11〕。

### 1.2 双行变体：本体行 + 伙伴/进化行

同 id 双行多为「本体行+伙伴行/进化行」**同构互锚对**——两行同模板、参数档位递进
（888 row603/608：免疫反弹 3 次异常 + 攻击随机烧伤/冻伤/中毒，第二行 50%→60% 进化档，
args `3 3 2 50 1` vs `3 3 2 60 1`，2026-11-04 dump 现查）〔源: docs_local/docs/02-效果系统/魂印机制族聚类-调研-二期.md §二〕。
同类互锚对还有 1151（60%→70% 项羽）、1237（伙伴行）、1460/1470/1480/1805 等
〔源: docs_local/docs/02-效果系统/魂印机制族聚类-调研-二期.md §四.族B〕。
批产时两行同单互锚落地，防止单行硬编码把进化档做没了。

### 1.3 boss 尾注归属四读法

tips 的「boss」尾注有**四类措辞**，机器口径只有一类：

| 尾注措辞 | 行数/处置 | 口径 |
|---|---|---|
| 「boss无效」 | 1593 行 → `boss_invalid_effects.json`（1397 id） | 唯一有机器口径：boss 挑战对局节点不注册不执行 |
| 「boss有效」 | 反向标记，如 150 row2027 | 清单生成时**排除**、不进 boss_invalid |
| 「仅boss有效 / boss对战中」 | 同上排除（清单 note 明载） | 同上 |
| 「boss免疫」 | **仅 4 行**（357/360/644/738） | ⚠️ 无机器口径，两读法并存待 S4 裁决 |

〔源: docs_local/docs/06-交接/boss免疫尾注口径裁决-2026-10-21.md §二〕。
「boss免疫」按三证（官方语料战龙哈莫 opus / 官方清单 / 词频分布）应读作「boss 有效」
——谱尼 644 已按此落地（boss_invalid=false），而 357 的 K257 实现用了相反解读
（boss_invalid=true），两份实现并存、白班裁决未下〔源: docs_local/docs/06-交接/boss免疫尾注口径裁决-2026-10-21.md §一/§三〕。
引擎侧 `boss_invalid` 的实际作用点仅在 `is_boss_challenge`（boss **挑战对局**模式），
与「boss 精灵」是两件事：`src/entities/soul_mark_manager.cpp:450/486/533`（现查 2026-11-04，
裁决文档所记 :424/461/505 已漂移）〔源: docs_local/docs/06-交接/boss免疫尾注口径裁决-2026-10-21.md §三〕。

### 1.4 双注册空间：effect 1004 ≠ 魂印 1004

技能效果（SKILL_EFFECT，moves 空间）与魂印（SOUL_MARK/SOUL_PROGRAM，soul 空间）是
两个独立 id 空间：技能效果 1004（使用技能附加固伤）≠ 沧岚挂泪 soul mark 1004，
检索前先定空间〔源: docs_local/docs/00-组件导航/常识与工具速查.md §二〕。
同号双注册是常态而非事故：628/808/617/608/718 等宏在 effect_info（技能空间）都有同号
不同文的模板，魂印以 effect_icon tips 为权威〔源: docs_local/docs/05-任务清单/已收官/K组魂印批产工单.md:44-48〕。

## 三、行参绑定：bind 协议与 a.row 坑（支撑「行≠宏」的实现面）

1. **bind 协议**：`bind_soulmark_args` 把宿主注入 `args[0]=own / args[1]=opp / args[2]=主体槽
   host_slot`，**丢弃 DB 行参前两位**、`args[3..] = DB args[2:] 原样跟后`
   （函数体 src/entities/soul_mark_manager.cpp:376-389，注释 :370-375，现查 2026-11-04）

   传 `{0, 0, 参…}` 占位前两位〔源: docs_local/docs/02-效果系统/K系魂印实现形态-SOP.md §一〕。
