## 一、PP 模型：每技独立、上限随槽、消耗在"行动后收口"

### 1.1 每技独立 PP

- PP 挂在**技能槽**上而非宠物整体：`skills[skill_index].pp / maxPP`，一场战斗里
  每条技能各自计消耗、各自归零〔源: src/fsm/battleFsm.cpp:446-447〕。
- 特殊槽位：`pp == -1` 表示**无限 PP**，一切消耗与恢复原语都不碰它
  （消耗侧 `pp == -1` 直接返回 0〔源: src/fsm/battleFsm.cpp:451-452〕；
  恢复侧 pp_restore/pp_restore_slot 同样跳过〔源: include/primitives/battle_primitives.h:379-381〕
  〔源: include/primitives/battle_primitives.h:781-782〕）。
- 每侧两个出战位、每宠五技能槽——效果事件里的槽位编号即 0..4
  〔源: include/effects/event_center.h:108〕。

### 1.2 用技消耗时机：先手/后手各自的 After Action 收口

PP 的**用技消耗**不在出手前、不在伤害管线里，而是在每侧行动结束的 FSM 态收口：

- 先手方：`handle_BattleFirstAfterAction` → `consume_selected_skill_pp(battleContext, first_mover_id)`
  〔源: src/fsm/battleFsm.cpp:1937-1939〕；
- 后手方：`handle_BattleSecondAfterAction` → 同原语、second_mover_id
  〔源: src/fsm/battleFsm.cpp:2079-2081〕。

`consume_selected_skill_pp` 本体三道门（2026-11-04 现查）〔源: src/fsm/battleFsm.cpp:432-466〕：

| 门 | 字段/判据 | 语义 |
|---|---|---|
| 幂等门 | `ws.skill_pp_cost_consumed[robot_id]` 已置位 → 不再扣 | 同一侧一次行动只扣一次〔源: src/fsm/battleFsm.cpp:422-425〕 |
| 就绪门 | `ws.skill_resolution_ready[robot_id]` 未就绪 → 不扣 | 技能解析没完成不扣（拦截/失效路径不误扣）〔源: src/fsm/battleFsm.cpp:426-428〕 |
| 有效门 | `resolve_selected_skill_index(...) >= 0` | 没有可扣的已选技就不扣〔源: src/fsm/battleFsm.cpp:429-430〕 |

三道门前置封装在 `should_consume_skill_pp`〔源: src/fsm/battleFsm.cpp:419-434〕。
**扣减量 = `ws.skill_pp_cost_multiplier`**：每侧默认 1〔源: include/fsm/battleWorkspace.h:150〕
〔源: include/fsm/battleWorkspace.h:359〕，实际扣除 `min(当前 pp, 倍率)`、不为负
〔源: src/fsm/battleFsm.cpp:461-464〕——这是"PP 消耗翻倍/翻 5 倍/翻 20 倍"类效果
（§三·四）的挂载点。

### 1.3 两个非标准消耗：PP 反转与倍率归零

- **PP 反转**（魂印信号 `ctx->pp_reverse`，无为觉者 2260 线）：使用后
  `pp = maxPP - 原pp`（当前 PP 与已损失 PP 互换），PP=0 使用时反转为满；此时
  不走倍率扣减、返回变化量〔源: src/fsm/battleFsm.cpp:454-460〕。
  2260 现查三面齐（2026-11-05 S17）：effect_icon row 1862（pet 4661，tips 即「使用之后
  的PP值消耗改为反转当前PP值与已损失PP值」句）+ registry soul + 写入方定位
  soulmark_2260_pp_signals（ROUND_START 常驻修饰每回合重断言 pp_reverse/ignore_pp/
  force_execute_on_pp0 三信号）〔源: resources/soul_lib/wuxiang_2260.cpp:30-40〕
  〔源: tools/soul_effects_dump.py 2260（2026-11-05 现查 row 1862）〕。
- **倍率为 0 或当前 pp≤0**：不扣（免费行动）〔源: src/fsm/battleFsm.cpp:461-463〕。

## 二、PP 操作原语全表：效果侧增减的唯一合法通道

### 2.1 原语一栏

效果（魂印/技能宏/插件）动 PP 必须走原语，**禁止直写 `skills[i].pp`**——原语负责
发事件、跳无限槽、钳边界〔源: include/primitives/battle_primitives.h:769-773〕。

| 原语 | 签名要点 | 口径 | 出处 |
|---|---|---|---|
| `pp_reduce` | (ctx, target, amount) → SUCCESS/INVALID_PARAM | 降低目标方**所有技能** PP（clamp ≥0）；每槽各发一次 EVENT_PP_REDUCED。首刀用途：无相谛 700"先出手时降低对手所有PP"〔源: include/primitives/battle_primitives.h:758-767〕 |
| `pp_zero_slot` | (ctx, target, slot, actor=-1) | 清零目标**指定一个槽位**；"随机{0}项技能PP值归零"族专用；无限槽返回 INVALID_PARAM 且**不发事件**；实际归零（原值>0）才发事件〔源: include/primitives/battle_primitives.h:769-775〕 |
| `pp_restore` | (ctx, target, amount, only_empty) | 恢复目标**所有技能** PP：只补不削（clamp ≤ maxPP）、无限槽不参与、`only_empty=true` 只补 pp==0 的槽（亮节口径）；返回实际变化的槽位数。两载体（S17 落 id）：极渊DS-001 2414「20%令自身所有技能PP值+1」（only_empty=false）与无极圣武 2436 亮节「给对手 pp 为 0 的技能恢复 5 点」（only_empty=true）〔源: include/primitives/battle_primitives.h:777-785〕〔源: resources/soul_lib/jiyuan_ds001_4797.cpp:167-168〕〔源: resources/soul_lib/wuji_shengwu_4800.cpp:554-566〕 |
| `pp_restore_slot` | (ctx, side, pet_slot, skill_slot) | 恢复**到 maxPP**；三址寻址 (侧,宠槽,技槽)——换宠后 `getPet(side)` 已是新宠，出场 PP 转移链要恢复的是场下上只（精灵王线，2026-09-24）〔源: include/primitives/battle_primitives.h:377-381〕 |
| `pp_restore_points` | (ctx, target, slot, points) | 指定槽恢复**指定点数**（钳到 maxPP），返回实际恢复量〔源: include/primitives/battle_primitives.h:381-382〕 |
| 插件透出 | core_api 函数指针五件 | pp_reduce / pp_zero_slot / pp_restore / pp_restore_slot / pp_restore_points 全部对插件层透出〔源: include/plugin/core_api.h:125-140〕 |

**已知缺口——直接赋值原语缺失**：K405 的 2510「回合结束后所有技能 PP 随机重置为
m-n」没有"逐槽写值"原语，实现用 pp_zero + restore_points **组合逼近**，"随机重置"
语义的专用原语在内核缺口箱记档〔源: docs_local/docs/05-任务清单/已收官/K组魂印批产工单.md:276〕。

### 2.2 事件面：EVENT_PP_REDUCED

- 触发者：**只有效果侧**的 pp_reduce / pp_zero_slot；载荷 target=PP 变化方、
  actor=来源方（不带归因则 -1）、slot=0..4、amount=本次该槽减少量；逐槽各发一次
  （扫全槽时变化的槽才发）〔源: include/effects/event_center.h:106-110〕。
- 边界（易错）：**用技消耗**（§一 consume_selected_skill_pp）与**嗑药回 PP 不发**
  ——监听方语义是"被效果动了 PP"〔源: include/effects/event_center.h:110-112〕。
- 恢复侧**暂无事件**：pp_restore 注释明确 EVENT_PP_REDUCED 是"被削"语义，将来出现
  "被恢复 PP 时响应"类效果再补 EVENT_PP_RESTORED〔源: include/primitives/battle_primitives.h:783-785〕。
- 效果注册侧的类型位：`PpReduce`（param0=每技能减 N 点 PP）〔源: include/effects/effect_unit.h:23〕。
- **直写绕过缺口**：`直写 skills[i].pp 绕过原语 = 绕过事件`，存量直写点待逐步收编
  〔源: include/effects/event_center.h:111-112〕。

### 2.3 官方模板句 → 引擎原语对照表

官方效果模板句（effect_info.info 的 {n} 句式）与引擎原语并非一一对应——同一句式
可能落在不同原语上，逐条对照如下（模板句与实现文件均为 2026-11-04 现查）：

| 官方模板句（节选） | 落点原语 | 依据 |
|---|---|---|
| 「使对手所有技能PP值减少{0}点」（848/1430 全技减量侧） | pp_reduce（全槽扫、逐槽发事件） | 〔源: include/primitives/battle_primitives.h:763-767〕〔源: docs_local/docs/05-任务清单/已收官/K组魂印批产工单.md:269〕 |
| 「{0}%令对手随机{1}项技能PP值归零」（1519 族） | pp_zero_slot（单槽清零；随机选槽在效果层抽，原语只管清） | 〔源: include/primitives/battle_primitives.h:769-775〕〔源: resources/moves_lib/j_chance_drop_pp_zero.cpp:10-16〕 |
| 「所有技能PP值+{0}」/「给 pp 为 0 的技能恢复」 | pp_restore（only_empty 两档口径） | 〔源: include/primitives/battle_primitives.h:777-785〕 |
| 「随机重置为 m-n」（2510） | **无专用原语**：pp_zero_slot + pp_restore_points 组合逼近，缺口箱记档 | 〔源: docs_local/docs/05-任务清单/已收官/K组魂印批产工单.md:276〕 |
| 「当回合用技PP消耗{0}倍」（1780/1935 主动切换） | 不动存量 pp，写 `ws.skill_pp_cost_multiplier` 改**下一次**消耗量 | 〔源: include/fsm/battleWorkspace.h:359〕〔源: src/fsm/battleFsm.cpp:461-464〕 |
| 「使用后 PP 反转」（无为觉者线） | 消耗原语内分支 `ctx->pp_reverse`（pp = maxPP - 原pp） | 〔源: src/fsm/battleFsm.cpp:454-460〕 |

对照表的读法：**"改存量"与"改消耗"是两条不同的轨**——前者动 `skills[i].pp` 走
原语+事件；后者动倍率/反转信号，在消耗收口（§1.2）一次性生效。混写两条轨是
PP 类效果最常见的实现事故。

## 四、贯穿案例：场景 7520——PP 断言如何做到"无随机精确"

PP 效果多半带概率（"50%…""随机 1 项"），照 S6 范式给一个可复现的实测案例，
看验证通道怎么把概率钉成确定值（K398 首批单文件 21 块 538 断言的口径来源）：

- **概率不裸断**：759 的"回合开始 50% 先制+2"不用概率断言——审计槽（990398100 段）
  记逐回合掷点，断言写"掷点 → 先手权/preemptive_level 精确值"，另跑 40 回合
  统计带侧证 [12,28]（期望 20）〔源: 场景7520:6-9〕〔源: docs_local/docs/05-任务清单/已收官/K组魂印批产工单.md:269〕。
- **随机归零也不裸断**：场景造"双方 NONE 回合"（不耗 PP、无 accuracy 掷），
  把 PP 状态钉住后断言「恰好 N 槽归零 / 全技-N」〔源: 场景7520:11-12〕。
  这依赖 §1.1 的模型事实：消耗在 After Action 收口且 NONE 回合不触发
  （§1.2），否则断言会被用技消耗污染。
