## 一、全景：11 个阶段与它们的出处

引擎阶段序（`DamagePipeline::kOrder`，`kPhaseCount=11`）〔源: include/effects/damage_pipeline.h:109,159-171〕：

```
GUARD_DETECT → AMP → AMP_EXTRA → REDUCE_TRAIT → REDUCE_FLAT → REDUCE_PCT
  → FLOOR → CAP → BLOCK → DETECT → FINAL_CORRECT
```

这个顺序不是拍脑袋，是**两条官方口径的合并**（2026-09-14 用户逐条确认）〔源: include/effects/damage_pipeline.h:22-26〕：

- **时点链**（官方原文 L345《关于693增伤，护盾和保底伤害》）：
  「当前时点为**犀牛魂印—通用增伤—693增伤—保底伤害—护盾（从先到后）**」〔源: 官方原文 L345〕
- **减伤区固定顺序**（官方原文 L402《bug修复解读 2024.1.5》）：
  「分出增伤区、减伤区，不再进行相互穿插。减伤顺序将固定为：
  **点数减伤——百分比减伤——伤害锁定——伤害免疫**」〔源: 官方原文 L402〕
- 辅以官方原文 L254：「坚硬是靠前的减伤，乘法计算，**时点早于保底伤害**」→ 保底在减伤之后〔源: 官方原文 L254〕。

**版本演化（易踩的口径坑）**：2026-09-14 首版落地为 **10 阶段**（场景 045 头注至今仍写
10 阶段序）〔源: 场景045 头注：10-15 行〕；2026-09-15 在 AMP_EXTRA 与 REDUCE_FLAT 之间
新增通用特性阶段 **REDUCE_TRAIT**（坚硬），变 11 阶段〔源: include/effects/damage_pipeline.h:28-30〕。
场景 045 的代码用 `kPhaseCount` 自适应所以仍绿，但其头注/收官日志文本未同步
〔源: 场景045:368-371〕——**引用旧文档的"10 阶段"表述时以 11 阶段为准**。

`kOrder` 是**一个可改常量**：实测口径若有出入，改一行顺序即可，不用动任何回调
〔源: include/effects/damage_pipeline.h:35〕。

## 二、逐阶段详解

> 每阶段四件套：**谁注册**（引擎落点）→ **读到什么值** → **实战案例** → 源。
> 执行方式：walk 按阶段序走，**每阶段内先攻击方桶、再防守方桶**〔源: include/effects/damage_pipeline.h:131-133〕；
> 效果通过 `ctx->resolvedDamage` 读写当前伤害值〔源: include/effects/damage_pipeline.h:99〕。
> 写探针/效果的常见坑：防守方的减伤跑在 **owner 1（防守方）**的桶里——挂 owner 0
> 会把减伤观测点整体前移一格〔源: 场景045:69-74〕。

### 阶段 1 · GUARD_DETECT（高伤检测——"犀牛位"）

- **谁注册**：内核 `install_default_damage_guard_detect`，在管线第一位把判定值写进
  链首快照 `ws.guard_detect_damage`；魂印 1217（不灭地威·萨瑞卡，effect_icon pet_id=[3637]）
  的两分支（>350 回满 / <350 反弹 50% 固伤）消费这个快照〔源: 场景049 头注〕。
- **读到什么值**：**未增伤**的裸伤——**已含暴击与暴击抗性减免，未含任何增伤/减伤**
  〔源: 场景049 头注〕。放链首是刻意的：让"之后才发生的增伤/保底"穿过它
  〔源: include/effects/damage_pipeline.h:101-102〕。
- **实战案例**：见 §三 案例一（693 乱穿犀牛）与案例二（保底不触发回满）。
- **阈值口径**：官方魂印原文「受到的攻击伤害**大于350**则恢复自身所有体力，**小于350**
  则反弹给对手造成伤害50%的固定伤害」〔源: 场景049 头注引魂印原文〕；
  官方机制解析文写的是「剩余的体力值是否大于**340/350**」（瞬杀免疫语境，两数并列）
  〔源: 官方原文 L443《机制解析—瞬杀》〕；引擎取 **350**〔源: 场景049 R3 断言〕。
  350 阈值的文本出处：`reference/archive/技能与断回合.txt` 不灭地威·萨瑞卡
  「受到超过350红伤恢复自身所有体力」〔源: docs_local/docs/05-任务清单/待做-变威力与增减伤时点.md §3.4〕。
- **暴击参与判定的证据链**：必暴把 ~250 顶到 ~500 → 照样回满（检测含暴击，R4）；
  必暴 + 35% 暴击抗性 → 链首值 ~331 <350 → 不回满（暴击抗性参与判定，R5）；
  必暴 + 100% 暴击抗性 → 伤害归 0、不回满也不反弹（抗性**乘整段**，R6）
  〔源: 场景049 R4/R5/R6 断言〕。

### 阶段 2 · AMP（通用增伤——加法）

- **谁注册**：效果在 SKILL_EFFECT 时点写 `ws.damage_add_pct[attacker]`（攻击方槽），
  "造成攻击伤害提升X%"一族〔源: 场景045:112 + 官方原文 L352〕。
- **读到什么值**：**加法**汇总——两条 +50 合计 +100 → ×2.0，**不是** ×2.25
  〔源: 场景045 P2 断言 + 官方原文 L352「所有的通用增伤加法计算」〕。
- **实战案例**：场景 045 P2/P4——通用 +100% 与 693 各 ×2 → 合计 ×4，且 AMP 探针
  看到的是"只施加了通用增伤"的中间值〔源: 场景045 P4 断言〕。
- **上限**：L351 关于「通用减伤…超过100%…失效」是减伤区的历史描述，不是增伤
  上限证据；减伤溢出 bug 已修的用户澄清见 §二.6〔源: 官方原文 L351〕。
  增伤区引擎落码**无上限钳制**——AMP 默认回调对
  `ws.damage_add_pct` 直接 `checked_pct_mul`（×(100+pct)/100），唯一保护是
  int 溢出响亮 throw（实际对局触不到），与减伤区加算槽"钳 ±100%"形成对照
  〔源: src/fsm/battleContext.cpp install_default_damage_amp +
  include/numerical-calculation/calculation.h:18-32〕；
  场景 7760 实证 +250% 精确 ×3.5、+10000% 精确 ×101 直通
  〔源: 场景7760 A1/A2 断言〕。

### 阶段 3 · AMP_EXTRA（非通用增伤——乘法，693 位）

- **谁注册**：写 `ws.damage_add_extra_mul[attacker][槽]`，"造成攻击伤害**额外**提升X%"
  一族；**判据 = 文本里的"额外"二字**。693 在此；"精神"（特攻门控增伤）也在此阶段
  〔源: include/effects/damage_pipeline.h:47 + 场景045:113-114 + 官方原文 L352〕。
  776「翻倍」不带"额外" → 留在加法通道（AMP）〔源: docs_local/docs/05-任务清单/待做-变威力与增减伤时点.md §3〕。
- **读到什么值**：**乘法**连乘——两条 50% → ×1.5×1.5 = ×2.25 ≠ ×2.0
  〔源: 场景045 P3 断言〕。
- **实战案例**：案例一（§三）。
- **为什么会乱穿犀牛**：官方修复史——693 原本会被变威力覆盖，策划把增伤时点后挪
  避免覆盖，结果挪到**犀牛挡伤时点之后** →「693增伤乱穿犀牛」〔源: 官方原文 L348〕。

### 阶段 4 · REDUCE_TRAIT（通用特性·坚硬）

- **谁注册**：2026-09-15 新增（new_se stat=1 的通用特性，见 effects/trait_state.h）；
  坚硬落在此处〔源: include/effects/damage_pipeline.h:28-30〕。
- **读到什么值**：**乘法**减伤；**非**通用减伤区成员、时点早于保底（官方原文 L254）、
  **只免红伤**〔源: include/effects/damage_pipeline.h:48〕。
- **为什么单列**：若并入 REDUCE_PCT，"坚硬 × 保底"的先后就说不清了——官方明确
  坚硬早于保底，而通用减伤区整体也在保底之前，但坚硬是特性不是减伤效果，
  官方把它单独点名〔源: 官方原文 L254〕。
- **实战案例**：场景 054（通用特性·坚硬+精神专属场景）——H1 坚硬 3 星红伤 ×0.90、
  H2 args 故意填 DB 错值 7 而实际按语料修正表 8%（防回归成"读 args"）、
  H3 坚硬先于 REDUCE_PCT（(base×0.9)×0.5 可区分）、H4 不免粉伤；乘数档 =
  语料修正表 5/6/8/10/9/10%（坚硬是"官方读数错误"的唯一特性）
  〔源: 场景054 头注与 H1/H2/H3/H4 断言〕。同类消费：hamo_wing_family 两处 REDUCE_TRAIT
  注册（乘法、早于减伤区、回调实时读体力/层数）
  〔源: resources/soul_lib/hamo_wing_family.cpp:52,130-142〕。

### 阶段 5 · REDUCE_FLAT（点数减伤）

- **谁注册**：写 `ws.damage_reduce_flat[defender][槽]`，"受到的伤害减少N点"一族
  〔源: 场景045:115〕。
- **读到什么值**：直接减点数；**排在百分比减伤之前**——先扣点数、再按扣完的值打折
  〔源: 官方原文 L402 + 场景045 P5 断言〕。
- **实战案例**：场景 045 P5——裸伤先 -5 再 ×50%，与反序 (×50% 再 -5) 数值可区分；
  断言锁死正序〔源: 场景045 P5 断言〕。
- **同类不同位的官方判例**（时点离散）：「吉罗德的第五减伤300会被变威力无视，但
  龙裳的魂印减伤300不会被变威力无视——一个在变威力之前，一个在变威力之后」
  〔源: 官方原文 L351〕。2026-11-05 清缴复核 L351 全文：点数减伤时点"特别零散"，
  逐效果时点表在官方外部表格（docs.qq.com，库内语料不含）→ 此类"变威力前点减"
  **确需独立时点**；引擎变威力重算在管线之前（apply_variable_power_recalc），统一放
  REDUCE_FLAT 即"变威力后"口径——首个变威力前载体（吉罗德第五减伤未入库）落地时，
  需在 stage_simple_attack_damage 之前挂管线外点减，引擎现状无此槽位
  〔源: 官方原文 L351 + 场景045 头注（变威力在管线前）〕。

### 阶段 6 · REDUCE_PCT（百分比减伤）

- **谁注册**：写 `ws.damage_reduce_add[defender]`（加算槽）与
  `ws.damage_reduce_mul[defender]`（乘算槽）〔源: 场景045:106-117〕；
  魂印侧 K1 族 3/254/280/317 等"减伤%"宏也消费此阶段（红伤）
  〔源: resources/soul_lib/k_guard_family.cpp:5-19〕。
- **读到什么值**：**加算槽求和后钳 ±100%，乘算槽连乘**〔源: include/effects/damage_pipeline.h:50〕。
- **实战案例（钳制）**：加算 150% → 钳到 100% → 伤害 0，**不溢出成负数**（P9）；
  加算 100% × 乘算 100% → 仍 0（P9 第二段）〔源: 场景045 P9 断言〕。
- **用户澄清与旧裁决勘误（2026-11-06）**：官方减伤叠加溢出**曾是 bug，后已修复**；
  不能继续把旧文的「失效」当作普遍的现行官方原则。已知现代引擎有钳制；本地当前
  `applyDamageReduction` 的加算槽钳 ±100、P9 的 150%→0 伤害是既有实现/场景记录，
  **不是本轮新定的官方数值算法**，本轮未改数值、未对拍
  〔源: src/fsm/battleContext.cpp REDUCE_PCT 注册点 +
  include/numerical-calculation/calculation.h:97-121〕。
  **历史证据保留**：L351 写「叠加超过100%时…失效」，L432 写「叠加到100%…失效」
  并称「机制保护效果」〔源: 官方原文 L351〕〔源: 官方原文 L432〕。
  S28 曾据二者及其它回绕案例作「文本侧定向=失效 / 与引擎钳法分歧」裁决；该裁决
  经用户澄清撤回，不再以「防常驻免伤」或其它数值回绕作类比推导。若后续核对具体
  引擎数值，应另行取得修复后版本证据并走授权验收，不能凭旧帖直接改算法；见 §五 原#4。

### 阶段 7 · FLOOR（保底伤害）

- **谁注册**：内核默认回调 `install_default_damage_floor` 已落地——effect 447 族
  "造成的伤害不少于{0}"（131 技；`ws.damage_floor[attackerId]` 在 SKILL_EFFECT 写入）
  〔源: src/fsm/battleContext.cpp install_default_damage_floor +
  resources/moves_lib/damage_modifier.cpp:330〕；沸涌 36（effect_des 304「受到的
  攻击伤害至少为其最大体力的30%，对手打出致命一击时效果提升至50%」）在内核 FLOOR
  守方桶注册（crit 分档、与 447 并存取 max 语义）〔源: src/fsm/battleContext.cpp
  install_default_abnormal_mods FLOOR 段〕；插件侧另有咒怨层数>5 一次性保底等注册
  〔源: resources/moves_lib/d_fifth_skills.cpp FLOOR 段〕。
  （2026-09 首版曾"零注册、探针演示"，场景 045 头注为旧态记档。）
- **读到什么值**：减伤之后的值；保底把伤害**抬**到下限。位置 = 减伤之后、锁伤之前
  〔源: 官方原文 L254（保底在减伤后）+ 场景045 P6 断言〕。
- **实战案例**：场景 045 P6——守方减伤 50% 把伤害打到 <60 → FLOOR 抬到 60 →
  CAP 再锁到 40（锁伤最后说话）。若保底在减伤之前，会得 30 而不是 40〔源: 场景045 P6 断言〕。
- **结构性推论**：保底在 GUARD_DETECT 之后 → **保底抬起来的伤害不触发犀牛超350回满**
  （用户口径：保底不触发犀牛回满〔源: 场景045:10-11〕）——见案例二。

### 阶段 8 · CAP（伤害锁定）

- **谁注册**：阶段在、内核零默认回调；**锁伤的具体效果在魂印插件里**——
  K1 的 766（格罗姆特 3107「受伤不超过260」/ 观星派派 4836「受伤不超过400」）
  是管线 CAP 阶段**首批消费者**〔源: include/effects/damage_pipeline.h:37-40 +
  resources/soul_lib/k_guard_family.cpp:20-24〕；K392 的 928/1191/1938（受伤 ≤ maxHP/2）
  是第二批〔源: resources/soul_lib/k_damage_cap2.cpp:43-44〕；K394 双领域
  （机械领域 CAP 60% / 次元领域封回血，1780/1935）按档位差消费
  〔源: resources/soul_lib/k_dual_domain.cpp:9-15〕。
- **读到什么值**：保底之后的值；**最后再拦一次**（没穿锁伤凭证的话）
  〔源: include/effects/damage_pipeline.h:19,52〕。
- **实战案例**：案例三（§三，697 凭证穿锁伤）。
- **断言口径**（写场景必读）：锁伤断言用**精确值**（loss == maxHP/2——钳制剪掉随机
  浮动带）；697 穿透用区间（loss > cap 且存活）〔源: 场景7450 头注〕。

### 阶段 9 · BLOCK（挡伤/免伤归零）

- **谁注册**：`install_default_damage_block`（次数型免伤的 `consume_immune` 扣次）、
  "免疫下1次攻击伤害"、概率挡伤（effect 525）等〔源: docs_local/docs/02-效果系统/技能判定流程与无效效果体系.md §8.7〕；
  免致命族（K1 的 150：万魔天尊 50%/圣婴圣皇 35%/保姆派派 60%）也落 BLOCK 票
  （isCrit 门 + 概率）〔源: resources/soul_lib/k_guard_family.cpp:10-11〕。
- **读到什么值**：前面的最终值；命中即**整段归零**。连击 N=3 的攻击挂"免疫下1次"
  时**整段归零**——这是"一次公式 ×N"与"N 次独立结算"的分水岭〔源: 场景044 C6 断言〕。
- **与减伤的类别隔离**：官方口径"使对手挡伤失效"只废归零类，**减伤不被无视**
  （「减伤100%、点数减伤全都是不能被无视的效果」）〔源: include/effects/damage_pipeline.h:61-63〕。

### 阶段 10 · DETECT（受击检测/触发）

- **谁注册**：反伤、附伤等"受击后触发"类。注意：**犀牛的反弹不在这里**——它挂
  `EVENT_TAKE_DAMAGE`（伤害落地之后），因为 `_AFTER_ACTION` 类时点桶只跑当回合
  mover 一侧，犀牛作为非 mover 不执行（谱尼虚无同款坑）〔源: 场景049 头注〕。
- **可被抑制**：DETECT 是独立类别，会被"挡伤失效"掩码一并压制〔源: 场景045 P8 断言〕。

### 阶段 11 · FINAL_CORRECT（最终修正）

- **谁注册**："归零/不可击穿的锁伤"——比 CAP 更靠后的终审位〔源: include/effects/damage_pipeline.h:20,55〕。
- **实战案例**：暂无已实现效果（2026-11-05 复核：全库 grep `DamagePhase::FINAL_CORRECT`
  零消费者）。哪个官方效果属于"无法被击穿的锁伤"（与 CAP 的区别 = 697 凭证是否
  还能穿）**见 §五清单#6**（与清单同题，不再行内重复挂 ⚠）——2026-11-05 语料全量
  检索（无视伤害限制/穿锁伤/无法击穿族）为**负结果**：L473《挡伤/锁伤》枚举的
  全部锁伤均可被穿透（套装增伤 ×1.3/×1.6、龙哈式增伤、常妈/机王威力叠加、697 族，
  "其他锁伤均为同理"），未见"穿不掉"的锁伤描述 → 阶段保持零消费占位，官方实例
  待新精灵语料〔源: 官方原文 L473（锁伤节）〕。

### 类别抑制：蚀砚之泪与 suppress_mask

四类 `DamageEffectCategory`：AMP（进攻增伤）/ MITIGATE（减伤/保底/锁伤，**不可被
"挡伤失效"无视**）/ BLOCK（挡伤归零，可被无视）/ DETECT（受击检测，可被无视）
〔源: include/effects/damage_pipeline.h:70-75〕。
怒涛·沧岚"蚀砚之泪≥4滴" = 置对手 `damage_suppress_mask |= BLOCK|DETECT`，
walk 时跳过被抑制类别的所有条目；新效果声明类别即可被同类抑制自动覆盖，无两两硬编码
〔源: include/effects/damage_pipeline.h:65-68〕。
实测：压制后 guard/block/detect 探针计数全 0，减伤与增伤探针计数仍 1
〔源: 场景045 P8 断言〕。

### 注册生命周期：切换清、断回合不清

条目带 `valid_id`（注册时该方的 `pipeline_valid_id[owner]`）——换宠后不匹配即惰性失效；
`team=true` 的条目（队伍被动/绑定对手的印记）不受切换影响。**刻意不复用**
`round_effect_valid_id`：**断回合不该清管线条目**（管线的执行周期在一次效果执行的内部，
那时不会有断回合；"管线既然跑到了，就说明这个效果当下是有效的"）
〔源: include/effects/damage_pipeline.h:80-91〕。

## 三、三个贯穿案例（真实数值演算）

### 案例一：693 乱穿犀牛（场景 049 R2）

**面板**（K393 校准后）：攻方 atk=375、全力一击（10033，物理 power 120、必中）；
守方不灭地威·萨瑞卡（魂印 1217），HP 3000，回合开始魂印已把守方防御推到 150、
攻方速度 600→400 / 守方 100→150（攻方仍先手）〔源: 场景049:42-46〕。

1. **裸伤公式**：0.84×375/150×120+2 = 254；×浮动 [0.85,1.0] → **~216~254**，
   稳在 350 以下〔源: 场景049:104〕。
2. **链首**：犀牛 GUARD_DETECT 看到 ~216~254 <350 → 走**反弹分支**（反弹链首值 50%
   固定伤害给攻方），不回满〔源: 场景049 R1 断言〕。
3. **693 生效**：「造成攻击伤害**额外**提升100%」（args {0,1,1,100}）在 AMP_EXTRA
   把实际伤害 ×2 → **~432~508 >350**〔源: 场景049 R2 断言〕。
4. **结局**：实际伤害过 350，但犀牛**不回满**——它的检测早于 693，看不到被顶起来的
   伤害〔源: 场景049 R2 断言〕。这就是官方修复史里那个「挪动到犀牛的挡伤时点之后，
   于是出现了 693增伤乱穿犀牛」的现象〔源: 官方原文 L348〕。

**官方算例对照**（L347）：攻击伤害 300、增伤 50%、护盾 200——修复前 300×1.5-200=250；
修复后（300-200）×1.5=150〔源: 官方原文 L347〕。引擎里护盾还在管线之后
（见 §四.4），故引擎只复刻了"693 在犀牛之后"这半边。

### 案例二：保底不触发"超350回满"（场景 045 P6/P7 探针演算）

- **机制**：保底（FLOOR）在 GUARD_DETECT **之后**才把伤害抬起来——链首快照永远
  看不到保底值〔源: include/effects/damage_pipeline.h:18 + 场景045 P7 断言〕。
- **演算**（场景 045 P6 探针）：守方百分比减伤 50% → 减伤后 reduced<60；
  FLOOR 探针把伤害抬到 60；CAP 探针再锁到 40。断言序列 `reduced<60 → FLOOR=60 →
  CAP=40`，且若把保底挪到减伤之前会得 30≠40——位置由此钉死〔源: 场景045 P6 断言〕。
- **对到实战**：犀牛对局里，攻方哪怕有"保底 1000 伤害"的魂印，犀牛的检测值
  （裸伤）没过 350 就照样走反弹分支——保底**不触发**超350回满〔源: 场景045:10-11 +
  场景049 头注〕。
- **注意**：本案例由探针演示（锁的是**阶段顺序**，不是某个精灵）
  〔源: 场景045:17-18〕。真实保底已落地并有端到端场景：沸涌 36 把攻击伤保底到
  30% 最大体力精确断言（场景 097 D 块）、effect 447 族光箭攻击 12546
  `ws.damage_floor` 直写（场景 820）
  〔源: 场景097 D 块断言 + test/scenario/scenario_820_residue_family.cpp〕。

### 案例三：697 凭证穿锁伤（K1/K392/K394 三处消费实证）

## 四、管线之外：五条边界（读机制前先对表）

1. **变威力重算在管线之前，管线只跑一遍**。落点 `apply_variable_power_recalc`：
   ATTACK_DAMAGE 桶之后、`damage_pipeline_.run()` 之前；若 `ws.skill_power_view`
   带 rewritten 标记就重跑一次 `stage_simple_attack_damage`（覆盖式）。管线不重跑，
   所以次数免伤不重复扣、概率挡伤不重掷、粉伤不重打〔源: docs_local/docs/02-效果系统/技能判定流程与无效效果体系.md §8.7 + 场景043 头注〕。
   官方定义：「当命中效果对技能威力值进行修改时，会以当前状态重新进行伤害结算覆盖
   原本的伤害值」〔源: 官方原文 L128〕；「提升0点威力也属于变威力」〔源: 官方原文 L453〕。
   连击同理：N>1 本身即变威力 → 连击吃得到暴击破防（044 C4：必暴+防+2 时 N=3 ≈ N=1
   的 6 倍 = 3×连击 × 2×破防）〔源: 场景044 C4 断言 + 技能判定流程§8.8〕。
2. **打盔（技能无效）时管线整段不跑**。`handle_*_AttackDamage` 早退 → 次数型减伤/
   免伤**天然不被消耗**——官方「打盔是不会消耗点数减伤，既然不消耗那自然也不会触发」
   〔源: include/effects/damage_pipeline.h:104-105 + 官方原文 L54〕。
   例外：带变威力词条的技能被打盔时，effect 2501 类效果改写视图威力 → 走早退出口的
   变威力检查点 → **隔着盔打出红伤**（「变威力结算过于靠后，因此可以隔着盔打出攻击
   伤害」〔源: 官方原文 L390〕）；无变威力词条则零伤害〔源: 场景046 V1/V4 断言〕。
3. **粉伤是另一条管线**，不进红伤 11 阶段。粉伤管线 `PinkDamagePipeline` 自带
   10 阶段（RESIST → IMMUNE → REDUCE_EXTRA → AMP → PINK_TO_HOOD → PINK_TO_TRUE_IMMUNE
   → CAP → HOOD → PINK_TO_TRUE_UNHARMED → FINAL），一段 = 一次 `deal_pink_damage`
   调用、逐段独立结算取整〔源: include/effects/pink_damage_pipeline.h:126-137,162〕。
   （2026-09-14 的旧记档写「粉伤通道完全不过管线」〔源: docs_local/docs/05-任务清单/待做-变威力与增减伤时点.md §3〕，
   指的是不过**红伤**管线；粉伤此后有了自己的管线，引用旧表述时注意。）
   免粉票挂在粉管 IMMUNE 阶段，与红伤挡伤同一条 RuleCenter 路；**次数型免粉只挡一段**
   〔源: include/effects/rule_center.h:50-58〕。
4. **护盾/护罩仍在 deal_damage（管线之后）**。官方四源对照（2026-11-05 清缴复核）：
   L345 是唯一直接实测帖——「经测试下来，最终结论为……**护盾时点依旧没有改动**」，
   链=犀牛魂印—通用增伤—693增伤—保底伤害—护盾（护盾末位）；L269 是**体验服规划**
   （「点数减伤—百分比减伤—护盾/护罩」，自述"体验服还没改完"）；L347 算例
   （修复后 (300-200)×1.5=150，护盾先于增伤）为挪前前瞻分析、被 L345 实测链覆盖；
   L351「当前的护盾节点在通用减伤之前」同为挪前旧态描述。引擎护盾留 deal_damage
   （管线后）与 L345 实测链一致 → **不挪进管线**；跟踪项 = 体验服挪动正式服落地后
   复查本节〔源: 官方原文 L345/L269/L347/L351 +
   include/effects/damage_pipeline.h:40-42〕。
5. **属性伤害不走全管线**。`run(phase_mask)` 只跑掩码里的阶段——属性伤害只吃
   锁伤/挡伤类阶段，不吃攻击伤害的增·减伤〔源: include/effects/damage_pipeline.h:136-138〕。
   另：属性技（category=4）本身无伤害阶段，完全不掉血、不进管线〔源: 速查§五〕。
