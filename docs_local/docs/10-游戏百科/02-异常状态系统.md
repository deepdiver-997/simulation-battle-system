**衍化的两条铁纪律**：

1. **衍化不走 `apply_anomaly`**。官方语义是"同一异常改变了形态"（语料 idx=59：
   「精灵还是算作处于异常，可以正常触发某些'处于异常则xx'效果」）——走新施加会重跑
   免疫/抗性/转化/弹控全链，"冰封→冻伤"会被目标的冻伤免疫挡掉，与官方相反
   〔源: include/primitives/battle_primitives.h:247-252〕。
2. **衍化附带的弱化无视任何免弱**（语料 idx=37「异常转化为弱化会无视免弱」、
   idx=466「不能免疫异常带来的弱化（焚烬，冰封，感染）」）→ 落地用
   `stat_drop_piercing` 穿透版弱化〔源: include/abnormal-system/abnormal-types.h:394-396 +
   include/primitives/battle_primitives.h:253〕。

**衍化在什么时候发生**：异常自然结算点 `tick_abnormal_statuses`——顺序依官方
idx=59「回合结束时**先转化异常，再回合扣减**」与 idx=429《时点表》（沉默/束缚/
烈焰诅咒均在该时点结算）：①回合扣减点档伤害（仍在生效的沉默 30/烈焰诅咒 24）→
②到期项："…结束时"档伤害（束缚 28）→ 衍化 → ③过期回写清槽
〔源: include/primitives/battle_primitives.h:233-246〕。
这个时点存在的理由：引擎的异常过期原本是**纯读比较**（`roundCount < end_round`，
从不清槽），"到期的瞬间"不存在，衍化无处落脚——`tick` 补上了它
〔源: include/primitives/battle_primitives.h:228-232〕。

## 四、四通道：施加 / 免疫 / 清除 / 反弹

### 4.1 施加通道——三原语与一条检查链

**三个原语 = 三条不同的检查链**（2026-09-16 双通道口径，用户拍板 + 语料
《浅谈主动毒与魂印免控判定》）〔源: include/primitives/battle_primitives.h:44-61〕：

| 原语 | 通道 | 检查链 | 适用 |
|---|---|---|---|
| `apply_anomaly` | Modern 现代 | **全链**：次免/回合类免疫 → 弹控反弹 → 异常抗性 → 魂免 → 转化 → 落地 | 参数化模板族（"「{0}%令对手{1}」×100+ 条模板"，主流）〔源: include/primitives/battle_primitives.h:46-50,72-74〕 |
| `apply_anomaly_ancient` | Ancient 古早（**主动毒**） | **只查 ImmunityTier::Ancient 层免疫**；跳过异常抗性与转化；对一切弹控不可见（不反弹） | 古早"命中后{0}%令对方XX"模板族（effect 10/11/12/14/15/114）+ 通用特性接触施加（Eid 6/66/67）〔源: include/primitives/battle_primitives.h:105-118〕 |
| `apply_anomaly_raw` | Raw 遗留裸施加 | **什么都不检测**——免疫（含 Ancient 层）/弹控/抗性/转化全穿，直接落地 | 带电/高热/冰冷/阴森特性被动毒专用〔源: include/primitives/battle_primitives.h:127-136〕 |

- **为什么分代**：数据库证据——施加模板分两代（古早"写死异常名"族 vs 现代
  参数化族），官方运行时走不同施加例程 → 对免疫/抗性/转化的可见性不同。
  官方侧**无字段区分**这两代 → 通道由施加方效果的实现选择调用哪个原语表达，
  这是**认证数据层的解释，不是官方数据的事实**〔源: include/primitives/battle_primitives.h:46-54〕。
- **首消费实证**：K2 概率异常族（effect 114/262/265/306/358/662）——114 暗黑鲁斯王
  10% 冻伤走 **Ancient 通道**（核心 API 注释点名的古早模板族之一），262/265/306/358
  走 Modern 全链〔源: resources/soul_lib/k_anomaly_chance.cpp:1-15〕。
- **施加结果十二档**：`ApplyAnomalyResult`——SUCCESS / TARGET_IMMUNE /
  BLOCKED_BY_EFFECT / TARGET_DEFEATED / INVALID_PARAM / REPLACED_EXISTING /
  DURATION_EXTENDED / RESISTED_BY_RESISTANCE / REFLECTED / CONVERTED /
  **ROLL_FAILED**〔源: include/primitives/battle_primitives.h:27-42〕。
  **ROLL_FAILED 是"概率没过门"，与"被免疫/被抗性"是不同的档**——官方"未触发则…"
  补偿子句认的就是这一档；只有调用方**申报了概率**（chance_pct>=0）才可能出现
  〔源: include/primitives/battle_primitives.h:38-41〕。
- **概率申报协议**（2026-09-22）：`chance_pct<0`=未申报（闸门不介入，旧调用点行为
  不变）；`>=0`=申报——原语**先问概率闸门**（亮节族改写）、**再掷一次**
  （0→必不触发、>=100→必触发均不耗 rand，其余一次 `sbs_rand()%100`）。
  掷点必须在闸门之后：官方"以实际概率为准"判的是本次实际值
  〔源: include/primitives/battle_primitives.h:81-90〕。
  闸门管辖面按来源过滤：亮节四类全管（套装/特性/魂印/技能）、永沐不含特性
  主动毒/被动毒——所以来源必须是可查数据 `ChanceSource`〔源: include/effects/rule_center.h:80-97〕。
- **实战纪律**：掷点收口在内核闸门（`apply_anomaly_checked`），插件不得本地
  `roll_percent` 再调原语——审计面与掷点单一来源；K172 808 / K396 全族同款先例
  〔源: resources/soul_lib/k_prob_compensate.cpp:31-32〕。
- **未触发补偿的落地读法**：概率带行 = ROLL_FAILED 单档；无概率字面的"必定"句
  （如 1040 满体受击害怕）= "未落地（免怕/抗性等）即补偿"读法——两读法并集
  〔源: resources/soul_lib/k_prob_compensate.cpp:29-33 + resources/soul_lib/k400_anomaly_offense_defense.cpp 口径①〕。

**随机异常附加**（"随机附加{0}种异常状态"模板族）——`attach_random_anomalies`
三步全收口〔源: include/primitives/battle_primitives.h:174-183〕：

1. **解析池**：base_pool ⊕ 池改写票（RuleCenter ANOMALY_POOL_MOD，授予序折叠）——
   改在掷骰之前（改的是池本身），与掷出后转化（anomaly_conversion）分两层
   〔源: include/primitives/battle_primitives.h:177-179〕；
2. **概率门**：**整个子句掷一次**（官方"{0}%令对手随机进入…"是子句级判定）
   〔源: include/primitives/battle_primitives.h:180-181〕；
3. **挑选 + 施加**：从有效池**不重复**挑 requested 个，逐个走 `apply_anomaly`
   （现代单入口，免疫/抗性/弹控/转化/凝滞免控/次免消耗全继承，**绝不直写**）
   〔源: include/primitives/battle_primitives.h:182-183〕。

官方两池头内联：`anomaly_pool_control()`（按 is_control_abnormal_status 判别；
**诅咒 23 官方自述即控制类**——活动版魔尊 1263"若控制范围包含诅咒才转化施加范围"
对控制池恒真）/ `anomaly_pool_all()`（全 44 id 字面全收——**边界待拍板**：是否该剔除
免疫 17/18、异常免疫 21 这类保护型条目，首个消费方接上后按实测收敛）
〔源: include/primitives/battle_primitives.h:202-224〕。
**六池实战**（K401 的 888）：主支池 {烧伤2, 冻伤5, 中毒1} 等概率挑一；
补偿窗池 {害怕6, 麻痹0, 疲惫7}〔源: resources/soul_lib/k_entry_window_family.cpp:56-60〕。
**三段账**：`RandomAnomalyResult{requested, rolled, landed}` 面向"未触发则…"补偿子句，
消费方按自己的口径读，原语不代做补偿〔源: include/primitives/battle_primitives.h:162-171〕。

### 4.2 免疫通道——票、抗性、魂免三件不同物

1. **免疫票**（`grant_immunity(owner, ImmunityType::ANOMALY, coverage, ...)`）：
   `coverage` = anomaly_mask 细分（0 = 全异常免疫，否则按位）；次数型（counts>0）
   每次消费一次，窗口/永久型每段都查不扣〔源: include/fsm/battleContext.h:1244 +
   include/effects/rule_center.h:55-56〕。**免疫+反弹一体票的实战**：K401 的 888
  「首次登场免疫并反弹下3次异常」= 次数型 ANOMALY 免疫票（counts=3、duration=0 不随
   回合过期）+ 事件 watcher 反弹——因 `grant_reflect` 暂不支持 counts，插件侧自记
   反弹余量计数器，票 scope=ON_STAGE 切走即失效、重登场不重授（"首次"严格一次）
   〔源: resources/soul_lib/k_entry_window_family.cpp:45-54〕。
2. **异常抗性**（训练得来，非票）：`ResistanceSystem` 三槽×两类（控制类/非控制类）
   + 全异常免疫百分比；判定顺序 = 全异常免疫 → 控制类槽 → 非控制类槽，
   逐槽 `sbs_rand()%100 < percent`〔源: include/abnormal-system/resistance-system.h:10-19,104-135〕。
   **抗性成功的奖励是"直写附加免疫异常(21, 2回合)"并击穿魂免**（官方优先级用户修正：
   次免/回合类免疫 → 异常抗性 → 魂免）〔源: include/primitives/battle_primitives.h:35-36 +
   场景015 头注〕。⚠ exploit 同框记录：免疫异常 21 本身可被转化异常转走
   （21→焚烬 22，绕过抗性+魂免，场景 015 O2 实证）〔源: 场景015 O2 断言〕。
3. **魂免**（魂印免疫，soul=true 段）与**次免/回合类免疫**（soul=false）：在检查链上
   分属两段——次免先挡（不 roll 抗性、不挂 21），抗性成功则击穿魂免
   〔源: 场景015 O1/O3 断言〕。

### 4.3 清除通道——四条原语两条路

**"效果解除"与"自然到期"是两条路**，机制差异本身就是考点：

| 原语 | 语义 | 到期伤害/衍化/事件 |
|---|---|---|
| `dispel_active_anomalies` | 解除**全部**生效中异常（星启/律理虚浮用） | 无——直接清槽，**不发** EVENT_ANOMALY_EXPIRED（"解除后异常已不在身上，谈不上结束"）〔源: include/primitives/battle_primitives.h:285-292〕 |
| `cure_anomalies` | 按**名单**解除（圣甲·盖亚逆转机甲 544「解除自身的烧伤、冻伤、中毒状态」首用；名单外原样保留） | 同上〔源: include/primitives/battle_primitives.h:295-303〕 |
| `reduce_active_anomaly_rounds` | **加速消耗**：全部生效异常 end_round 一齐减 delta（宙始星刻 2207）；压到期的由下一轮 tick 自然收尾——"星盘族只认前者" | 照常走（自然到期才发事件）〔源: include/primitives/battle_primitives.h:260-272〕 |
| `set_anomaly_rounds` | **直接设定**某条已存在异常的剩余回合（2399"衰弱回合数归1"族）；允许向下刷新、不存在则不动（不无中生有） | 同上〔源: include/primitives/battle_primitives.h:275-282〕 |

 STAT_CLEAR（免消除强化）等 stat 系免疫**不归异常通道**——那是能力等级侧的票
（查 `ImmunityType::STAT_CLEAR`，三入口：消除/转化/吸取都要查，否则同一层保护被绕道）
〔源: include/effects/rule_center.h:59-66〕。

### 4.4 反弹通道——弹控的边界

- 弹控（REFLECTED）是 Modern 检查链的一环：目标免疫并**把异常反弹给施放方**，
  **最多反弹 1 次**（reflect_depth=1 由原语自理，防循环——双方弹控+双方免疫时
  1 次反弹即止，不卡死）〔源: include/primitives/battle_primitives.h:36 +
  场景015 O4 断言〕。
- Ancient/Raw 通道**不触发弹控**（检查链里就没有这一站）〔源: include/primitives/battle_primitives.h:51-52,114〕。
- 反弹施加用 `apply_anomaly(Modern, actor=自身)`，与内核内置弹控同形；事件不带
  原时长 → 按 `random_anomaly_duration()`=2 口径〔源: resources/soul_lib/k_entry_window_family.cpp:47-54〕。

## 五、两个贯穿陷阱（新人最常翻车的两处）

### 陷阱一：1/8 maxHP tick 是"真实伤害"——不吃减免，还会打死你的统计带

- **机制面**：中毒/烧伤/冻伤/寄生的行动开始扣血是 **TruePercent 档**——1/8 最大体力、
  **真实伤害**：护盾护罩不响应、不吃伤害抗性〔源: include/abnormal-system/abnormal-types.h:313-321〕。
  新人直觉"挂个减伤就能扛 tick"是错的；_percent 档（沉默/烈焰诅咒/束缚）才吃减免。
- **测试面（场景构造陷阱，2026-10-30 K396 记档）**：冻伤/烧伤类「行动开始扣最大体力
  1/8」tick 的异常在身时，**同局 40 回合统计带必打死对手**——统计带（概率效果的
  期望验证）必须改用**独立短局探针**（K7190 式），别把 tick 异常挂进长局
  〔源: 夜跑晨报-2026-10-30-a03-orch §二〕。
- **数值感**：满血目标挂冻伤，行动开始扣 max/8（3000 血 → 375）；连续两回合未处理
  再扣 375——短局探针里 6 回合内掉 ~2250，40 回合长局必死，统计带的"存活率≈期望"
  假设直接崩〔源: include/abnormal-system/abnormal-types.h:352-355（档位定义）+
  夜跑晨报-2026-10-30-a03-orch §二（场景教训）〕。**引擎时点语义已被场景 7761 钉死**
  （2026-11-05）：tick = **携带者自身行动开始**（BATTLE_FIRST/SECOND_ACTION_START 的
  stage+settle，先于"能否行动"短路——受控无法行动照样扣、每回合恰扣一次、
  不存在"对面回合替你 tick"通道）〔源: src/fsm/battleFsm.cpp 两处 mover 行动开始块 +
  场景7761 T1/T2 断言〕。⚠保留（官方读法侧）：effect_des 文本「每回合**对手**行动
  开始时」存在同句双「对手」同指读法（effect_des 279「扣除最大体力的 1/8 **恢复至
  对手**」——holder 视角下两处"对手"同指=受害者对面 → tick 应落在**对面**行动开始），
  引擎取"受害者自身行动开始"（applier 视角读法）——两读法需官局对拍（判据局：
  受害者残血 ≤1/8 且先手出手的局，看它死于出手前还是出手后）。

### 陷阱二：boss_invalid 尾注——"（boss无效）"管到哪一句？

- **机制面**：`SoulMarkNodeRef::boss_invalid` 置位后，boss 挑战对局
  （`is_boss_challenge`）中该节点**不注册不执行**；标注单位 = **带尾注的子句**
  （tips 按 `|` 分句；同一子句的所有节点必须统一置位，漏标会产生半初始化状态）
  〔源: include/plugin/plugin_interface.h:40-48 + include/fsm/battleContext.h:522-525〕。
- **归属判例一（最近邻原则，K401 的 888）**：「首次登场免疫并反弹下3次受到的异常状态」
  ① +「免疫能力下降」② +「随机进入异常，未触发则…（BOSS无效）」③——尾注紧贴③句尾
  → **仅③** watcher 回调手动门 `is_boss_challenge`（①②无尾注，boss 局照常免疫）
  〔源: resources/soul_lib/k_entry_window_family.cpp:61-62〕。
  同文件 2087：「击败对手后恢复…」②带尾注 → 仅②节点 boss_invalid=true
  （尾注最近邻归属，K394 口径）〔源: resources/soul_lib/k_entry_window_family.cpp:64-78〕。
- **归属判例二（全句覆盖，K395）**：K395 七行全部是全句尾注「（boss无效）」→
  全节点 boss_invalid=true（K193 惯例：boss 对局节点不注册不执行）；
  K373 同款读法记档「尾注覆盖全部分句 → 全节点统一置位（漏标=半初始化）」
  〔源: resources/soul_lib/k_iceburn_family.cpp:72-73 +
  resources/soul_lib/k_anomaly_gate_drop_heal.cpp:33〕。
- **坑案（S4 证据包已交付，待用户终裁）**：K393 曾有「boss_invalid 不置位」结论——dump 实证
  「（boss无效）」尾注**属受击子句**而非全句（与"覆盖全句"读法冲突）
  〔源: 夜跑晨报-2026-10-26-a01-orch §三〕。**两种读法（最近邻 vs 全句覆盖）在
  K 系实操中并存，以尾注在行文中的物理位置为准**（勘误 2026-11-06 S28：此句原引
  「夜跑晨报-2026-10-30-a03-orch §五」，经核该晨报 §五为"终门与合并"、全文无尾注
  内容——实为**本节对上列两判例（K401 888/K395）+ K393 坑案的综合归纳口径**，
  改记为本 wiki 自立口径，待用户终裁时一并回写）。
  S4 调研 v2 证据包已于 2026-11-05 交付：推荐倾向 **B（"该效果在 boss 对战中无效"）**
  置信度中等——新增较强证据是同精灵相近效果在 4399 旧文写「boss免疫」、现行本地
  官方资产库写「boss无效」（含纯自身保护类反例）；**终裁权在用户，本文不因证据包
  改变任何实现口径**〔源: docs_local/docs/06-交接/boss免疫尾注口径裁决-证据包-v2-2026-11-05.md 零节〕。
- **给新人的操作口径**：写/读魂印行时先按 `|` 分句，尾注跟紧它所在子句；
  同子句多节点必须统一置位；拿不准时在文件头记档两读法 + 场景锁可观测的那一边
  （范式：K396 810 行「行参解码（四行尾位 1 = boss 无效尾注旗——不消费，boss 口径
  按尾注落注册面，K372 纪律）」〔源: resources/soul_lib/k_prob_compensate.cpp:17〕）。
