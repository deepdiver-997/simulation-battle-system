## 二、克制矩阵：676 格、四档倍率、7 对免疫

### 2.1 表结构与加载链

### 2.4 双属性怎么乘：四分支

克制查询 = **技能系别视图 × 防守方系别视图**（不是攻方精灵系别——官方机制，
场景 012 头注与公式注释两处同口径〔源: 场景012:2-4〕
〔源: include/numerical-calculation/calculation.h:73-81〕）：

```
1v1：m00
2v2：m00 × m11            （攻方双系各对守方双系，两对相乘）
2v1：m00 × m10            （攻方双系各自对守方单系，相乘）
1v2：m00 × m01            （守方双系各自被攻方单系克，相乘）
```
〔源: include/numerical-calculation/calculation.h:127-146〕
（**J322 修订 2026-11-05：上述四分支相乘口径已作废**——引擎改为官方均值口径，
实现见本节下方「官方聚合口径」段与 §2.5；原文保留供回放。）

双属性相乘可以叠出 4 倍（2×2）乃至 0（任一对免疫即全免）——官方档位本集
{0, 0.5, 1, 2}，乘积域 {0, 0.25, 0.5, 1, 2, 4}，引擎属性直伤注释明言
"双属性相乘后可为 4 等"〔源: src/primitives/battle_primitives.cpp:1207-1210〕。

**官方聚合口径是算术平均、不是相乘（S16 三例互证，2026-11-05 破案，原待验证 #4 关单）**：
官方原文三道例题的克制系数都能用「攻守全部属性对倍率的算术平均」精确复算，
引擎相乘口径全部对不上——

1. L99 红月祭司（神秘+超能，合并 id 51）大招残月鸦天咒（双系技、25 威力）打
   天启帝君（轮回单系 224）：神秘→轮回 2.0、超能→轮回 1.0，平均 **1.5**——例题
   "{…}×1.5×1.5" 前一个 1.5 是本系、后一个即克制均值；相乘读法得 2.0 ✗
   〔源: 官方原文 L99〕（倍率现查见机校清单② SQL）。
2. L101 永夜冰狐王（冰+暗影，合并 id 45）先三打谱尼（圣灵单系 16）：两对均 0.5，
   平均 **0.5**——例题"×0.5克制系数"；相乘得 0.25 ✗〔源: 官方原文 L101〕。
3. L100 冰王打瀚宇星皇（自然+圣灵，合并 id 88）：四对 {1.0, 0.5, 1.0, 0.5} 平均
   **0.75**——例题"×0.75克制系数"；引擎 2v2（m00×m11）得 0.5 ✗〔源: 官方原文 L100〕。

→ 引擎四分支相乘口径与官方例题存在**系统性分歧**（1v1 两口径一致，分歧只现于
含双属性的对局）；叠加 §一 所记双系技合并 id 未分解问题，双系克制是引擎当前
最大的官方偏离面。修复属内核授权轮（章末清单 #3/#4）；本单只记录不改码。
（**J322 修订 2026-11-05：已落地，引擎与官方三例全部吻合**——内核授权轮
（a24-orch 担保）改造 `calculateRestraintMultiples` 为官方口径：

### 3.1 官方公式（L101《赛学扩展4—连击计算（新）》）

```
[(攻击方的等级×0.4+2)×技能面板威力×攻击方的攻击÷防御方的防御÷50+2]
  ×本系修正 ×克制系数 ×(217~255)÷255 ×暴击抗性 ×暴击系数 ×连击次数
```
〔源: 官方原文 L101〕。取整口径（L99《关于暴击对连击的影响》）：
"计算全程向下取整，局部取整，大概 5 次：**浮动前一大段取整，浮动计算后取整、
暴击系数计算后取整、抗性计算后取整、连击次数取整**"；L101 补充
"方括号内属于一个整体不可拆分……伤害浮动算完需向下取整，从浮动之后每次计算均
向下取整"〔源: 官方原文 L99〕〔源: 官方原文 L101〕。

### 3.2 引擎公式（calculation.h）

```cpp
damage = (0.84 * Attack / Defense * power + 2) * restraint
        * (217 + sbs_rand() % 39) / 255;
if (ws.force_involve[attacker] || involve(...)) damage *= 1.5;   // 本系加成
return damage;                                                    // double→int 截断
```
〔源: include/numerical-calculation/calculation.h:86-94〕

其中 `Attack` 取攻方 `skill_type_view` 对应槽（物理=0 攻击、特殊=1 特攻），
`Defense` 取 `type+2` 槽（2=防御、3=特防）〔源: include/numerical-calculation/calculation.h:39-54〕；
数值槽序 **0攻 1特攻 2防 3特防 4速 5体力**〔源: include/entities/numerical-properties.h:6-13〕。

**0.84 是哪来的（算术折叠，非独立语料）**：官方括号项 `(等级×0.4+2)÷50` 在
等级 100 时 = 42/50 = **0.84**。引擎把这一项**写成常量**、公式再无等级项——
官方对拍管线直灌面板即可对齐（"面板直灌 base=[2×race×lv/100+5+six ×5, hp_max]
（伤害公式无等级项，calculation.h 实锤）"〔源: 协议文档§22.3〕）。推论：**非 100 级
攻方**按官方公式应乘 `(lv×0.4+2)/42 < 1` 的折减，引擎不做——低级对局会系统性
高估，见待验证清单 #4（原 #2，S27 迁号后指向已裁决段同题记录）。

### 3.3 官方 vs 引擎逐项对照表

| 项 | 官方口径（L99/L101） | 引擎现状 | 一致性 |
|---|---|---|---|
| 括号段 | (等级×0.4+2)×威力×攻/防÷50+2，**整体取整** | 0.84×攻/防×威力+2，double 连乘不取整 | 100 级时数值同构；取整时点不同 |
| 克制系数 | 乘在括号后、浮动前 | 同为括号后、浮动前（同一表达式） | ✅ 一致 |

| 本系修正 | 乘在克制前（括号后第一项） | 乘在**浮动之后**（calculation.h:91-93） | 乘法交换下数值同；取整次序不同 |
| 暴击抗性/系数 | 各自取整 | 整数步 ×200/100、×(100-抗性)/100，各截断一次 | ✅ 逐位一致 |

### 3.4 进公式之前的三层修正（都在 stage_simple_attack_damage/物化层）

1. **威力打底 + 烧伤减半**：面板威力物化进 `skill_power_view`；攻击方处于烧伤
   （含虚拟烧伤）时威力先 `power/2`——引擎刻意走 `materialize()` 而非效果改写，
   **不触发变威力重算**〔源: src/fsm/battleFsm.cpp:498-514〕。
2. **防御侧折减**：套装"忽略对手防御 15%"在防御进公式前按
   `defense_ignore_pct` 折减（腐蚀者 387 线）；"无视对手能力提升"族（195/494/486）
   把防御/特防**正**等级视作 0（弱化保留，`pierce_boost`）〔源: include/numerical-calculation/calculation.h:46-57〕。
3. **能力等级缩放**：攻防值 = 面板 × 等级系数——正等级 `(lv+2)/2`（+6 → ×4），
   负等级 `2/(2-lv)`（-6 → ×0.25），读端钳 ±6（night fuzz #9 加固）；
   体力槽**没有**能力等级（槽 5 是命中不是体力——两套索引只在前 5 重合的高频坑）
   〔源: include/fsm/battleWorkspace.h:588-598〕〔源: 速查§三〕。
   另：防御面板 ≤0 时钳 1.0（除零守卫，2026-11-03 fuzz 首曝）——官方口径防御
   永不为 0，钳制只消灭异常路径的 UB〔源: include/numerical-calculation/calculation.h:58-65〕。

**威力视图的哨兵是 -1 不是 0**：`skill_power_view` 未物化 = -1（回退技能静态
威力）；**0 是合法值**——强制执行打盔时故意置 0 表达"只有效果、没有红伤"
〔源: include/fsm/battleWorkspace.h:71-75〕。

## 四、系数逐项：每一个乘数挂在哪

### 4.1 克制系数怎么进管线（源代码实证）

完整数据流（一次普通攻击）：

```
resolve_skill_execution        物化 skill_element_view（含 2490 类"以XX系别"授予）
  → stage_simple_attack_damage calculateDamage：查矩阵得 restraint，乘进 base
    → 次数型增伤 → 暴击 → 连击                （仍在快照 base 上）
      → finish_attack_damage：变威力重算 → 裸伤台账 → damage_pipeline_.run()
```
〔源: src/fsm/battleFsm.cpp:518-527,644-687,891-909〕

**关键结论：克制在 11 阶段修正管线之前就已折叠进 base**——管线 AMP/REDUCE
各阶段看到的都是已含克制的值，增减伤按含克制的基数放大/缩小（管线序见 01 章）。

引擎给效果留了**四个克制改写口**（都在 calculateDamage 读矩阵之前生效）：

| 改写口 | 语义 | 源 |
|---|---|---|
| `skill_element_view` | "以XX系别计算克制倍数"——改的是**技能**系别视图；本系判定不受影响（读真实系别） | calculation.h:73-77,88-93 |
| `restraint_view ≥ 0` | 固定倍率直写（最优系别等直接覆盖矩阵查询结果） | calculation.h:79-81 |
| `no_weakness`（effect 760） | 克制 <1（微弱）时钳到 1，克制 >1 不动——官方模板原句"攻击时造成的伤害不会出现微弱（克制关系为微弱时都变成普通）" | calculation.h:82-85 |
| `optimal_elem_rounds` | 最优系别视图（圣莫 K7 线）：在 {对手在场系别, 上一次在场系别} 候选取克制最优者，算完还原 | battleFsm.cpp:670-690 |

（表内行号均为 include/numerical-calculation/calculation.h 与 src/fsm/battleFsm.cpp；
effect_info 760 原文现查〔源: src/db/official_data_repository.cpp 消费的 effect_info 表，
id=760〕。）

**系别视图是"半持久化"的**：绑定在场精灵槽，换宠/下场才从新精灵重基，
`ws.reset` 不清——改系别效果跨回合存活并真实改变克制倍率（场景 014 N1：
回合 1 草 0.5×、回合 2 改水 2.0×，受击 ≥3 倍差；N2：换宠即重基）
〔源: src/fsm/battleFsm.cpp:561-569〕〔源: 场景014:72-123〕。

**属性直伤支线**（`deal_attribute_damage`，"属性伤害"类）：不走攻防面板与
威力，而是**点数 × calculateRestraintMultiples**（吃克制！）、截断取整、
且只跑管线子集 BLOCK（+未持穿透凭证时的 CAP）——"免疫下N次攻击伤害"票不响应
〔源: src/primitives/battle_primitives.cpp:1200-1230〕。即：**属性直伤吃克制
与锁伤/挡伤，不吃增减伤**（管线 phase_mask 语义同口径，01 章 §四.5 有专节
〔源: include/effects/damage_pipeline.h:130-137〕）。

### 4.2 本系加成 ×1.5：技能真实系别 vs 精灵系别

- 判据 `involve`：单系技能——精灵**任一**系匹配即 ×1.5；双系技能——两系全配
  才 ×1.5〔源: include/numerical-calculation/calculation.h:147-151〕。
  官方直证（S27 补，2026-11-05）：L455《机制解析—圣谕之风·岚》本系判定第二则
  「技能图标的属性与精灵自身双属性图标的其中1个属性是否相同，**满足视为本系技能**」
  ——任一匹配即本系（OR），与引擎单系 OR 读法一致〔源: 官方原文 L455〕。
  （**J322 修订 2026-11-05：双系技全等读法已改为相交读法**——技能组件集合
  （复合 id 经映射层拆开）与攻方精灵属性集合**相交非空** → 本系 ×1.5；
  单系技 OR 读法保留、单属性×单属性行为逐字节不变。改前复合技（type_id 21~132）
  按全等读法永不命中 → 双系技本系加成整体丢失；改后 L99 例题"{…}×1.5×1.5"的
  前一个 1.5（本系）才能成立（红月祭司 神秘+超能，复合技含神秘组件即本系）
  〔源: include/numerical-calculation/calculation.h:180-203〕。
  场景 7860 T7866/T7867 锁死：相交命中/无交集不命中/单系 OR 保留 + 真战斗
  本系带 [195,232] 与对照带 [130,155] 不交叠
  〔源: 场景7860:T7866-T7867〕。属性视图 `ws.view_elementalAttributes` 语义
  **不变**：槽值仍是单属性 id，直接参与相交与聚合，effect 2210 双槽直写等
  生产者零改动。）
- 官方例子同构：L101 例题"{42×602÷393÷50+2}×**1.5本系加成**×0.5克制系数"
  〔源: 官方原文 L101〕。
- **改系别只改克制、不改本系**（刻意设计）：本系读 `skill.element` 真实系别；
  要"强行获得本系加成"的效果（effect 2490 族）走 `ws.force_involve` 显式开关
  〔源: include/numerical-calculation/calculation.h:88-93〕。
  effect_info 2490 官方模板："此技能微弱对手时技能先制+3、获得本系属性加成并
  以神灵系进行伤害结算"——先制+本系+改系别三件套正是这套视图层的消费者。
- 位置差：引擎把本系乘在**浮动之后**（§3.3 对照表），官方公式文本里它排在
  克制之前——乘法交换律下数值相同，只有取整次序差异。

### 4.3 随机浮动 217~255

- 引擎：`(217 + sbs_rand() % 39) / 255` → 39 档均匀、值域 [0.851, 1.0]
  〔源: include/numerical-calculation/calculation.h:86-87〕，与官方
  "(217~255)÷255" 完全对齐〔源: 官方原文 L101〕。
- **场景断言口径（写场景必读）**：红伤裸伤带 = 公式值 ×[0.851,1.0]，实测锚
  atk300/def100 拍打 raw∈[87,102]；数值带断言以 (85,104) 为 raw 带推导，
  **禁止拿单次抽样最小/最大值当边界**；相邻档位带间距小于波动幅度时改用比值断言
  〔源: 速查§五〕。
- 浮动**重掷**时机：变威力第二次结算是"一次完整结算"，`sbs_rand()` 重掷
  （暴击则**不**重掷，一次技能只掷一次）〔源: src/fsm/battleFsm.cpp:805-806〕；
  官方侧双源同向（2026-11-06 S28 补证）：L99 算例暴击段一次算完、×6 尾乘连击，
  L453《机制解析—变威力》第二次结算重算清单（能力等级含暴击破防/克制/威力）
  不含暴击掷点〔源: 官方原文 L99〕〔源: 官方原文 L453〕。
- 官方"217~255 内随机取一整数"的**分布是否均匀**见 §六清单#5（与清单同题，
  不再行内重复挂 ⚠；引擎按均匀实现）。

### 4.4 暴击：掷点、系数、抗性、破防四件套

**掷点（query_usage ①.5，只攻技、只掷一次）**：

- 判定位在 miss 之后、门判定之前——**只有 miss 能阻止暴击**；打盔/命中失效
  都保留暴击结果（"打在盔上一样可以触发暴击并破防"）；属性技能不掷
  〔源: src/entities/skills.cpp:964-973〕。
- 暴击率 = 技能自带 `crit_rate`（官方 moves.crit_rate，**分母 16 的分子**：
  8→50%、16→100%、**0=永不必暴**）× `crit_rate_mod`（乘算）+ `crit_rate_add`
  （加算，蓄气族 effect 32 "+1/16" 形）〔源: src/entities/skills.cpp:456-460,974-981〕。
- 通用特性·会心：0 星加法 +6.25%（=1/16）；1~5 星独立二次结算
  （75/88/100/120/140 万分比）〔源: src/entities/skills.cpp:982-993〕。
- `must_crit`（effect 58 圣光气族"下N回合必定致命一击"）单列开关——乘算修正
  表达不了"0×任何数=0"的必定语义；rate≥100 直接必暴〔源: src/entities/skills.cpp:974-996〕。
- 现查 moves.crit_rate 分布：27103 个技能暴击率 0（无引爆效果就永不暴击），
  非零共 **204** 个（2~16 档，疾风刃 10003=4 即 25%）——机校清单④。

**系数与抗性（乘在快照 base 上，先系数后抗性、抗性乘整段）**：

```cpp
snapshot.base = snapshot.base * crit_mult / 100;        // ① 暴击系数（默认 200 = ×2）
snapshot.base = snapshot.base * (100 - crit_resist) / 100;  // ② 暴击抗性（乘整段）
```
〔源: src/fsm/battleFsm.cpp:714-720〕；默认系数 200〔源: include/fsm/battleWorkspace.h:147,554〕。

- **"抗性乘整段"是用户 2026-09-14 纠正的口径**：原本 100 → 暴击 ×2=200 → 35%
  抗性 → 200×0.65=**130**，不是 100+100×65%=165。官方同源：L99"暴击系数×暴击
  抗性一般都是默认对手 35% 拉满，可以折算为 **2×0.65=1.3**"
  〔源: src/fsm/battleFsm.cpp:706-713〕〔源: 官方原文 L99〕。
  场景 014 N7 锁死：100% 暴击 + 50% 抗性 → 净 1.0×（"只削加成"读法会得 1.5×，
  两读法数值可分）〔源: 场景014:196-238〕。
- ~~原行内待验证标记（2026-11-05 已裁决）：暴击系数 200 之外有无"暴击伤害提升"类效果改写 `cached_crit_damage`
  （引擎槽在、生产者未见）。~~ **已裁决（2026-11-05，S16 grep 现查）**：写点已找到——
  effect 1558 繁嚣此寂（圣光莫妮卡组）"下{0}回合若打出致命一击则攻击伤害提升{1}%"，
  窗口内每回合 ROUND_START 对 `cached_crit_damage` **乘算放大**（×(100+bonus)/100）
  〔源: resources/moves_lib/shengguang_monika_skills.cpp:489-491〕；引擎槽仍只此一条
  写链（K356 2374 走 must_crit+damage_add_pct，不写本槽）〔源: resources/soul_lib/k_foe_boost_crit_damage.cpp:16-19〕。

**破防（crit_defense_break）**：暴击命中时把守方**对应防御槽的正等级直接归零**
（物理破防御、特殊破特防，槽=type+2 与公式取值同源）；**故意不查免消除强化**——
破防是暴击自带规则、不是"消除强化效果"（用户 2026-09-13 口径）；零/负等级不动
〔源: src/primitives/battle_primitives.cpp:1648-1668〕。时点在第一次伤害公式

〔源: src/fsm/battleFsm.cpp:764-775,796-801〕〔源: 场景044 C4 断言〕。

乘在 base 上是刻意的——下游管线/护盾/次数型免伤全只消费 final，
"免疫下 1 次"吞的是**整段**（N=3 整段归零，场景 044 C6）
〔源: src/fsm/battleFsm.cpp:722-743〕〔源: 技能判定流程§8.8〕。

### 4.5 抗性三槽：暴击/固定/百分比（上限 35）

- 本体三槽挂在精灵身上、跨切换保留：`damage_resist.{crit,fixed,percent}_pct`
  〔源: include/entities/elf-pet.h:178〕；组装层**官方钳制单项 ≤35**（调查 §4.5
  口径；异常抗性槽另 ≤50）〔源: src/entities/pet_factory.cpp:718,726-728,733,741〕。
- 计算一律读 ws **有效视图**（`eff_*_resist_pct`），回合开始/换宠从本体重基；
  临时 buff 只改视图不改本体——"抗性视为 100%"类 buff 只提升**非 0** 本体
  （本体 0 时 buff 不生效，场景 014 N9a/N9b 两分支锁死）
  〔源: include/fsm/battleContext.h:886-901〕〔源: include/fsm/battleWorkspace.h:320-328〕
  〔源: 场景014:282-310〕。
- 消费位各不相同：**暴击抗性**乘在攻击红伤的暴击步（§4.4）；**固定/百分比抗性**
  消费在**粉伤管线** RESIST 阶段（固定走 fixed、百分比走 percent 槽；取整按官方
  "伤害量−伤害量×抗性"乘法向下取整，L84《关于伤害抗性的改动》）
  〔源: include/fsm/battleContext.h:1513-1518〕〔源: 官方原文 L84〕。

## 五、10-21 皮皮局 0.40 比值悬案——「百科如何记录未决问题」样板

> 本节同时是一份格式示范：未决问题按 **现象→证据→互斥解释→已排除→验证路径→
> 回写点** 六段记，正文不断言结论、只断言证据本身。

**现象**：2026-10-21 官方局离线对拍（A 薇尔诗 vs B 六皮皮）中，38423
（"向未来的祈愿"，神灵系 223）五连发的**官方/引擎伤害比恒 ≈0.40**
（官方实效 ≈18k vs 引擎 ≈45k），五发全同向、无一例外
〔源: 协议文档§22.4〕。

**证据**：

1. 官方侧原始读数：38423 五连发逐只秒杀，伤害 **17k~36k**，能力等级块 count=0、
   状态数组无变化〔源: 协议文档§20.2〕。
2. 引擎侧当时读法：223(神灵) 克 4(皮皮/飞行) 按本地矩阵 ×2，叠加本系 ×1.5
   〔源: 协议文档§22.4〕。
3. 对拍工具链本身已互证：皮皮"撞击 2↔2 完全一致"（dual 局低倍率带），管线
   主链正确——偏差集中在**克制系数**一侧〔源: 协议文档§22.4〕。
4. **矛盾点（10-30 记档自我标注）**：现库 `types_relation` 查
   (deity, flying) = **1.0**（双向），与 10-21"引擎 ×2"的读法不符——
   "本身即待裁决点"〔源: 协议文档§22.5〕。本单现查（2026-11-04）复核仍为
   1.0（机校清单②可复跑）。
5. **官方上游当前值（S16，2026-11-05 重拉）**：官方数据源
   `typesRelation.bytes`（SeerAPI/seer-unity-assets 镜像，fetch 链见
   scripts/fetch_seer_unity_bytes.py）解析 676 格与现库 **0 diff**，
   (deity, flying) = **1.0**——官方当前值即 1.0（与 §2.3 勘误注同一复核）。

**互斥解释（均未排除）**：

- ① **DB 漂移**：10-21 时引擎加载的克制表是旧值（×2），其后数据管线更新为
  1.0。该 sqlite 是抓取管线产物（symlink 到数据仓、不入版本库）——今日查证
  无版本史可回放，此解释**无法离线仲裁**（证据 5 之后成立条件更苛刻：须存在
  一版 (deity,flying)=2.0 的上游 bytes，不可证）。
- ② **读法误差**：10-21 对拍报告对引擎侧倍率的读数有误（45k 的拆解里
  ×2 与 ×1.5 的归因可能记反/记重）——官方上游当前=1.0 的硬证据（证据 5）
  使此解释权重上调，但仍未定谳。
- 残差另有两处已知口径债：皮皮 lv1/8 歧义（只影响其攻防低位，秒杀局不敏感）

  待标定清单里〔源: 协议文档§22.4〕〔源: 协议文档§19.4〕。

**验证路径**（协议文档已备好的 #7 标定局设计）：同阵容同守方换技能——

**回写点**：标定局出数后，①本节补「已裁决」段（勘误不抹改，见 00 章 §五）；

  （互斥解释 ② 权重上调；① DB 漂移不可证伪但无版本史支撑）——无论当时是
  哪种，**改后引擎按现库 1.0 结算**：38423（deity）打皮皮（flying）引擎实效
  ≈×1（无克制），与官方当前镜像吻合；对拍残余偏差若再出现，应查面板合成

  报错（§2.5），"引擎悄悄用了与库不同的倍率"这一类错误在结构上被排除。

  指向官方**局内实现**与官方**镜像数据**的差异（超出引擎职责，另行立单）。
