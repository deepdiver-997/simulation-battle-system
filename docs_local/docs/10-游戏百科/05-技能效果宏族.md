## 一、moves 效果体系全景：side_effect 链模型

### 1.1 链是什么

- 每个载体技的 `moves.side_effect` 列是一个 **JSON 数组**：元素 = 效果 id，数组序即
  执行链序（管线侧约定"数组字段一律存 JSON 数组文本、不做空格拼接"，side_effect
  定义表在迁移期即 2023 行）〔源: docs_local/docs/06-交接/数据管线迁移到Unity端-交接.md:63〕。
  纯链（单效果位）例：36845「拈红渲紫」= effect 1731 一位 + 切片参数 [4,300,2]
  （窗长 4 回合 / 每回合末固伤 300 / 全技能 PP-2）〔源: docs_local/docs/05-任务清单/已收官/J组批量效果工单.md J199 行〕。
  复合链例：23906「无法无天」= effect 57、585、656、730 四位 + 17 个切片参数——
  参数串按链上各效果位的 arg_count 分摊给各效果位〔源: resources/moves_lib/j_meta_template_window.cpp:9-10〕
  （2026-11-04 现查 moves 23906：side_effect=[57,585,656,730]）。
- 引擎侧每个效果位由插件以 `SKILL_EFFECT(id)` 注册一个效果函数，落点集中在
  `resources/moves_lib/`（427 个文件：J/E/F/G/H 批产家族文件 + 单体宠技能文件）
  〔源: resources/moves_lib/selection_seal.cpp:717〕〔源: 速查§五〕。
- 链上各位**相互独立**：任一位未注册，该子句即静默 no-op（技能能放、子句不生效）——
  这正是覆盖率盘点的对象（§三）〔源: docs_local/docs/08-参考/效果覆盖率与新精灵支持度盘点-2026-10.md 头注〕。

### 1.2 effect_info 模板与 {n} 参数

- `effect_info` 表每行一个效果定义：`id / args_num / info（官方模板句，{n} 占位）/
  param / analyze`〔源: docs_local/docs/06-交接/数据管线迁移到Unity端-交接.md:63〕。
  例：effect 917 模板「命中后{0}%使对手{1}，未触发则附加自身最大体力值1/{2}的百分比
  伤害」（args_num=3，2026-11-04 现查）〔源: 速查§五〕。
- `{n}` 不一定是标量：effect 730 的 `{1}` 吞 6 参 = **语义序六槽向量（攻,防,特攻,
  特防,速,命中）**，映射引擎槽 kStatMap{0,2,1,3,4,5}——按引擎序直读会把防/特攻读反，
  须用 4399 载体文本交叉定案。这是全家族最易踩的**双序坑**〔源: 速查§五〕
  〔源: resources/moves_lib/j_meta_template_window.cpp:3-7〕。
- 写效果实现时**不信任切片、先读模板**：用 effect_info 模板 {n} 个数 + 4399 载体文本
  反推参数语义，切片只当索引〔源: 速查§五〕。

### 1.3 切片双表口径（arg_count 优先、args_num 兜底）

- `side_effect` 定义表（`id / arg_count / raw_json`）现查 **2023 行**（与迁移期行数
  一致——定义面稳定，漂移发生在引用面）〔源: docs_local/docs/06-交接/数据管线迁移到Unity端-交接.md:63〕。
  这是"效果定义全集"的权威表、§三 覆盖率的分母之一。
- 运行时切片数取 `side_effect.arg_count` **优先**、`effect_info.args_num` 兜底——
  两表曾有 **16 处不一致**（73/116/117/118/596/816/919/1154/1515/1531/1654/1794/
  2001/2190/2191/2217），R1 修正过其中 13 处（118/596/816/919/1154/1515/1531/1654/
  1794/2001/2190/2191/2217），修正依赖 `tools/db_patches/apply_all.sh`——**管线重建
  后必须重放**，否则切片敏感场景转红〔源: 速查§五〕〔源: docs_local/docs/05-任务清单/已收官/J组批量效果工单.md 背景速查节〕。
  （本文 §1.1/§1.2/§四 引到的 1731/2161/730/675/2190 现查双表一致——不一致清单之外
  的 id 不能想当然，逐 id 对表。）
- author 切片必须 `json.loads` 后按 `arg_count` 位切：对 side_effect 原始字符串直接
  切片是**按字符**错位（J185 实测，1953 全量错切、重切后 9/9 自洽）〔源: 速查§五〕。

### 1.4 本地私有效果段（900000+，J325 首例约定）

- **技能空间私有段约定**：id 段 **900000+** 留给"本地语义效果"——官方模板拆分出的
  子句、本地组合语义等不经官方管线的自造效果位。三件套缺一不可：
  ① `side_effect` 表本地 INSERT（arg_count+raw_json 标注语义，raw_json 引擎不消费、
  note 字段自由记档）；② 引用方 `moves.side_effect` JSON 数组挂链；③ 插件
  `SKILL_EFFECT(id)` 注册实现。**effect_info 表不建行**（官方权威不动，
  fill_effect_metadata 查无行安全返回）〔源: tools/db_patches/j3/1526_split_900001.sql〕。
- **arg 分配安全性**：arg_count=0 的链位不消耗切片参数——链尾追加私有 id 不改变
  前序效果的 [lo,hi] 等参数定位（build_skill_effects 按 arg_count 顺序切片）。
  追加式补丁幂等靠 `NOT LIKE '%id%'` 防御（json_set '$[#]' append 重放安全，
  J325 二次重放实测链形不变）〔源: tools/db_patches/j3/1526_split_900001.sql〕。
- **管线重建免疫**：私有段行会被 import 重建刷掉 → 靠 apply_all.sh 重放恢复
  （与 R1 修正同一防线）；撞号审计由 SKILL_EFFECT 宏自带 source
  （include/plugin/id_collision.h）。首例：1526 后缀拆分 900001（§六）。

## 六、内核缺口类型学：一个「未实现」的三条通道

「效果未实现」在引擎里有三种完全不同的真相（J129 实测口径）〔源: 速查§五〕：

1. **插件注册通道（宏族主通道）**：SKILL_EFFECT(id) 注册效果函数——J 板批产吃的
   就是这条，§二 目录全部在此通道。
2. **内核硬编码通道**：效果本体在内核流程里，插件只是外壳或无需插件。实例：
   连击占位 effect 31 的本体动作在 loadSkills 的 combo 表（combo_arg_indices 消化，

   选择期表版绿、case 版先手断言必挂）〔源: 速查§五〕。
3. **运行时文本 parser 兜底通道**：无插件注册的效果由 skills.cpp `parse_effect_unit`
   原生解析官方模板句并执行——effect 917 会被解析活（100% 档直接上异常）。
