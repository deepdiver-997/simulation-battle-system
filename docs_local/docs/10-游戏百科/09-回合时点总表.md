# 09 · 回合时点总表——State 桶 × 事件 × 管线

> 状态：已写（S14，2026-11-04）+ S18 清缴修订（2026-11-05）。所有行号现查于当日工作区（分支 feat/s14，
> 基线 main-local @34b7a9a3）。本章是收拢章：把 01 章的管线阶段、各章散落的
> 时点知识收成一张总表，并为"写效果选哪个挂点"给一棵可执行的决策树（§五）。
> 一句话总纲：**引擎里有三套"时点"——FSM 的 State 桶（谁在哪个时点执行）、
> EventCenter 的事件（"发生了什么"的通知）、DamagePipeline 的 11 阶段（一次伤害
> 内部的修正序）——选错套，效果要么不触发、要么时序错。**

## 一、三套时点系统总览（先分清再选）

| 系统 | 回答的问题 | 载体 | 执行时机 | 总源 |
|---|---|---|---|---|
| **State 桶** | "到某个回合流程位置时，谁的效果该跑" | `State` 枚举 42 项 + `TimedBucket`（魂印/套装/技能/被动四容器） | handler 跑桶 → FSM 推进 | 〔源: include/fsm/state.h:11-57 + src/fsm/battleContext.cpp:1015-1045〕 |
| **事件** | "刚才发生了一件什么事，谁在听" | `EventType` 29 项 + `EventWatcher` | 原语成功路径末尾 emit **入队**；每个 State 桶跑完、推进下一 State 前 drain 投递 | 〔源: include/effects/event_center.h:249-259 + src/fsm/battleFsm.cpp:1278-1280〕 |
| **管线阶段** | "一笔伤害内部，增伤/减伤/保底/锁伤谁先谁后" | `DamagePhase` 11 阶段（01 章全卷） | `damage_pipeline_.run()`，在 ATTACK_DAMAGE 桶内部 | 〔源: include/effects/damage_pipeline.h:44-58〕 |

三者不互斥而是嵌套：一个 State 桶里跑的技能效果会触发管线，管线与原语在成功路径
末尾 emit 事件，事件在**这个 State 桶结束之后**才投递给监听者〔源: src/fsm/battleFsm.cpp:1278-1280〕。

### 2.1.1 选技期用药与回合末死切（用户 2026-11-06 已定）

**药品仅在选技期（State 1）可用；回合末死切（State 37）不能嗑药**。
CHOOSE_AFTER_DEATH 是强制补位换宠输入期，不是额外的选技/用药期；
这里的药品使用规则与 §2.2 的「嗑药后哪些桶会跑」是两件事，不能相互替代。
权威说明为 `docs_local/docs/02-效果系统/时点判定流程表.md`「操作阶段 / 选择使用技能 /
选择使用药剂」的 **2026-11-06 用户口径补充**（非原图转写）。本轮不改代码，未复测。

### 2.2 执行方语义：mover 侧桶、嗑药守门、桶内定序

1. **动作流程时点（枚举 6–13、16–23）只跑出手方**。handler 只传 mover 的 robotId，
   对方在这些时点**没有任何桶会跑**——受击类效果因此不能挂时点桶（§2.3）。
   代码口径：`is_action_flow_state` = id 6–13 与 16–23〔源: src/fsm/battleContext.cpp:1004-1013〕；
   先手方各 handler 只传 `first_mover_id`（如行动开始〔源: src/fsm/battleFsm.cpp:1838〕）。
2. **mover 自己嗑药/空操作也不跑动作桶**。`execute_registered_actions` 对非出手
   （roundChoice 非 SELECT_SKILL）跳过魂印/套装/技能三桶，但**被动桶照跑**——
   "就算嗑药也触发"的效果（死亡印记结算等）注册进被动桶〔源: src/fsm/battleContext.cpp:1022-1044〕。
   死亡/额外动作时点不属动作流程，不受此守门〔源: src/fsm/battleContext.cpp:1008-1009〕。
3. **桶内容器序 = 魂印 → 套装 → 技能**（官方"先结算魂印，后结算套装"），被动桶最后
   且不守门〔源: src/fsm/battleContext.cpp:1034-1044〕。同一 State 双侧执行时 0 侧
   （房主）先于 1 侧（挑战方）〔源: include/effects/event_center.h:78-80〕。
4. **回合结束时是唯一"按先手权分支定序"的双侧时点**：SEER_ROBOT_1（房主 0 侧
   持先手权）→ 1→0；SEER_ROBOT_2（挑战 1 侧持权）→ 0→1；NONE 为防御分支（0→1）
   〔源: src/fsm/battleFsm.cpp:2126-2138〕——持权方**恒后结算**。SEER_ROBOT_1/2 的
   语义已钉死（S18 2026-11-05）：resolve_first_mover_id 与 is_second_mover 两处
   消费口径一致——ROBOT_1 → 0 侧先手、ROBOT_2 → 1 侧先手〔源: src/fsm/battleFsm.cpp:44-49〕
   〔源: include/fsm/battleContext.h:941-951〕。对照官方两句（时点判定流程表 §回合结束时）：
   句②「双方均出手或者任意一方出手时，未获得先手权的一方先结算」**一致**；
   句①「双方都不出手时，获得先手权的一方先结算」**相悖**——引擎对双嗑药轮的先手权
   做 sbs_rand 随机 tie-break〔源: src/fsm/battleFsm.cpp:1764-1768〕且仍让持权方后结算。
   场景 7791 R1-R3 实证（均出手 [1,0] / 一方嗑药 [0,1] / 双嗑药不变量），分歧实录与
   内核修法见 §六.1〔源: 场景7791 R1-R3 断言〕。
5. **「被击败效果失效」压制**：该方被置压制位时，它的"被击败时/被击败后"类时点
   桶整体不执行（百罗鬼帝 2085 诅咒包）〔源: src/fsm/battleContext.cpp:1029-1044 + include/effects/event_center.h:394-397〕。

### 2.3 mover-only 坑：受击效果为什么必须挂事件（谱尼虚无/犀牛）

**坑**：「自身受到攻击伤害后……」一族效果，若挂在 `_AFTER_ACTION`（行动后）等
动作流程时点，**防守方根本不会执行**——那些桶只跑当回合 mover 一侧，
而受击方通常不是 mover〔源: resources/soul_lib/legacy_guards.cpp:66-68 + resources/soul_lib/puni_1038.cpp:185-190〕。

- **谱尼·虚无**（1038）「自身受到攻击伤害后，免疫下1次受到的技能伤害」挂
  `EVENT_TAKE_DAMAGE` 监听；头注明说"也不能改挂'行动后'时点……谱尼作为防守方时
  根本不会执行（903 之赐就是靠这个语义'未行动不回血'）"——同一个语义，对 903 是
  特性（不出手就不回血），对虚无是坑〔源: resources/soul_lib/puni_1038.cpp:185-190〕。
- **犀牛**（1217）同理：回血/反弹挂 `EVENT_TAKE_DAMAGE`（伤害落地之后）而非
  `_AFTER_ACTION`，且"恢复自身所有体力"必须晚于扣血〔源: resources/soul_lib/legacy_guards.cpp:66-70〕。
- **判据**：效果主语是"自身 X 时"且 X 由**对方行动**引发（受击/被断/被消强）→ 挂
  事件；主语是"自身出手前后"（我方 mover 才有意义）→ 挂动作流程时点桶。

## 三、事件时点表（EventCenter，29 项）

### 3.1 事件模型三行（读表前必读）

1. **emit 只入队，绝不内联执行**：原语在成功路径末尾 emit，FSM 在"每个 State 的桶
   跑完后、推进下一个 State 前"统一 drain——桶迭代安全、无重入〔源: include/effects/event_center.h:249-259 + src/fsm/battleFsm.cpp:1278-1280〕。
   watcher 内再 emit 合法（级联），一次 drain 最多投 8 波，超限响亮告警丢弃〔源: include/effects/event_center.h:334-354〕。
2. **事件记"发射当时"的时点**：drain 时 FSM 已推进，回调里读 `ctx->currentState`
   拿到的是**下一个**状态——`BattleEvent.state` 在 emit 当场记录，判"这次伤害是
   哪个时点造成的"必须读 `ev.state`〔源: include/effects/event_center.h:173-179〕。
   犀牛与虚无都用它过滤"只认攻击伤害时点"〔源: resources/soul_lib/legacy_guards.cpp:118-122〕。
3. **唯一例外（emit 后立即 drain）**：`EVENT_BEFORE_SKILL_HIT` 是全局锚点——监听方
   必须在先手方该时点桶执行**之前**完成授票，故 emit 后立刻 drain，不等统一投递点
   〔源: src/fsm/battleFsm.cpp:1856-1866 + include/fsm/battleFsm.h:67-68〕。

## 五、「写效果选哪个挂点」决策树（给批产 agent 的实操页）

> 用法：拿到一句官方效果描述，从 Q0 顺着答，落到底即得挂点与注册写法。
> 三种挂点的注册面：时点桶 = `SOUL_PROGRAM(id,{SOUL_NODE(State::X, fn,…)})`
> 〔源: include/plugin/plugin_interface.h:33-63 + resources/soul_lib/k_anomaly_threshold_1210.cpp:279-281〕；
> 事件 = `ctx->event_center_.register_watcher(EventType::X,…)`〔源: include/effects/event_center.h:274-283〕；
> 管线 = `register_damage_effect(DamagePhase::X,…)`〔源: include/fsm/battleContext.h:1357〕。

**Q0 效果是"一笔攻击伤害内部的修正"吗？**（增伤/减伤/保底/锁伤/挡伤归零/受击检测）
→ 是：进管线，按语义选阶段——"额外"二字=AMP_EXTRA、通用增伤=AMP、点数减=REDUCE_FLAT、
百分比减=REDUCE_PCT、保底=FLOOR、锁伤=CAP、次数免伤/BLOCK 票=BLOCK、受击触发=DETECT
（全表与案例见 01 章 §二）〔源: include/effects/damage_pipeline.h:44-58 + docs_local/docs/10-游戏百科/01-伤害管线与时点链.md §二〕。
粉伤进粉管 10 阶段，不进红伤管线（01 章 §四.3）。

**Q1 效果主语是"自身受到/被 X"吗？**（受击后、被打死后、被消强后——被动方语义）
→ 是：**禁挂动作流程时点桶**（6–13/16–23 的桶只跑 mover，防守方不执行，§2.3）。
挂事件：受击=EVENT_TAKE_DAMAGE（红/粉/真分kind）〔源: include/effects/event_center.h:26〕、
受粉伤=EVENT_TAKE_PINK_DAMAGE〔源: include/effects/event_center.h:49-53〕、
预死亡=EVENT_HP_EXHAUSTED〔源: include/effects/event_center.h:55-61〕、
被消强=EVENT_STAT_REMOVED（带归因）/EVENT_STAT_BOOSTS_LOST（不带）〔源: include/effects/event_center.h:135-142〕。
回调内判"是不是攻击伤害"读 `ev.state` 是否 ∈ {FIRST/SECOND ATTACK_DAMAGE}
〔源: resources/soul_lib/legacy_guards.cpp:118-122〕。

**Q2 效果主语是"自身出手前后"吗？**（使用技能后、命中时、造成伤害后）
→ 是：挂 mover 的动作流程时点桶（ACTION_START/AFTER_ACTION/ACTION_END…，§2.1 表）。
"使用即触发"字面（哪怕 miss 也算）→ 不挂桶，监听 EVENT_SKILL_USED（它在使用起点发）
〔源: include/effects/event_center.h:33-35〕。

**Q3 效果要跨侧感知对方动作吗？**（"若对手使用属性技能""对手回血时""对手 PP 被降低"）
→ 是：事件面。技能声明类型=EVENT_SKILL_USED.used_attribute〔源: resources/moves_lib/j_must_crit_window.cpp:10-14〕；
回血落地=EVENT_HEAL_RESTORED〔源: include/effects/event_center.h:126-134〕；
PP 被效果动=EVENT_PP_REDUCED〔源: include/effects/event_center.h:106-113〕；
对手盔被结算=EVENT_SKILL_ARMOR_RESOLVED（grant_id 区分自己那条）〔源: include/effects/event_center.h:40-48〕。

**Q4 效果与"写后即知"的瞬时状态有关吗？**（同回合内对方强化了就压回去）
→ 是：事件面（EVENT_STAT_CHANGED）。时点桶在同一 State 内按 0→1 定序，先跑的一方
看到旧等级、压制迟到一拍；事件是唯一"写后即知"通道〔源: include/effects/event_center.h:76-82〕。

**Q5 效果是死亡/击败相关吗？**
→ 己方死亡兜底/复活=EVENT_HP_EXHAUSTED（反应型在回调写血即否决倒地）
〔源: include/effects/event_center.h:55-61〕；秒杀检测=EVENT_HP_TO_ZERO〔源: include/effects/event_center.h:62-65〕；
亡语/击败获利=EVENT_DEATH（target/cause 过滤；⚠别用 EVENT_OPPONENT_DEFEATED，它零 emit，§六.3）
〔源: include/effects/event_center.h:22 + resources/moves_lib/kongyuan_zhishi.cpp:229〕；
消逝≠死亡，监听亡语别认 EVENT_VANISH〔源: include/effects/event_center.h:66-70〕。

**Q6 效果是"到某个回合位置就做某事"吗？**（回合开始六项变化、回合结束回血、N 回合后引爆）
→ 是：时点桶。回合开始=BATTLE_ROUND_START（犀牛 1217 六项，
〔源: resources/soul_lib/legacy_guards.cpp:141-149,190〕）；回合结束=BATTLE_ROUND_END
（K250 1536 口径〔源: resources/soul_lib/k_curhp_attach_roundend_heal.cpp:30,180〕）；
新版精灵"回合结束后"=BATTLE_ROUND_REDUCTION_NEW_ROUND_END（官方时点表口径，§2.1）；
定时引爆=BATTLE_ROUND_REDUCTION_ALL_ROUND_MINUS〔源: resources/moves_lib/g_delayed_damage.cpp:12-16〕。
⚠注意：挂在 6–13/16–23 的节点，主人嗑药时不跑（§2.2.2）；"就算嗑药也触发"的
注册进被动桶（`registerEffect` 的 passive 容器，〔源: src/fsm/battleContext.cpp:1041-1044〕）。

**Q7 效果要在"先手方命中前"抢先布防吗？**（下 1 次技能命中前清零/授票）
→ 是：EVENT_BEFORE_SKILL_HIT（emit 后立即 drain，赶在桶执行前完成授票）
〔源: include/effects/event_center.h:114-125 + src/fsm/battleFsm.cpp:1856-1866〕。

**Q8 战前面板改写呢？**（能力减半、双防=双攻较低项）——不走 State 桶：战前魂印补丁
