## 检索惯例

- **查某机制怎么实现的** → 02-效果系统（主题档）+ 06-交接（grep 调研过程）；
- **查某精灵做了什么** → 06-交接（按精灵 grep）+ 已收官看板的 ✅ 行摘要；
- **领任务/夜跑** → [05-任务清单/夜跑总入口.md](../05-任务清单/夜跑总入口.md)（开工六步：领 agent ID → 读策略档 → 选板 → claim）；
- **夜跑基建** → `tools/night/`（README 有 v4 说明：agent ID + policy.json）；
- **服务器/部署** → 09-部署与运营（**mx2 维护走阿里云跳板**，上海直连晚高峰不可用）。

## 归档口径（2026-09-29 定，2026-10-20 增补）

1. 看板/工单：所有任务行 ✅ 且后续组接管后 → 移入 `05-任务清单/已收官/`；
2. 开工单（"开工-*"）：项目落地后移入 `已收官/`；
3. **设计文档不归档**：02-效果系统 的机制档是"现状描述"，随实现持续更新——
   它们的"完成"体现在内容里，不按时间归档；
4. 交接日志不拆分：编年体保完整，通用结论以附录/主题档承载；
5. **晨报归档**（2026-10-20 增）：`06-交接/夜跑晨报-*.md` 移入 `06-交接/晨报归档/`——
   晨报是时点记录（当夜做了什么），价值随合并记录沉淀而衰减，归档降检索噪音；
   合并记录/事故记录等**结论性文档留 06-交接 顶层**。
