# 培养数值构成调查（种族值/学习力/性格/刻印 → 面板）

> 状态：**调查 + 落地**（feat/peiyang，2026-09-26/27）。§1-3 调查与定稿口径；§4.0-4.5
> 设计议定；§4.4 刻印数据管线已建成；§4.6 培养合成+抗性已实现全绿（含 §4.4 六维序
> 勘误）；§4.7 控制台培养编辑器已实现并全链路验证；§7 复现与持久化简评。魂印对数值的
> 修改**不在本篇**（用户口径：那是另一部分）。

## 0. 一句话

**进对局面板（用户 2026-09-26 定稿口径）= 基础能力值（种族×2+学习力÷4+天赋，性格修正）
+ 刻印 + 体力上限加成（恒 +20）+ 战队加成**；套装/魂印的数值加成**一律局内结算**（不吃局外、
但它们的百分比在局内乘到上述全部固定加成上）。本引擎当前**完全没走这套**——`numerical_base`
直传六维成品，缺省全 0 时**种族值原样当面板**（没有 ×2、没有学习力/性格/刻印）。

## 1. 现状：数值怎么进对局（已核实代码）

| 环节 | 位置 | 现状 |
|---|---|---|
| 协议入口 | `BattlePetMessage`（include/entities/pet_factory.h:14） | 每宠 `numerical_base[6]` 直传成品；二进制可选尾段已有成熟模式（equip/standby/medicines） |
| JSON 入口 | `parse_pet`（src/server/battle_init.cpp:49） | 可选 `"base": [6]`，缺省全 0；web 控制台/gateway **不传**（gateway/catalog.py 只展示种族值） |
| 面板落账 | `PetFactory::create_numerical_base`（src/entities/pet_factory.cpp:426） | `直传值 > 0 ? 直传值 : monsters 表种族值`——**兜底 = 种族值原样** |
| 测试 | test/test.cpp:25、全部场景 | 一律 `{0,0,0,0,0,0}` → 全服实际跑的"面板"就是种族值 |

结论：学习力、天赋、性格、刻印在数值链路里**完全缺位**；直传成品数值是唯一"培养结果"通道，
代价是配置者要自己算好六维（麻烦，也不带结构信息）。

装备（套装）线是唯一已接的"培养类"数值：per-side `equip_item_ids` →
`BattleContext::resolve_equipment`（src/entities/suit.cpp:25，ctor 期）把
`custom_equip_stats` 的 flat/百分比行加到精灵本体（numericalBase+numericalProperties 同步）。
⚠️ 注意那是**玩家装备**（穿在赛尔身上、全队生效），与**刻印**（每只精灵自己的刻印孔）是两个系统。

## 2. 官方口径：面板数值构成（网络语料，2025-03 攻略）

来源：4399《【赛尔号巅峰之战攻略】PVE精灵配置详解》（2025-03-09，a.4399.cn）+ 百度百科"全能刻印"
+ 性格表（百度知道）等，均为社区对现行官方游戏的归纳，标注为**口径**而非官方文档。

### 2.1 基础能力值（等级、种族、学习力、天赋、性格）

```
非体力项 = floor[(种族值×2 + 学习力÷4 + 天赋值 + 5) × (等级÷100) × 性格修正]
体力     = floor(种族值×2 + 学习力÷4 + 天赋值 + 110)          ← 满级口径
```

- 满级 100 时非体力项退化为 `(种族×2 + 学习力÷4 + 天赋 + 5) × 性格修正`。
- **学习力**：玩家自由分配，总和上限 **510**、单项上限 **255**（TapTap 攻略口径，
  与主游戏历史口径一致）。
- **天赋（个体值）**：0–31/项，洗练道具可刷；竞技环境默认**全 31**（确定性，这就是
  用户没把它列进四要素的原因；落地时建议做成常量 31，协议不传）。
- **性格**：约 24 种，五维（攻/特攻/防/特防/速）各 ±10%，**体力不受影响**；
  5 种平衡性格修正 1.0。性格表需要做成**本地静态表**（24 行，无官方结构化数据需求）。

### 2.2 面板合成（4399 攻略原文归纳，供参照）

```
面板能力值 = floor[(基础能力值 + 专属特性加成 + 刻印加成 + 年费加成 + 称号加成 + 目镜加成)
                   × 绝大多数套装百分比加成
                   + 道具加成]
```

- 固定值加成**先进括号相加，再统一吃套装百分比**（"绝大多数"= 有例外套装，攻略原文保留）。
- 4399 该文是 PVE 语境：其"专属特性加成"疑即 `new_se` stat=2 训练加成类（官方注明
  **赛尔间对战无效**，docs_local/docs/06-交接/数据管线迁移到Unity端-交接.md:117）。
- 年费/称号/目镜为本引擎**不建模**项（用户口径未列入培养链；如将来要加，属 per-side 常量段）。

### 2.3 定稿口径（用户 2026-09-26，覆盖 4399 原文与本篇初版推断）

**进对局前**（全部 pvp/pve 通用，两项口径无差别）依次完成：

1. 天赋拉满 31（常量，协议不传）；
2. 升到满级 100；
3. 性格配置好；
4. 学习力点好；
5. 刻印装好；
6. 最后叠加两项固定加成（**都是逐精灵开启**，用户 2026-09-26 确认）：**体力上限 +20**
   （任何精灵可加，上限 20，直接裸加）与**战队加成**（六维都有值，工作数值见 §2.4）。

**进入对局**后：套装、精灵魂印的数值加成才结算——它们的**百分比因此乘到上面所有固定加成
（刻印/体力上限/战队）之上**。套装加成整体不进局外计算：有的套装除数值外还有机制，
"数值局外、机制局内"拆两个阶段太麻烦（用户原话），所以套装的数值行和效果行**都留局内**。
魂印/套装是唯一存在 pvp/pve 口径差异的部分，本篇不涉及。

对引擎现状的含义：套装线本来就在 `BattleContext` 构造期（局内）做 `resolve_equipment`，
且应用顺序就是"先 flat 后 pct"（`base = (本体 + flat) × (100 + pct) / 100`，
src/entities/suit.cpp:136）——**与定稿口径天然吻合，套装线无需改动**；培养线只需保证
局外面板合成不含任何套装项。

### 2.4 两个额外固定项

| 项 | 口径 | 数值 | 来源/状态 |
|---|---|---|---|
| 体力上限加成 | **逐精灵开启**，上限 20，裸加体力 | 恒 +20 | 用户口径（2026-09-26 确认逐精灵）；游戏内系统名疑为"养成加成/永固体力合剂"，名称待核（不阻塞建模） |
| 战队加成 | **逐精灵开启**，六维都有值 | **工作值：体力 30、攻/特攻/防/特防 15、速度 10**（B 站科普指南 5 级口径；用户拍板先按体力 30 算） | 网上无权威数值表，工作值待游戏内最终校 |

建模：两项都是 per-pet 布尔开关 + **数值放配置表**（后续官方数值校准只改数据不改代码）；
实际对局里通常全队点亮，协议可以做成 per-pet 可选字段、缺省全开。

### 2.5 刻印系统结构（百度百科 + 社区攻略）

- **每只精灵 3 个刻印孔**（最多 3 件），装配后绑定不可转移；配装黑话"252/353/555"=
  三孔的角数组合。
- 分类：**全能刻印**（两角/三角/四角/五角，角数越多越强，2014 改版核心）、
  **专属全能刻印**（只有对应专属精灵能装）、冠名刻印（活动顶级）。
- 数值量级：全能刻印单项加成普遍 100+，顶级约 260；示例（4399 圣系列页）：
  圣·虚无 = 体力90/攻击55/防御25/特防25/速度35（角刻印可只覆盖部分属性项）。
- 刻印还带**战斗被动效果**（类似套装的程序效果）——这部分属效果线，数值线只管加成值。
- **本地无刻印数据**：seer_official/seer_unity 两库均无刻印表（`equip` 表 351 件全是
  战盔/腰带类玩家装备，0 件刻印）→ 需要新数据管线（图鉴/百科采集 + 认证数据层新表，
  仿 `custom_equip_stats` 离线编码模式：stat_index/amount/add_way/scope + 效果 id）。

## 4. 落点建议（培养线接缝，供后续任务拆分）

### 4.0 合成逻辑放哪：组装层，不是客户端也不是对战内核（2026-09-26 议定）

用户问"客户端算好面板直传行不行——对局内没有效果能动天赋/清战队加成，内核只收开始前的
数值就够"。**结论：对战内核确实不需要知道培养**（这点判断正确，局内只读面板），
但合成逻辑也不该放调用方客户端，而是放**组装层 `PetFactory`**——这正好落在
CLAUDE.md 分层的"组装层（entities）"，不碰内核层/调度层：

1. **刻印目录在库里**：合成要查刻印 flat 加成（未来的认证数据层新表），客户端没有
   DB 访问；PetFactory 本来就读 monsters，刻印表是顺手的事。客户端合成就得复制一份
   刻印表或新开查询接口，两头维护。
2. **单一实现**：公式 + 性格表 + EV 上限校验只有一份，web 控制台/测试/机器人/AI 训练
   全部免费获得；客户端各写一遍必然漂移。
3. **协议传培养字段而非成品面板**：结构信息（性格/学习力/刻印）进请求才能支撑
   AI 预测（§5）——既然字段都要过协议，合成放引擎侧零额外成本。
4. **对战内核零改动**：FSM/效果层照旧只读 `numericalProperties`，"局内没有机会改
   天赋/清战队加成"在引擎里本来就不存在这些概念。

### 4.1 协议

`BattlePetMessage` 加可选尾段（沿用 equip/standby 模式）：
`ev[6] + nature_id + keryin_item_ids[3] + hp_cap20_flag + guild_flag`；JSON lineup 加可选
同名键。缺省 = 现行为（直传面板/种族值兜底），旧包零影响。hp_cap20/guild 缺省**全开**
（拟真默认，实际对局通常全队点亮）。

### 4.2 面板合成（组装层，局外）

`create_numerical_base` 扩为两模式：
- 直传（兼容，调试自由模式）；
- 培养合成（拟真模式）：
  `面板 = (种族×2 + ev÷4 + 31 + 5) × 性格 + 刻印flat合计 + 20×开关 + 战队六维×开关`
  （体力槽无性格项、+110 口径）。合成点在 PetFactory（per-pet，能查 monsters 种族值）。

### 4.3 套装不动

数值与效果都留局内（`resolve_equipment` + 套装桶，现状即符合定稿口径）。
唯一要保证的是局外合成**不含**任何套装行，避免双重结算。

### 4.4 刻印数据管线（✅ 已建成，2026-09-26）

**数据源钉死**：游戏内系统名 = **mintmark**。Unity 端配置 `mintmark.bytes`（刻印目录）+
`mintmarkElevare.bytes`（升级链），走现有镜像管线（SeerAPI/seer-unity-assets，30 分钟同步），
solaris 自带 `MintmarkParser`/`MintmarkElevareParser`——**零新解析代码**，三步管线各接一处：

1. `scripts/fetch_seer_unity_bytes.py`：`BATTLE_CONFIGS` 增 `mintmark`/`mintmarkElevare` 两行；
2. `scripts/decode_seer_bytes.py`：零改动（按 solaris 解析器清单自动覆盖）；
3. `scripts/import_seer_unity_sqlite.py`：SCHEMA + 三个 importer（DELETE 重灌模式，
   `custom_equip_stats` 等手工表不在 IMPORTERS、安全保留）。

**入库结果**（scripts/data/processed/seer_unity.sqlite）：

| 表 | 行数 | 内容 |
|---|---|---|
| `mintmark` | 3837 | 刻印目录全量。type 0=属性刻印 386（微型/初级/全能/**专属单体**，`arg`=[6] 固定加成）；type 1=技能刻印 660（绑定 `move_id`，先制+1 等，已绝版）；type 3=系列成长刻印 2788（`base`→`max` 六维，圣·虚无/帝皇之戎专属全能等）；type 4=碎片素材 3 |
| `mintmark_class` | 97 | 系列名（睿智/狂战/圣系列…） |
| `mintmark_elevare` | 20 | 升级链 origin→elevare（泰坦之威α[Ⅰ]…）+ 材料清单 |

**关键字段口径（已实测钉死，含一次勘误）**：

- **⚠️ 官方六维序 = [攻, 防, 特攻, 特防, 速, 体]**——初版误判"与引擎序一致"，场景 135
  断言翻车后勘误：圣·虚无 effect_des 五项（攻/防/特防/速/体，**无特攻**）↔
  max=[55,**25,0**,25,35,90]，防在 index1、特攻恒 0 在 index2；圣·元素
  max=[55,**30,0**,30,30,85] 同构印证。`load_mintmark` 已把官方序重排为引擎序
  [攻,特攻,防,特防,速,体]，引擎侧一律拿引擎序（DB 存官方原序）。
- 成长型（type 3）：`base_attri_value`（强化前）→ `max_attri_value`（强化满）。
  **引擎面板按强化满（max）计入**——竞技环境默认满强化（与天赋恒 31 同理）。
- `extra_attri_value`：342 条系列刻印的额外成长段（base+extra≤max），是否独立于 max
  叠加**待实测**，先落库不参与合成。
- `monster_id`：2519 条专属绑定（天雷鼠体力刻印→15 等）；`hide`：84 条隐藏/未放出
  （合成时建议过滤）。
- 顶级数值量级与百科口径互证：专属全能刻印 max 合计 ~240（帝皇之戎 55+25+25+40+95），
  系列刻印单项 max 最高 55/70（睿智 体70+防32）。

**回归**：重建库后 `sim_smoke_test` + 场景 001 通过；`custom_equip_stats` 16 行原样保留。

**遗留**：`statinfo` 字段（负大整数，疑 hash）不落引擎；角数与 `quality`/`grade` 的映射
（圣·虚无 quality=5=五角?）待与游戏内界面核对——不影响数值合成，只影响"252/555"式
配装黑话的解析。

### 4.5 抗性系统接入（伤害抗性×3 + 异常抗性 3+3，组装层收口，内核零改动）

**官方口径**（4399 抗性系统解析 + 百度百科"精灵抗性"，2026-09-26 查证）：

- 抗性系统 per-pet **开启制**：没开启的精灵永远不触发抗性抵抗。
- **伤害抗性**（暴击/固定/百分比）：开启后初始各 **5%**，红宝石强化单项上限 **35%**。
- **异常抗性**：控制类 3 槽 + 非控制类 3 槽（槽位自选异常种类），绿宝石强化单项上限 **50%**。
- **全免抗性**：累计 200 绿宝石解锁（对应 `ResistanceSystem::complete_immunity`），
  概率值待游戏内确认。

**内核现状（2026-09-26 核实，两侧都已通，无需改动）**：

- 异常抗性：`apply_anomaly` 在魂免前 roll `pet.resistance.isResistantTo()`；
  槽位全 0 时 roll 永不命中 = "未开启永不触发"天然成立。
- 伤害抗性：`sync_damage_resist_view` 回合开始/换宠从本体重基 ws 视图；
  暴击抗性进红伤暴击段、固定/百分比抗性进粉伤管线 RESIST 段。
- "开启"不需要内核开关：未开启 = 组装层强制全 0，行为等价且零侵入。
  （`ResistanceSystem` 类内校验保持 0–100 通用 sanity；**官方上限 35/50 在组装层钳**，
  游戏数值与通用容器各管各的。）

**接入方案（全部在组装层 + 协议）**：

1. 协议：`BattlePetMessage` 可选 `resist` 段：
   `{enabled, damage[3]≤35, control[3]{anomaly_id,pct}≤50, uncontrol[3]{anomaly_id,pct}≤50,
   complete_immunity?}`。
2. **阵容级默认**（用户要求，免得逐精灵配置）：lineup 级 `resistDefault`：
   `off`（缺省，全 0）/ `opened`（伤害 5/5/5，异常槽 0）/ `maxed`（伤害 35×3，异常槽自选满 50）；
   per-pet 显式配置覆盖默认。注意 `maxed` 的异常槽必须带 anomaly_id（防谁抗谁不明确）。
3. `PetFactory::create_pet` 落账：按官方钳制（damage ≤35、异常槽 ≤50、anomaly_id 合法性
   复用 `is_valid_abnormal_status_id`）；`enabled=false` 强制全 0。
4. 场景测试既有用法（直改本体 + 手动 `sync_damage_resist_view`）不受影响。

## 5. 对"引入刻印后预测对手配置"的简评（用户问题的第二半）

成立，而且收益不止数值预测：

- **结构约束收窄解空间**：自由直传的六维是 6 个无结构整数；培养合成后，面板被
  `面板 = (2×种族 + ev÷4 + 36)×性格 + 刻印 + 20 + 战队` 反向约束——ev 总量 ≤510/单项 ≤255、
  性格只有 24 种离散修正、刻印来自有限目录且仅 3 孔。给定观测（面板/血量/出手顺序），
  可行的 (性格, ev, 刻印) 组合远比自由六维少 → AI 推断对手配置更精确。
  体力上限与战队加成是固定常量开关，**不增加预测不确定性**，有信息量的仍是刻印/性格/学习力。
- **AI 训练不受"合成在引擎侧"影响，反而更顺**（回答"不载入内核会不会影响预测"）：
  预测器要学的正是"观测面板 → 反推培养配置"，需要 (结构化输入, 合成面板) 成对数据。
  合成放组装层后，AI 训练走正常建队路径就同时拿到**真值配置和合成面板**（同进程同库），
  标注免费；对战内核照旧只读面板、不需要培养概念。反过来若在客户端合成、协议只传
  6 个成品数，AI 才真的丢结构信息——那是要避免的形态。
- **确定性效果可预判**：刻印/专属刻印自带战斗被动（同套装）。对手"555 配置"这类
  信息一旦确定，对应被动效果是**确定性**的，AI 可直接把"对手可能挂着哪些套装/刻印被动"
  纳入决策，而不是只猜数值。
- **代价**：配置空间从 6 个自由数变成结构化输入，协议和测试夹具都要跟着改；
  建议保留直传通道作为"调试自由模式"，培养合成作为"拟真模式"。

## 7. 复现与持久化简评（用户 2026-09-27 问）

**培养文件持久化：现在不做。** 阵容 JSON（含 `cultivate` 段）天然就是培养配置的持久化
载体，导出/导入 = 把 lineupPayload 存/读文件，控制台加两个按钮的事（约一小时），
不需要单独的文件格式设计。等真出现"分享配置/批量备份"需求再做不迟。

**对局复现（存阵容 + 操作序列）：设计上成立，今天就能用，但有两个前置条件要认清。**

- 引擎 FSM 对 (初始面板, 操作序) 是确定的；操作按提交序排队，FSM 无墙钟依赖。
- ⚠️ **随机数**：引擎 9 个文件直接用全局 `std::rand()`（暴击/命中/浮动/抗性 roll 等），
  从不 `srand(time)`——默认种子下同平台序列固定。因此：**同机、同引擎版本、独占运行**
  （一次只跑一局）时，`阵容 JSON + 操作序 [(robot, actionType, index)...]` 可精确复现。
  但 sim_server 多线程跑多局时（--threads 4），全局 rand() 被各局交错 → 单局不可复现。
- **要做生产级复现**（随时、并发多局）需一次 RNG 收口：每局一个带种子的本地生成器
  （lineup 带 seed、快照记录 seed），把 9 处 `rand()` 调用换成局上下文注入——工作量中等
  （机械替换 + 场景回归），建议等复现需求真正落地时做。
- 另注意复现绑定**引擎版本**（效果实现演进会改变序列）：回放记录里存 git commit 一并落盘。
