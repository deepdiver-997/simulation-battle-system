# 10-内核注 —— 内核头文件的长注释下沉模块

## 目的

`include/` 的内核头是**契约面**（被 sim_core 与插件 dylib 双镜像共享），本应一眼概览
全部成员与函数；现状是 40% 行数为设计裁决长文，注释淹没结构。本模块承接这些长文：
**声明处只留 1-3 行规整短块（= clangd hover 显示面），长文按符号名锚点下沉到这里。**

## 边界（2026-11-22 用户裁决）

- **只收内核头**：`include/fsm/battleContext.h`、`include/fsm/battleFsm.h`、
  `include/effects/{rule_center,event_center,spirit_lifecycle}.h` 等被双镜像共享的契约面。
- **效果库（resources/）不进本体系**：307 个实现文件的头注（锚点/四查/记档/键段）
  已是它们自己的文档体系——自包含、与实现同址、registry+场景提供发现面。跨效果
  的机制规格仍在 `docs/02-效果系统/`。本模块只记录**内核缺失的注解**。

## 条目格式（五段，固定）

```markdown
## <符号名>            ← 锚点 = 声明处的 C++ 符号名（跟随 rename，不用行号不用序号）
一句话语义：…
谁写谁读：…
生命周期：…
裁决史/引注：…（原文照搬，含用户口径日期与语料 idx）
关联：…（同机制的其他符号 / 外部文档）
```

## 代码侧指针格式

声明上方短块（≤3 行）的末行：`详: 内核注#<符号名>`——可 grep 直达；hover 显示
短块 + 指针行，快捷查看与零空间占用兼得。**不用文件+行号**（必漂），不用数字
序号（无语义、多一层映射、会冲突）。符号 rename 时本目录同步改标题（diff 可见）。

## 迁移规则

- ≤5 行且无裁决史 → 留原地，不下沉；
- >5 行或含裁决史/多方案对比 → 下沉，声明处留短块；
- 迁移时**原文照搬**进"裁决史/引注"段（只删排版缩进），不做意译压缩——裁决
  细节丢一句就是口径事故；
- 效果参数解包、伤害管线等**已有专属文档**的主题（docs/02-效果系统/）不重复
  建条目，短块里直接指过去。
