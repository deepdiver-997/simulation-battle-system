# 线协议规格（sim_server 二进制协议 + 调试台网关）

> 面向想自研客户端/控制台的开发者。读完本文 + 任一参考实现即可接入，
> 不需要读引擎源码。规格与实现同步维护：改协议先改
> `include/server/protocol.h`（枚举与帧）与本文。
>
> 参考实现：
> - C++ 命令行客户端 `tools/training_cli.cpp`（最小直连样例）
> - 服务端侧 `src/server/session.cpp`（命令分发）、`src/server/output_json.cpp`（JSON 组装）
> - Web 网关 `web/gateway/app.py`（REST+WS ↔ 二进制协议翻译层，本地维护）

## 0. 总览：三层与两条自研路径

```
你的客户端 ─┬── 路径 A：直连 sim_server，说本文的二进制线协议（:4399）
            └── 路径 B：连调试台网关（:8070）的 REST/WS，JSON 交互
                 └── 网关 ── 二进制线协议 ──> sim_server（未改动协议本身）
```

- **路径 A**：适合 CLI、机器人、自动化测试。零中间层，协议即本文 §1-§6。
- **路径 B**：适合浏览器/富前端。网关额外提供目录/图鉴/覆盖率等只读数据 API（§7）。
- 服务端**没有任何鉴权**（见 §8 安全模型）；网关可选共享 token 鉴权（§7.3）。

## 1. 传输与会话生命周期

- 传输 = TCP；服务端默认 `127.0.0.1:4399`（`--port`/`--host` 可改，须在仓库根运行）。
- **单连接单对局**：一条连接 = 一个座位。`solo` 模式（默认）一条连接打一局（对面是
  FSM 镜像）；`--mode pvp` 两条连接撮合一局，先连的坐 0 号位。
- 生命周期：连接 → 客户端发 `INIT_BATTLE`/`INIT_BATTLE_JSON` 开局（服务端分房，
  回 `ROOM_INFO`）→ 双方按 `INPUT_REQUIRED` 轮流提交动作 → 引擎推到 `FINISHED`
  后服务端推 `BATTLE_OVER` → **连接可复用再开下一局**（再次 INIT 即重开）。
- 断开：solo 断开即弃局；pvp 一方断开，另一侧收到 ERROR 后对局作废。
- 引擎推进一步会连带产生一串事件帧（§5）；客户端只需循环"等 INPUT_REQUIRED →
  发动作 → 收事件带"。

## 2. 帧格式

所有帧（双向）：

```
偏移  长度  字段
0     4    total_length  大端 uint32，含自身（= 10 + payload 长度）
4     2    command       大端 uint16（命令枚举见 §4/§5）
6     4    uuid          大端 uint32，= 服务端 match_id（路由遗产，客户端可忽略/原样回显）
10    ...  payload       二进制或 UTF-8 JSON 文本（按命令定）
```

- 全部多字节整数**大端**（手写编解码，不依赖 `<arpa/inet.h>`，见 `protocol.h`）。
- 帧长校验：`10 ≤ total_length ≤ 1 MiB`，越界直接断连（防内存放大，`include/net/framing.h`）。
- ⚠️ 已知坑（`protocol.h` 头注释原文）：动作 payload 如果误用本机小端写
  `action_type=1`，服务端会读到 `16777216` 落进 default 分支，动作被拒
  （"rejected, please resubmit"）。一律大端。

### 3.1 INIT_BATTLE_JSON（solo = 双方阵容；pvp = 只有自己一侧）

```json
{
  "side1": { "pets": [ {...}, ×6 ], "traitId": 0 },
  "side2": { "pets": [ {...}, ×6 ] },
  "resistDefault": "off" | "opened" | "maxed_damage"
}
```

单宠对象（字段全部可选除 petId；校验在 `src/server/battle_init.cpp`）：

```json
{
  "petId": 4912,            // 必填，>0，精灵 id
  "level": 100,
  "skills": [id,id,id,id,id],   // 恰好 5 个技能 id
  "traitId": 3,                 // 通用特性 id
  "effectParams": [ {"skill":id, "effect":id, "index":n, "value":v} ]
                                // 词条参数覆盖（调试台线）：改某技能某模板第 n 个 {n}
}
```

pvp 下改发 `{"party":[...×6], "traitId":0}`（只含自己一侧的宠物数组，键名 `party`），
服务端按座位落边。解析失败回 ERROR（"bad lineup: <原因>"）。

### 3.2 动作 payload 的 action_type

与 `BattleFsm::ActionType` 枚举序一致：

| 值 | 动作 | index 含义 |
|---|---|---|
| 0 | CHOOSE_PET | 上场的场下槽位 |
| 1 | SELECT_SKILL | 技能槽 0-4 |
| 2 | USE_MEDICINE | 药剂槽 |
| 3 | NONE | 跳过出手（回合类效果照常触发），index=0 |
| 4 | SEND_EMOJI | 未使用 |

robot = 座位号（0/1；solo 固定 0）。动作合法性以 `INPUT_REQUIRED.legal` 为准——
发引擎不收的动作会回 ERROR/rejected，白消耗一轮。

## 4. 客户端主循环（伪代码）

```
connect :4399
send INIT_BATTLE_JSON(lineup)
loop:
    f = read_frame()                      # 按 §2 切帧
    switch f.command:
        INPUT_REQUIRED: if f.payload.player == my_seat:
                            choice = pick(f.payload.legal)   # 你的策略层
                            send SELECT_SKILL(robot, type, index)
        BATTLE_OVER: break
        ROOM_INFO / TAPE / SYNC_STATE / ERROR: 渲染或记日志
```

完整可跑样例见 `tools/training_cli.cpp`（含 auto 自动对打）。

## 5. 服务端 → 客户端 JSON

### 5.1 INPUT_REQUIRED（轮到你）

```json
{
  "match": 1, "player": 0, "round": 3,
  "state": 46, "stateName": "后手方技能效果结算",
  "reason": "choose_action | choose_pet_after_death",
  "snapshot": { ...权威快照，同 SYNC_STATE，收到即可直接渲染... },
  "legal": {
    "canAct": true, "prospective": false, "reason": "",
    "mustChoosePet": false, "canSkip": true,
    "skills": [ {"index":0,"id":38283,"name":"忷魔涸焦血","pp":5,"maxPp":5,"usable":true}, ... ],
    "pets":     [ {"slot":1,"id":4912,"name":"生之焰·灰蛾","hp":3000,"maxHp":3000,"onStage":false,"usable":true,"reason":""}, ... ],
    "medicines":[ {"index":0,"itemId":1,"name":"药剂","count":2,"usable":true}, ... ]
  }
}
```

`legal` 与服务器 `compute_legal_actions` 同源（切换锁/死亡/凝滞瘫痪过滤已做），
`mustChoosePet=true` = 死切期（此时合法集合只含 CHOOSE_PET）。

### 5.2 TAPE（事件带）

一次推进内每个 FSM 时点一条采样：`{"match":1,"from":seq,"to":seq,"samples":[...]}`，
sample 含时点 id/名、叙事文本、伤害落点等（组装在 `output_json.cpp: tape_to_json`，
采样源在 `BattleContext::tape_`）。客户端按 seq 排序回放即可。

### 5.3 ROOM_INFO

`{"match":1,"seat":0,"seats":1,"mode":"solo"}`

### 5.4 BATTLE_OVER

`{"match":1,"winner":0|-1(平),"reason":"normal|...", "snapshot":{...}}`。
胜负口径（2026-10-01 D5 结算模型）：按终局立旗时的存活数判（其后亡语复活不改判），
"视为存活"加账（黄金万象）叠加，双方皆 0 = 平。

### 5.5 HELLO 版本指纹（2026-10-01）

连接建立后客户端应先发 HELLO，服务端原样回命令号，payload：

```json
{"protoVersion":1,"registryHash":"a071f28f5975f2a1","stateSchemaHash":"39936744ff540485"}
```

| 字段 | 演化方式 | 变化意味着 |
|---|---|---|
| protoVersion | 手动 bump（`protocol.h kProtocolVersion`），仅破坏性变更 | 帧语义不兼容，客户端必须升级 |
| registryHash | **自动**：注册表导出全文 FNV-1a | 时点/异常/票类型对照表或已注册效果变了——显示面对照表该刷新 |
| stateSchemaHash | **自动**：快照 JSON 顶层键集 FNV-1a | 快照加/删字段——渲染快照的代码该跟进了 |

设计动机：网关对战斗帧透明转发，内核加字段时旧显示面会**静默漏显**。指纹让
"引擎加了新东西"在连接时被发现：网关与自己的基线比对（引擎被单独重建→大字报警），
前端与 localStorage/启动时指纹比对（引擎更新→不可关闭的刷新横幅）。姿势对齐插件
ABI 校验（core_api.h verify_plugin_abi：内容自描述、连接即核、响亮报警）。
stateSchemaHash 为空串 = 探针失败（降级不阻塞握手）；老服务端不识别 HELLO 会回
ERROR 帧——客户端按"指纹不可用"处理，不要当致命错误。

### 5.6 SYNC_STATE 快照

权威状态 JSON（`BattleContext::getStateJson`，`src/fsm/battleContext.cpp:1189`）：
双方 onStage/hp/场上宠详情/round 等。完整效果表转储用 DEBUG_FULLSTATE
（`getFullStateJson`）。**schema 不在本文逐字段展开**——它是引擎状态的直接投影，
随引擎演进；客户端应宽容未知字段（JSON 向后兼容）。

## 6. DEBUG_MUTATE 白名单（调试手术）

payload `{"ops":[{...},...]}`，仅在 FSM 泊车（等输入/单步/断点停）时执行，
推进中拒绝（注入语义要求"此刻"）。逐条回执 DEBUG_MUTATE 帧
`{"ok":true,"notes":[...]}` / `{"ok":false,"error":...}`：

| op | 参数 | 语义 |
|---|---|---|
| set_hp | side, slot, value | 直写体力（走引擎钳制） |
| set_pp | side, slot, skill, value | 直写技能 PP |
| set_level | side, stat, value | 改能力等级 |
| anomaly | side, id, rounds | 施加异常（走 apply_anomaly 原语） |
| cure | side, id | 解除异常 |
| mark | src, dst | 挂印记 |
| unmark | side | 清印记 |

白名单设计的动机：客户端不能裸写 context（会把免死/复活/清除时点等不变量改破），
具名操作走引擎存储与校验落地（`src/server/room.cpp: debug_mutate`）。

## 7. 调试台网关（:8070，本地维护 web/gateway）

浏览器(JSON/WS) ⟷ sim_server(二进制) 的翻译层 + 数据面。一条 WS 连接 ⟷ 一条
sim_server solo 会话，帧双向转发（网关不解析动作语义，只翻译帧容器）。

### 7.1 REST（节选，全部 GET 除注明）

| 路由 | 内容 |
|---|---|
| /api/pets, /api/pets/{id} | 精灵目录/详情（4399 图鉴展示优先，DB 回退） |
| /api/moves/{id}, /api/moves/{id}/effects | 技能与效果链切片 |
| /api/traits, /api/meta | 通用特性 / 元信息 |
| /api/effect-index | 注册表导出（moves/soul 已注册效果，K 板数据面） |
| /api/coverage (+ POST /refresh) | 效果覆盖率 |
| /api/sample-lineup, /api/cultivation/* | 示例阵容 / 培养 |

### 7.2 WS /ws/battle

浏览器消息 = JSON 包裹的线协议帧（cmd/payload 字段），网关转成二进制帧发给
sim_server，反向同理。前端因此完全不必实现二进制编解码。

### 7.3 鉴权（网关有，sim_server 没有）

- 默认关。`--auth-token 'tokenA,tokenB'`（或 `SBS_AUTH_TOKEN`）启用**共享 token**
  （每人一把便于日志归因），客户端请求带 `Authorization` 头；附带按 IP 限流/封禁、
  可选 TLS（`--tls-certfile/--tls-keyfile`）、`--trust-proxy` 取 X-Forwarded-For 末跳。
- **对外监听（--host 0.0.0.0）而不启用 token 会在网关日志打 WARN**：任何能连到
  端口的人都可开局/对账。
- 网关 → sim_server **无鉴权**（本机回环信任模型）：sim_server 只应监听 127.0.0.1，
  对外暴露一律走网关这层门。

## 8. 安全模型小结

| 层 | 鉴权 | 威胁模型 |
|---|---|---|
| sim_server :4399 | 无 | 只监听回环；帧长越界断连；DEBUG_MUTATE 白名单防不变量破坏 |
| 网关 :8070 | 可选共享 token + IP 限流封禁 | 面向 LAN/隧道暴露时的门；token 错 10 次封 IP |

## 9. 兼容性注记

- 帧 uuid 字段是"单连接多对局"时代的路由遗产，现为 match_id 回显；新客户端可忽略。
- HELLO 前服务端无任何握手；客户端不发 HELLO 也能正常对局（指纹是报警器不是门禁）。
- INIT_BATTLE 二进制格式（13×int32/宠）为老兼容保留；新客户端一律用 INIT_BATTLE_JSON。
- 未知 command → ERROR 帧（不静默）；未知 JSON 字段应被客户端宽容（快照会随引擎加列）。
- 协议演进约定：只加命令/加字段，不改既有语义；改协议先改 `include/server/protocol.h`
  并同步本文。
