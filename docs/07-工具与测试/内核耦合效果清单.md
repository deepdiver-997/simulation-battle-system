## 5. 驱逐/切出成因（src/fsm/battleFsm.cpp，2026-11-21）

「驱逐」是内核概念，不是效果：效果层只做两件事——**授策略票**与**置待决位**，
执行全部在 FSM。外部贡献者要接这条线时，改动点等同内核改动：

- **切出成因改写**（玄武 2553 / 蜃都之源 539 同款子句「双方的主动下场均视为
  驱逐下场」）：效果层经 `RuleCenter::grant_leave_cause_reclass` 授
  `LEAVE_CAUSE_RECLASS` 票（condition 回调 = 持有者存活于出战背包）；FSM 在
  `handle_OperationChooseSkillMedicament` 收包转化（CHOOSE_PET→EXPEL，参数不变，
  **不发 EVENT_SWAP**）。查询桥是内核唯一耦合点——不要在效果层自己拦操作流。
- **强制驱逐执行**（effect_des 402 通用机制；混元天尊 403"辛死亡驱逐对手"）：
  插件契约 = 触发时置 `ctx->forced_expel_pending[side] = 1`（单写者）。守卫
  （对象存活 + 存在合法替补）、随机补位（**排除 `is_locked` 放逐锁**——
  2026-11-21 用户口径）、机器填 `EXPEL` op、`perform_switch(EXPELLED)` 全在
  `handle_BattleRoundStart` 入口锚点（`apply_forced_expels`）。
- **面板锁**：`compute_legal_actions`（server）与 FSM 收包校验是同一标志的
  双消费（只认 NONE / 合法集合只剩空过）——改任何一侧必须同步另一侧。
- **场域管辖开关**（2026-11-21 用户裁决）：本机制实质是"场下源改写场上判定"，
  官方现状双标（新精灵不受薇尔诗 2513 场下源抑制影响）→ 票默认豁免
  （`kReclassSubjectToOfffieldBlock=false`，rule_center.h）。一视同仁翻这一个
  常量即可；授予方可按效果用 `outfield_block_exempt` 显式点名。查询门在内核
  has_leave_cause_reclass——开关必须全局可翻，不下沉插件。
- 锚定数据：effect_icon 行 2144（effect_id 2553）、effect_des 402/403/539、
  语料《机制解析—镇世神岳·玄武》（all_posts_final.jsonl 行 489）。
- 场景：test/scenario/scenario_8740_expel_switch_cause.cpp（号段 8740-8749）。
