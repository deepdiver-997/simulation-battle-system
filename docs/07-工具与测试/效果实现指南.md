# 效果实现指南（AI 贡献者主工作流）

一个效果的完整落地 = 查库 → 插件 → 场景 → 变异 → 全量门 → PR。
每一步都有机器可验证的完成标志，不需要任何人工"感觉上对了"。

## 1. 查库：效果的事实来源（只读 SQLite）

```sql
-- 模板句与参数个数（{n} 占位符与 args_num 一一对应）
SELECT id, info, args_num FROM effect_info WHERE id = <effect_id>;

-- 哪些技能引用它（载体清单，PR 描述里贴这个）
SELECT m.id, m.name FROM moves m, json_each(m.side_effect) j
 WHERE j.value = <effect_id>;
```

数据库从社区镜像构建（`scripts/fetch_seer_unity_bytes.py` →
`scripts/decode_seer_bytes.py` → `tools/db_patches/apply_all.sh`），产物
`scripts/data/processed/seer_unity.sqlite` **不入库**。

**写效果不信任切片、先读模板**：`side_effect` 的参数是扁平数组，必须按
`effect_info.args_num` 切分、以模板 `{n}` 占位符理解每个下标的语义。

## 2. 实现插件

- 文件放 `resources/moves_lib/`（技能效果）/ `resources/soul_lib/`（魂印，
  `SOUL_MARK`/`SOUL_PROGRAM`）/ `resources/suit_lib/`（套装）；
- `SKILL_EFFECT(<id>, …)` 声明即注册，**id 留编译期**——写错编译不过，
  重复注册触发撞号审计（strict 门直接失败）；
- 文件头注释三要素：effect_id、实现理由（模板短句可引一句作锚点，禁整段照搬）、
  证据链接（社区解析帖 / 实测记录 URL）——CI 对新增文件做引注检查；
- 参数经 EffectArgs 读官方切片；需要跨时点状态走内核原语与 TimedBucket，
  **不裸写 BattleContext**。

## 3. 场景测试

- `test/scenario/scenario_<序号>_<名>.cpp`，序号在既有最大号上递增；
- 真实 `BattleFsm` + `main()` 内 assert，头注写：被测效果 / 对照组设计 / 断言点；
- 断言只对可观察行为（HP / 异常 / 时点顺序 / 管线驻留值）；
- 构建系统 GLOB 自动发现，无需改 CMake。

## 4. 变异验证（MUT：场景有没有锁定力）

摘除你的实现 → 场景必须转红；还原 → 复绿。转不了红说明场景断言和实现
没有咬合，等于没测。

## 5. 全量门

```bash
cmake --build build -j8
# 全量场景回归（每个 sim_scenario_* 二进制依次跑）
for b in build/sim_scenario_*; do "$b" || echo "FAIL $b"; done
./build/sim_server --dump-registry-exit build/registry.json   # 注册表对账
```

CI 会跑同一套（PR 只跑变更相关场景， nightly 跑全量）。

## 6. PR

按 `.github/PULL_REQUEST_TEMPLATE.md` 填：分类 / 场景号 / MUT 证据 /
门结论 / 引注。纯新增 + E1 引注 + CI 全绿 = 自动合并。

## 7. 边界自查（提 PR 前 30 秒）

- 我改的文件只落在 `resources/` 与 `test/scenario/`？碰了 `src/` `include/` 请拆 PR；
- 我有没有发明 id？载体清单里查得到它吗？
- 我的注释有没有整段照搬官方文本？短句锚点可以，语料不行；
- 这个效果在 `docs/07-工具与测试/内核耦合效果清单.md` 里吗？在就开 issue。

## 8. 显示面义务（2026-11-22 起）

效果显示的完整规范见《`效果显示gate规范.md`》（同目录）。主循环三条增量义务
（G4 落地前"先登记后实现"）：

- 跨时点计数状态优先走桶/票/Mark；确需 `plugin_storage` 时 key 用 STATE_DISPLAY 登记，
  禁止裸魔数 key 无显示地散落；
- 场景若含"挂 buff/上票/加印记"路径，补一条 fullstate 含本效果条目的显示断言；
- 描述可解析是 PR 义务：effect id 在 effect_info 无模板（soul 空间无 tips）时 PR 里注明缺口。
