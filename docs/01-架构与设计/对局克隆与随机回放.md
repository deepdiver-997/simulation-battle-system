# 对局克隆与随机回放

克隆解决的是「让两局从同一状态各自继续」；随机回放解决的是「在重跑时，有选择地固定某次随机的结果」。**克隆保留 RNG 的当前位置，因此只做克隆不会得到新的随机样本。** 这两个功能也都不是从 C++ 函数中途恢复执行。

## 从哪里调用、从哪里读

库调用者想自动拿到分支时，从 [`LocalBattleControl`](../../include/fsm/local_battle_control.h) 开始：`set_auto_branching(id)` 后，`run(id, input)` 返回已到达下一等待输入点或终局的分支 ID、权重和轨迹。用 `inspect(id)` 看状态，用同一个 `run` 继续，用 `close(id)` 丢弃。应用不用自己 clone。第一份输入已经能触发随机，因此一次 `run` 只消耗一份输入，不会等第二位都交好才启动回放。完整用例见[公开示例](../../examples/public/native_branch_demo.cpp)。

引擎维护者已经持有本地 `BattleCloneBranch` 时，从 [`battle_clone.h`](../../include/fsm/battle_clone.h) 的 `clone()` 开始。它内部持有源的推进锁；调用方仍要串行使用分支，但不要再持有 `run_mutex`：

```cpp
std::string error;
auto fork = branch.clone(error);  // 不推进原件，也不推进副本
if (!fork) {
    // error 说明该暂停点或所含组件为什么不能克隆。
    return;
}
const auto result = fork->run();  // 继续运行，到等待输入、终局或报错
// 若从等待输入点克隆，run() 不会凭空生成动作，请使用 fork->submit(...)。
```

如果持有的是 `LocalBattleControl` 内的对局 ID，用 `control.clone(id)`；它给副本分配本地 ID，不对外复用旧事件历史。持有独占源的底层调用者走 `BattleClone::owned_at_decision()`。该底层入口要求调用方已持有源锁和控制块的独占许可，只接受输入决策点。不要混用两种锁约定。引擎内部的分支对象不等于客户端协议中的房间或观察。

```text
branch.clone(error)         已有本地分支，内部加锁
owned_at_decision(...)      已持源锁与独占许可的调用方，只接受决策点
       │
       ▼
owned_from_pause：校验暂停位置和源所有权 → 审计所有要复制的组件
       │
       ▼
新控制块 + 新 FSM + 新 BattleContext → 复制数据并重绑引用 → 返回独占副本
       │
       ▼
副本 submit / step / run → 从 currentState 的 handler 入口继续
```

读源码时，先看 [`battle_clone.cpp`](../../src/fsm/battle_clone.cpp) 里的 `owned_from_pause`，再看 [`battleFsm.cpp`](../../src/fsm/battleFsm.cpp) 的 `run_loop` / `runInternal`。要找局内数据，再看 [`battleContext.h`](../../include/fsm/battleContext.h) 和 [`battleWorkspace.h`](../../include/fsm/battleWorkspace.h)：前者拥有整个对局，后者是里面那份每回合重置的工作区。

## 哪个位置可以继续跑

| 暂停位置 | 续跑含义 | 当前支持 |
|---|---|---|
| 等待输入 | 没有待消费的输入包。可以保留本回合已收好的一方动作；下一份输入从正常入口提交。 | 支持通过输入点准入的对局。 |
| 下一时点入口 | 上一 handler 已返回、事件投递和采样已结束；下一 handler 还未执行。 | 本地分支的显式 `step()` 真正抵达 `BATTLE_FIRST_MOVE_RIGHT` 时支持。其它非输入入口尚未放行。 |
| handler、事件回调或 `drain` 中途 | 可能已经消费标志、更新工作区或改了状态号，还有没结束的栈帧。 | 不支持续跑；要从更早的入口重跑。 |

`branch.step()` 最多执行一个完整时点；`branch.step(player, action, index)` 先按 `submit` 的规则校验并放入一份动作，再至多执行一个时点。若还在等待输入而没有动作可消费，单步可以成功返回但不前进。它不借用网络调试标志。比如在一局双方同速、同先制的测试里，两边逐个提交 `Skip`，再单步到 `BATTLE_FIRST_MOVE_RIGHT`，此时可以克隆。原件和副本都从先手 handler 第一行执行，各掷一次等速先手，结果相同。要在运行中查看 `context()` 时只读它，不要手改推进状态来制造入口。

为什么不看 `currentState` 就直接复制？FSM 在 handler 内可能已经把状态号改到下一时点，**随后**才排空上一步的事件；而事件中心会把正在投递的一波搬到栈上的局部队列。反过来，handler 可以在状态号尚未变化时先消费一笔状态。例如回合开始的强制驱逐先清待处理标志、后抽替补；此处中断后即使状态号不变，重新进入也可能跳过驱逐。复制 `BattleContext` 不会复制这些局部变量与执行位置。故只在明确停下的入口建立副本，不在函数内部加 `goto`，也不在持推进锁的回调里同步重入同一个 context。

## 复制了什么，为什么不是整类赋值

| 组件 | 复制方式与原因 |
|---|---|
| FSM、控制块、锁 | 新建独立这一套，把副本的 `m_fsm` 指向新 FSM。只接受默认 handler 表，不共享 Room、外部终局回调、输入调度或控制块临时载荷。 |
| 阵容、回合字段、工作区、RNG | 复制已经结算到的值，包括 RNG 位置、抽数计数和已收动作。专用构造器重绑副本内部引用，不重新装配或激活装备、魂印、插件，也不重放建局效果。 |
| 参数、技能和插件状态 | 效果参数必须拥有自己的 backing，并在复制后重绑参数视图；审计过的不可变解析程序可以共享。未知 `std::any`、外借 `extra`、未经审计的效果/魂印与运行回调不能盲拷。 |
| 效果时点桶、伤害管线 | 已审计的技能桶节点逐个深拷，保留键和寿命计数。其它时点桶不能携带未支持的动态节点。红伤、粉伤管线分别检查已安装的回调，再复制管线状态。 |
| 规则、事件 watcher、事件带 | 保留已审计条目、ID、索引及下一个 ID。复制已有事件带和序号，把事件 sink 改绑到副本自己的事件带。待派发事件、派发中状态和外部 sink 不跨检查点。 |
| 活动随机回放 | 不复制。原生 `run` 在 `ctx` 的回放槽中拥有这一趟的记录和游标；旧探针也可能借用解析器。源还有活动回放时直接拒绝，控制器只在干净入口暂时摘下后保存副本。 |

克隆失败应该让源局原样留在原地，而不是悄悄略去会影响恢复的成员。新增状态时，先分类：是要复制的值，是副本需重绑/重建的引用，还是没有审计就必须拒绝的外部状态？可变数据要证明两边独立，不可变共享要说明所有权和有效期；回调还要证明不捕获源局的数据。新增检查点时，还须用真实 FSM 抵达并比较恢复后的状态、抽数和事件，而不能只把测试上下文的 `currentState` 改成目标值。

## 随机回放怎样接到克隆上

1. **选择起点。** 从同一安全决策根复制一局，在第一份输入前装上临时解析器。输入本身就可能换宠、触发 watcher 和随机判定，不能等出招才装。
2. **正常走 FSM。** 平常的随机包装直接取票。回放时，有语义的包装将规则/子位点、双方、当前状态和有效候选分布等信息交给解析器。稳定标识不是本次对局第几次调用。解析器可以让该点按自然结果采样，也能给出一个合法的固定结果。
3. **核对选择，保持抽数。** 不按队列盲弹结果：同一规则可能因为场上状态改变概率或候选顺序。重跑时要核对对应的位点和有效分布，确认结果仍有效；强制结果也消耗自然路径会消耗的 RNG 票，包括重抽规则。有些单一结果仍耗票，有些（如 0%/100% 的百分比）不耗，遵从各包装的契约。纯采样点仍影响战斗，但不会凭空成为可展开的树边。
4. **退出 FSM 后派发。** 已指定的结果在运行中依次核对；新点取一个合法结果继续，并记下候选。回到控制侧以后，才把兄弟结果连同它之前的选择记成待办，从最近的已验证检查点重跑，不接着跑已经中断的 handler。更换结果之后的路径重新发现。位点或前缀漂移是重放失败，不是战斗输赢。只有下一正常决策或终局才交付可继续的子局，中间检查点不对外交付。

随机契约看 [`binary_chance.h`](../../include/fsm/binary_chance.h) 的 `ChancePoint` / `ChanceResolver`，抽数实现看 [`battleContext.cpp`](../../src/fsm/battleContext.cpp) 的 `choose_weighted_impl` 与区间包装。调用者可以让后段的兄弟从 `BATTLE_FIRST_MOVE_RIGHT` 入口续跑；入口之前发生的状态变化和 RNG 位置已经在快照里，不重复提交输入。无法另存该入口时，仍可回到原决策点重跑。另见[调度层导航](../00-组件导航/include-fsm.md)。
