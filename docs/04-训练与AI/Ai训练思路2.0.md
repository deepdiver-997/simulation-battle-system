# 原作游戏回合制对战AI训练方案（技术总结）

## 一、项目概述

目标：训练一个能在原作游戏回合制对战中达到高水平的AI，处理部分可观测信息（敌方数值、配招、道具等隐藏），并具备段位自适应能力。

核心思路：基于AlphaZero框架，但扩展到POMDP（部分可观测马尔可夫决策过程），通过信念状态处理隐藏信息，结合MCTS搜索与自对弈训练。

## 二、模拟器设计（基础）

1. **必须精确实现**：
   - 属性克制表（18种属性循环）
   - 伤害公式（含随机浮动0.85~1.0、STAB、属性克制、暴击）
   - 所有异常状态（烧伤、冻伤、中毒、睡眠、麻痹等）及持续效果
   - 换精灵机制（上场回合、出场效果）
   - 天气/场地效果
   - 道具效果（剩饭、气势披带、生命宝珠等）
   - 特性效果（普特/梦特）

2. **概率性机制**：
   - 命中率（按官方数值实现）
   - 暴击率（一般1/24或特定技能更高）
   - 技能附加效果触发概率（如10%烧伤）
   - 随机浮动因子（0.85~1.0）

3. **验证**：用已知对战案例（如社区录像）测试模拟器输出是否与真实一致。

## 三、状态表示（信念状态）

由于敌方配置部分可观测，不使用完整真实状态，而是维护**信念状态**：

```
信念状态 b = {
    'my_team': [精灵1, 精灵2, ...],          # 己方完整信息（已知）
    'active_enemy': {

        'hp_percent': float,                 # 可见血量百分比
        'hp_range': [min, max],              # 通过伤害反推的HP范围
        'stats_range': {                     # 通过伤害反推的数值范围
            'atk': [min, max],
            'def': [min, max],
            'spa': [min, max],
            'spd': [min, max],
            'spe': [min, max]
        },
        'used_moves': list,                  # 已使用的技能（可见）

        },

            'intimidate': 0.6,

```

**编码为神经网络输入**：将上述结构化数据展平为固定长度向量（如512维），注意归一化数值范围。

> ⚠️ **`my_team` 的"已知"只在对战内决策这一层成立。** 它在**对手视角下是私有信息**（对手并不知道你带了哪 6 只、带什么配置），而"选配置"本身是决策变量、不是常量。这一层不在本文范围内，见 `配置选择与BP建模.md`。

## 四、敌方推断模块

### 4.1 伤害反推数值（确定性计算）

基于原作游戏伤害公式（类似宝可梦）：

```
damage = floor(floor(floor(2*level/5+2)*attack*power/defense)/25) + 2
damage *= random_factor (0.85~1.0)
damage *= STAB (1.0 或 1.5)
damage *= type_effectiveness (0.25/0.5/1/2/4)
damage *= critical (1.0 或 1.5)
```

已知：己方攻击值、技能威力、等级、属性克制、暴击与否、实际伤害
未知：敌方防御值、随机浮动因子

**反推公式**：

```
base_damage = damage / (STAB * type_eff * crit_mult)
# base_damage 已去除所有乘算因子，剩下：
# base_damage = floor(floor(2*level/5+2)*attack*power/defense)/25 + 2
# 忽略 floor 的整数舍入，近似：
defense ≈ floor(2*level/5+2)*attack*power / ((base_damage - 2)*25)
```

由于随机因子在0.85~1.0之间，可得防御值的**范围**。多次观测后范围收窄。

### 4.2 配招推测（贝叶斯更新）

1. 建立主流配招库：每个精灵常见的3~5种配招组合
2. 先验概率：根据段位/环境设定（低段位冷门配招概率稍高）
3. 观测到使用某个技能后：剔除不包含该技能的配招组合，归一化剩余概率
4. 若观测到四个不同技能：配招完全确定

### 4.3 道具/特性推测

基于行为模式：
- 每回合回血 → 剩饭
- 承受致命伤存活 → 气势披带
- 使用自残技能（如舍身冲撞）且无副作用 → 可能携带生命宝珠
- 速度突然变化 → 可能携带围巾/专爱系列
- 特性触发效果（如威吓登场减攻击） → 确定特性

### 4.4 对手画像更新

- 段位：从对战平台获取（已知）
- 风格：前2~3回合统计技能选择倾向（攻击技能比例、换精灵频率）
- 水平：基于操作合理性（是否打出明显失误，如无效换人）

## 五、MCTS 在 POMDP 中的改造

### 5.1 标准 MCTS（完全信息）回顾

```
每个节点 = (状态 s, 父节点)
- 选择：根据 UCB1 公式选择子节点
- 扩展：添加新子节点（合法动作）
- 模拟：从新节点用默认策略 rollout 到终局
- 回溯：更新路径上所有节点的访问次数和价值
```

### 5.2 原作游戏场景的改造

由于敌方配置不确定，MCTS 节点应基于**信念状态**而非真实状态。

**方案A（推荐，简单有效）**：在每个 MCTS 节点，从信念状态中**采样一个具体的敌方配置**（数值、配招、道具、特性），然后在这个具体配置下用模拟器推演。多次搜索后，结果自动集成不确定性。

```
function mcts_search(belief, num_simulations):
    root = Node(belief)
    for _ in range(num_simulations):
        node = root
        # 1. 选择
        while not node.is_terminal and node.is_fully_expanded:
            node = select_child(node)  # UCB1
        
        # 2. 扩展
        if not node.is_terminal:
            action = select_unexpanded_action(node)
            # 从当前信念状态采样一个具体敌方配置
            sampled_config = sample_from_belief(node.belief)
            # 用模拟器推演一步（己方动作 + 对手反应）
            next_belief = simulate_step(node.belief, action, sampled_config)
            child = Node(next_belief)
            node.add_child(action, child)
            node = child
        
        # 3. 模拟（rollout）
        value = rollout(node.belief)  # 使用快速策略（如heuristic）
        
        # 4. 回溯
        while node is not None:
            node.visits += 1
            node.value += value
            node = node.parent
    
    # 返回访问次数最多的动作
    return best_action(root)
```

**关键点**：
- 每个节点保存的是信念状态，而非具体状态
- 展开节点时，从信念中采样具体配置，用模拟器推演一步，然后**更新信念**（根据新观测）
- 多次搜索自然集成了不确定性

**方案B（更精确但复杂）**：每个节点维护信念状态，展开时考虑所有可能的对手反应（概率加权），形成信念树。但计算量过大，不建议。

### 5.3 对手模型

MCTS 模拟对手动作时，应根据对手画像选择策略：

```python
def get_opponent_action(belief, opponent_profile):
    if opponent_profile['estimated_level'] < 0.3:
        return heuristic_ai(belief)  # 低水平：规则AI
    elif opponent_profile['estimated_level'] < 0.7:
        return my_policy_net(belief)  # 中等水平：使用当前策略网络（但可能较弱）
    else:
        return my_policy_net(belief)  # 高水平：使用强策略网络
```

也可以用一个统一的对手模型（如另一个神经网络）输入对手画像输出动作。

## 六、训练流程

### 6.1 阶段一：上帝视角预热（Oracle 模型）

**目标**：训练一个知道完整信息的强策略网络，作为后续 POMDP 训练的教师。

**方法**：
1. 模拟器提供完整状态 S（包括敌方所有隐藏信息）
2. 用 AlphaZero 标准流程训练 Oracle 模型：
   - 神经网络输入：完整状态 S（编码为向量）
   - 输出：策略 π_oracle(S)、价值 V_oracle(S)
   - 训练数据：自对弈（双方都用 Oracle + MCTS）生成的 (S, π_MCTS, z)
3. 训练至收敛（约50万局自对弈）

**产出**：Oracle 策略网络 π_oracle，能在已知敌方配置时做出最优决策。

### 6.2 阶段二：敌方推断模块训练

**目标**：训练从观测序列到敌方配置后验分布的映射。

**方法**：
1. 用阶段一的模拟器生成大量对局数据，记录：
   - 完整观测序列 [o_1, o_2, ..., o_T]
   - 真实敌方配置（数值、配招、道具、特性）
2. 训练一个推断网络（或直接用贝叶斯公式+你的小工具）：
   - 输入：历史观测序列（或当前信念状态摘要）
   - 输出：敌方配置的分布参数（如数值范围的均值和方差、配招概率向量等）
3. 也可以用纯贝叶斯更新（无需训练），但神经网络可以学习更复杂的模式（如根据对手行为推测风格）

**注意**：如果你的伤害反推和贝叶斯更新逻辑足够准确，此阶段可以省略神经网络，直接用确定性代码实现。

### 6.3 阶段三：POMDP 策略训练

**目标**：训练一个在部分可观测条件下决策的策略网络。

**方法**：

1. **数据生成**：
   - 在模拟器中自对弈，但只给模型观测（隐藏敌方配置）
   - 使用 Oracle 模型作为"教师"：
     - 对当前信念状态 b，从敌方配置分布中采样 K 个具体配置
     - 对每个采样配置，用 Oracle 模型计算最优动作 a*
     - 用期望价值加权：选择期望价值最高的动作作为"教师动作"
   - 记录 (b_t, π_teacher, z) 作为训练数据

2. **网络训练**：
   - 输入：信念状态 b_t（编码为向量）
   - 输出：策略 p(b_t)、价值 v(b_t)
   - 损失函数：L = (z - v)² - π_teacherᵀ log p + 正则项
   - 类似行为克隆（Behavior Cloning），但使用教师策略而非 MCTS 策略

3. **迭代改进**：
   - 用当前 POMDP 策略网络替换教师中的 Oracle（或与 Oracle 混合）
   - 继续自对弈生成数据，训练更新
   - 最终模型应学会在不确定性下做出鲁棒决策

### 6.4 阶段四：端到端强化学习微调

**目标**：进一步优化 POMDP 策略，使其超越教师（Oracle）的水平。

**方法**：
1. 用阶段三的 POMDP 策略初始化网络
2. 在模拟器的部分可观测模式下进行自对弈
3. 每步决策使用 MCTS（方案A），记录 (b_t, π_MCTS, z)
4. 用这些数据继续训练网络（标准 AlphaZero 损失）
5. 此时网络直接学习从信念状态到最优策略的映射，不再依赖 Oracle 教师

### 6.5 阶段五：真实环境校准

**目标**：弥合模拟器与真实官方的偏差。

**方法**：
1. 将模型部署到真实对战平台（通过 API 或手动输入）
2. 收集真实对局数据（包括隐藏信息的逐步揭示）
3. 对比模拟器预测与真实结果，找出偏差最大的机制
4. 修正模拟器规则（如伤害公式、特性效果）
5. 用真实数据微调 POMDP 策略网络（offline RL 或 DAgger）
6. 重复以上步骤，直到模拟器与真实环境一致

## 七、段位自适应策略

**原则**：不需要训练多个模型，在信念状态中加入对手画像即可。

**训练数据多样化**：
- 60%：自对弈（高水平）
- 30%：vs Heuristic AI（中低水平）
- 10%：vs 随机策略（极低水平）

**推理时**：
- 输入段位信息（从平台获取）
- 前2~3回合快速推断对手风格
- MCTS 中的对手模型根据对手画像选择（低段位用 heuristic，高段位用策略网络）
- 可调整风险偏好参数 λ：低段位 λ > 0（冒险），高段位 λ < 0（保守）

## 八、关键参数与超参数

| 参数 | 推荐值 | 说明 |
|---|---|---|
| MCTS 搜索次数（训练时） | 400~800 | 平衡质量与速度 |
| MCTS 搜索次数（推理时） | 800~1600 | 更高质量 |
| 自对弈局数（Oracle） | 50万 | 视收敛情况 |
| 自对弈局数（POMDP） | 20~50万 | 视收敛情况 |
| 信念采样数 K | 5~10 | MCTS 节点展开时采样数 |
| 折扣因子 γ | 0.97~0.99 | 鼓励速胜可降低 |
| 风险偏好 λ | 0（中性） | 可在线调整 |
| 学习率 | 0.001（Adam） | 可衰减 |
| 批次大小 | 256~1024 | 视显存 |
| 网络架构 | ResNet 或 Transformer | 输入维度约512，输出策略维度=动作数 |

## 九、潜在陷阱与对策

1. **模拟器偏差**：定期用真实数据校准，重点关注伤害公式和特性效果。
2. **信念状态坍缩**：如果敌方推断模块过于自信（分布过于尖锐），可能导致模型误判。可加入狄利克雷噪声或保持最小概率。
3. **MCTS 搜索不稳定**：由于信念采样带来的随机性，MCTS 结果可能有方差。增加采样次数 K 或提高 MCTS 模拟次数可缓解。
4. **训练不稳定**：POMDP 训练初期，教师策略可能不一致（因为 Oracle 对不同采样配置给出不同动作）。可采用 DAgger 算法，逐步让模型参与数据生成。
5. **过拟合**：确保自对弈数据多样性（不同配招、不同策略风格）。
