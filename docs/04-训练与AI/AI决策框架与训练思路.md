# AI 决策框架与自博弈训练思路

整理时间：2026-08-03

说明：

- 本文从原作游戏 PVP 对战框架出发，梳理"为什么手写规则会输、为什么需要模型、模型在决策里到底扮演什么角色、以及后续怎么训练"的一整套理解。
- 本文是训练方向的前置设计笔记，供后续实现自博弈 / 强化学习时参考。
- 核心结论：游戏 AI、搜广推、LLM 解码是同一个骨架——**打分函数 + 候选集 + 选择/搜索**。本项目本质是 AlphaZero 形状，不是 LLM 形状。

## 一、统一视角：一切决策系统都是"打分函数 + 候选集 + 选择/搜索"

- **候选集**：游戏 = 当前所有合法操作；搜广推 = 召回阶段筛出的物料子集；LLM = 词表。
- **打分函数**：给定状态 / 上下文，给候选集里每一个元素打一个分。
- **选择/搜索**：argmax / top-k / beam / MCTS 决定最终输出哪一个。

| 系统 | 候选集 | 打分函数 | 选择/搜索 |
| --- | --- | --- | --- |
| 原作游戏 AI | 当前合法操作 | 价值函数 V(s) | MCTS / argmax |
| 搜广推 | 召回物料子集 | pCTR / pCVR 模型 | top-k |
| LLM 解码 | 词表 | transformer 权重 → P(token\|context) | greedy / sampling / beam |

结论：游戏不需要"特殊性"的算法，它和搜广推、LLM 是同一个骨架，区别只在候选集大小、以及打分函数的参数从哪来。

## 二、为什么手写规则一定会输：近视打分 vs 远期价值

典型翻车案例：

> 当回合多杀对面一个精灵（本回合的局部最优）→ 结果吃下了对面专门的拦截 / 反制 → 自身状态崩坏 → 被对手主力找到启动机会一波平推。

手工规则只能编码"遇到某个精灵该做什么"，它编码不了"做完这个动作之后的那个状态值不值"。击杀是当下的收益，而状态是否会被反制、主力能否启动，是未来的价值——规则没有"状态价值"这个概念。

结论：**不要标注策略（"遇到 X 就做 Y"），标注结果（胜率），让价值函数自己从对局里长出来。** 这是"近视打分必须被远期价值纠正"的具体体现。

## 三、为什么纯模拟器不够：三个前提缺一不可

理论上"完美模拟器"就能杀死比赛，但需要同时满足三个条件，本项目目前一个都不满足：

1. **完美规则**：引擎 FSM / 时点 / 断回合 / 结算必须完全正确，目前尚未实现完。
2. **足够算力**：50 回合的分支是组合爆炸，回合选择时间到了也算不完所有路径。
3. **完全信息**：对面隐藏数值未知，且伤害计算有随机浮动。

其中第 3 点是本质难点，专业上叫**部分可观测随机博弈（POSG）**：

- 对面防御 / 速度 / HP 只能从观测数据（伤害数字、HP 条、换宠）反推；
- 每次伤害都是带噪观测，反推结果是**分布不是点**——伤害浮动存在一天，就永远无法"完美反推"；
- 因此正确做法是维护一个**贝叶斯信念分布**，每次观测让它收窄，并让策略对整个分布鲁棒，而不是赌一个猜测。

但请注意：以上只覆盖了"**我看不到对手**"这一半。另一半是"**对手看不到我**"——己方配置（精灵 / 配招 / 道具 / 特性）在对手视角下是私有信息，而它本身又是你开局前要做的决策。这一层不是 POMDP 而是元博弈，见 `配置选择与BP建模.md`。

## 四、模型（价值函数）的真正作用

模型在决策里的本质作用是**在搜索前沿估值**：

> 搜到某一层（受时间预算限制）就停，模型负责估算"从这个局面继续打下去到终局的期望价值"。

由此派生出两个效果：

- **剪枝 / 引导搜索**：每个局面都有可靠价值分，搜索才知道往哪个分支多投算力。这是估值的副产品。
- **隐式处理不确定性**：V(s) 在定义上就是对训练分布中随机浮动和对面配置的期望平均。模型把"你不知道的东西"压缩进打分里，决策时不必再手动处理那团不确定性。

关键红线：**估值错了，剪枝就会剪掉好分支。** 价值函数错了，最优行为会被当成分支砍掉——这是"优化一个坏目标到全局最优依然是垃圾"的根本原因。

## 五、价值函数怎么写：硬约束用过滤，不用权重

- **硬约束（关键精灵绝对不能死）用过滤 / 词法优先级**，不用权重。有限权重永远可以被"别的收益买走"，只有先过滤掉致死方案、再在安全方案里打分，才能保证不死。
- **权重是"凸性"的粗糙近似**：按"还能扛几回合"（HP / 每回合期望承伤）排序，比线性权重按 HP 下降更接近真实的危险度。
- **未来价值是条件期望，不是常数**：未来价值 = 期望产出 × 存活概率 × 未来真的需要它的概率（例如护卫 / 治疗的权重 = 吞吐量 × 存活折扣 × 后续威胁概率）。

## 六、每回合决策循环（MCTS 形状）

1. **观察**：收集系统输出的数据（伤害数字、状态变化、对面显形）；
2. **估计**：更新对对面隐藏数值的信念分布；
3. **枚举**：生成当前所有合法操作；
4. **模拟 + 估值**：用模拟器把每个操作向前推若干层（时间预算内），前沿局面用价值函数打分；
5. **选择**：取期望价值最高的操作。

模拟器负责第 4 步的"下一步结果"，模型负责第 4 步的"这个结果以后值多少"。

## 七、训练路线：自博弈强化学习

自博弈 RL 需要三件套，本项目已经具备前两件：

1. **模拟器** ✅（战斗引擎本体，已完成大部分）；
2. **高频对局接口** ✅（`LocalTrainingRunner`：`submit_action` / `run_until_need_input` / `snapshot` 已设计）；
3. **算法** ❌（待实现）。

关键点：

- **胜率是唯一标签**，不需要人工标注策略；
- **对手必须是自博弈**（两个正在学习的自己互打），不是固定脚本——打固定脚本只能学会"怎么赢这个脚本"，不是通用策略；
- **鸡生蛋问题**：评估当前策略 → 改进 → 再评估，迭代进行（policy iteration），不能一步到位；
- **黑盒不可解释但能力强**：黑盒 = "不能自我解释"，≠ "不可分析"——有模拟器就能做反事实 / 消融 / 行为模式提取；
- **务实的 MVP**：先用 MCTS + rollout 估值（不学神经网络），用模拟器生成海量对局、拟合一个简单价值函数，再迭代换强。

## 八、和 LLM 解码 / 搜广推的对照

- **LLM 解码**：词表就是候选集（自包含在模型文件里，输出层维度 = 词表大小）；每步对全词表打分（上下文 + 权重共同决定），解码策略（greedy / sampling / beam）做选择。
- **游戏 vs LLM 的结构差异**：游戏有"便宜的精确 oracle"（规则 / 模拟器），推理时负担得起搜索 → **AlphaZero 形状**；文本没有这种 oracle，只能靠模型本身 + beam → **LLM 形状**。本项目本质是 AlphaZero 形状。
- **搜广推**：召回 = 搜索 / 建候选集，精排 = 打分 + top-k，pCTR / pCVR = 概率模型。骨架之外的真实难点在数据侧：有偏日志（曝光偏差 / 位置偏差）、代理目标 vs 真实目标（点击率只是留存 / GMV 的代理）、多目标加权。

## 九、下一步

1. 把 FSM / 时点 / 断回合 / 结算逻辑补齐并验证（模拟器正确性是自博弈的地基：垃圾模拟器 → 垃圾策略）；
2. 实现训练通道（`LocalTrainingRunner`，绕过 socket 的进程内接口）；
3. 跑通"枚举 + 单回合精确结算 + 简单价值函数"的决策闭环，作为 MVP；
4. 再迭代为"自博弈生成对局 → 拟合价值函数 → 改进策略"的完整循环；
5. 补引擎的**可见性投影层**（内部真值 → 各玩家观测），并让训练通道对外只暴露观测、而非整个 `BattleContext`。否则网络会学到"偷看对手队伍"的捷径，上线必崩（见 `配置选择与BP建模.md` §5.2）；
6. 对战层跑通后，再把**配置选择与 BP** 建模为独立的元层，接口是胜率（同上文 §二、§六）。
